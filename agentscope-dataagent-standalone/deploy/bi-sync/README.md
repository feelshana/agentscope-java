# BI七表镜像任务

新增六表使用独立 [extra_sync.py](extra_sync.py)，不会加入本脚本或改变旧控制进度/02:00任务。部署和02:15新调度见 [六表指南](../../docs/guides/66-bi-extra-sync.md)，业务字段与单位见 [DDL](extra-schema.sql) 和 [业务口径](extra-business-rules.md)。

入口和完整阶段命令见[66正式库切换与BI同步](../../docs/guides/66-formal-database-and-bi-sync.md)，实施范围见spec109/ADR0125。只作为固定数据同步工具，不提供任意SQL接口或5.7问数兼容。

2026-11-05扩展口径（ADR0139/spec119）：95个业务字段，见本目录source-selects.sql和业务口径.md。项目3列、关系4列、人员18列(原表排除password/phone/email)、报表23列、仪表盘39列（仅排除明确的配置字段）、日志各4列。全部操作类型同步，不存log_type，统计仅称操作记录数，不能区分查看/导出。源库禁止新增索引；利用既有项目+时间索引取数和计数，项目从日志索引枚举，覆盖已删除项目，不依赖当前项目维表。

`configure.py`交互生成服务器私有database.env和bi-sync.json，密码不接受命令行参数；模板不可填写真实密码后提交。`bi_sync.py`依赖运行镜像已有mysqlclient，不需要66额外联网安装。`docker/bi-sync.sh`以应用相同不可变镜像运行，源/目标不经Wren查询。

| 命令 | 行为 |
| --- | --- |
| check | 只读检查两端版本/连接、所需字段、两日志既有项目+时间索引；缺少则拒绝，不建源索引 |
| migrate | 已有任务暂停后，核对源/目标并为两对象表追加列；保留所有日志及进度，支持跨表中断续作 |
| refresh-basics | 暂停下全量刷新五基础表并核对计数、标记新增字段已补齐；不访问日志数据或推进水位 |
| init | 检查任务归属后创建7表和控制表；不复制业务数据 |
| sync | 首次从2026-01-01开始，按项目已提交进度补齐至东八区今天00:00；每次刷新5张维表 |
| verify | 只读对账维表计数和日志逐日计数，默认全年已完成日范围 |
| status | 只读输出success_until及两张日志的exclusive水位；null代表尚无整批成功 |
| pause | 仅连目标，持久暂停后续同步；运行作业协作退出，需status确认running=false |
| resume | 仅连目标，解除暂停；不立即执行，不自动恢复cron |

sync取得互斥锁后，用独立目标连接记录last_run的起止/结果/耗时/固定失败阶段，源连接失败也能记录；目标不可达时无法持久记录，页面提示不可用或中断。暂停标记经独立自动提交观察连接读取，不受正在写入事务旧快照影响。固定错误摘要不保存驱动异常原文、SQL或密码。最近成功日期与最新运行结果分开，旧数据可用不表示最新任务成功。

管理员只读页面在“更多→BI数据同步”，从Java应用已有数据集连接读取固定元数据，不依赖此JSON、源库或Shell。定时任务退役使用`python3 docker/install-bi-sync-cron.py remove`，只移除本工具精确匹配的任务；先pause并确认退出，详情见主指引H。删除知识库/取消全员权限不自动停任务，暂停不删数据。

`--until YYYY-MM-DD`表示不含该日，不能晚于东八区今天。每个项目当日写入、私有计数账本和项目进度同事务提交；表截止日只在全部项目完成且账本日计数与目标核对后更新，整批截止日只在7表成功后更新。日志空日批量推进，避免逐项目逐空日大量提交。sync失败可原命令重跑；不使用日志最大ID，不每天重扫已完成事件。verify按日志项目索引核对源历史与目标逐日计数，不是全行内容校验；此版不自动修复迟到/历史修改删除，发现差异先停任务核对，不删除控制表强行重来。

五张维表每张上限10万行，先全部读取成功再同事务替换，失败不暴露空表。日志项目枚举上限10万个，字段只用于源索引分段，不落业务日志；支持空值/空字符串项目(源实际字段NOT NULL)，值全部参数化。每个项目按时间窗口一次流式读取，以(log_time,id)稳定排序，避免每页或每天反复扫描全表。用户提供的项目833/项目枚举EXPLAIN均使用既有索引，但不代表所有项目的实际同步耗时已验收。

首次部署沿用v2-basic任务归属，使用95列新结构；现有39列任务须显式migrate再refresh-basics，不修改owner、不重新init。若之前手工运行过旧46列版本，脚本会拒绝复用，保留原数据，不自动ALTER/DROP；先核对现场后另定迁移，不能强改owner标记。源库一律不发DDL。

只读问数账号只授予7张bi_业务表SELECT（DBA模板readonly-grants.sql.example），不包含bi_sync_control，不包含平台表、其他上传表或写权限。该模板没有建用户权限和密码，现有应用双库ALL不等于可创建/授权新账号。

新建公共知识库后关联同一个正式MySQL8数据源的7张表，上传本目录业务口径.md，整理字段/角色/日志时间范围、建模试问并发布。不要把控制表关联给问数助手，不导入参考答案。资料中的日期是示例，按现场已同步范围调整。

已有线上任务扩字段按[对象字段升级指引](../../docs/guides/66-bi-asset-fields-upgrade.md)执行；先旧代码pause并确认running=false，再更新源码。DDL有隐式提交，失败保持暂停重试migrate，不能直接运行旧脚本回退；升级/补齐过程不重置日志进度，不重装cron。本次用户明确不备份。

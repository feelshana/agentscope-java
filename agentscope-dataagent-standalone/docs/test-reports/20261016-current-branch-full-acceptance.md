## 已确认问题（持续补充）

### P1：例行任务没有用户归属隔离

创建者建立一个生效日在 2099 年、无收件人、已暂停的任务。无该库权限的另一账号调用 GET `/api/scheduled-tasks` 能看到任务，PUT 同一任务 ID 返回 200 并改名成功；随后恢复原名并保持暂停。

原因可从 `ScheduledTaskController#list/create/update/updateStatus/delete` 核对：接口不接收当前 Authentication，list 使用 findAll，create 的 createdBy 是固定文本，修改/删除仅按 ID 取记录。该入口被用户保留在首发，因此需要按用户/授权范围补齐后再上线，不能因目前只是 CRUD 就忽略任务中可能包含的问题和业务说明。

### P1：原生 ECharts 图表缺少归属校验

真实 render_chart 创建的图表，创建者与无权限另一账号 GET `/api/charts/{id}` 均返回 200、内容相同。PNG/CSV 私有附件另测，不能以其 404 结果代替图表接口结论。

原因：`ChartController#get` 仅按图表 ID 读 option，`ChartOptionEntity` 没有资源 owner 关联。需要在创建时绑定身份/会话，并在 live/history 读取时做归属校验；旧无归属记录需有明确处理策略。这轮只记录，不修改。

### P1：自然月结束边界导致漏算

三个已完成场景出现相同模式：工具实际 SQL 为 `date >= '2025-01-01' AND date < '2025-01-31'`，最终答案却称统计整个一月。

| 问题 | 独立参考 | 本次错误回答 |
|---|---:|---:|
| 电商一月有效订单数 | 158 | 154 |
| 彩铃一月已订购收入 | 8,137 | 7,874 |
| 阅读一月去重用户 | 1,472 | 1,469 |

实际调用选择了 Cube，并把区间终点传为当月最后一天；执行 SQL 的终点是排他的。三题追加显式 `[2025-01-01, 2025-02-01)` 的新提问后均算对，支持日期参数解释问题的判断；不能用诊断正确覆盖首次失败。需要围绕官方工具契约和自然月口径改进 Agent 指引/回归，不能在平台 SQL 路由中偷偷改写官方 SQL。

### P1：复购率混淆订单粒度与明细粒度，错误示例参与召回

真实回答复购率 100%（200/200）；独立按不同 order_id 计算应为 99.5%（199/200）。实际 SQL 在订单明细视图按客户 COUNT(*) 判定两次及以上，客户只有一笔订单但两条明细时被错误算作复购；后续诊断也用明细 COUNT(*)，未纠正。

`knowledge/sql` 的建模示例存在同类表达式，问数召回后沿用。该问题需建模资产与问数都检查 grain，不能仅以 build/query 成功判定业务正确。本轮保留错误资产和会话供复现，不擅自修复业务代码/模型。

额外提问明确要求不同 order_id 后，模型先得到旧 Cube 的错误结果，随后用原始逻辑订单模型重算为 199/200=99.5%，并识别 Cube 问题。原先错误答案仍计失败，现有错误 Cube/示例尚未修复。

### P1：SQL 问答对编辑吞掉结构分隔换行

真实连续编辑点赞来源条目后 PUT 返回 500，列表不再显示该条。使用两个独立临时条目进一步复现：

- 只有 nl/sql 的 folded YAML：更新后成为 `sql: SELECT ...---`，关闭分隔符不再单独占行，接口 500、条目消失。
- sql 后有 tags 的 YAML：更新后成为 `sql: SELECT ...tags:`，接口仍 200，但 YAML 解析失败，列表 SQL 包含 tags 文本。

`SqlQaExampleService#update/replace` 用正则整体替换 SQL 段，匹配包含分隔前换行，替换值没有补回；写文件后直接重建索引并重新查条目，没有可回滚的完整结构校验。需要保留官方 Markdown/YAML 结构、校验后原子替换、索引失败可恢复，并覆盖普通/folded/带标签/特殊字符和重复编辑。测试被破坏的条目已从有效快照或原问题/SQL恢复，临时条目已清理；生产实现没有修复。

### P1：外联恢复后仍复用损坏的 Wren 连接实例

只断开本轮可控本地 TCP 代理，不动用户 SSH 或云数据库。故障时数据库连接测试失败，问答明确说明失败且无成功查询结果。代理恢复后，独立新连接 COUNT=100、平台连接测试成功，但旧 Wren 查询仍失败；重新发布触发实例重建后查询成功。

`WrenQueryGateway` 实例生命周期/连接故障分类与失效重建需要补齐，并保持只读、授权复核和有界重试；不能用旧答案替代成功。本轮临时代理、知识库和连接已清理，正常两云库保留。

### P1：重启后历史可见，模型却没有续聊上下文

重启前同会话跨库追问能记得“商品基数=100”。停止本轮 JVM及其子进程，再启动同一源码/配置后：14 库、授权、PNG 字节哈希、暂停任务和历史显示记录均保留；历史接口实际含此前问题、100与500，但同会话追问时模型表示没有任何历史上下文，无法回忆“商品基数”。共享用户的新查询仍正常。

当前配置没有持久 AgentStateStore Bean，`DataAgentConfig#builderBootstrap` 使用 `InMemoryAgentStateStore` 回退；`SessionHistoryService` 持久化的是展示投影，不能自动等同引擎续聊状态。应选用现有框架可持久化状态存储并验证重启/多实例恢复，或明确补齐历史重放契约，避免在业务层复制 ReAct。此项属于当前配置/装配的上线准备缺口，不能归因为“数据库历史被删了”。

### 建模与体验问题

- 边界模型把物理 VARCHAR 的 is_active 改成 BOOLEAN，官方 validate/build 通过，但平台发布防线正确拦截。经真实对话反馈、授权修改草稿和说明后，平台验证/发布成功；原始物理数据未动。需让模型优先遵循真实类型，不把“布尔含义”当作“已是布尔存储”。
- 极小表名单题只实查 COUNT=3，用采样描述给出全部名字；数字恰好正确，但证据不足，单独列出，不计作严格查询通过。
- 业务文档与真实状态/渠道枚举不一致，空 FK 实际比例高于文档声称；财务/IT 的坏列属于测试源质量。不能无依据把采样值升级成完整枚举。
- 工具右栏的 JSON 字符串、Python 重复代码、失败工具显示“完成”等已在 UI notes 记录并做原型；真实组件没有改。对话中英语过程说明、附带解释矛盾也影响上线体验。

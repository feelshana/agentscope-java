## 结论

时间门禁确实执行：execution-timing.log三条sql_window_gate分别是北京时间09:44:42（696ms，建模明细）、09:45:56（501ms，建模联表明细）、09:48:31（733ms，一月营收），均ALLOWED。未出现DENIED，不代表拒绝路径已通过验收。

“25年的营收”主Agent只调用get_instructions、recall_queries、describe_model、get_data_source，没有SQL工具调用，因此没有SQL门禁事件。其逐表检查表格由Agent生成，不是平台门禁返回。随后“25年1月的营收”真实调用run_sql，SQL左闭右开2025-01-01到2025-02-01，门禁放行，返回99元/1单。查询轮5.115秒，检测733ms。

SqlWindowGate直接调用Model.stream，不经过主ReAct Agent的LLM日志中间件，因此检测模型消息没有写入LLM.log/LLM-modeling.log。FactQueryWindowPolicy记录的结构化decision写普通类logger，当前logback根logger仅CONSOLE；独立文件只留耗时/终态。相同SQL、相同配置的本轮通过缓存可跳过重复模型检查。空配置也直接返回，但这三条真实事件在非空配置路径记录。

## 主要问题

1. 动态配置写进MDL：建模日志1259、1424等将31天写入字段及模型description。问数describe_model读到了固定31天，并在LLM.log的回复中称应修改“已发布MDL”的窗口。这与配置独立存数据库冲突，今后配置改为90天时可能仍被旧描述提前拒绝。运行门禁仍读数据库，问题是LLM认知来源与提示被污染。
2. 拆分建议自相矛盾：“全年营收”先称不允许拆年规避，后又建议按月分批合计；一月答案末尾继续提出逐月拼全年。没有实际执行拆分，但前后指引冲突。当前门禁只检查单条SQL，不具备整轮累计跨度约束；是否允许用户确认后按月汇总，需要统一产品口径，不能声称单条SQL门禁已禁止这种行为。
3. 样例日期由Agent选择：原始自动建模请求没有具体日期，Agent使用2025-01-15到2025-02-15；起点恰与采样观察值一致，未见用户先确认日期。这不能当用户指定范围，也不能证明数据完整。日期合法只证明执行范围满足31天。
4. 业务口径不完整：日志2394保存为“有效订单”的联表SQL漏order_status=1；日志379的一月营收SQL未关联customers、未排除is_internal=1。get_instructions明确存在有效订单及排除内部账号规则。99元是当前执行结果，但不能证明生产业务口径完整。
5. 工具冗余错误：raw不存在一次、已有模型用write_file两次被拒后改edit_file、cube list被当作Cube构建拒绝。OfficialWrenToolkit当前对所有cube子命令一概拦截，包括只读list。它们不属于日期门禁失败，后续validate/build/query/memory完成。

## 性能与验收范围

全年问题23.811秒，主模型累计4.257秒，get_instructions和recall_queries各约16.6秒且重叠，不能相加，不是SQL扫描耗时。一月查询5.115秒，主模型累计2.873秒，工具1.184秒（含门禁733ms，不另相加）。工具计时包含调度、索引、等待或确认，不能当纯数据库耗时。

本次能确认建模策略上下文已加载、查询门禁正向路径运行、建模样例写回后被问数召回，不能确认真实多事实表缺条件、超窗、UNLIMITED或拒绝停止分支，更不能从LLM日志证明采样弹窗UI验收完成。

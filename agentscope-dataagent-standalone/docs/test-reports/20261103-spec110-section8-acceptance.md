## 发现与处理

- **只列缺口、不提问**：两轮中助手都在 `analysis` 列出 2 项缺口（如"回访口径未定义"），但没有出确认卡或提议，自行按假设写进了"假设"行。第二轮已加了提示词约束，仍然这样。
  - 按"违反两次改为代码约束"处理：页面在没有关联卡或提议时，把这些项标为"按假设处理"，结论注明有几处假设、需在核对 SQL 时留意，避免与"现有模型可以回答"矛盾。
- **首轮 SQL 问题**：第 1 题 SQL 嵌套聚合，且没有应用默认过滤，dry-plan 没有拦住。第二轮在能读到查询模板后改用了"报表类有效访问明细"，默认过滤正确。dry-plan 不检查聚合嵌套这类语义错误，仍需人工核对 SQL。

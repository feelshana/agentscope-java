# Wren 集成架构审查（2026-10-16）

状态：审查结论与改造建议，未实施。依据当前源码、安装版官方 usage、ADR0069、已有真实验收报告及本次用户日志；未运行新的模型对照实验或构建。在线官方文档访问网络失败，不对当前最新版作判断。

## 判断

存在集成架构薄弱点，不能把反复故障都归因于Wren引擎。当前是AgentScope LLM读取官方skills、写工程/SQL、调用CLI/MCP；并未部署官方完整自然语言问数应用。Wren负责语义编译和执行，业务理解及答案仍由外部LLM负责。详见ADR0069。

1. WrenMcpToolkit#listTools将官方schema作为文本返回；callTool只暴露通用tool_name/arguments Map。实际工具调用schema与官方具体工具schema分离，模型承担二次封装。本次五次缺tool_name直接体现该薄弱点。候选：复用框架McpTool按当前授权工程暴露具体工具schema，调用前及排队后继续鉴权；不把全局MCP裸注册给共享Agent。需先验证会话隔离与框架生命周期。
2. DataAgentConfig#MODELING_SCRIPT已有大量流程规定，包含固定过滤必须执行、构建后检查等，本次仍遗漏。官方技能偏CLI使用，问数通过MCP包装，模型还需理解平台权限及元数据。更多提示不能替代工具契约与验证；不能据此认定模型能力不足，需同题受控对照。
3. MdlPublishService#validateInternal检查validate/build及对象查询计划，证明可编译/执行，不证明业务正确。推广指标排除部门仅写描述仍可发布。建议开发验收增加独立预期结果与边界夹具，并对产品需要的固定指标提供明确验证证据；不是强制用户每次填写问题表，也不引入自研SQL路由。
4. WrenMcpToolkit#callTool将JSON、回执及附件说明拼接；答案的数字、图表及来源标注仍依赖模型维护。此次渗透率分母错误、叙述比例错误说明缺少结果到答案的可核验联系。候选结构化结果引用及统一图文数据源只能减少抄写/算术错误，不能自动证明业务口径正确。
5. answer_question/query_type及最终采用关系依赖模型标注。此次业务SQL显式标DIAGNOSTIC；点赞不等于业务正确，历史验收已有错误memory。建议区分候选执行回执和最终采用回执，避免要求模型提前声明未来采用结果；保留用户点赞授权，不自动修业务记忆。
6. 沙箱检查失败与Wren语义执行是不同故障域。Docker当前API500不能证明日志时点根因。错误保留、有限恢复及资源预算必须独立处理；此前多Wren实例内存实测风险不是当前Docker故障根因证据。

## 为什么反复修改仍不稳定

此前混合了协议兼容、提示优化、基础设施和业务准确性四类问题，局部测试与编译通过不能证明端到端语义正确。历史81/83有效数值题通过不能代表复杂开放分析稳定；新日志多步骤分群分析暴露了不同错误。需要冻结版本、模型和题集，让每次修改可比较，而非以一次成功对话判断修好。

## 建议验证与改造顺序

先固定三层对照：A已知正确SQL直接官方CLI/MCP，B相同SQL走当前平台，C相同题目由当前Agent生成并回答。分别记录协议失败、执行结果、业务口径、图文一致性、耗时与调用数。再增加同模型具体schema接入对照及另一模型对照，一次只改一个变量。不以当前证据承诺更换模型或官方完整应用必然更好。

优先验证具体schema接入及独立沙箱故障；同步建立复杂分析语义回归。保留现有Wren语义层、权限和发布隔离。若受控对照仍不满足目标，再评估完整官方应用与当前平台的集成成本及效果。本建议涉及ADR0069和AGENTS当前双工具入口约定，实施前需新ADR/spec明确替代范围；本轮未修改这些边界。

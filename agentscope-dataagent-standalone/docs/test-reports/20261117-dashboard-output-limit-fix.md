# 看板长HTML生成截断：根因与修复

2026-11-17 Asia/Shanghai。用户明确授权增加诊断、复现并修复。沿用spec141/ADR0149及原生Agent/会话/权限边界，本轮缺陷修复不新增spec/ADR。此报告取代上一份诊断记录中“上游/截断/解析尚未分清”的待定位状态，历史记录保留。

## 原始现象与定位

用户截图新看板前5次write_file缺path/content，第6次突然成功；201729ms执行中模型占193648ms。此前另一看板重复28次后超时；不是文件写盘或数据查询耗时。

通过只读加载本地已应用模型配置，在隔离Python探针中请求同一服务；密钥只在内存，不写日志。不执行模型返回的工具，不改用户看板或正式发布。对照使用原对话转录和系统上下文，指定同一write_file工具以隔离输出参数；探针不是完整Agent会话，其时间不冒充整轮生成时间。

| 对照 | 输出预算 | 实际结果 |
| --- | --- | --- |
| 原样回写已生成HTML，探针1 | 未指定 | 25857字符参数，1368分片，tool_calls正常结束；参数合法，HTML逐字符一致 |
| 业务上下文生成，探针3 | 未指定 | 25784字符参数，2200分片，finish_reason=length，JSON字符串未结束 |

| 同业务上下文，探针4 | max_tokens=16384 | completion_tokens=9023，finish_reason=tool_calls；29582字符完整参数，path/content均在 |

探针1原始分片经IDEA所加载的Java解析器/累加器离线回放，完整保留path及24438字符HTML。这排除“所有长参数都会被Java丢失”，不排除其他独立协议缺陷；当前已实际复现的故障为默认8192输出额度不足。

因果链：长HTML输出超过默认8192 → 上游正常以length结束但截断工具参数 → 累加器吞JSON解析异常并退化{} → 执行器误报缺path/content → Agent反复重新生成，每次约30秒。偶尔生成得较短，在额度内写完整JSON便成功；IDEA启动本身不是修复。

另补原生Agent+ChatCapacity真实订阅测试，修复前即使等待取消2秒，底层Flux订阅仍未取消；修复后测试通过。原因是takeUntilOther的截止publisher通过error结束，外层报错未实现预期源取消；先正常触发截止取消，再报告超时可消除此泄漏。

## 代码修复

- 仅dashboard-agent申请16384输出tokens；不更换模型服务、凭证、流式开关或整轮超时，不降低用户看板设计要求。全局连接设置仍固定本轮，单Agent输出预算合并保留。
- `ReasoningContext#processChunk`发现工具输出length立即抛明确截断错误，未执行残缺调用。模型正常完成时验证工具原始JSON；非法参数不再化为空对象进入无效循环。中断的部分消息仍可保存，不当成可执行调用。
- 分段日志增加模型输出预算、结束原因、参数字符/分片/调用数；不记录原始参数/提示词/凭证。模型截断与字段漏填可以明确区分。
- ChatCapacity绝对期限先正常触发截止以取消模型流，再报告超时；SSE工具事件截止同样保证订阅关闭。Python阻塞操作保留原有实际结束前占用预算的规则。
- 看板界面消费工具结果，写入失败显示未成功，成功后才显示页面已写入；终止错误直接显示具体原因。

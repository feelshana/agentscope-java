## 真实流程与发现

初次模型生成已完成查询验证，但长文件写入返回空参数，反复调用至600秒超时；超时后会话仍占用，重启本轮后端后用原会话恢复。分段write_file/edit_file的下一轮71秒完成真实HTML并经官方GenBI verify。后续精修、修错及发布均通过同一对话/页面完成，没有人工直接写入运行看板冒充Agent生成，也未修改模型服务配置。

实际修复：刷新时加载态innerHTML删掉canvas而实例缓存未释放；月同比日期键未减一年；Object.assign覆盖了万元刻度formatter。均由助手实际edit_file修复并verify，再由管理者页面发布更新。证明复杂生成必须做浏览器回归，官方verify并不能覆盖这些运行问题。

## 浏览器和视觉核验

IAB本轮工具不可用，改用Playwright CLI的真实Chrome会话。已用view_image在同轮对照[完整概念](../samples/retail-showroom/design-concept.png)和最终实际截图，检查以下项目：

| 对照点 | 实现证据与修正 |
|---|---|
| 布局层次 | 深蓝品牌栏、四KPI一行、主次图区域、底部门店表；修正宽屏仍2×2的浪费 |
| 配色 | 白/近白画布、海军蓝文字、青绿收入、钴蓝品类、琥珀未达目标，与概念系统一致 |
| 字体与数字 | KPI大字、表格金额右对齐、标题和控制层级清晰；万元轴实际500000→50 |
| 图表信息 | 周趋势14点、月趋势3点且同比3个非空值，环图中心总额和渠道金额列表，6区域/4品类 |
| 真正交互 | 区域、渠道下拉会重查并更新KPI；周/月切换；净销售排序由上海首行改为兰州首行 |
| 稳定与移动 | 连续刷新3次canvas均为4；390×844内页340/340无横溢出，移动仍有4张canvas |

概念原生1536×1024与实际同尺寸核验，另验390×844。初始浏览器日志及最终验收无pageerror/查询错误。以上是当前Chrome与样板的实测，不代表所有浏览器。

允许的设计差异：概念示意2025Q1/四渠道/其他品类和数字，实际按用户已授权的CSV换成2026Q3、三渠道、四品类、12门店；趋势以同比替代概念示意目标曲线，目标保留在KPI/区域比较；没有额外引入首屏营销文案。概念中的小图标和KPI装饰sparkline省去，以保留真实数据和可读性。未实现逐店详情抽屉，现有表格为可排序明细；不保留假按钮。整体按确定的设计系统核验，未宣称与概念逐像素一致。

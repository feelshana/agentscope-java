# 2026-11-03 spec114 一期验收：问数教练

环境：本地 8080，Wren 0.15.0，模型 `qwen/deepseek-v4.1-flash-1017`；测试账号 newuser10，知识库"我的第一个知识库"（`65af755f`，已发布 v4，含查询模板与两张加工表）。真实模型调用。

## 结果

| 验收项 | 结果 | 证据 |
|---|---|---|
| 1 初次建模只做基础 | 提示词与工具约束 | 自动建模、处理文档、写入确认、试问轮次调用 `propose_modeling_change` 一律返回错误（单元测试）；未做新的自动建模实测 |
| 2 建模对话不主动提议 | 通过（有瑕疵） | "以后要看每个用户连续访问报表的天数"：助手尝试提议被工具拒绝，未生成提议，回复提示加入问数教练，但回复开头仍写"我提议建一个查询模板"；"请帮我建一个查询模板：每个用户每天的报表访问次数……"：生成 explicit 提议，页面在助手空闲后自动发起资产轮次起草 |
| 3 问数教练出方案 | 通过（有瑕疵） | 4 题：各部门访问次数→能答对、不提议；流失用户→提议 rule；外协对比→提议 rule 与 calculated_field；第几次访问→已有同名 view 提议、不重复。四题均写入 `q-coach-*.yml`，未写规则、关系或 views/。瑕疵：流失用户存在范围与截止日歧义，助手未用确认卡提问，只在提议要点中写"需按用户确认结果写入" |
| 4 批准后才起草 | 通过 | 批准"外协与正式员工判定"（rule）与"人员类型"（calculated_field）后，普通轮次写入 `## Naming conventions` 与四张表的计算字段，`context validate --strict` 通过；未批准项未写文件 |
| 5 SQL 只核对不执行 | 通过 | 重新生成后外协对比题 SQL 直接用 `人员类型`；`/plan` 返回 Wren 展开后的 SQL（计算字段展开为 CASE WHEN），未执行；确认后状态为已确认 |
| 6 资产验证不执行 | 单元测试 | `SemanticAssetServiceTest`：验证调用 `MdlPublishService#planDraft`，判定基于 SQL |
| 7 资产自检只用 dry-plan | 提示词断言 | `ModelingTurnRules.ASSET` 要求不执行 dry-run |
| 9 窗口/聚合视图提示 | 单元测试 | `SemanticAssetService#warnings`：依赖受限表且含窗口或聚合时提示，普通拼接不提示 |
| 10 权限 | 沿用 `DatasetGroupService#getGroup` 与 `AgentAccessGuard` | 未单独实测 |
| 11 MDL 与规则面板 | 通过 | 问数教练"查看 MDL 与规则"：规则按小节分组，草稿新增的两条规则高亮；可切换草稿/线上，MDL 复用编译后 MDL 组件 |

页面：问数教练三栏（常用问题、建模方案、核对 SQL）正常显示；起草查询模板后，相关已确认问题自动进入"口径变更待复核"（spec112 联动）。

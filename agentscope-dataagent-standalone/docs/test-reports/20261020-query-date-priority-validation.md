## 验证结果

- 最终 `mvn spotless:apply` 仅格式化本轮测试夹具，随后 `spotless:check package` 成功：705 项，0 失败、0 错误，20 条件跳过。包含后端测试、前端 `npm run build`、JAR 和发行包生成。日志 `target/spec088-complete-package.log`。
- 此前 `mvn test`、`mvn package -DskipTests` 已分别通过；其后主提示词通用化与夹具调整的最终全量验证以上一条为准，不混用较早的 702 项计数。
- 显式启用 QueryDateBehaviorLiveTest，真实项目模型 + 原生 ReAct：3 个业务场景，各含缺日期、补日期、口径解释、新日期按日查询，共 12 轮对话；3 项测试均通过。日志 `target/spec088-live-generic.log`；原始材料 `target/spec088-live-query-date-orders.json`、`-stock.json`、`-observations.json`。
- EmptyOrdersQueryFixtureTest 验证真实空表总聚合返回 0/NULL 行，分组查询返回零行，以及日期字面量和不同模型的结果形状。夹具只使用隔离 SQLite 内存库，常见日期表达式适配仅限测试；没有生产 SQL 直查回退。
- 真实模型验收不验证官方 Wren 方言、日期解释准确率、生产数据或性能。首次跨场景验收中部分合法日期语法因 SQLite 差异失败后被修正，之后已补夹具兼容及单元测试；这不能记成业务服务发生过 SQL 失败。

## 保留的失败与独立缺陷

- 初轮格式检查失败与格式选择参数错误已修正，日志保留；真实模型首次连接因沙箱网络限制失败，经授权联网后继续。
- 原夹具把所有 SQL 都返回零行，导致无分组总聚合形状错误；已替换为内存库实际执行，并按每轮空结果后的 SQL 批次检查，不强制所有分析只能发一条 SQL。旧材料 `target/spec088-live-before-fixture.json` 保留。
- 较早真实模型仍在业务查询中夹带日期 MIN/MAX，相关验收失败保留在 `target/spec088-live-corrected-fixture.log`、`target/spec088-live-verified.log`。最终改为通用信息最小化、禁止附带日期探查的规则，跨业务验收通过，不以特定营收措辞作为生产规则。
- **联表门禁漏检未解决**：`target/spec088-live-final.log` 的 `missing_joined_date` 场景中，CLI 正确拒绝，MCP 那次模型却只返回表 a，遗漏表 b 的日期检查并放行，执行替身被调用一次。不是业务数据库查询，但证明真实检测模型可能漏检。未修改断言、未删失败日志、未通过重跑掩盖，不宣称全部 18 项真实门禁场景通过。
- 先前出现的 allowed 与明细/解释矛盾仍是独立问题；本次没有加入一致性自动复核。普通单元测试通过不能消除此类真实模型风险。

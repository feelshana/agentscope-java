# spec 041: 知识库成员、问答权限与 BI 身份接入

更新：2026-10-13。状态：知识库权限、共享上下文、成员管理、分页及每轮多库选库已实施；BI 接入尚未实施。对应 ADR 0050。

## 权限矩阵

| 操作 | QUERY 使用 | MANAGE 管理 | 全局管理员 |
| --- | --- | --- | --- |
| 卡片、基于库问答 | 已授权库 | 已授权库/本人创建库 | 所有库 |
| 下载本人问答 CSV/图片/报告 | 是 | 是 | 自己的会话附件 |
| 进入详情、预览原始数据 | 否 | 是 | 是 |
| 维护数据、描述、字段、文档、建模和发布 | 否 | 是 | 是 |
| 成员授权、撤销、删除库 | 否 | 是 | 是 |
| 读取他人私有历史/附件 | 否 | 否 | 不因库管理权自动获得 |

MANAGE 包含 QUERY。普通用户没有授权不显示卡片，直接调用详情/工具接口也拒绝。首期不分组织，不做行列级权限，旧库保持私有。

## 用户同步与登录契约

- 全量 BI 用户同步到本地目录，稳定 BI ID 唯一映射 userId，改名保留会话和授权。
- 建议幂等新增/更新/停用，不物理删除历史身份；同步频率及停用生效时效待确认。管理员角色明确映射，不自动导入所有 BI 用户为管理员。
- 无重复登录操作，但后端需要可信身份凭据。建议短期身份交换或可信网关；具体协议待确认。
- 裸用户名和统一密码不作为生产免登录契约。签名凭据校验签名、发行方、受众和有效期；一次性票据限制有效期且拒绝重复兑换；网关验证 BI 会话、清除客户端伪造身份头，后端仅信任约定入口。
- iframe 展示由 BI 前端决定，约定嵌入 Origin、HTTPS、会话传递、过期与登出。浏览器参数不能授予管理员。

## 实际实现

### 1. 数据库与权限判断

新增三张平台表，由当前 Hibernate ddl-auto=update 在启动时创建：

| 表 | 用途 |
| --- | --- |
| dataagent_knowledge_base_grant | group_id + user_id 唯一，QUERY/MANAGE、授权者、创建/更新时间 |
| dataagent_knowledge_base_grant_audit | 记录操作用户、目标用户、库、旧/新权限及时间；撤销后仍保留 |
| dataagent_conversation_dataset_scope | 用户 + 会话最近接受的选择、全选模式，以及按提问消息 ID 保存的实际范围/名称快照；撤权不清除历史 |

创建者天然 MANAGE，全局管理员以本地用户表当前 admin 角色判定。旧库不补默认共享记录。成员操作不能降级/撤销创建者或全局管理员；普通管理成员可以修改/撤销其他显式授权，也可以撤销自己的授权。授权变更与记录在同一事务内保存，按知识库行锁串行修改。

KnowledgeBaseAccessService 是统一入口。详情、预览、数据维护、说明、术语、建模、发布和成员管理需要 MANAGE；问答和查询工具需要 QUERY。没有授权返回不存在/未授权，只有 QUERY 访问管理操作返回 403。

### 2. 共享数据与私有结果

DatasetScope.ownerId 旧字段名保留，但含义是当前操作用户，绝不将运行身份替换为创建者。服务端授权后获取真实知识库 owner；在共享库中上传/关联的新数据及建模文档归到该库 owner 下。关联数据库时使用管理成员本人已有的数据源，外部数据源配置继续按用户隔离，不公开别人账密。

Wren 通过已授权 groupId 找该库的发布工程；查询概览、知识检索和模型工具都校验范围。历史、工作区、沙箱和生成附件仍属于提问用户，库管理权不能打开其他人的私有结果。用户反馈记忆也保留当前用户身份。

### 3. 每轮选库、续聊和撤权

用户于 2026-10-13 最终确认：普通问答可不选、单选、多选或全选，同一会话可在回答结束后切换选择，保留聊天上下文。建模仍针对一个当前知识库，建模会话不可换库。

| 选择 | 本轮查询范围 |
| --- | --- |
| 未选 | 普通聊天，不自动加载所有库，也不继续查询历史选过的库 |
| 指定一个/多个 | 仅这些有使用权限的库；模型自行判断查询哪些库 |
| 全选 | 每次发送时由后端展开最新有使用权限的库，新授权加入、撤权移出；不是点击时的固定 ID 清单 |

前端每次发送显式提交 groupIds（空数组表示普通聊天），全选发送 allGroups=true。旧调用省略 groupIds 时兼容恢复最近具体范围，不能扩大为全部库；省略 allGroups 兼容为 false。

新查询只能使用本轮范围。历史回答帮助理解追问，但旧数据、旧 SQL、子任务和模型上下文不能扩大新查询范围。各库仍分别使用自己的已发布模型和 Wren 实例，按 group_id 分别调用，再综合结果；本轮不新建跨库联合语义模型，不自动把不同库模型写入同一 SQL，不猜测关联键和业务口径。

普通会话范围在 gateway 获取会话执行锁后复核授权并保存，后续排队请求不能覆盖当前正在执行的范围。typed DatasetScope、运行时会话 ID 备用范围与子任务使用本轮具体 ID。SSE scope 事件和 done 回传本轮快照，不读取可能已被下一轮更新的全局最新值。

沿用 dataagent_conversation_dataset_scope 表，增加可空 selection_json，保存全选模式及知识库名称；旧记录仍可读取。按 turn:<用户消息 ID> 写入历史范围快照，历史投影批量读取，不为每条消息逐次查库。提问下方显示普通聊天、单库名称、多个库数量或当轮全选数量，悬停可看具体名称。旧历史没有快照时不虚构范围。重开历史恢复最近接受的选择；全选模式继续每次发送展开最新授权。

每次 Wren 查询会在排队结束、实例取得后、实际调用前再次检查权限。撤权阻止后续新查询；已经开始的数据库查询可能完成。此前本人历史和附件继续可读。

### 4. 列表及成员接口

- 新 GET /api/dataset-groups/page：page 从 0 开始，size 默认 20、上限 100，search/sort/manageOnly；返回 items/total/page/size。SQL 先 ACL 过滤，再搜索、排序、分页。数据集数量、创建人和当前角色批量查询。
- 旧 GET /api/dataset-groups 的数组契约保留兼容；真实卡片页和对话选库使用新分页接口，选库框支持搜索、翻页及创建人展示。
- GET /api/dataset-groups/cards?ids=...：只返回有使用权限的卡片元数据，供对话显示名称，不能代替详情访问权限。
- GET /api/dataset-groups/{id}/members：授权成员分页和创建者固定管理信息。
- GET /api/dataset-groups/{id}/members/users：按用户名搜索和分页选人，只返回用户名、稳定 ID、角色标记，不返回密码。
- PUT /api/dataset-groups/{id}/members/{userId}：请求 {role: QUERY|MANAGE}；新增或更新。
- DELETE 同一路径：撤销显式授权。上述成员/选人接口均要求 MANAGE。
- 删除知识库时清理 grant 成员表；变更审计和会话范围保留，历史/附件按原规则保留。

### 5. 界面与使用方法

1. 创建者、管理成员或全局管理员打开知识库卡片的三个点 → 成员与权限；详情页顶部也有入口。
2. 添加成员 → 搜索用户名 → 选择“使用”或“管理” → 授予。现有本地用户即可操作，不依赖 BI 同步。
3. 被授权用户看到卡片和权限标签；使用成员只出现提问入口，管理成员出现详情、编辑、授权和删除。
4. 业务术语页面只列出有管理权限的库；普通问答可多选，同一会话回答结束后可调整范围。
5. 对话选库下拉使用页面内存缓存：首次获取一页 20 项，反复打开不重复请求；总数不超过该页实际条数时，在前端即时搜索。数量更多时按关键词/页码缓存服务端结果，未缓存搜索使用 200ms 防抖；快速开关复用在途请求，缓存最多 32 页。离开对话页后清空，返回重新加载。选中已缓存卡片时不额外查询名称。缓存只影响元数据展示，问答和管理操作的后端实时授权检查不变。

## 验收场景与剩余范围

| 场景 | 预期 |
| --- | --- |
| 无授权猜测库 ID | 不列出，拒绝详情、工具和源文件 |
| QUERY 共享库问答 | 查库所有者数据，结果归提问用户 |
| QUERY 直接调用详情/预览/编辑/授权 | 后端拒绝 |
| MANAGE 维护和授权 | 可操作，记录变更 |
| 全局管理员跨创建者管理 | 管理所有库，不自动获得他人历史 |
| 撤权回看/下载旧结果，再续问 | 旧内容可读，新查询拒绝 |
| 伪造用户名、角色、ownerId/groupId | 不能换身份或扩权 |
| 用户改名/停用 | BI 接入后补充，当前尚无停用同步 |
| 分页搜索 | 结果和总数仅包含有权限库 |
| 不选库、多库、同会话切库 | 普通聊天、指定库内查询、保留上下文且新查询只用本轮范围 |
| 全选与历史恢复 | 每轮取最新授权，历史保持当时快照，恢复全选模式 |
| 重启后续聊、排队中撤权 | 恢复最近选择，实际新查询复核权限 |

上述为第一阶段主要权限验收；BI 伪造身份、用户停用同步仍须随可信免登录接入验证。普通多库问答和建模单库规则见上文；跨库联合模型、云部署、备份恢复、10 并发压测及完整重新建模/发布不作为本轮已验收能力。

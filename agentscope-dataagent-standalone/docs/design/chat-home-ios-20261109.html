明天起收进侧栏
为什么清单要竖排

四列时每列只有 ≈250px，12px 描述被压成 3 行；竖排每行 72px 能放「标题 + 一句说明 + 一个按钮」，且当前步有整行底色，扫读成本低一半。

现在这页的六个具体问题

不是审美问题，是三个层级的冲突：信息层级、材质层级、交互层级。每条都能在代码里对上。

1首屏同时有三个「下一步」

4 步清单、3 张推荐问题、输入框各给一个行动，强度接近。用户不知道该点谁 → 决策疲劳 → 观感"乱"。Apple 的做法是一屏只留一个主行动。

2四列清单塞不下中文

.da-ob-steps 是 4 等分栅格，min-height:142px 靠 flex:1 撑。每列约 250px，12px 描述被压成 3–4 行，还要塞图标、序号、链接 — 密度过高的根因。

3没有"材质"，只有"描边"

画布 --da-canvas-bg 和卡片都是 #fff，靠 .5px 发丝线区分。iOS 的层次来自底色差（#F2F2F7 托白卡），不是线框。所以现在加再多圆角也不"高级"。

4侧栏还是 Web 后台语法

实色 #f6f7fa、12px 正文、激活态用左侧 3px 竖条 — 这是 Ant Design 的处理。iOS 是半透明毛玻璃 + 圆角填充块，无竖条。

5历史标题全是日期前缀

标题 = 首问截断 40 字（SessionHistoryService:251）。截图里 8 条有 5 条以 2026-05-01 至… 开头，截断后完全同形 → 列表等于没有信息。

664px 面包屑在白占

.da-chat-header 高 64px，写"对话 / 新对话"。新会话没有导航价值，却把 30px 问候语往下推，还和它抢同一段竖向节奏。

现状

  • 问候语 30px 紧跟品牌行 → 三条递减文字挤在一起
  • 输入框 1080 宽、满幅，工具栏三枚 chips 平铺
  • 推荐问题 3 列、min-height:107px，日期前缀占半行
  • 清单 4 列 + 头部进度条 + 底部说明条，共 5 个可点
  • 侧栏 12px 历史、单行截断、无时间、无知识库归属

方案

  • 去品牌行与面包屑，问候语 33px 独占一段；上方一行状态替代品牌
  • 输入框收到 720px，重心居中；只有发送键是实心紫
  • 推荐问题 2×2（A）/ 竖排 3 行（B），标题重写，去掉日期前缀
  • 清单收成 44px 一行（A）或右侧竖排路径（B），全局只留 1 个实心按钮
  • 侧栏 238px 毛玻璃，历史两行式：标题 + 知识库·时间

改动清单（可直接对着改）

大部分是 CSS 变量与几个类的替换，DOM 结构只有清单和推荐问题需要重排。

1先建分组材质

--da-canvas-bg:#f2f2f7，卡片保持 #fff；.da-landing-wrap 去掉白底，加一层极淡径向光晕。这一步做完，页面的"白"立刻有层次。

2侧栏换毛玻璃

.shell-navigation：width:238px、background:rgba(247,247,250,.78)、backdrop-filter:blur(28px) saturate(180%)、右发丝线 .075。删掉 .rail-nav-item.is-active::before 的竖条。

3删掉 landing 的 header

ChatHeader 在 isLanding 时返回 null；把侧栏收起按钮移进主区右上角悬浮。省下 64px 给英雄区。

4输入框收窄 + 单焦点

--da-landing-max:720px；.da-composer-glow 的 2px 渐变边改成 1px 发丝 + shadow-1，聚焦时加 0 0 0 4px var(--tint-ring)，不要变紫边。

5清单改竖排或收条

.da-ob-steps 由 repeat(4,1fr) 改 1fr 并放进 296px 右栏；行高 72px，.is-current 整行 --tint-soft 底，序号圆填色。窄屏自动落到内容下方。

6历史标题要"人话"

后端在 shorten() 前先剥掉 date 至 date 前缀，再对同前缀做去重编号；条件允许时用一次轻量模型生成 ≤14 字标题并缓存到 SessionHistoryEntity.title。

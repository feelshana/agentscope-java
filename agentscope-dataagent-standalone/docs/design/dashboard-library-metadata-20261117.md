# 仪表盘资料与列表管理评估

状态：用户已批准全部建议，已按[spec144](../specs/144-dashboard-library-management.md)实现本地体验版；以下保留前一轮评估依据。日期2026-11-17。

## 评估时的代码事实

DashboardLibrary只支持范围与名称/知识库搜索；先前范围在左、搜索在右，本轮按知识库统一为搜索在前、范围在后，靠左排列并保留窄屏布局。DashboardController/Service没有元数据修改接口，Asset/View没有description或createdAt，仅updatedAt；服务端列表已按updatedAt倒序。dashboardStatus已有草稿/已发布/有未发布修改/清理待重试，但没有状态筛选或卡片列表切换。

## 已批准的方案

- 支持名称与选填描述，卡片菜单提供编辑基本信息，编辑页也可进入；权限沿用可编辑者，服务端复核，清理中禁用。新建仍只要求知识库和名称。修改这些资料不调用模型、不改HTML、SQL或已发布内容修订；列表名称和HTML内标题边界须说明。
- 描述说明用途/受众/关注指标，最多两行展示并纳入搜索，空值不占大块区域；不代替指标口径说明。
- 状态筛选沿用已有真实状态，普通只读者不得由此得知未发布草稿；权限先过滤，再搜索/筛选/计数。草稿含未生成/已生成但未发布；“生成失败”不应成为永久资产状态。
- 排序默认最近更新，另提供最近创建、名称排序；创建时间应单独持久化，旧记录未知时明确处理，不用updatedAt假装createdAt。访问和查数不应改变内容更新时间。
- 默认卡片，增加列表以支持较多看板；复用同一筛选结果及操作权限，记住个人视图偏好，避免切换后条件丢失。
- 完整工具行顺序与知识库一致：搜索 → 全部/我创建的/共享给我 → 状态 → 排序 → 卡片/列表。沿用知识库组件与视觉。

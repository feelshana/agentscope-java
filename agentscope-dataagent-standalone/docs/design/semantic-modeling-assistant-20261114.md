## 这次处理什么

只设计 AI 助手对话和本轮建模输出。沿用参考稿的顶栏、左右窄栏、草稿栏与颜色；中间模型画布只是布局占位，不在此确定整个建模状态流。

- 全屏：正文最大宽度 780px，输入区 820px，避免大屏文本拉满。
- 并排：助手 440px（中等屏幕 410px），缩减间距，保留相同结果与口径信息。950px 以下优先保留对话，通过“专注模型”查看画布。
- 对话不再全部装进巨大气泡。用户消息用浅紫色，助手正文开放排版；过程、结果、待确认问题各自承担一个职责。
- 过程默认折叠，展示动作类别数量；相关步骤归组，可打开内容、工具输入、工具输出。运行态只说明当前动作与耗时，不虚构进度百分比或严格阶段。
- 本轮结果按模型逐项列出，点击查看业务说明与字段示例，保留编辑与在模型中定位。结果位于草稿，统一在原草稿栏发布。
- 口径确认逐题展示，原因按需展开；保留推荐选项、其他选项、自定义、暂不建立、稍后处理。未选择推荐项时不伪造继续建模结果。
- 长 YAML/工具原文在独立阅读层查看，支持内容/输入/输出切换、换行、复制和 Esc 关闭。打开内容不会把主对话撑成长日志。
- 失败说明已保存和未完成的内容；停止单独描述为用户主动停止，不误报服务失败。线上已发布模型保持可问数，草稿修改与发布分开。

## 如何评审

1. 顶部切换待确认、执行中、完成、受阻四个示例状态。
2. 产品顶栏切换专注对话、并排查看、专注模型。展开过程、选择自定义再切换布局，可观察状态保留。
3. 展开建模过程，点击“完善模型 · 示例客户”，查看 YAML、工具输入和输出。长内容只在阅读层滚动。
4. 点击结果中的模型名称，查看字段、编辑业务说明、在模型中定位。编辑只保留在页面内存。
5. 待确认态点击推荐方案的“确认并继续”，进入完成态；底部显示关联结果与待发布状态。其他选项保留所选值并说明后续实际由助手继续，不模拟未经实现的 Agent 行为。
6. 执行中点击输入框的停止按钮，展示主动停止；受阻态则展示服务校验失败，两者提示不同。

所有数据、执行时间、错误与结果均为明确的设计夹具；发送、编辑、确认、重校验、发布不会调用实际接口。草稿“全部结果”仅展示本原型的一轮，正式产品仍沿用累计结果列表。主环节导航、对象分类和画布没有实现为完整产品。

## 与现有代码的对应

| 当前能力 | 设计调整 | 实施时保留的边界 |
| --- | --- | --- |
| `ModelingChatPanel` 的 ReplyBody / ToolGroup / TaskRow | 收敛过程摘要，工具详情放到阅读层 | 继续展示现有工具事件，原文可追溯，不新增执行或存储链路 |

| `ConfirmationCards` | 明确问题、依据可展开、选择区层级 | 复用现有确认协议，自定义和稍后处理保留 |

上述为设计映射建议，并非已经批准的产品改造。正式落地前应进一步核对真实流式事件、历史恢复、同时多项确认、草稿编辑错误与不同资产的字段映射。示例中的模型详情不是对所有真实资产编辑表单的替代方案。

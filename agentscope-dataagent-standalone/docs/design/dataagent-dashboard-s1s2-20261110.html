    卡片详情

    为什么现在只能按时间筛

    S2 的筛选下推只做一件事：把卡片查询里那段平台规范时间谓词按新范围重建，再交给官方只读通道执行。全程不请模型改写 SQL，也不由平台拼 WHERE。

    -- 卡片存储的查询定义 SELECT COUNT(DISTINCT o.order_id) AS 订单量 FROM orders o WHERE o.order_date >= '2025-09-01' AND o.order_date < '2025-10-01' -- 切到「本季度」后重建的同一条 SELECT COUNT(DISTINCT o.order_id) AS 订单量 FROM orders o WHERE o.order_date >= '2025-07-01' AND o.order_date < '2025-10-01'

    地区这类维度要怎样才能筛

    需要一类建模资产
    带 ## Default filters 的已发布视图（日后是 Cube 的参数化维度），卡片声明它支持哪一列下推。这不是前端能自己解决的事。
    当前做法
    卡片保持全量并在筛选栏置灰，避免"看起来能筛、其实只筛了已加载的行"这种假交互。
    可点的路径
    缺口清单与这里的「提议补充可筛视图」都会转成一条建模提议，发布后重新生成即可生效。

    发布「电商销售概览」

    发布前统一校验，逐条给结论：

    发布后，具有此知识库 QUERY 权限的成员可以打开；每个成员按自己的授权实时取数，缓存按「用户 + 筛选 + 查询版本」分键。

    本稿演示的边界

    S1 · 卡片来源
    每张卡引用一条已确认问答对或一段受治理 SQL，卡片不存数据、也不存图表配置，打开时实时取数、服务端确定性生成图表。
    S2 · 全局筛选
    只支持时间范围：按平台规范形态重建那一段谓词再过逐表窗口门禁，切筛选零模型调用。
    口径状态可见
    已确认 / 待复核 / 口径未确认 / 派生 / 快照表，五种状态在卡片上直接可见，发布前汇总校验。
    降级与缓存
    取数失败显示上次成功值、时间和原因；重复打开同一范围命中缓存并标注。
    不做的事
    不做拖拽布局（对话 + 卡片按钮改盘）、不做 Wren genbi 式静态应用与公网链接、不把数据打包出域。
    本稿未覆盖
    S3 一句话生成的构建指令与 verify 全过程、S5 定时刷新与订阅、卡片级行权限。

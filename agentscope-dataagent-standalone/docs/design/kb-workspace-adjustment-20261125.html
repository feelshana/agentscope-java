三条规则

规则说明
只改这三类① 删掉重复表达；② 把「空」换成有用信息或收起来；③ 修尺寸与对齐。不新增功能、不改路由、不动接口返回结构。

X1

左侧顶部把知识库名又写了一遍，而它下面只有一个菜单项

现在
顶栏面包屑是「知识库 / 总部常规分析-本地复刻」，左侧又有一块 30px 高的灰底胶囊，写着同一个名字 + 书图标 + chevron。点开只有一个「返回知识库列表」。这一块占 52px（.kbw-rail-title 的 padding 9px + 30px 控件 + 分隔线），等于为了一个按钮做了一整个下拉。
改成
删掉 .kbw-rail-title 整块，目录从「工作区」直接开始。WorkspaceMenu 在这里没有第二个用途，不要为了保住组件而保留位置。如果以后要做「切换到其他知识库」，那是一个真正的切换器（带搜索、最近访问），不是现在这个单项菜单。
验收
目录第一行是「工作区」分组标题；.kbw-sidebar 内不再出现知识库名称；返回列表只剩面包屑一个入口。
X2

数据集子目录默认展开，5 个长表名把下面两整组挤到看不见

现在
useState(true) 让它一开始就是展开的。5 个 sync_hhweb_2026_*_m 占 135px，用户第一眼看到的是 5 行读不懂的物理表名；「语义模型」整组被推到 400px 以下。表名去掉 _m 后仍然太长，截断成 kpi_i…，而 12px 的字段数就贴在省略号右边，视觉上读成「kpi_i 12」。
改成
① 默认折叠，仅在 datasetId 存在（正在看某张表）时自动展开并用淡紫标出当前表；② 子项显示去掉公共前缀的短名：sync_hhweb_2026_lzgx_kpi_index_m → lzgx_kpi_index，完整名进 title；③ 字段数改成右对齐固定 16px 列、字号 9.5px，与省略号之间留 6px。
验收
首次进入知识库时目录只显示 10 项、总高 ≤ 380px；展开后 5 项 ≤ 135px，且每项都能读到业务主干词。
X3

「返回知识库列表」有两个入口，一个在顶栏、一个在目录最底部

现在
面包屑的「知识库」是可点的，目录底部又有一个 ← 返回知识库列表。后者在滚动区之外、固定贴底，看起来像全局操作，实际和面包屑同义。两个入口会让用户以为它们去的地方不一样。
改成
删掉 .kbw-rail-footer > button。保留面包屑作为唯一返回路径，并给它一个左箭头（s-chev-l）提示可点。目录底部只留状态，不放入口。
验收
目录底部不再有可点文字；面包屑「知识库」前有 10px 左箭头；点击回到 /configure/datasets。
X4

组标题右侧的「v15」和「5」用了同一种徽标，语义完全不同

现在
「数据集 5」的 5 是数量；「语义模型 v15」的 v15 是发布版本。两者位置、字号、底色完全一致，用户会顺读成「语义模型有 15 个」。而顶栏已经有一枚「已发布 v15」，这里是第三次说版本。
改成
组标题右侧只放计数类信息：语义模型组显示「33 条规则」（有草稿时改为「3 处草稿」并用琥珀色）。版本号不在目录出现，唯一位置是顶栏的绿色胶囊。
验收
目录内搜索 v15 无结果；语义模型组标题右侧为灰色小字「33 条规则」。
X5

内容少的页面顶到上边、下面留 300–400px 白

现在
草稿与发布：一张 170px 卡，下面 400px 空。成员与权限：一行表 + 三张卡，下面 260px 空。问数优化：一个 textarea，下面 380px 空。三屏都是「内容天然少 + 容器撑满」。
改成
统一一条规则：内容少的页面用窄栏。列宽 min(720px, 100%) 左对齐，剩余空间留给背景而不是卡片。并且空白必须被一个「下一步」占住：发布页放「去建模」，成员页放「邀请成员」，问数页放「示例问题」。不准出现「只有上边有东西」的页面。
验收
在 1440×900 下，发布 / 成员 / 问数 / 设置四页的主内容列宽 ≤ 720px，且页面最后一个元素离底 ≤ 220px。
X6

标签条和顶栏都是浅色，中间只隔一条 0.5px，两块粘在一起

现在
标签条底色接近白（#f7f7fa 系），顶栏纯白，当前标签与普通标签只差一点底色。浏览多个知识库时，眼睛找不到「现在在哪一张」。
改成
标签条底色压到 #e9e9ef，当前标签纯白且高度多 2px，与顶栏连成一张纸；普通标签文字降为 #5c6070，圆点降为 #b9bbc7，当前标签圆点点亮为品牌紫。
验收
截图去色后，当前标签仍可与其余标签区分（明度差 ≥ 4%）。

O1

流程条和指标卡都在报同一组数字

现在
三条状态条写「5 个数据集 · 总行数未统计」「v15 已发布」「已发布版本可用」；紧接着四张卡又写「数据集 5」「已发布版本 v15」。同一组数字在 90px 之内出现两次，读者会先读上面、再读下面，然后发现是同一件事。
改成
分工：流程条只回答「走到哪一步、下一步去哪」，一个数字都不报；所有数量归指标卡。每段右侧给一个去处的文字链接（数据集 / 关系图 / 问数优化）。这样两块各自有唯一职责，不再互相复述。
验收
.kbw-steps 内除序号外不出现任何数字；四张指标卡上的数字在全页只出现一次。
O2

四张卡一样重，但「v15」不是数量，是状态

现在
四张卡等宽等高，都用 23px 大字：5 / 33 / 2 / v15。前三张是"有多少"，第四张是"现在是什么状态"，却穿同一件衣服。卡片可以点（跳数据集 / 规则 / 视图 / 发布），但没有任何可点的暗示，右上角也没有箭头。
改成
前三张保留计数卡（数字 23px）；第四张改成状态卡：绿点 + 「v15 已发布」15px，副行写发布时间与"问数使用线上版本"。计数卡右上加 11px 箭头（30% 透明度，hover 到 100%），整卡 hover 上移 1px、阴影加深一档。
验收
四张卡里只有 3 个 23px 数字；「v15」所在的卡字号 ≤ 15px 且带绿点；hover 有位移。
O3

数据集表里有两列是零信息

现在
「数据来源」5 行全是「总部常规分析 · 本地模拟 MySQL/data_agent_sy…」，被截断且完全相同；「版本」5 行全是 v1。这两列占了约 340px，但没有任何一行与其他行不同——用户读不到差异，等于白占宽度。
改成
删掉这两列，换成「业务说明」列：12/12 正常、15/17 用琥珀 chip 标出缺 2 个。这一列是这张表里唯一"每行都不一样、且影响问数质量"的信息。来源统一在顶部连接条说一次。
验收
表格 = 4 列（数据集 / 字段 / 业务说明 / 操作）；每行至少有一处与其它行不同的值。
O4

右栏两卡不等高，底部还有一条 860px 宽的"一句话"

现在
「最近变更」120px、「成员与权限」96px，两卡内容量差不多但高度不同，内部留白也不一致。底部「问数已可用」横跨 860px，只有一句「当前问数使用 v15」，右侧 700px 全空——这一条既不承担信息，也不承担动作。
改成
右栏统一三张等高卡：发布 / 成员 / 数据源（数据源是真实信息：连接对象、5 张表、检测入口）。底部那条改成 48px 的入口条：图标 + 「问数已在这个库上启用」+ 一句说明 + 右侧「去问数」按钮。要么能点，要么删掉，不做纯装饰。
验收
右栏三卡高度差 ≤ 2px；底部条右侧有可点按钮，右侧不留空白。

不要顺手做的事

看起来该做，但先别做原因
把「上传文件」「关联数据源」加回左侧目录它们是数据集页的动作，不是目的地。加回去会重新制造"我在上传页还是数据集页"的判断成本。
给业务规则加"引用次数 / 影响多少道题"接口拿不到。设计稿里画了就等于让人以为有，最后实现只能编。
把概览的四张卡做成图表这四个数都在 100 以内，折线/柱状不增加信息，只增加视觉噪音。
给空态加插画这四类空态都有明确动作（上传 / 关联 / 邀请 / 去建模），一句人话 + 一个按钮比插画有效。

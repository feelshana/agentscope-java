先说核实结果：那些入口在这个状态下确实是死的

SemanticModelingPage.tsx 里，<main className="modeling-workbench-body mw-body"> 的 display 由 screeningPending 控制。字段整理进行时整块主工作台是 none， 而 4 个页签、布局切换、右侧栏、助手全在这个 <main> 里。

所以不是「删掉功能」，而是按状态切换头部：整理中 = 聚焦态，只留「返回 · 知识库 · 步骤条 · 退出」； 整理完成立刻恢复完整头部。这样既不丢功能，也不会出现点了没反应。

字段整理：四个决定

1说明全程可编辑，藏在输入框里反而不好用

代码里本来就是常驻 textarea rows={2}（第 205 行），已纳入字段一直能直接改 —— 是我上一版画错了。问题在长得像表单：19 个带边框的输入框并排，把每行撑到 76px。改成文字块（hover 浮浅底、聚焦出环、失焦保存），一行读完，需要时才变输入态。

2AI 建议这组按钮保留，并和「只看待确认」同排

按 AI 建议勾选 / 全选 / 全不选 与「AI 只依据字段名、样例值和空值判断，仅供参考。」在 fs-actions 里本来就成对存在（第 165–170 行）。上一版我没画，这次放回同一条 bar，右边接「只看待确认」，两件事一次做完。

3行的状态比功能更重要

四种状态：默认、悬停、聚焦编辑、未纳入。其中「未纳入」过去是整行变灰 + disabled 输入框，用户看不出说明还能不能写。现在说明保持可读并且照样能改（真实代码里它是 disabled，要去掉）、勾选框空着、字段名删除线，一行小字说清「说明不会进入模型」。

4筛选收敛成三档

原来是 全部 / 业务 / 技术 / 不确定。业务是默认态（19 个里 16 个），点它等于没筛；「不确定」才是用户要看的。 改成 全部 19 / 待确认 3 / 技术 0，三档都有人会点。若更想保留四档，把「业务」加回即可，只是多一档空筛选。

准备这一步：先判断要不要，再决定怎么问

现状

  • 时间范围是独立模态，automatic 模式下自动弹出；但只有数据源表 + 非维度 + 有日期列时才进候选，上传文件永远不出现
  • 业务文档是页面里另一张卡，与「开始建模」的卡片分开
  • 两个按钮「开始自动建模」「没有文档，直接开始」调同一个 startModeling
  • 没有事实表时整步跳过，但界面上没有任何交代，用户会以为漏了

方案

  • 合成一张清单卡；时间范围一旦出现，配置就地展开在它下面，不再点「修改」弹窗
  • 条件不满足时整块（行 + 配置）都不渲染，也不留占位 —— 副标题里一句话交代原因
  • 只有一个主按钮「开始自动建模」，文档既然是可选的就不需要第二个入口
  • 「不是事实表？标为维度表」这个出口保留在内嵌区右下角，标完这一行立刻消失
  • 点开始后这张卡原地换成助手四阶段，不跳页 —— 衔接第 3 部分

知识库形态候选事实表准备清单里怎么表现
数据源关联 + 事实表 + 有日期列有出现，配置就地展开（第 3 屏）

落地：3 段箭头步骤条塞进 52px 头部

原产品是 5 步（采样 / 字段整理 / 时间范围 / 业务文档 / 开始建模），但采样是后台自动跑的， 时间范围和业务文档又在同一页连续做完 —— 这 5 个节点里只有 3 个需要用户停下来做决定。 所以收成 3 段：整理字段 / 准备 / 自动建模。段数该对应用户的决定数，而不是系统内部的步骤数。

位置搬回头部：原来那条独立横栏（5 个带数字的节点，约 40px）整条并进 52px， 替掉 56px 的页签行，头部总高从 96px 降到 52px。

形状上，5px 细条的问题不是不好看，而是装不下名字——用户得先读右侧「准备 2/3」才知道在第几步。 改成 26px 高的箭头条（chevron），名字直接坐进色块里，状态、名称、顺序三件事一次说完。 箭头本身还带着方向：流程往哪走，形状就在往哪指。

咬合方式按你说的：每段左端凹进一个三角、右端凸出一个三角，一节咬着一节； 首段左端平直（左边没有东西可咬，开口反而像缺角）。凹和凸都取半高、12px 深（近似 45°）， 所以相邻两段的斜边完全平行，2px 缝就是一条等宽的斜线，看着才像同一条链。

配色沿用同一条原则：已完成的绿要淡，当前的紫要实。 三段都实心等于三个焦点；已完成混到 14% 淡绿、文字用深绿，它退成「走过的痕迹」， 未做的是 6.5% 灰 —— 屏幕上只有一处实色，眼睛自然落在「现在在做什么」。

「没有文档，直接开始」在准备环节还要不要

你截图里那个按钮，和新手引导最后一步是同一个东西。代码里它确实是两个按钮干一件事： startOffer 卡上「开始自动建模」和「没有文档，直接开始」的 onClick 都是 startModeling（SemanticModelingPage.tsx:488–493），区别只在文案。 同一动作给两个名字，反而让用户以为前者要求先传文档。

保留第二个按钮的代价

  • 两个都等价于「现在开始」，用户要花一秒判断"我算不算有文档"
  • 并排两个按钮，主按钮会被分走点击
  • 「业务文档」行既然标了「可选」，就已经说过"可以跳过"了

改用三层表达，不占第二个按钮

  • 行标题后挂一个「可选」小标
  • 副文案：未上传 · 写了指标口径会更准，不传也能开始
  • 主按钮左侧一行小字：不传文档也能开始

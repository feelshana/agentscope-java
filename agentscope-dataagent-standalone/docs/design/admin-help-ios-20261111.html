DataAgent · 界面优化提案

全局管理员 & 帮助与引导

延续产品的 iOS 材质体系（画布 #F2F2F7 · 22px 连续圆角 · 发丝线 · 单一焦点），把这两个「管理型」界面从信息表格改成可判断、可操作的工作面板。

一 · 全局管理员：问题不在排版，在「判断依据」

这一页现在只有三列，而授予权限恰恰是最需要依据的动作——谁是初始管理员、谁什么时候被授予、最近还在不在用。同时它没有接入 workspace-overview.css 的材质体系，从「更多」点进来像换了个产品。

1两套视觉体系并存

「更多」页是 #F2F2F7 画布 + 22px 白卡 + 三层阴影；点进「全局管理员」变成纯白底 + sunken 表头 + 8px 圆角的小按钮（AdminHistory.css）。同一路径下气质断裂。

2三列里有两列没有信息

「部门」三条里一条是 —、两条重复；「操作」整列只有一个红色文本按钮。真正该出现的权限来源、授予时间、最近活跃都没有，用户无法判断该不该移除。

3危险操作裸露且反馈错位

每行都摆一个「移除权限」，无图标、无危险色、无就近确认；点了以后确认面板出现在列表上方（GlobalAdministratorsPage.tsx:63），滚动到第三行时根本看不到。

4三行撑不满一屏

列表结束后约 400px 空白，页面没有回答「全局管理员到底能做什么」。这是授予前最该读的一段，现在完全缺失，只能靠人问。

5添加要跨三次面板

点添加 → 顶部展开搜索区 → 输入并点「搜索」→ 选中 → 顶部再出现确认区。三个面板依次堆在标题下方，页面跳动且失去上下文。

6唯一的管理员为什么不能移除

只有一位时按钮被禁用，提示「至少保留一位全局管理员」却放在页脚最下方（AdminHistory.css:133），与按钮相距整屏。

二 · 帮助与引导：把「说明书」做成可扫读的工具

HelpPanel 是 20 多个内联 style 对象堆出来的：460px 固定宽、24px 内边距、18px 间距，没有跟随产品圆角与层级。更重要的是三个按钮抢同一个焦点，而真正需要的「查」却没有入口。

1三个按钮抢一个焦点

「开始逐步指引」「重新打开新手任务」「重置新手任务」上下叠放，中间还是实心紫。用户读不出「重新打开」和「开始指引」的区别，也不敢点重置。

2说明写的是实现不是结果

「问数首页会再次显示清单，并从今天起重新计 7 天」——讲的是代码逻辑。用户只关心：清单会不会回来、之前的进度还在不在。

3段落没有落点

问数 / 建模 / 分析都是「标题 + 13px 正文」，靠 1px 分隔线连着；唯一的行动入口「去问数 ›」放段落最底部，是视觉最弱的位置。

4只有一屏，没有第二层

没有搜索、没有锚点。用户想问「权限怎么给」「字段说明在哪」时无处可查，只能从头读一遍。内容一旦增加，抽屉会变成无限长的滚动条。

5两件事共用一个滚动区

「新手任务的进度」是流程状态，「使用说明」是查阅手册，权重完全不同，却挤在同一个 460px 竖列里，互相稀释。

6入口卡片没有任何状态

「更多」页的帮助卡只写「查看使用说明」，看不出还有 2/4 步没做。用户点进去才发现有未完成任务——入口不承载状态就浪费了一次提醒。

三 · 改法与取舍

核心原则：管理页先给判断依据，再给动作；帮助页先给检索，再给流程，最后才是阅读。两处都只保留一个实心紫。

现在

  • 白底 + 8px 表格，与「更多」材质不一致
  • 三列：用户 / 部门 / 操作
  • 每行一个「移除权限」文本按钮
  • 确认面板插在标题与列表之间
  • 添加：搜索区 + 结果 + 确认三段式
  • 帮助抽屉 460px、内联样式、全部分隔线
  • 三个行动按钮纵向堆叠

方案

  • overview-surface 白卡 + 头像 + 状态点，同一套材质
  • 六列：成员 / 部门 / 权限来源 / 授予时间 / 活跃 / 菜单
  • 行尾「···」菜单，危险操作只用一次，且锚定在行上
  • 确认以浮层出现在该行下方，取消后回到原位置
  • 添加：弹层内输入即筛，结果行直接「添加」并原地变「已添加」
  • 抽屉 516px、独立 HelpPanel.css、卡片分组
  • 一个主按钮 + 一个文字链，重置收进菜单

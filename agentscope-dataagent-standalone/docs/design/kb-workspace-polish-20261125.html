改对了形式、没改掉重复：5 个新问题

01 顶栏和左侧目录，同一组入口放了两遍

现在
顶栏右侧「成员与权限」「设置」两个按钮，和左侧「协作与管理」组的两项目录，调的是同一个 select('members') / select('settings')。同一屏两个入口，用户会以为它们是不同页面。
判断
这不是遗漏，是第一轮没管顶栏。X1 只删了侧栏那块库名胶囊，没处理顶栏与目录的横向重复。
对应
V1

02 同一个东西两个名字：语义模型 / 语义建模

现在
左侧目录叫「语义模型」，概览流程条第二段叫「语义建模」。第一段更明显：「数据」+ 副行「数据已就绪」，同一句话说了两遍。
判断
术语不统一比排版错误更贵——用户在搜索、在跟同事描述时会用错词。
对应
V2

03 业务规则写「33 条 · 3 个分组」，但 tab 有 6 个

现在
groupsCount = allCounts.size，只数「有规则的小节」，所以显示 3。而六个官方小节是固定契约，tab 上明明白白列了 6 个，其中三个是 0。
判断
数字对不上，用户会怀疑规则丢了一半。这类错误在验收里最容易被抓。
对应
V13

04 标题栏被当成工具栏用

现在
资料页标题栏塞了 8 个控件（搜索、阅读/原始文本、A−/A+、引用到对话、更多、新增文档）；公共视图塞了 5 个（边聊边核对、工程文件、⋯、使用指南、起草）。
判断
标题栏应该只放「这一页做什么」，文档级操作应该跟着文档走。
对应
V19 V20

05 内容少的页仍然「上边有东西、下边是白的」

现在
发布页 260px 内容 + 640px 空白，「去建模」在页底；成员页空态 270px；问数页待处理卡 72px + 300px 空白。
判断
第一轮把「下一步」放进去了，但放得太远，等于没有占住空白。
对应
V21 V22

怎么用这一稿

只改什么
仍然是三类：删重复、把「空」换成有用信息、修尺寸。这一轮不新增任何功能，包括不要为了让某块不空而去加图表、加插画、加引用次数。
优先级
V1–V4 是壳，先做；V5–V9 概览是入口；V13–V16 收益最大；其余按 08 章顺序。
验收
每条都给了可量的数：高度差 ≤ 2px、出现次数 ≤ 1、宽 ≥ 300px。改完在 1440×900 下量，不用评审。
01

壳与跨屏：V1–V4

这四条改完，每一屏的左侧和顶栏都会变，所以要第一个做。其中 V1 和 V2 是「改对了形式、没改掉重复」的典型：结构没问题，但同一个入口、同一个词出现了两次。

V1

顶栏右侧与左侧目录，同一组入口放了两遍

现在
顶栏有「成员与权限」「设置」两个按钮，左侧「协作与管理」组也有这两项，代码里调的是同一个 select('members') / select('settings')。同一屏两个入口，用户会以为它们去的地方不一样。
改成
顶栏只留 「基于此库提问」（主按钮）和一个 「⋯」，把「复制链接 / 成员与权限 / 设置」收进菜单。成员与设置归左侧目录，顶栏不再重复。
验收
顶栏可点元素 ≤ 2 个；「成员与权限」不同时出现在顶栏与目录。
V2

同一个东西两个名字：语义模型 / 语义建模

现在
左侧目录叫「语义模型」，概览流程条第二段叫「语义建模」。第一段更直接：主标题「数据」、副行「数据已就绪」——同一个词说了两遍。
改成
全站统一为 「语义模型」；流程条三段的副行改成「已就绪 / 已发布 / 已启用」，不再重复主词；第三段删掉「已发布版本可用」。
验收
全站搜索「语义建模」0 处；「数据」与「数据已就绪」不再相邻出现。
V3

目录底部三个词没有状态，只是在重复流程条

现在
左侧底部一行「● 数据 ● 模型 ● 问数」，三个灰点、三种颜色都一样，既不表达进度也不表达可用性；而顶部流程条已经把这三件事说过一遍。
改成
删掉这一行。 目录底部留空，或只放不重复的信息（例如「上次发布 11/22」）。要表达状态就让流程条表达，不要做第二次投影。
验收
目录底部不出现与流程条重复的三段文字；侧栏高度不变。
V4

建模六个子页，顶栏动作三页三套

现在
关系图、业务规则有「模型检查 / 变更与待办 / 建模对话」三个；问数、公共视图、资料、发布只有两个（没有模型检查）；发布页只剩「建模对话」一个。同一个工作台，顶栏每换一页就变一次。
改成
统一三个按钮，按页禁用而不是隐藏：发布页禁用「变更与待办」（因为当前就在这一页），问数页禁用「模型检查」并给 tooltip 说明原因。
验收
六个建模子页顶栏按钮数量与顺序完全一致；禁用态有 title 说明。

02

概览：V5–V9

概览是每天第一眼看的页，所以它的重复最贵。第一轮把数字从流程条上拿掉了，但「发布」这件事在同一屏仍然说了三到四遍；业务说明列则从「零信息」变成了「全绿零信息」。

V5

发布状态一屏说三遍以上

现在
顶栏「已发布 v15」→ 流程条第二段「版本已发布」→ 第三段「已发布版本可用」→ 指标卡「v15 已发布」→ 底部条「问数使用线上版本」。同一件事，五个位置。
改成
发布状态只保留 顶栏胶囊 和 第四张指标卡 两处。流程条三段只写阶段名和下一步；删掉底部整条入口条，「去问数」并进流程条第三段右侧。
验收
概览正文（不含顶栏）「已发布 / v15」≤ 2 次；「问数可用」类表述 ≤ 1 处；页面少一条 48px 的横条。
V6

目录的「33 条规则」和指标卡的「33」撞车

现在
第一轮把目录里的 v15 换成了「33 条规则」，但主区第一张卡就是「业务规则 33」。同一个数字在左栏和主区各说一次，等于把 X4 的问题从「版本重复」换成了「数量重复」。
改成
目录默认态 不显示纯数字徽标；只在有草稿时显示琥珀色「3 处草稿」——那是状态，不是数量。数量归指标卡。
验收
目录默认态无数字徽标（草稿数除外）；搜索「33」在侧栏无结果。
V7

业务说明列 5 行全绿，又变成零信息

现在
五个绿色 chip：12/12、17/17、19/19、16/16、23/23。5 行全绿，没有任何一行与其他行不同——这正是第一轮 O3 想解决的「零信息列」。而且「12/12」要用户猜是字段数还是有说明的字段数。
改成
全绿时降级为 灰色文字「已覆盖」，不出绿色；只有存在缺项的行才显示琥珀 15/17 并可点。列头从「业务说明」改成 「字段说明」。
验收
全绿状态该列不出现绿色；有缺项的行出现琥珀且可点；列头文字为「字段说明」。
V8

右栏三卡差 12px，卡内还有空白

现在
实测「发布」96px、「成员与权限」104px、「数据源」108px。三张卡内容量差不多，高度各不相同，且每张卡标题到按钮之间有 20–30px 空白。
改成
固定 96px 等高：标题 + 一行信息 + 按钮，按钮贴底（margin-top:auto），不留中间空白。
验收
三卡高度差 ≤ 2px；每张卡内垂直空白 ≤ 12px。
V9

底部入口条与流程条第三段是同一句话

现在
流程条第三段「问数 · 已发布版本可用」，页面底部又有一条 48px 的「问数已在这个库上启用 · 问数使用线上版本，新的模型改动发布后生效」。
改成
删掉底部条，把它唯一的动作 「去问数」 移到流程条第三段右侧（与「数据集 >」「关系图 >」同一位置）。
验收
概览内「问数可用 / 已启用」类表述 ≤ 1 处；「去问数」按钮仍在首屏。

03

数据集与表详情：V10–V12

这一页第一轮改得不错：连接条、导入记录一行、来源 chip、表脚说明、两个虚线入口都到位了。剩下的三个问题都在「细节对不上」，但其中 V11 是用户一眼能看见的错。

V10

上传入口被禁用，但理由看不懂

现在
「上传文件」卡片是灰的，下面写「此库已关联数据源，请在独立知识库上传」。「独立知识库」是内部说法，用户不知道什么是「独立」；也没说点了会怎样。
改成
文案改成 「此库通过数据源接入。上传文件需在未关联数据源的知识库中进行。」 右侧给一个可点的「了解区别」，打开一张两行说明（文件库 / 数据源库）。
验收
禁用卡上有可点解释入口；全站不出现「独立知识库」四个字。
V11

表详情里有两列完全一样，最右列还被硬切

现在
左侧 # 列是 1–12，紧接着的「主键ID」列也是 1–12，两列值完全相同；用户会以为一个是行号、一个是业务主键，但看不出差别。同时 12 列放不下，最右「指标口径…」被切掉一半，没有任何渐变或提示。
改成
保留 # 作为行号，隐藏 id 列（自增主键没有业务含义；若确需，移到「技术信息」tab）。横滚区右侧加 36px 渐变遮罩，并在表脚保留「向右滚动查看其余 3 列」。
验收
相邻两列没有相同值序列；横滚时右侧有渐变；遮罩与提示文字同时存在。
V12

表脚三个数字互相矛盾

现在
表脚写「显示 20 行 · 总行数未统计」，但表格里只有 12 行；上方采样说明写「采样 200 行」。三个数字分别指「显示行数」「样本量」「总行数」，但没有任何一个词区分它们。
改成
表脚改成 「显示 12 行 · 采样自 200 行 · 总行数未统计」。三个数字各自带主语，且显示行数由程序计算而不是写死 20。
验收
三个数字能互相解释；显示行数 = 表格实际行数。

业务规则：V13–V16

这一页第一轮的方向是对的：两行式列表、右栏四块、底部两个按钮都落地了。但有两个必须修的硬错——标题写「3 个分组」而 tab 是 6 个；有 3 条锚点只有 2–8 个字，扫读时完全不知道是哪条规则。

V13

标题写「33 条 · 3 个分组」，但 tab 上是 6 个小节

现在
代码里 groupsCount = allCounts.size，只统计「有规则的小节」，所以是 3。而六个官方小节是后端契约，tab 上明明白白列了 6 个（三个为 0）。数字与 tab 对不上，用户会怀疑规则丢了一半。
改成
标题改成 「33 条 · 6 个小节（3 个有内容）」；或更短「33 条 · 6 个小节」。数字必须与 tab 数量一致，不要用「分组」这个和「小节」混用的词。
验收
标题数字 = tab 数量 = 6；全站不出现「个分组」。
V14

三条锚点只有 2–8 个字，扫读时认不出是哪条

现在
「全国」「月份」「业务类型各层级中」——这三条的首个停顿太早，取到 2–8 字就断了。用户扫列表时看到「全国」，无法判断这条规则讲的是什么。
改成
锚点不足 8 字时延伸到下一个停顿，上限仍是 28 字。例如「全国」→「全国 · 未指定会员类型时按全量统计」；「月份」→「月份 · 统计周期必须按整月读取」。
验收
33 条锚点长度均 ≥ 8 字且互不重复；「全国」「月份」不再单独成行。
V15

详情栏 240px，正文只有 4 行高

现在
右栏实测 240px，textarea 只有 4 行，规则原文读不全要滚动；底部按钮上方还有 70px 空白；「保存到草稿」按钮宽 190px，几乎占满整栏。
改成
右栏加到 300px；正文区 flex:1 撑满（≥ 10 行）；「保存到草稿」按内容宽度，不铺满；底部固定 8px 内边距。
验收
右栏宽 ≥ 300px；正文可视行数 ≥ 10；底部无 40px 以上空白；保存按钮宽 ≤ 110px。
V16

三个 0 条小节没降透明，分组标题也不吸顶

现在
「指标口径 0 / 外部编码 0 / 货币 0」三个 tab 的视觉权重和有内容的完全一样；分组标题「默认过滤 11」滚动时会跟着列表走掉，滚到第 20 条就不知道自己在哪一节。
改成
0 条小节 opacity:.5；分组标题 position:sticky; top:0，带白色背景遮挡下方行。
验收
0 条小节对比度明显低于其他；滚动时分组标题固定可见。

问数 / 公共视图 / 资料：V18–V20

这三页第一轮的结构都对了，问题集中在同一处：把标题栏当成了工具栏。资料页 8 个控件、公共视图 5 个按钮，全挤在页面标题右边，等于没有主次。

V18

示例问题问的是「足球会员」，这个库里没有足球

现在
右栏三条示例：26年10月份的足球会员、2026年10月各省咪咕视频在订会员数排名前五？、2026年10月咪咕游戏各一级业务类型的付费用户数分别是多少？。这个库的 5 张表是彩铃、游戏、音乐、阅读、视频——没有足球。而且第一条不是完整问句，只有八个字。输入框占位符「上个各品类的净销售额是多少？」还有语病（应为「上个月」）。
改成
示例从当前库的 5 张表与 33 条规则生成，三条分别覆盖视频、音乐、游戏；第一条补成完整问句。占位符改成 「例如：2026 年 10 月各省咪咕视频在订会员数」。
验收
3 条示例里的业务实体都能在 5 张表中找到；无错别字；第一条长度 ≥ 12 字。
V19

公共视图标题栏塞了 5 个按钮

现在
标题右侧依次是「边聊边核对」「工程文件」「⋯」「使用指南」「+ 起草公共视图」，其中 ⋯ 夹在中间，顺序没有逻辑；而页面的主任务（起草新视图）反而在最右边。
改成
主按钮 「+ 起草公共视图」；「⋯」 收「工程文件 / 使用指南 / 批量处理」；「边聊边核对」移到列表底部的虚线新建卡旁边，因为它是「没有视图时」的替代动作。
验收
标题栏可点元素 ≤ 3；⋯ 菜单 ≥ 3 项；起草按钮在最右。
V20

资料页标题栏 8 个控件，文档操作离文档 600px

现在
一行里挤了：在文档中查找、阅读 / 原始文本、A− / A+、引用到对话、更多、新增文档。前五个都是「针对当前这篇文档」的操作，却放在页面级标题栏，离正文 600px；「新增文档」反被挤到最右边缘。
改成
页面级只留 「+ 新增文档」；「阅读 / 原始文本、字号、引用到对话、更多」移到 文档头部右侧，与文档标题同一行；搜索留在左栏目录上方。
验收
页面标题栏控件 ≤ 3；文档工具条与文档标题同一水平线；新增文档按钮在右上显眼处。

不要顺手做的事

把「成员与权限」「设置」再加回顶栏

原因
它们已经在左侧目录里。顶栏和目录是同一组 handler，加回去就回到「两个入口」。

给「字段说明」列加进度条 / 环形图

原因
这列只有两个状态：覆盖、有缺项。全绿时它应该消失，而不是变成可视化。

为了填满规则页右侧而加统计卡

原因
右侧是编辑区，不是看板。正文撑满就够了，空白是正常的。

给示例问题编不存在的业务实体

原因
「足球会员」就是这么来的。示例必须从当前库的表和规则生成，否则用户点进去得到空结果，比没有示例更糟。

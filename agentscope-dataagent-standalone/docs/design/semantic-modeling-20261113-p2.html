第 2 部分：语义模型画布与对象栏

建模完成后进入的工作台：左边对象栏、中间画布、右侧详情抽屉。 这部分要解决三件事：对象栏把「模型 / 关系 / 视图 / 规则 / 检查」五类混在一列里，其中「检查」不是对象； 画布节点只给一行小字，看不出「这是什么表、有多少字段」；关系标签是浮在路径中点的按钮，跟端点的 N/1 是两套画法。 方案：对象栏按类型分组、检查沉底；节点加角色徽标；关系标签做成药丸、端点统一贴着卡片边缘； 缩放控件从工具栏挪到画布右下角悬浮。

先说现状：三个真实问题

代码都在 SemanticWorkbench.tsx 和 workbenchLayout.ts。这一页在「对象、画布、详情」三块都有可以收的地方：

位置现在是什么问题
对象栏 「模型 / 关系 / 视图 / 业务规则 / 检查」五组一列排下来；搜索要回车；「标出草稿改动」「需要处理」与对象并列 「检查」不是对象，是过滤器和状态；回车搜索在 2026 年显得旧；五组无视觉层级
画布节点 228 × 64，图标 + 名称 + 一行小字（「事实表 · 19 列 · 2 衍生」） 「事实表 / 维度表 / SQL 衍生」只是一行灰字，扫一眼分不出谁是谁；「未关联」只在对象栏里红，画布上看不出
关系 贝塞尔曲线 + 中点一个药丸按钮 + 两端浮着的 N/1 文字 标签按钮和端点文字是两套样式；N/1 浮在半空，没贴在卡片边缘；边没有「选中时跟节点一起亮」
缩放 工具栏右侧：− 80% + 适应 自动布局 全屏，六个控件一排 画布缩放是「就地操作」，放在顶部工具栏离手远；Figma / Miro / Linear 都在画布角落悬浮

对象栏：五组收成「对象 + 状态」两层

现在

  • 五个 RailGroup 并列：模型、关系、视图、业务规则、检查
  • 「标出草稿改动」是开关、「需要处理」是数字 —— 都不是对象，却和对象混在一起
  • 搜索框在最上面，但 onKeyDown Enter 才触发
  • 「未关联」只在模型行尾一个小红字，容易漏

方案

  • 上层四组只放对象：模型 / 关系 / 视图 / 规则；「关系」「视图」组头带 ＋ 直接新建
  • 「标出草稿改动」「需要处理」沉到底部固定区，和对象分开，视觉上是状态栏
  • 搜索输入即过滤，命中字染紫，每组显示「2 / 5」，空组给一句「没有匹配的模型」
  • 收起成 64px 图标列，未关联 / 待处理变成角标跟过去

画布节点：一眼分出「这是什么表」

现在节点的小字是「事实表 · 19 列 · 2 衍生」，角色混在一行灰字里。 改成角色徽标 + 数字：事实表是紫底小胶囊、维度表是青底、SQL 衍生是浅紫， 和图标色一一对应。扫一眼就知道这张表的「身份」，不用读字。

未关联的模型不该只在对象栏里红。画布上给它一条琥珀色的边，副行直接写「未关联」—— 一个模型建出来却没人用它，这是建模最常见的疏漏，应该在图上一眼看见。

关系：标签、端点、选中态，三件事一套语言

现状里关系标签是个按钮、N/1 是浮着的文字，两者样式无关。统一成： 标签始终是药丸（白底发丝边，悬停变紫边，选中变实紫）； N/1 始终贴在卡片边缘、用等宽字体； 点中一个模型，它连出的所有边和端点一起变紫 —— 这是「这条线属于谁」最直接的回答。

落地：关键样式

/* 对象栏：上层对象、下层状态，中间一根发丝线 */

.sw-rail-foot  { flex:none; border-top:.5px solid var(--da-hairline); }  /* 检查沉底 */

/* 搜索：回车 → 输入即过滤 */
<input value={query} onChange={e => setQuery(e.target.value)} />   // 不再等 Enter

这一步不做的三件事

×不做小地图（minimap）

模型数是个位数，画布一眼看完。等真有几十张表，先考虑的该是分组和筛选，小地图是最后的手段。现在加了也是占角落的装饰。

×不把字段列进全图节点

dbt / Hex 的大节点全图在 5 张表时就已拥挤。字段属于「聚焦视图」的中心卡，不属于全图 —— 全图只回答「有哪些表、谁跟谁连」。

✓给聚焦视图留的接口

双击节点进入聚焦，顶部出现「‹ 全图」返回条。这条返回条的位置和第 3 部分「建模助手运行中」的顶部状态条是同一个槽位，第 3 部分直接复用。

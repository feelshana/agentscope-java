① 准备 · 字段整理：每张表勾选纳入哪些字段、补业务说明；头部 3 段箭头条标示「整理字段 → 准备 → 自动建模」。对应 FieldScreeningPanel（mode=setup）。
① 准备 · 行状态全览：字段行的各种状态（AI 建议、已写说明、疑似无值、关联键）一屏看全，便于核对视觉层级。
① 准备 · 数据源表：字段整理完成后，时间范围就地展开（不弹窗），业务文档可传可不传；「开始自动建模 / 没有文档，直接开始」。对应 FactQueryWindowSettings + BusinessDocumentsPanel。
① 准备 · 上传文件：CSV / Excel 来源没有查询时间范围，准备步骤少一项——步骤按真实条件出现，不留空行。
② 空态与入口：欢迎卡说清「先落草稿、你确认才发布」；四条示例按类型分好（术语 / 口径 / 字段 / 关系），点一下直接成句；「开始建模」与准备页是同一个动作。新手引导改成顶部条，不再压住输入区和下一步卡。对应 ModelingChatPanel welcome + GuidedTour。
② 运行中：四阶段轨道（读取资料 → 确定口径 → 写入草稿 → 校验编译），当前阶段下挂一行具体到文件的动作；你新发的话进排队条——输入框、底栏、头部三处口径统一为「可以继续说，会排在后面」。「检查 —」表示还没跑过检查。对应 ProgressCard。
② 口径确认（业务 · 蓝）：影响统计结果的问题才来问你；推荐项在前、自己写其次、「不采用」收进文字链；答完最后一题一起交回助手。蓝色与写入授权的紫色分开：一种是业务判断，一种是工程动作。对应 ConfirmationCards + request_user_confirmation。
② 写入授权（工程 · 紫）：授权之前不写入草稿；先给预检结论，再给 diff；按钮三级——主「采用并写入 / 采纳」、次「编辑 / 调整」、文字链「让助手修正 / 跳过」。预检失败时主按钮禁用并说明原因，「让助手修正」升为主。对应 ModelingHitlCard 的六种授权形态。
② 一轮完成：每轮带锚点（#1 · 14:32），四阶段变成可回看的阶段史，过程折叠成三行摘要——读了什么 / 定了什么 / 写了什么；失败与被否决的步数默认可见，点「查看 31 步明细」回溯。不再是「一结束就失忆」。对应 TurnResultCard + NextStepCard。
② 异常与窄栏：左：读取失败（阶段红 + 失败步骤行）时给明确出口——重试 / 跳过这列继续 / 停止；断连有横幅，内容先存本地。右：并排模式下右栏只有 440px 时，确认卡收成「一句话 + 打开详情」，diff 进抽屉——而不是挤成一团换行。四阶段的「跳过」虚线态见左图。对应 ModelingHitlCard 错误分支 + dock 宽度策略。
③ 模型画布 · 全图：对象栏按模型/关系/视图/规则分组、检查沉底；节点带角色徽标与字段数；关系是药丸标签，N/1 端点贴卡片边缘。对应 SemanticWorkbench。
③ 模型画布 · 对象栏三态：默认分组列表 / 搜索过滤 / 收起为 66px 图标列，三种形态并排对照。
③ 模型画布 · 聚焦视图：双击节点后只看它的直接关系：中心卡列出字段与关联键，邻居围一圈，点邻居跳转。
③ 模型画布 · 选中 + 详情抽屉：选中节点/关系后右侧抽屉给出说明与字段明细，可直接改描述（写回草稿）。
④ 校验与确认 · 待确认面板：「助手在问你的」与「助手改了、你还没看的」合并一栏；看过变灰，可定位到画布/规则，可撤销回线上版本。对应 PendingPanel。
④ 校验与确认 · 校验未通过：发布前自动检查失败时，错误定位到具体关系（红色虚线 + 标签打叉），底部草稿条给出一键「交给助手修复」。对应 DraftBar 的 issues 提示。
⑤ 发布 · 可发布：口径全部确定、校验通过后，对话末尾的「下一步」卡与底部草稿条同时给出发布入口（同一动作）。对应 NextStepCard + DraftBar。
⑤ 发布 · 已发布：头部出现「线上 v1 · 可问数」；发布后索引与预热约半分钟，「去问数」按钮随之从「问数准备中…」变为可点。版本菜单可查看线上版或与草稿对比。
⑥ 迭代 · 问数优化 + 试问：左：问题清单按待分析/待生成/待确认/已确认推进；右：试问面板逐题核对 SQL，确认后发布才会被问数召回。对应 QueryCoachPanel + TrialPanel。
⑥ 迭代 · 公共视图：建设中能力说明 + 立即起草入口：把反复出现的查询逻辑沉淀成可复用视图，批准后才进草稿。对应 SemanticAssetsPanel。
⑥ 迭代 · 资料：数据（表与字段纳入情况、单表重建模）与业务文档（上传/替换/删除，变化自动同步草稿）的常驻入口。对应 SemanticModelingPage overview 页签。
高级 · 工程真相层：画布下沿那行 11px 灰字改成有位置的入口（带快捷键）；点开升为模态，左侧对象树、右侧代码，一次只看一个对象，不再把 4 个 YAML 面板纵向堆在画布下面。顶栏切「草稿 / 线上 v1」，草稿产物标出「之后有 2 处改动未编译」，并说明线上这份就是问数通过 wren://mdl 读到的那份。只读，但给出「在对话里问这段」把查看接回修改。对应 CompiledMdlPanel + AssetYamlBrowser + ModelSnapshotPanel。

贯穿全流程的五条规则

1单一焦点。任何时刻只有一处主按钮：准备页的「开始自动建模」、草稿条的「发布 v1」、下一步卡里的「发布」是同一个动作的两个入口。

2草稿即真相。助手所有写入都落在草稿；画布、规则、待确认读同一份草稿。「查看线上 vN」只是只读快照，不产生第二条时间线。

3不确认不阻塞保存。口径未定也能继续建模、也能发布（会提示）；确定后自动补写规则，并把等待该口径的 SQL 生成出来。

4准备不强制。文档可选、上传文件不需要时间范围；步骤按真实条件出现，不为了对齐形状留空行——3 段箭头条的形状始终不变，位置感才稳定。

5真相可查，但不可改。界面上任何一个模型，都能一步看到编译器真正读进去的 MDL；标明是哪一版、什么时候编译的。只读——要改仍走对话，避免出现「改了源文件却没进草稿」的第二条真相。

接缝处的三个决定：① 建模中禁止在画布改字段（避免和助手抢写），但允许看；② 发布前必须先过校验，失败定位到具体关系而不是只报一句话；③ 发布后问数预热约半分钟，「去问数」跟着可用性变灰/变亮，而不是点进去才失败。

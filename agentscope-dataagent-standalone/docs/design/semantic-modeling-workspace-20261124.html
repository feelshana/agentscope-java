01

统一信息架构：一个壳、四组目录

三条路由收进一个壳，不是重写功能

下面是全稿唯一的导航依据。S1 是它的完整示范；02 章的 10 屏只是同一壳换选中项与右侧内容；03 章的业务规则也挂在这个壳的「语义模型 / 业务规则」下；04 章的组件图左侧是简化壳，不作准。

现在的割裂不在视觉，而在导航结构：知识库详情、数据集详情、建模是三条路由，其中建模页还会把整个全局侧栏隐藏掉，等于跳进另一个应用；从详情页去建模，只能点进度条右端那颗「完善建模 / 去建模」按钮。这一章把它们收进同一个知识库工作台：顶部标签条说明「你打开了哪个库」，顶栏用 知识库 / 库名 面包屑（点「知识库」在当前标签页回到列表，不再放 logo 图标），左侧是一份完整目录，右侧只换内容。建模不再是按钮，是目录里的一个分组。

01

三条路由，三套导航

/configure/datasets/:groupId（库详情）、/table/:datasetId（数据集详情）、/modeling/:groupId（建模）。数据集详情是三级面包屑 + 全宽表格；建模页由 isModelingWorkbench() 把 AppShell 侧栏整个移除，再自建一套 68px rail。

改法：一个工作台壳常驻，目录承载全部一级导航；建模画布只是「语义模型」分组下的主区内容。

02

「去建模」是个按钮，不是一个位置

进度条显示 v14 已发布，入口却是右端一颗下拉按钮；导入文件成功后还会 navigate('/configure/modeling/...') 自动把用户传送过去。状态与导航分离，用户没有「我在库的哪里」的感觉。

改法：三步流程不再是跳转按钮，每一步指向目录里的固定项；建模入口始终可见、可选中。

03

空库和满库是两张完全不同的页面

0 个数据集时是三块大卡 + 独立上传表单，5 个时是表格；成员与权限、设置都藏在顶栏弹窗里，没有固定位置。功能一多，用户只能靠记按钮。

改法：目录四分组固定不变；有/无数据只改变目录里的子项与状态，不改变信息架构。

04

数据接入没有可回溯的位置

关联数据源、上传文件都是弹窗，导入进度条只在页面上临时出现一次。真实状态机有排队 / 上传 / 解析导入 / 准备模型草稿 / 已导入模型未就绪 / 失败 / 待确认 / 完成八态，却没有一个地方常驻。

改法：「数据」分组只留「数据集」一个入口；上传 / 关联是数据集页里的「添加数据集」动作，连接状态条与导入八态记录是该页的常驻区块，不再占两个一级目录项。渠道不是目的地——做成菜单项只会和数据集页里的按钮、拖拽区重复，还逼用户先想「我现在是在上传页还是数据集页」。

旧入口 → 新目录项：一次映射，功能不减

全部来自当前路由与组件，不新造能力，只重新给它们一个固定位置

为什么目录里不再有「关联数据源」「上传文件」：它们只是往知识库里加数据集的两种渠道，不是用户要去的目的地。数据集页已经有按钮、拖拽区和示例入口，再造两个一级菜单项等于把同一件事说两遍；渠道收进动作、状态留在同一页，目录只留一个数据入口。
为什么空库也保留语义模型分组：把未解锁的项整组隐藏，用户会以为系统只有上传功能；降权 + 一句原因，既保留信息架构，又说明先后顺序。顶部标签条与目录底部三步进度是同一份状态的两种投影，不会互相矛盾。

导航分两级

139px 文字导航挤着 5 个模块，对象目录只剩 193px，技术名必然截断。

250px 四组目录（工作区 / 数据 / 语义模型 / 协作与管理），顶栏从「知识库 / 当前库名」贯通到发布按钮。模块与对象在同一棵目录里，右侧只换内容，宽度够放两行技术名。

一个检查器槽位

一体化工作台的实现与真实数据

对应 S1–S24 的落地补充

场景产品实现数据与交互边界
S1、S6 · 进入或返回知识库卡片打开独立的浏览器标签页，落到概览。浏览器的原生标签承载图中的标签条；工作台通栏显示「知识库 / 库名」。面包屑返回当前标签页中的知识库列表。部署前缀、登录会话和旧建模链接继续适用。
S2、S7 · 数据集数据页集中上传文件、选择示例、关联数据库表、连接检测与导入记录。完成后继续在数据页查看结果。引导模式仍可继续到首次建模。导入状态取服务端已记录的八态与当前上传进度；解除关联沿用单表操作。
S3–S5 · 数据集详情目录选表，主区切换数据预览、字段信息与技术信息。预览列和字段列表使用右侧详情，说明在详情中编辑。样本仅用于观察。物理表结构显示接口提供的名称与类型。字段说明与模型业务口径仍走现有保存与发布流程。
S8、S11–S24 · 语义模型六个模块共用目录与通栏。关系图保留可展开的对象目录；草稿与发布复用同一变更、待办和发布校验。使用权限可看线上模型、规则和已确认问答。视图引用计数、同步审批等依赖额外数据的示意沿用现有能力范围。
S9、S10 · 协作与管理成员管理、名称与说明、事实表时间范围、删除知识库都有固定位置。管理权限才能写入；角色、表范围的校验、授权和删除确认复用现有流程。

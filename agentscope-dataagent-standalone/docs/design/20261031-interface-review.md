## 2. 核心判断

项目已经有完整业务能力，主要问题是能力的呈现方式没有形成稳定的秩序。用户需要同时理解知识库、数据集、草稿、模型、发布、准备状态；如果所有区域都用同等重量的框、紫色按钮和提示条，用户会觉得复杂，即使功能本身正确。

建议用四条明确的界面原则统一：

1. **业务人员先看任务和结果。** 首页先让人提出问题；答案先让人理解数据；技术过程按需展开。
2. **维护人员先看状态和下一步。** 每个工作区只突出当前最重要的动作，不把“上传/建模/发布/问数”都画成同等优先。
3. **保持上下文。** 知识库名、当前在看草稿还是已发布版本、是否能编辑，出现在固定位置。
4. **状态表达可核对。** 导入完成、写入草稿、发布完成、问数准备完成分别表达；不虚构百分比、预计耗时、准确率或实时健康监控。

这比全站换色、增加动效或再堆一批功能更适合当前上线阶段。首页、回答、知识库是用户最常见的三个接触点，应先形成一致印象。

## 4. 上线前建议选哪一批

**建议先选A1–A4，B1、B2独立安排。不要因为原型画全了就一次改完。**

| 批次 | 具体范围 | 预期收益 | 风险 |
|---|---|---|---|
| A1 首屏 | 首页去重、输入框/推荐问题/新手提示局部整理 | 第一印象清楚，用户容易开始 | 低，注意新手分支 |
| A2 回答阅读 | 标题/正文/图表间距、反馈复制一行、文件入口识别度；保留右侧预览 | 高频使用最明显，输出更像可用成果 | 低到中，保护长回答滚动和附件分支 |
| A3 资源导航 | 知识库卡片密度、无说明处理、空库入口、数据集表头 | 信息量更合适，寻找数据更快 | 低，权限/删除状态不得漏 |
| A4 连接与一致性 | 主机解释、连接错误、更多分组；统一少数按钮/表单/空态 | 减少真实操作困惑，页面更完整 | 低，局部限定CSS |
| B1 状态与下一步 | 知识库详情、建模列表主动作、未知状态、发布与准备提示 | 减少走错路径 | 中，需要状态组合回归 |
| B2 建模工作台 | 准备/对话/结果/确认/试问/发布的布局重排 | 复杂流程更容易理解 | 中高，上线前时间不足就后置 |

A1–A4可拆成独立的小补丁。初步估计**约2–3个开发人日，加至少1个针对性回归人日**，不是实测承诺；有冲突或接口差异时缩小范围。若只剩1–2天，优先A1、A2的纯排版以及A4的主机说明，知识库/建模动作条件先不动。

本轮不建议顺带做：全站组件库替换、统一状态机、自动简报/提醒、回答结构协议重写、报告编辑器、可拖拽建模画布、暗色模式、全局搜索、成果分享/收藏、数据库画像扫描。它们可作为上线后候选，不能归入“小而美”。

## 6. 调研转译：取设计原则，不复制产品能力

阅读官方公开说明，未进入竞品登录后台实测。

- [Linear：A calmer interface for a product in motion](https://linear.app/now/behind-the-latest-design-refresh)：强调导航退后、内容优先、减少无意义分隔与图标。对本项目的推论：降低框和按钮的同等权重，使操作位置可预期。
- [Notion：Gallery view](https://www.notion.com/help/galleries)：画廊的大小与可见属性可按内容调整。对本项目的推论：卡片应承载对业务有用的信息；没有封面与视觉内容的知识库无需硬加大图或装饰。
- [Quick BI 智能小Q](https://help.aliyun.com/zh/quick-bi/user-guide/smartq)：将自然语言提问、快捷问题、多轮分析组织成明确使用入口。对本项目的推论：优先让普通问数简单，再按需进入已有归因/异常/预测；不照搬其报告/搭建Agent等未实现能力。
- [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)：本轮以其可访问性、焦点、表单反馈、长内容和减弱动效要求作检查参考；它不能替代实际产品验收。

## 7. 工程观察与验证边界

1. `DatasetsPage`创建表单上下各有一处`formError`输出，可在局部改造时合并成字段附近单一错误。

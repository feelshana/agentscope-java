走查结论：九类问题，都有实测依据

分支 develop-2.0 · spec149 / spec153 · 1440×900 · 0.82 缩比进稿

9 类问题 · 5 组实测

先把边界说清楚：这一版只分析界面，不改产品代码。所有数字来自 getBoundingClientRect() 与真实接口返回， 不是目测。两个知识库：普通问数用已有的「总部常规分析-本地复刻」（5 表 / 33 规则 / v16），口径问数用我新建的「UI走查-口径问数」 （上传 视频.xlsx + 用户.xlsx + 《视频口径手册.md》，实测 14 处草稿）。

P0

不可逆决策被写成脚注

创建弹窗实测约 517×547；「创建后不能更改」是选项下方一行 9.4px 灰字，两个模式只有标题+两行说明，用户看不出选错的代价。

P0

两种模式共用一套 IA

口径库多一个「口径」菜单，但「关系图 / 业务规则 / 问数优化 / 公共视图」在口径模式下多为引导或空态，却与「口径」同权同色。

P1

垂直空间普遍只用一半

概览、成员、口径总览、问数优化：内容止于 y≈470–520，900 屏下半约 350px 全白。实测 main 1196×848，卡片是铺满宽度的，问题在纵向。

P1

同一屏多个「下一步」竞争

关系图首次建模同时出现顶部淡紫横幅「确认建模字段」与中央黄卡「还没有建立关系」；口径总览每张表卡各有一个实心紫按钮。

P1

黄色系统泛滥

模型卡底部「未关联 N 列」黄条 + 中央提示卡黄底，与淡紫主色同时出现，整屏泛黄。黄色应只做 6px 状态点。

P1

空态不像一个页面

问数优化未发布时只有一行居中 12px 文案；成员页用 520px 高的表格容器装 1 位成员；对话建模空态只有一张草稿卡 + 底部输入框。

P2

信息重复计数

概览页「数据集 5」在状态条、统计卡、表格三处出现；顶部 4 张状态卡 + 3 张统计卡 + 右栏 3 张卡都在讲同一件事。

P2

抽屉挤压主内容

「边聊边核对」抽屉约 420px，把公共视图详情挤到 470px，长段说明换行 5–6 行，反而更难核对。

P2

术语不统一

同一流程里交替出现「审阅草稿 / 完成口径 / 去问数 / 检查并发布 / 发布检查 / 发布前检查」，指向的状态还不一样。

一个反直觉的诚实修正：我一度以为各页右侧留了 330px 空白；实测证明卡片是铺满 1196px 主区的（概览右栏到 x=1410、设置右栏到 x=1410）。所以问题不是宽度没用满，而是纵向没用满、以及层级没拉开。这条写进稿里，免得改错方向。

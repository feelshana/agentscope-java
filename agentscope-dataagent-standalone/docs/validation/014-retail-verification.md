# specs/014 + specs/015 零售语义建模与 Wren-only 验证指南

## 1. 准备数据

本地 MySQL 已使用 `014-retail-fixture.sql` 创建以下表：

- `data_agent.ds_demo_customer`：6 行
- `data_agent.ds_demo_product`：5 行
- `data_agent.ds_demo_order`：10 行
- `data_agent.ds_demo_order_item`：11 行
- `data_agent.ds_demo_refund`：4 行

脚本可重复执行，不会删除其他表或数据。

在系统中创建一个测试知识库，把上述 5 张表从本地 MySQL 数据源一次性关联到同一知识库。建议保留原表名作为数据集名，并开启采样，让 JDBC 注释和低基数枚举先进入字段元数据。

关联请求成功返回前应自动完成一次 BASELINE 发布，无需在建模页手工发布即可调用 `wren_describe_model` 和 `wren_run_sql`。工具清单中不应再出现 `prepare_data_context` 或 `query_structured_data`。建模页各区域应显示“表名称 — 中文业务含义”，而不是 datasetId 或 `ds_*` 物理名。

## 2. 路径 A：上传文档验证

上传 `014-retail-semantic-source.md` 作为该知识库的说明文档，然后打开“语义建模”页：

1. “文档语义增强”卡片先显示“分析中”，之后变为“已完成”。
2. 应看到 Relationship、Cube、View、业务术语、业务规则中的多种提案；实际拆分数量允许因模型而不同。
3. 已被字段注释完整覆盖的列描述或状态枚举不应重复形成提案。
4. `quantity * unit_price` 应显示为 `MANUAL_FIX`，不能直接采纳。
5. `CONFLICT` 提案不能直接采纳。
6. 逐条采纳 Relationship、Cube、View 后，MDL 状态应变为 DIRTY；Wren 查询继续使用上一版基础快照，直到显式执行 SEMANTIC 发布。
7. 采纳 Term 或 Business Rule 后无需发布 MDL，下一轮问数即可看到它们。
8. 再次点击“重新分析”，已采纳或仍待处理的同一提案不应重复出现。
9. 使用另一账号访问该知识库或提案 ID，应统一得到不存在/无权访问结果。

建议优先采纳以下资产：

- 4 条业务关系：订单→客户、明细→订单、明细→商品、退款→订单；
- Cube：`有效订单分析`；
- View：`customer_monthly_net_sales`；
- 术语：高价值客户、净销售额、客单价；
- 规则：有效订单、有效退款、区域名称；
- 保留订单明细行金额为人工处理。

最后在“MDL”区域校验并发布模型；发布后确认新 Relationship、Cube 和 View 可由 Wren 查询。

## 3. 路径 B：不上传文档验证

不要上传文档，直接在“对话建模”中粘贴 `014-retail-semantic-source.md` 的全部正文，并补充：

> 请先读取当前建模状态、术语和业务规则，逐项判断 NEW、PARTIAL、CONFLICT 或 COVERED。不要重复创建已覆盖内容。先向我展示拟变更清单；只有我确认后，才分别调用关系、Cube、View、术语或业务规则工具落库。计算列没有安全落点时只报告人工处理。

预期行为：

1. 助手先调用 `list_modeling_state`、`list_terms`、`list_business_rules`，不应直接写入。
2. 助手说明每项差异及落点，冲突项停止并询问。
3. 用户确认后，助手调用对应工具；业务规则保存后提示“下一轮问数立即生效”。
4. Relationship、Cube、View 变更后执行 `validate_mdl`，并提示用户仍需发布。
5. 重复粘贴相同内容时，助手应识别已覆盖内容，不创建同名资产绕过冲突。

## 4. 问数验证问题与预期结果

以下预期结果以“有效订单”和“有效退款”规则为准。

1. “2026 年第一季度有效订单有多少笔，实付金额合计是多少？”
   - 预期：6 笔，39000 元。
2. “按原订单支付月份统计净销售额，并画趋势图。”
   - 预期：2026-01 为 13000 元，2026-02 为 7500 元，2026-03 为 17000 元。
3. “哪些客户属于高价值客户？给出累计净销售额。”
   - 预期：星河科技 13500 元、北辰制造 13500 元。
4. “按区域统计第一季度净销售额，从高到低排序。”
   - 预期：华东 13500 元、华北 13500 元、华南 10500 元。
5. “第一季度每月有效订单数是多少？”
   - 预期：1 月 2 笔、2 月 1 笔、3 月 3 笔。
6. “订单 O1009 的净销售额是多少？说明为什么。”
   - 预期：6000 元；R004 状态为 REJECTED，不能冲减。
7. “逻辑删除订单 O1006 是否计入 2 月销售额？”
   - 预期：不计入；2 月有效销售额仍为 7500 元。
8. “美元订单 O1008 是否计入有效订单指标？”
   - 预期：不计入；有效订单规则只统计 CNY。
9. “按商品品类统计有效订单购买数量，哪个品类最高？”
   - 预期：FOOD 9 件最高，其次 HOME 3 件、DIGITAL 3 件。
10. “查询 customer_monthly_net_sales，列出星河科技各月净销售额。”
    - 预期：2026-01 为 10000 元，2026-03 为 3500 元。
11. “客单价是多少？”
    - 预期：6500 元，即 39000 / 6。
12. “退款发生在 2 月的 R002 应归属哪个销售月份？”
    - 预期：归属 2026-01，因为按原订单 O1001 的支付月份归属。

## 5. 重复与冲突验证

- 再次上传同一文档：已采纳提案不应重新进入 PENDING。
- 修改文档，把“有效订单包括 CANCELLED”后重新上传：应产生 `CONFLICT`，且审阅卡不提供直接采纳。
- 删除文档内容后手动触发：任务应进入 FAILED，并显示“知识文档为空”。
- 临时停用模型后上传：上传本身应成功，增强任务失败但不影响知识文档保存。

# ADR 0048: 持久会话历史、附件与受限沙箱生命周期

日期：2026-10-08
状态：已接受（已实施；运行验收范围见 spec 039）

## 背景

懒加载本身未消除历史请求中的沙箱访问；列表为生成标题和摘要逐个读取完整消息，使历史量与请求延迟耦合。Python 产物依赖临时容器，回收或下一次执行可能使历史链接失效。Wren 的 CSV 交接也会提前创建容器。

## 决策

1. 分离展示、续聊和执行：数据库 `session_history` / `session_message` 提供列表和消息分页；引擎本地日志与上下文继续支持续聊；Docker 仅承担临时执行。列表默认 20 条，正文默认 50 条。
2. 展示消息是本地引擎日志的持久投影：后台增量补齐，回答完成时刷新；未落引擎日志的 token 不保证恢复，不把投影描述为分布式事件日志。
3. 附件实体 `session_artifact` 管理所有者、会话、批次、文件名、大小及来源。内容保存到可配置持久目录；临时文件写入后移动，再登记数据库，失败补偿清理。工具返回永久附件链接。
4. 附件仅对所属用户开放，前端通过 Authorization 请求头获取 Blob 展示或下载；永久附件接口拒绝 query token。没有公开分享功能。
5. Wren CSV 先持久保存，Python 使用时自动准备最近 10 个输入文件、预算 100 MiB，并检查工作区空间。旧输入可由 `restore_artifact` 显式恢复；不删除已有永久文件。每次 Python 调用使用独立执行目录。
6. 附件默认单文件 20 MiB、每用户 1 GiB、每会话 100 个、全站 10 GiB，磁盘预留 2 GiB。分段用户锁协调写入与删除，全局短临界区预占容量；这些保障限定单应用实例。
7. 每分钟分批检查最多 100 条附件记录和 100 个目录项，对超过一天宽限期的孤立文件进行补偿清理；跳过正在写入的用户，单项失败记录日志后继续。正常会话及附件不自动过期。
8. 沙箱按用户和 agent 复用，活动租约防止执行期间空闲回收；配置容器数、CPU、内存、PID、临时空间限制。启动清理只匹配 managed 与 instance 标签，旧版无标签容器需人工处理；删除确认前不释放容量名额，失败后台重试。
9. 删除及重置会话清理展示消息、引擎历史文件和关联持久附件；运行中的会话拒绝删除或重置。

## 权衡与边界

- 数据库列表避免请求中读取完整日志和 Docker；并不意味着模型生成、SQL、后台索引或大历史数据库查询没有性能成本。
- 本地持久目录适合当前单实例规模，部署须挂载持久卷；备份必须同时覆盖数据库、附件与引擎工作区。
- 不是多实例协调方案；共享配额、统一沙箱调度和对象存储留待实际部署规模需要时设计。
- 收集产物使用二进制读取及大小检查，绕过 Docker exec 输出截断；不备份沙箱内任意文件或 Python 内存变量。
- 正常历史的定期过期删除由 ADR 0049 定义，默认关闭；孤立文件清理仍不能解释为业务保留策略。容量告警目前为日志，未接外部告警平台。

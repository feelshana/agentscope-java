# ADR 0063：统一 Wren SQL 与相关示例召回

- 状态：Accepted（用户已授权开发）
- 日期：2026-10-09
- 关联：ADR 0062、specs/055；取代运行流程中的 Cube 优先策略。

## 背景

自由问数不依赖固定报表。Cube 增加成员、时间粒度与筛选参数的调用路径；最新日志出现时间分组代替时间筛选、输出别名被误认为模型字段等问题。已点赞示例保存成功，但安装版 Wren 的 grep 后端只匹配英文/数字，中文改写召回不足。用户明确取消 Cube，并自行删除旧数据，本轮不迁移或删除历史资产。

## 决策

1. 运行产品统一通过 Wren 在已发布普通逻辑模型、SQL 定义模型和视图上执行 SQL；不开放物理 SQL 回退。模型、关系、指标公式、时间归属、单位和规则形成业务上下文，必要的强制过滤与复杂关联落到保留身份及原始时间的明细视图。Cube 工具、目录注入、页面入口与写面全部停用；旧 Cube API 拒绝操作，不自动处理历史数据。历史 MDL 解析类型可保留以减少无关存储变更。
2. 建模沿用 YAML-first、副本技术预检、完整方案 HITL 和显式发布；问题可选。统一工具返回与页面下一步，避免再次要求全题确认。提示词要求尽量一次提交关系、视图和规则，修改后重取 base_revision。
3. SQL 生成前明确对象、指标、时间范围、分组与排序，必要时澄清；时间必须写入筛选，列名来自模型详情。复杂 SQL 先规划检查，执行异常自动修正，空结果先检查条件。只在工具调用与答案查询声明结束后输出完整最终答案。
4. 召回优先复用官方多语言向量 memory。合并建模确认示例与显式点赞样例，仍按 ownerId/知识库隔离；检测并报告实际后端、索引或依赖不可用状态。降级时提供中文文本相关性检索，排除仅年份/数字重合的命中，明确其不具备向量语义能力。示例只是生成 SQL 的参考，必须按新问题改写并重新执行。
5. 从本轮可信执行历史保留原始用户问题、业务子问题、SQL 与实际行数限制；官方 memory 中使用可独立复现的 SQL 表达 TopN，问数调用时仍按本工程协议传 limit 参数，不直接执行含 LIMIT 的召回文本。内存声明工具不写样例，只有最终答案点赞后保存；执行失败、诊断、未采用和被替代的查询不保存。保存错误明确显示，撤销仅撤掉本次来源。

## 取舍

SQL 的灵活性增加，同时指标公式必须作为显式上下文提供，不能认为视图能覆盖所有计算。向量依赖与嵌入模型可用性必须可观察；本机不可用时不会把 grep 宣称为语义检索。中文降级检索用于可用性，不替代官方向量召回。查询参数保存属于执行含义完整性，不引入样例可信等级或版本有效性治理。

## 不做

旧数据迁移/删除、指标回归引擎、资产适用范围检查、样例可信等级、模型版本有效性和发布范围治理、自动点赞或未反馈自动保存。

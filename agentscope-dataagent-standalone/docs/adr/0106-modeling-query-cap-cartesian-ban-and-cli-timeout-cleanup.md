# ADR0106：建模查询单轮硬上限、禁止笛卡尔积、超时进程树清理与屏蔽 Cube 参考

## 状态

已接受，2026-10-20。补充 ADR0104/0105。ADR0104 中"探查只用软约束、不新增计数"的部分由本条取代。

## 背景

上传库"ttt"的建模中出现了以下问题：

- 单轮执行了 18 条查询，远超 ADR0104 建议的每表 2 条，其中包括取值分布、手机号去重，以及为量化"项目名含逗号"连续写的多条查询。
- 最后写出 `用户列表 CROSS JOIN 报表访问明细`，约 2 亿行，运行 181 秒后被 CLI 超时终止。
- 加载了被提示禁止的 `references/cube_proposals.md`。
- 用完 30 次迭代上限，关系未写入，最终修改也未校验。
- `ProcessWrenCli` 超时时先结束父进程。Windows 上 wren 启动器拉起的 python 子进程会因此成为孤儿进程。

## 决策

- **单轮硬上限。** `OfficialWrenToolkit` 对建模的 `query` 设单轮硬上限 `MAX_QUERIES_PER_TURN = 10`，探查与样例验证合计。计数保存在每轮重建的 RuntimeContext 中，不跨轮。超限时不执行 CLI，返回中文说明，要求基于已有结果完成建模，不得改写成其他查询重试。只计入通过参数、Cube 和门禁检查、实际执行的 `query`。
- **禁止笛卡尔积。** `OfficialWrenToolkit#requireReadOnly` 对去除字面量和注释后的 SQL 做词法检查，拒绝 `CROSS JOIN` 和 FROM 后逗号并列多表的隐式连接。它同时作用于建模 CLI 和问数 MCP 的 `run_sql`、`dry_run`、`dry_plan`。这是与只读检查同类的词法安全策略，不是 SQL 解析；子查询内的逗号连接、`ON 1=1` 等写法不在覆盖范围内。
- **屏蔽 Cube 参考。** `ModelingHitlMiddleware#onActing` 对读取 `cube_proposals` 的 `load_skill_through_path` 直接返回错误结果，不加载。官方技能文件保持不变，与"基础建模不开放 cube 命令"一致。
- **超时清理进程树。** `ProcessWrenCli#destroyTree` 先结束全部子进程，再结束父进程；超时和 finally 共用这一逻辑。
- **提示词同步。** 运行上下文和工具描述同步说明上述硬限制；发现复合值等数据问题时写入描述或 caveat，不连续查询量化。

## 后果

- 探查失控和长时间运行的笛卡尔积有了确定性上限。正常建模如果需要超过 10 条查询，需要分轮完成。
- 数据库服务端已发出的长查询不会因客户端进程结束而必然停止，必要时需要在 MySQL 上检查并 KILL。
- 计时日志仍把以文本返回的超时记为工具调用成功，排查时以返回内容中的"执行超时"为准。

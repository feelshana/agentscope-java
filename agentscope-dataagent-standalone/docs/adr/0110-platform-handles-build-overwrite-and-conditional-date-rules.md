# ADR0110：自动补编译、允许整文件替换、日期优先规则按受限表条件注入

## 状态

已接受，2026-10-20。补充 ADR0102/0105/0108。

## 背景

spec090 上线后的实测中，有三个问题在提示词和运行上下文都已写明的情况下，仍反复出现：

- 建模首次查询先于编译执行而失败（第 4 次）。上下文已写明"尚未编译"。
- `write_file` 覆盖采样生成的已有文件被拒（第 3 次）。
- 全是上传表、没有登记受限事实表的知识库，问数仍先追问年份（第 3 次）。原因是"问数最高优先级：缺少日期先询问"整段始终位于提示词顶部。

## 决策

- **自动补编译。** `OfficialWrenToolkit#execute` 在工程锁内，对 `query`、`dry-plan`、`dry-run`、`memory describe` 判断 `target/mdl.json` 是否存在；缺失时先执行一次官方 `context build`，记录 `wren_cli.auto_build` 计时并同步页面检查状态，再执行原命令。编译失败时不执行原命令，返回编译输出。编译只生成草稿，不改变发布。
- **允许整文件替换。** `WrenProjectFilesystem#write` 对已存在的项目文件做整体替换。路径、权限、models 目录限制和 YAML 语法检查不变。确认预览不再拒绝已存在文件，确认卡展示新旧差异。
- **日期优先规则按条件注入。** `WrenQueryContextMiddleware#dateRules` 只有在当前所选知识库登记了受限事实表时，才注入"受限事实表缺少日期先询问"，并列出表名；否则写明"没有登记受限事实表，不因缺少日期追问，未写年份按当年"。`QUERY_EFFICIENCY_RULES` 只保留通用的日期理解规则。外部受限表的行为和门禁不变。

## 后果

这三类行为从"靠模型遵守提示"改为平台确定性处理或按条件给出上下文。自动编译会让首次查询多花一次编译时间；整文件替换依赖确认卡的差异展示来防止误覆盖。

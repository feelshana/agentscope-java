# ADR 0050: 知识库共享权限与 BI 用户身份（待确认）

日期：2026-10-08
状态：待办；等待与同事确认产品、安全及 BI 身份规则后再实施

## 背景与当前代码

- 知识库 `dataagent_dataset_group` 以 `owner_id` 归属单个用户。`DatasetGroupService#getGroup/listGroups` 和数据服务按所有者过滤，其他用户无法看到创建者的库。
- Agent 已有 `RUN/EDIT` 授权，但它授权的是 Agent 功能，不授予数据集权限。全局 Agent 的 RUN 不能解释为任意知识库可问答。
- `ChatController` 把当前用户写入 `DatasetScope(ownerId, groupIds)`；`WrenToolkit#resolveGroup` 只枚举这个 owner 的知识库。普通聊天对 `groupIds` 尚无统一的知识库级授权检查。建模确认虽检查 owner，未来共享后也需按 EDIT 权限复核。
- 当前 DataAgent 使用本地账户与 JWT，JWT `sub` 是本地 `userId`。BI 打开前端页面不等于完成可信的统一登录。

## 决策草案

### 身份与授权边界

1. BI 后端与 DataAgent 使用可信的身份交换流程，服务端验证签名、发行方、受众、有效期，再映射为稳定的 DataAgent `userId`。浏览器传来的用户名、ownerId、groupId 或角色声明不可直接作为授权依据。前端打开方式、禁用用户、角色变更和登出后的令牌生命周期另行约定；BI 上线时同时收紧当前允许任意 Origin 且携带凭证的 CORS 配置。
2. 知识库授权独立于 Agent ACL。拥有 Agent RUN 且拥有知识库 QUERY，才能在该库问答；Agent EDIT 不自动获得知识库编辑权。
3. 新增知识库成员关系，主键 `(group_id, user_id)`，角色取 `QUERY`、`EDIT`。所有者自然具备 `MANAGE`；管理员由可信身份服务判定，可 MANAGE。私有库默认只有所有者可用；成员增删、角色变更仅 MANAGE 可做，记录操作者与时间。
4. 管理员跨用户管理仅限组织或租户边界。当前系统无显式组织字段，上线前需确认 BI 的租户标识与管理员作用域，不能仅凭本地全局 `admin` 角色跨所有租户读取数据。

### 各权限可见范围

| 操作 | QUERY | EDIT | MANAGE |
| --- | --- | --- | --- |
| 列表中看到知识库名称、说明、发布状态；选择问答 | 是 | 是 | 是 |
| 基于已发布模型问答并下载本人问答产生的结果 | 是 | 是 | 是 |
| 查看原始上传文件、原始数据预览、编辑页文件列表 | 否 | 是 | 是 |
| 上传/覆盖/删除数据、维护知识文档、建模/发布 | 否 | 是 | 是 |
| 成员授权、撤销、删除知识库 | 否 | 否 | 是 |

QUERY 允许模型根据库中的数据回答并可能返回明细、CSV 或图片；因此业务上必须把 QUERY 视为**数据读取权限**，不能以隐藏原始文件按钮代替数据脱敏或行级权限。若某库不能向问答用户暴露明细，应在数据源或查询策略层限制。

### 数据作用域

1. 请求选择一个或多个知识库时，服务端对每个 ID 重新查询 ACL；未授权、已删除或未发布的库拒绝，不能退回到“用户全部可见”或自动扩大范围。
2. 运行时把已授权的 `groupId + ownerId` 组合带入可信上下文。Wren、检索、概览、查询 CSV、建模工具和后续辅助工具必须从该上下文取库，不信任模型生成的 ownerId、工具参数或前端传入的 ownerId。执行敏感查询前复查授权，避免撤权后继续复用旧会话。
3. 当前 `DatasetScope` 仅有一个 ownerId。跨所有者选库时需改为多个已授权库引用；每次 Wren 调用按目标 groupId 确定所属 owner，查询始终限定该库。涉及跨库 JOIN、同名库、数据源连接凭证的语义需单独定义，第一期可禁止跨所有者 JOIN。
4. 空 `groupIds` 需要明确语义：建议只取当前用户有 QUERY 的已发布库，最多设定可控上限；如果没有可用库，提示用户选择或申请授权。不允许自动扫描平台所有库。
5. 建模、导入及写操作在工具层按 EDIT 重新验证；只给 Agent 输入“只读”提示不构成安全控制。

### 会话、附件、撤权

- 会话、回答、生成的图片/CSV/报告仍属于提问用户；库所有者和其他成员不能直接读取该用户历史或附件。
- 撤销 QUERY 后，立即阻止新问答、续问和对该库的新工具查询；已经生成的用户历史与附件默认按会话保留策略保存。历史内容可能包含原始数据，因此是否需要撤权时隐藏/清除既有历史，须由产品和安全负责人确定。
- 定时问答任务须以创建任务的用户身份及当前库权限运行；撤权后任务停止使用该库，不能继承创建者或系统账号的更高权限。
- 删除知识库前需处理共享成员、运行中的查询、定时任务、已发布模型及用户历史的引用；不得静默删除别人的会话。建议使旧历史可读但标注“知识库已删除”，禁止继续在该库查询。

## 迁移与兼容

现有库保持私有，保留 ownerId；新增成员表只增加显式分享。对外接口从“传用户 ID 作为 owner”逐步迁移为“当前身份 + 授权库引用”。前端显示 `tierForCurrentUser`，QUERY 只展示问答入口，编辑入口灰置或隐藏；所有操作仍由服务端校验。

## 待确认问题

1. BI 是否提供稳定不可复用的用户 ID、组织/租户 ID、可信令牌校验方式和管理员范围？现有 DataAgent 用户如何映射？
2. QUERY 用户是否允许下载问答生成的 CSV 明细？默认草案允许；如不允许，需要新增导出权限或查询结果行级限制。
3. 撤销权限后，用户此前的历史回答和附件是否继续可读？默认草案保留，且不允许继续基于该库问答。
4. 是否允许一次问题选中多个不同创建者的库？默认草案允许分别检索，第一期不做跨所有者 JOIN。
5. 管理员是否可以管理所有组织的库，还是仅自己组织的库？建议按组织限定。
6. QUERY 用户是否能进入知识库详情页看只读说明与建模概览，编辑控件置灰？默认草案仅开放问答入口及最小元信息；可按产品需要开放经过脱敏的只读详情。

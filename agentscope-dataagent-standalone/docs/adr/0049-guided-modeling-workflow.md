# ADR 0049：统一建模阶段与用户操作引导

日期：2026-10-07
状态：已接受（用户已授权 ADR、spec 和开发）

## 背景

基础 MDL 自动发布后即可通过 Wren 问数。当前工作台却将资产分类当作主导航，将前期需求收集与后期验收合并，并在工程校验通过后提前提示发布。LLM 日志还出现反复写空 SQL 文件、遗漏指标过滤和未经确认增加环比统计限制，用户无法判断下一步。

## 决策

1. 主流程为数据准备 → 对话建模 → 验证与确认 → 发布。业务文档可选；基础发布成功即可问数，建模期间普通问数继续用已发布版本，草稿验证使用工作区。
2. 后端提供唯一只读工作流快照：数据/发布可用性、草稿变更、工程校验状态、问题计数、发布阻断原因、下一步操作。由现有元数据与 YAML 事实源派生，不另建可漂移的阶段数据库。执行中/待 HITL 状态复用当前会话，不推断为全知识库已完成。
3. 工程校验收据由平台写入 .platform，绑定语义指纹；修改语义文件后失效。此收据用于引导，发布仍重新执行原校验链及必验问题门，不能由浏览器状态绕过。
4. 常用问题在对话阶段登记为需求，在验证阶段审阅同一批问题；不重复填写，不要求用户写 SQL。无问题兼容旧发布；系统推荐问题默认可选，变为必验需告知用户并征得认可。
5. 顶部持续显示四阶段、发布版本和下一步；资产类型移入模型详情。模型详情仍保留原 URL 深链接与高级操作，普通用户不必逐一创建关系/Cube/View。
6. 建模 HITL 优先显示业务变更原因与范围，技术细节折叠。确认变更与确认实际结果分别说明；禁止为减少交互绕过现有 HITL。
7. 助手先读取统一状态与文档；已有明确口径不重复询问，未知条件逐项澄清。强制业务过滤必须进入可执行资产，不能仅写描述。先推荐实现方案再写入，不让用户选择无法满足已确认口径的方案。
8. 问数不能擅自将“环比”限制为两月都有营收的客户；零基数应单独标注。空结果要先核查再解释。全程使用简体中文。

## 权衡与验证

按语义指纹失效保守但可追溯；没有问题的模型仍能发布，不强制凑够 3–5 个问题。动态数据不因收据而冻结。工作流快照不承诺永久可用连接，查询仍受 Wren 实际执行约束。补状态优先级、校验失效、越权、工具引导测试，执行格式检查、全量后端测试、打包、前端构建及独立本机 API/SSE 验证。

# ADR 0078：上传与问答并发后续集成及来源文档边界

日期：2026-10-15
状态：已接受，用户要求继续合入来源分支昨天两次提交；实现与验证状态见 CURRENT_TASK。

## 背景

ADR 0077 合入范围截至 32c6d292，当时来源尚未包含完整上传/问答准入。来源随后提交 a29cc754、6a75b6cf；当前上传已由 bc11f3a5 移植，工作区已有容量和框架改动。本次完成核对与集成，不将提交标题或来源历史验收直接当成本分支实测。

## 决策

1. 上传采用 DatasetUploadProperties、DatasetUploadAdmission、DatasetUploadIntake：全局在途文件准入，超额 429；浏览器有限调度；文件磁盘暂存、大小与解析规模限制、有限在途写批次、失败/取消清理及上传者状态隔离。成功导入与基础模型发布分开反馈。
2. ChatController 的 stream/send 对问数采用单进程 ChatCapacity：全局/每用户 active、有限 waiting、等待/执行时限、同会话互斥；建模保持来源的豁免。SSE capacity 与前端同步，排队不启动工作或沙箱。权限在准入前和实际执行时检查；问数的知识库权限仍以当前官方 Wren 入口为准。
3. Wren 工具发现与查询共用每库公平 ReentrantLock 和等待时限，保留发现前后/查询排队后的授权复核；实例总数通过信号量约束，空闲驱逐，关闭失败保留名额等待清理。预算只覆盖本 registry 的 MCP 实例，不代表所有 CLI 子进程总数。
4. 沙箱满额只驱逐无活动 lease 的空闲容器；复用 harness 的进程组取消、上下文绑定、命名空间锁和生命周期修复。Python 执行未真正退出时保留问答预算；网关使用 using 释放 turn lease。默认模型 HTTP/1.1，沿用来源的连接恢复修复。独立构建必须先安装同版本 harness 与 OpenAI 扩展依赖。
5. 当前官方 Wren skills/CLI/MCP、MDL 原样编译、显式发布、中文回执、LIMIT、问答对管理/召回保持当前分支实现。不得用来源旧建模/SQL/Cube流程覆盖。

## 限制与验证

容量为单 JVM；多副本全局预算、实际 16 用户吞吐/内存容量与公平性效果须单独压测，不以默认值宣称性能达标。建模不计入 ChatCapacity，普通 CLI 不计入 MCP 实例预算。模型 HTTP 请求仅对建立响应前的特定连接错误进行恢复，不重放已输出的流。

需通过上传、容量、沙箱、网关和 Wren 授权回归，以及来源框架回归、全量测试、前端构建和 package。Docker 条件跳过、真实模型/云源未验收必须明确记录。配置和发布步骤见 [系统运维补充](../platform-concurrency-and-release.md)。

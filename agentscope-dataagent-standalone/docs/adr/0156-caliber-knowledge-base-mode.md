# ADR0156：知识库分普通与口径两种模式；口径知识库只经 Cube 问数，一个结果只来自一行

## 状态

已接受，2026-11-25（用户确认：已有知识库不迁移、模式不可切换、口径列取值由平台统计且只提示不拦截、按 P7-1 至 P7-4 顺序实施）。实施 [spec149](../specs/149-caliber-views-and-cubes.md) P7。

取代（确认后生效，届时在 ADR0155 状态行标注）：ADR0155 第 15、18 条按表判断 `run_sql` 的部分，以及第 19–21 条中"同一知识库内初始化建模与口径轮并存、建模轮可就口径提问"的部分。ADR0155 其余各条（清单为唯一事实源、生成 View + Cube、逐行核查与验证、未完成清单不能发布）继续有效。

## 背景

- ADR0155 让同一知识库里有清单的表走 Cube、其余表走 `run_sql`。2026-11-25 两表两文档实测暴露三类问题：
  - 初始化建模与口径轮各自理解同一份文档：规则里写了口径条件和按列名读数的方式，问数走 Cube 时大多用不上，部分与清单重复。
  - 确认框来自两轮，同一问题问两遍、答复矛盾。
  - 混合知识库的选表目录只列口径表，并写有"目录没有的业务说明没有数据"，会误拒属于普通表的问题。
- 口径表都是统计结果表，每行是算好的结果。生成的 Cube 指标为 `SUM(列)`，对日表按月查询会把日活、月累计活跃、留存率按天相加，结果错误。

## 决策

1. 知识库建库时选定模式：
   - **普通知识库**：沿用现有建模与 `run_sql` 问数，不使用口径清单。
   - **口径知识库**：只放统计结果类表，每张表都必须有口径清单，所有清单核查验证通过才能发布；问数只用 `query_cube`，整库禁用 `run_sql`。
   - 两种模式不在同一知识库混用；问数每轮至多一个知识库的既有限制不变。
2. 口径知识库中：
   - 初始化建模只写列描述，不写规则、关系和清单，不弹确认框。
   - 口径轮是唯一提问和写入口径、指标、范围、表说明的轮次；确认框标明所属清单，平台对未答复的同一事项去重，答复只写回清单。
   - 规则目录只含平台按清单生成的表目录与口径说明。
3. 一个结果只来自一行，任何情况下不把多行统计结果相加或平均：
   - 查询时间粒度必须等于表的粒度。
   - 生成的指标只在恰好一行时返回值，多行时由平台拒绝并指出未定维度。
   - 跨周期问题只读文档定义的那一行（如月累计取月末）；文档未定义的周期先问用户。
   - 同比、环比、占比分别取数后用 `run_python` 计算。
4. 清单格式补充：指标周期含义与单位（口径可覆盖单位）；范围取值不能只列汇总值。
5. 键值类考核表（指标名、指标值、日期）每个指标名为一个口径。指标名可由平台在关联表时对文档声明的口径列统计一次取值作为起草依据；建模 Agent 仍不查询数据。

## 备选方案

- 同一知识库按表区分口径表与普通表，平台生成包含两类表的全局表目录：可行，但两类表的规则、确认框、选表说明会相互干扰，门禁需逐表判断；用户选择按知识库分开。
- 指标按口径声明跨时间汇总方式（求和、取末值、不可加）：统计结果表本不应多行相加，求和选项会掩盖错误，改为"一个结果只来自一行"加周期含义。
- 只靠提示词约束初始化建模不就口径提问：两次实测均失效，改为按模式由平台限制轮次职责。

## 后果

- 明细分析类表只能放普通知识库；口径知识库的问题范围受清单与文档定义的周期限制，超出时由助手说明并给出可选读法。
- 已有知识库需要确定模式迁移规则（spec149 P7 待确认）；口径知识库中无清单的表在补清单或移出前不能发布。
- 同比、环比等派生计算依赖 `run_python` 沙箱可用。
- 平台需在关联表时为口径列做一次取值统计，需与 ADR0135"建模不查询数据"的边界一并说明：统计由平台完成，结果只作起草依据。

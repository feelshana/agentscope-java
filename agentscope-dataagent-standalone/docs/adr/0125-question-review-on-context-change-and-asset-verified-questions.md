# ADR0125：口径变更后按依赖复核问答，资产验证通过的问题可存为问答

## 状态

已接受，2026-11-03。实施 [spec108](../specs/108-question-review-on-context-change.md)。

取代：无。补充 ADR0109（问答来源）与 ADR0123（资产验证结果的去向）；修订 spec091 "确认只绑定问题与 SQL 哈希、模型变化不使其失效"的约定。

## 背景

2026-11-03 真实使用中，用户先完成普通建模，试问并确认了"每天的报表访问次数"，SQL 查原表；随后在语义资产里建了加工表，并写了默认使用规则"统计访问次数默认用加工表"。

- 确认只绑定问题与 SQL 文本。旧 SQL 仍能通过发布时的 dry-plan，所以一直保持"已确认"，页面也没有修改入口。
- 发布后它成为问数示例。问数召回到完全一致的示例时照它查原表，新口径被绕过，结果 SQL 正确但数据错误。
- 资产验证中用户已看过真实结果并判定"符合预期"，比试问更严格，但结论只留在资产核查记录里，不会成为问答，问数也召回不到"用资产回答"的示例。
- 建资产时新写的默认使用规则与已有规则冲突（一条说按公司统计保留未匹配账号，一条说默认排除），没有任何提示。

## 决策

1. **确认记录依赖，依赖变化时标为"口径变更待复核"。** 确认问答时，平台记下这条 SQL 读到的模型或资产，以及它们的定义、相关关系、规则中提到它们的条目。这些依赖之后发生变化时，问答进入待复核，并写明原因。不因无关改动打扰用户，也不因口径变化静默失效。
2. **待复核由用户逐条处理，不自动改写。** 处理方式有三种：仍然正确（重新确认）、让助手按新口径重写、自己修改 SQL。助手只在用户点击后重写，结论仍由人确认。
3. **发布不拦截，待复核的问答不作为问数示例。** 模型、规则、资产照常发布，新口径立即生效；待复核问答复核后，在下次发布时恢复为示例。
4. **资产验证"符合预期"的问题可存为问答。** 判定时由用户选择是否同时保存（默认保存）。与已有问答问题文字相同时更新原问答，不新建重复项。问答来源因此为三种：用户逐题确认、问数点赞、资产验证确认。保存仍走现有确认链路，包括只读检查、时间门禁与草稿 dry-plan。
5. **资产轮次提示规则冲突。** 新的默认使用规则与已有规则说法相反时，助手按官方 enrich-context 的冲突处理向用户提问，不并存两条相反的规则，也不改写已有规则。

## 备选方案

- **口径一变，全部问答重新确认：** 问答多时用户会机械点击，复核失去意义；且大部分改动与多数问答无关。
- **维持只绑定 SQL：** 无法发现"SQL 能跑但口径已变"，今天的问题会在每次建资产后重现。
- **由 LLM 判断语义是否受影响：** 结论不可复现、成本高；依赖比对可解释、可测试，宁可多标不漏标。
- **待复核时阻止发布：** 把一条问答的复核变成整个知识库的发布门槛，代价过高；不作为示例发布已能消除危害。
- **资产验证结果自动全部存为问答：** 违背"问答只来自用户明确确认"，用户应能排除仅用于测试的问题。

## 后果

- 收据（`.platform`，Agent 不可写）需要保存依赖快照；历史收据没有快照时，以已发布版本作为基线比对。
- 规则依赖按"条目中出现的模型名"匹配，会偏宽，个别无关问答可能被标为待复核，用户一键"仍然正确"即可。
- 待复核期间相关示例暂不召回，问数可能少一条参考，但不会被旧口径带偏。
- 加工表、查询模板改动后，用它们回答的问答会自动进入待复核，与资产的重新核查、验证联动。

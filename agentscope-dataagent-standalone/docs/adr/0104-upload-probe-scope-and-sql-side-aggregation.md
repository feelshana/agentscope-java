# ADR0104：上传表探查按用途限定、全表验证的唯一性与问数统计在 SQL 中完成

## 状态

已接受，2026-10-20。收窄 ADR0103 的上传表探查范围；其余 ADR0103 决策保持不变。

## 背景

ADR0103 实施后，新建上传库的实测情况：

- 建模首轮执行了 14 条探查（含 2 条编译前失败），其中包括取值分布、明细导出和重复的总量统计。首轮耗时 110 秒，触发了上下文压缩。
- 官方 enrich-context 在 Auto-pilot 下不做探查。平台提示中的"可按官方技能需要探查（如 MIN/MAX、低基数取值、COUNT）"反而扩大了探查范围。
- 维度候选取值在采样阶段已经提取。
- 全表验证已证实被连接侧键唯一，但关系仍按保守规则写成 MANY_TO_MANY。
- `write_file` 覆盖采样已生成的文件，失败 5 次；编译前查询，失败 2 次。
- 问数时沙箱不可用，Agent 对 100 行结果手工汇总，工作区和负责人分布计数出现错误。

## 决策

- **上传表只允许两类探查：**
  - 每张事实表一次时间列 MIN/MAX，用于选择样例日期；
  - 每条候选关系一次合并查询，得出被连接侧键的全表唯一性和两侧匹配率。

  不执行 SELECT DISTINCT 或分布统计，不导出明细行，不重复统计；一般每张表不超过 2 条。外部数据源表仍然禁止探查。
- **唯一性：** 上传表经全表验证唯一（总行数等于去重数且无空键）时，可以声明 MANY_TO_ONE，并注明依据当前上传数据、非数据库约束，重新上传后需复核。
- **建模文件：** 明确采样后已存在的文件。`write_file` 不能覆盖已存在文件，整文件替换也用 `edit_file`。首次查询类命令前，若未成功编译，先执行 `context build`。
- **问数统计：** 答案中的计数、合计、分组分布和排名必须来自工具返回值，统计在 SQL 中完成。沙箱不可用时补一条聚合 SQL，不手工汇总。需要完整明细时，limit 不小于预期行数。

## 后果

以上均为提示词与运行时上下文约束，不新增工具计数或硬拦截；真实行为以加载后的日志为准。沙箱 Docker 未就绪属于运行环境问题，不在代码中处理。

# ADR 0049: 可配置的历史会话保留策略

日期：2026-10-08
状态：已接受（默认关闭）

## 背景

分页降低了单次历史请求的读取量，但不会限制数据库、引擎日志和附件的长期增长。无限保留会逐渐增加存储、扫描、备份与恢复成本。

## 决策

1. 增加完整会话保留任务，默认关闭；只有 `dataagent.history-retention.enabled=true` 时创建任务。
2. 以会话最后活动时间判断过期，默认 90 天；每天 `Asia/Shanghai` 03:00 执行。
3. 第一版只支持 `full-session`：复用用户删除链路，清理会话登记、展示消息、引擎日志、已读状态及附件。只删附件会在历史中留下失效链接，因此不提供该模式。
4. 默认 `dry-run=true`，只记录候选数量及预计释放的附件字节；运维确认后再关闭试运行。
5. 每次最多选择 500 条，每批处理 50 条。运行中的会话跳过；单条失败记录日志并留待下次重试，不中断整批。
6. 任务不把“查看会话”当成活动；只有继续问答等实际会话活动更新保留时间。

## 权衡与限制

- 90 天是初始默认值，需按业务、审计和合规要求调整。
- 预计释放空间只统计持久附件，不包括数据库、引擎日志和文件系统分配差异。
- 当前依赖单实例会话管理器判断活动状态，多实例部署需要统一任务所有权和会话锁。
- 删除是跨数据库和文件系统操作，无法形成单一事务；现有孤立附件任务提供最终补偿，日志用于定位其他失败。
- 首次启用必须先观察 dry-run；减少保留天数可能一次产生大量候选，应通过 `max-per-run` 控制速率。

# ADR0139：BI报表与仪表盘字段扩展

状态：已接受（2026-11-05用户确认并授权实施；线上待验收）。

局部取代ADR0126固定39列和拒绝已有任务结构迁移的约定，其他同步/权限边界不变。

## 原因与决策
用户需要报表与仪表盘除明确排除的配置字段外的全部当前字段，目标分别23/39列，七表合计95列。
固定字段白名单而非SELECT *；只在原目标表追加列，既有列顺序不变，新列可空。
显式 migrate 要求持原作业锁、任务已暂停、源指纹与归属一致；先核对全部源/目标结构，再逐表追加。
保留owner与所有日志进度，另记录结构版本/基础数据补齐状态。异常结构拒绝自动修复。
MySQL DDL隐式提交，第二表失败时保留第一表结果，通过同一命令幂等续作；不声称DDL事务回滚。
显式 refresh-basics 在暂停下复用五表事务刷新，不回扫日志；完成后再恢复原每日任务。
用户授权此次线上不备份；迁移不附带DROP、数据清理或历史重灌。用户选择另建知识库关联七表并重新建模，旧库自行删除；不修改应用字段刷新逻辑。

## 影响
字段量和基础表快照内存上升，隔离测试包含长字段；日志仍四列、按原项目/日期索引推进。
应用部署不会执行迁移；同步源码来自宿主挂载目录，必须先暂停再更新代码。

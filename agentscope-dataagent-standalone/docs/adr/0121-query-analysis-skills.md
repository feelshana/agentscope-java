# ADR0121：问数分析技能以固定脚本执行，参数先确认再取数

## 状态

已接受，2026-10-29。实施 spec102；依赖 spec101 的查询结果文件通道。

## 背景

问数只能回答"发生了什么"。用户追问原因、异常、趋势时，助手只能临时写算法代码，结果不稳定、不可复现。业界 ChatBI（Quick BI 小Q洞察、ThoughtSpot Spotter/SpotIQ、Power BI 关键影响因素等）以"固定算法 + 结构化参数 + 报告式结果"提供这类分析；开源 Agent（DB-GPT、Agent Skills 标准）把分析方法打包成"技能 + 沙箱脚本"。用户确认采用显式选择与结果追问两个入口、每次先出参数确认卡、由 Python 出图、分析结果不进入问答召回。

## 决策

- 三个内置分析技能（指标归因、异常检测、趋势预测），每个由 `SKILL.md` 与一个固定 Python 脚本组成，随平台发布（`classpath:analysis-skills/`）。启动时复制到本地目录并以只读技能仓库挂到问数助手；模型通过 `run_python` 调用脚本，代码引用 `skills/` 时平台把脚本上传到会话沙箱。模型不编写、不修改算法。
- 脚本只依赖标准库、numpy、matplotlib，相同输入得到相同输出；沙箱镜像不新增依赖。
- 问数请求新增可选字段 `analysis`、`analysisParams`。选择方法后的第一轮只提交参数（`propose_analysis`，页面渲染为可编辑的确认卡），平台在本轮拒绝查询；用户确认后的下一轮才取数和运行脚本。选择只对当前一轮有效。
- 原始统计值只来自 SQL；贡献度、异常判断、预测值和区间是脚本派生值，回答中注明来源；推断性解释标注"推断"。分析轮次的查询回执为 `queryType=ANALYSIS`，点赞只记录反馈，不保存为问答样例。
- "继续分析"按钮由前端按本轮最后一次查询结果的固定规则计算，不由模型决定，不改 SSE 协议。

## 备选方案

- 预装脚本到沙箱镜像：版本与平台解耦，改脚本要重建镜像；按需上传更便于随平台发布和测试。
- 让模型现场写算法代码：灵活，但结果不稳定、不可复现，且可能抄写数据或编造数值。
- 自动识别分析意图直接执行：省一步交互，但归因的对比期最易误解；一期以参数确认为准，自动识别留待后续。
- 用 statsmodels 实现 STL 与 Holt-Winters：算法更完整，但需改镜像；一期用 numpy 实现等价的稳健分解与指数平滑。

## 后果

分析功能依赖 Docker 沙箱；沙箱不可用时回答写明"分析计算暂不可用"并给出 SQL 数据。一次分析至少两轮对话、耗时 20–60 秒。新增分析方法需同时提供 `SKILL.md`、脚本与测试，并加入 `AnalysisSkills#IDS` 白名单。`shared/agents/data-agent/skills/` 下的旧种子技能因技能市场仍在使用而保留，未挂载到问数助手。

# ADR 0052：建模预检失败反馈与对话空间

- 日期：2026-10-07
- 状态：已接受

## 背景

建模日志中的 Top1 问题带 `LIMIT 1`，违反常用问题 SQL 预检规则。确认卡无法采用，但原生拒绝只反馈 `Permission denied by user`，助手再次提交相同提案。业务文档卡多行状态和内联全文同时挤占对话高度。

## 决策

1. 失败确认卡提供“让助手修正”：仍拒绝当前原生 HITL 工具调用，附带预检错误和修正要求；不自动写入、不绕过预检。确认 API 增加可选 `feedback`，仅拒绝可携带，长度上限 4000。
2. AgentScope 当前版本在原生确认恢复时不把入站用户文本加入上下文。`ModelingHitlMiddleware#onAgent` 暂存本次反馈到调用独有 RuntimeContext，`onReasoning` 仅在对应工具已由原生框架生成 DENIED 结果后补充用户反馈并持久化上下文。确认、拒绝、恢复和工具执行全部复用框架。
3. 提示词明确无显式 LIMIT/OFFSET 的 TopN 排名筛选、样例日期不是实际数据范围、普通口径确认不等于指定必验。既有问题的 required 缺省兼容保持不变，新建问题显式 false。
4. 文档入口保留显著上传按钮和成功/失败状态，改紧凑状态栏；全文使用原生 dialog 查看，不增加页面高度。收窄进度侧栏，助手回复使用全部可用宽度。

## 后果

无实体、配置或 SSE 帧变更。错误反馈属于用户消息而非可信系统指令。每次修正后仍需人员批准新提案，并通过 Wren 执行与结果确认。不同调用不共享反馈；空拒绝兼容既有行为。

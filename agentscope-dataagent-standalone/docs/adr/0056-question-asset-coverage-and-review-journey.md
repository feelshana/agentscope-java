# ADR 0056：问题资产覆盖与建模审阅交互

- 日期：2026-10-08
- 状态：Accepted
- 扩展：ADR 0054、0055；保留 YAML-first 与原生 HITL。

## 背景

只有问题 SQL 执行与人工确认，无法保证业务口径沉淀为可复用 MDL 资产。用户看不出哪些问题已发布，且写入/结果/发布确认界面混淆。

## 决策

由助手在问题 YAML 声明 modeling.strategy/reason/assets；MODEL、VIEW、CUBE 复用或构建实际资产，EXAMPLE 明确记录仅保存 SQL 示例的理由。新问题写预检要求声明，资产可以随后构建；执行验收和发布检查资产存在与 SQL 引用。工程和 Wren 验证负责执行可用性，人员仍负责业务正确性，不声称文本引用检查能证明口径等价。历史无声明的问题作为历史 SQL 示例兼容，升级不使有效确认失效；新声明进入问题指纹。

发布状态来自同组 published 快照与经确认示例，草稿确认单独呈现。右侧问题列表默认露出已发布状态，详情按需查看。验收页由服务端 workflow 提供就绪/阻断与快捷发布入口，不用前端推测发布门槛。

写入采用可读摘要、完整代码高亮、独立差异与放大阅读；一次采用恢复原生确认链路，禁止用自动确认消除不同提案的必要批准。维持现有租户上下文与白名单。

## 后果

用户不必学习资产分类，助手必须说明产物和覆盖关系。EXAMPLE 保留合理探索空间；重复资产不是完成指标。声明变更触发重验，旧工程可逐步补声明。

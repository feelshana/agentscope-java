# ADR0122：内置只读示例数据源

## 状态

已接受，2026-10-31。示例Excel于同日按用户要求经GitHub临时分发，线上验证后移除当前树副本、本地保留历史恢复脚本，见[66更新指引](../guides/66-update-operations.md)；其余决策有效，正文保留原始记录。

取代：无

## 背景

新手引导需要让没有数据库的用户也能体验外部表路线。外部数据源目前按 `ownerId` 归属到个人，没有所有用户都能使用的数据源。

示例数据使用用户提供的两份测试文件，用户确认内容已经过处理，原样内置。

## 决策

- 引入系统内置数据源：所有用户可选，只读，不可编辑或删除，由配置开启，默认关闭。
- 内置数据源是一条 `owner_id=__system__` 的数据源记录，下游的 Wren 连接、采样和发布不需要分支。凭证由配置提供，启动时同步到这条记录，不返回前端。使用独立的只读账号，只授权 `demo_data` 库。
- 内置数据源不是权限旁路：关联后仍走知识库归属、QUERY/MANAGE、官方 MCP/CLI 和时间门禁。用户看到的只有这一个公开示例库。
- `demo_data` 的内容对所有用户可见，没有用户隔离，只能放确认可以全员公开的数据。

## 备选方案

- 给每个用户复制一条数据源记录：不用改归属校验，但凭证分散，改密码要改全部用户。
- 新增独立的内置数据源类型：Wren 连接、采样、发布都要加分支，改动面大。
- 只用内置 Excel，不做外部库：体验不到关联路线，用户已明确要求两条路线。
- 管理员发布公共示例知识库：用户没有建模和发布的体验，达不到引导目的。

## 后果

- 数据源从"都属于个人"变为"个人 + 系统内置"，列表、关联、编辑、删除都要处理这一分支，相关测试要覆盖。
- 部署多一步：准备 `demo_data` 和只读账号。没有准备的环境保持关闭，指引只走上传路线。
- 配置了 `allowed-endpoints` 的环境，需要把示例库地址加入白名单。
- 示例文件放在部署目录，不进仓库和安装包，换环境要单独放置。
- 每用一次内置 Excel 就多一份约 10 万行的物理表；外部表路线没有这个成本。

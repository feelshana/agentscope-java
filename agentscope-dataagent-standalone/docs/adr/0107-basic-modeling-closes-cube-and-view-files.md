# ADR0107：基础语义建模对 Cube/View 文件既不读也不写，自动建模消息与探查边界一致

## 状态

已接受，2026-10-20。补充 ADR0085/0088/0106。ADR0085、0088 中"已有 Cube/View 可读取"的部分由本条取代。

## 背景

用户要求建模 Agent 对 Cube 和 View 相关内容不读也不写。此前平台只禁止写入 `cubes/`、`views/`，允许读取，Agent 会列出、读取这些目录。官方技能正文也会引导检查已有 Cube/View，消耗上下文和迭代次数。另外，自动发起建模的固定消息写着"不自行探测全表"，与上传表允许两类有限探查的运行上下文冲突。

## 决策

- `WrenProjectAccess#path` 将 `cubes/`、`views/` 设为封闭目录，读写都拒绝，并返回中文说明。原生 `ls`、`glob`、`grep` 经同一路径检查过滤，也不会暴露这两个目录。已有资产仍由官方 CLI 的 validate/build 直接读取，正常参与编译，不被删除或修改。
- 维持 ADR0106：`cube` 命令拒绝执行，`references/cube_proposals.md` 不加载。
- 建模提示词改为：不读写 `cubes/`、`views/`，跳过官方技能中创建或检查 Cube/View 的步骤，发现的需求只在最终说明中记录为提案；不再要求 Cube/View 走确认流程。
- `SemanticModelingPage` 自动发起建模的消息改为"数据探查遵守运行上下文中的表来源与探查边界"，规则只保留运行上下文这一个来源。

## 后果

- 基础建模看不到已有 Cube/View 的内容；如果已有资产与新模型存在冲突，由官方校验报告，不由 Agent 预判。
- 问数侧仍可使用已发布的 Cube/View（问数工具与提示未改动），是否收紧另行决定。

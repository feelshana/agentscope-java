# ADR0133：问数优化不提议查询模板，公共视图改从全部已确认问答中提炼

## 状态

已接受，2026-11-03。调整 [spec114](../specs/114-query-coach.md) 第 8 节；公共资产提炼另写 spec 后实施。

取代：ADR-0132（第 1、4 条中"问数优化（原问数教练）可提议查询模板"）

## 背景

ADR0132 让问数优化在分析一批常用问题时提议查询模板，spec114 第 8 节又收紧为"本批 2 道及以上的题复用同一中间结果才提议"。实测和评审发现：
- 一批最多 10 道题，从中抽出的逻辑往往是为这几道题量身定做的，不算公共资产；
- 单题需要的聚合、窗口函数由问数 SQL 直接表达即可，不必建模型对象；
- 外部方案评审（Codex）也建议：查询模板应来自大量已确认问答中反复出现的逻辑，并用来源问题回归核对。

## 决策

1. 问数优化只提议规则、关系、计算字段，不提议查询模板。需要聚合、窗口、多步计算的题直接写在该题 SQL 里。由 `propose_modeling_change` 在问数优化轮次拒绝 kind=view 强制执行，不只靠提示词。
2. 查询模板（页面称"公共视图"）的来源改为：
   - 用户在建模对话中明确要求（ADR0132 第 2 条不变）；
   - 待建设的"公共资产提炼"：从全部已确认问答中统计反复出现的逻辑，提议后经批准起草，并用来源问题重新生成 SQL 对照确认。

   在提炼上线前，"公共视图"页显示"建设中"说明。
3. 已有查询模板的核查、问题验证和发布门禁不变（ADR0128）。

## 备选方案

- **保留"本批 2 题复用才提议"：** 样本太小，提议的不是公共逻辑，实测两轮也未触发。
- **问数优化完全不涉及资产，连规则也不提议：** 规则缺口正是问数优化要解决的主要问题，保留。

## 后果

- 问数优化更聚焦"口径是否定义清楚"；多步逻辑在问题 SQL 中重复出现，直到公共资产提炼上线后统一整理。
- 公共资产提炼需要另写 spec（素材范围、统计方法、门槛、回归方式），届时可能再调整 ADR0128 的"资产单独出题验证"。

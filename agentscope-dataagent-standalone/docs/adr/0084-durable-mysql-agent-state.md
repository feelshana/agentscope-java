# ADR 0084：框架会话状态保存到平台MySQL

日期：2026-10-18。状态：已接受，用户明确授权实施；验收状态见spec073与专项报告。

## 背景

平台已有数据库展示历史和会话路由，默认AgentStateStore却是内存实现。真实重启后历史仍在、模型遗忘前文。用户要求保留历史会话继续追问，关注存储规模和响应影响。

## 决定

复用框架MySQL扩展，不在业务层重写状态序列化、消息恢复或ReAct。共用平台DataSource及当前数据库，`dataagent_agent_state`保存每用户/会话/状态键的最新JSON及版本。命名空间列使用二进制排序规则，避免数据库忽略大小写混淆身份。开发跟随既有DDL初始化策略，生产先迁移、启动校验，不悄悄回退内存。

H2开发使用框架JsonFileAgentStateStore，目录依平台数据库URL区分并位于持久user.home下；用户自定义状态Bean优先。会话删除、重置及保留清理接入同一状态删除路径，状态清理失败时保留注册条目供重试。

## 后果

每次调用读取当前会话，正常结束保存最新状态，不全量加载所有会话、不按token写数据库。长对话JSON整体读写有成本，沿用框架结果卸载和上下文压缩，实测记录字节/延时；快照表之外仍有原展示历史及数据库日志/备份。状态持久化不等于共享沙箱/分布式网关锁，多副本仍需独立设计。

已有丢失状态不会因接入新表自动找回；旧展示记录保留。未来按持久状态继续会话，当前权限和本轮选库依旧校验，恢复历史不授予旧权限。不更改业务口径和官方Wren技能，不把重启断点当自动续跑承诺。

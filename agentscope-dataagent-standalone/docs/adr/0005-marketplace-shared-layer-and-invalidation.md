# ADR 0005: 能力市场=「审批物化到共享层 + 沙箱失效重建」，市场源可插拔

- 状态：已采纳
- 日期：2026（市场机制落地时）

## 背景

用户在自己工作区沉淀的技能/子 agent 需要安全地共享给全体租户，
同时支持从外部源（Git 仓库、Nacos）引入技能包。

## 决策

1. 共享的物理载体是磁盘共享层 `shared/agents/<agentId>/{skills,subagents}/`，
   它以只读方式投影进每个用户沙箱（见 ADR 0003）。
2. 贡献流：用户提交（或 agent 经 `contribute_to_workspace` 提交）→ PENDING 落 JPA →
   管理员审批 → 物化到共享层 → `UserSandboxRegistry.invalidate(null, agentId)`
   使全用户沙箱失效，下次 borrow 重建并投影新内容——无需重启应用。
3. 市场源按 type 插拔（`UserMarketplaceRegistry` + 工厂注册）：
   `local`（审批落盘的共享技能）、`git`（per-user 克隆，避免工作副本竞争）、
   `nacos`（配置中心）。
4. 共享粒度是单个技能/子 agent/记忆片段，不是整个 agent
   （比 per-agent ACL 共享更细）。

## 理由与权衡

- 审批闸口保证共享内容质量与安全（知识自下而上流动，但有门）。
- 失效重建而非热更新：实现简单，代价是审批后首个请求的容器冷启动。
- 代价：共享层是单机磁盘，多副本部署时需共享存储（NAS/对象存储同步），
  否则各副本共享层不一致。

## 被否决的替代方案

- 数据库承载技能内容 + 运行时注入：偏离 harness「工作区文件即技能」的模型，
  与 skills/ 目录投影机制重复。
- 免审批直接共享：技能可包含提示词注入风险，必须有管理员闸口。

## 适用与失效条件

适用于单副本或共享层可共享存储的部署。多副本无共享存储时，local 市场会不一致，
应改用 git/nacos 源或引入共享存储后重审。

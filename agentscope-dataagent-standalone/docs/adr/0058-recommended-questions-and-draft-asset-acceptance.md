# ADR 0058：推荐问题、草稿资产依赖与业务确认边界

- 日期：2026-10-08
- 状态：Accepted（用户通过本轮讨论明确要求同步文档）
- 补充并部分替代：[ADR 0057](0057-wren-guided-modeling-and-published-query-context.md) 的问题入口与业务方案应用边界；按仓库约定保留旧 ADR，不改写历史决策。
- 实施范围：specs 047–050；当前仅文档，尚未实现。

## 背景

后续讨论明确：agent 从现有模型和可选文档推荐问题，用户可选择、改写、增补。问题的查询可能依赖视图、Cube 或 SQL 定义模型；这些资产必须先存在，但验收前不需要正式发布。用户审阅资产业务含义，而非逐项批准 YAML/SQL；技术工作由 agent 完成。

## 决策

### 问题选择与资产规划

agent 根据有权访问的当前模型、文档和已有问题生成可选推荐，附来源、分析价值与缺失口径。用户采纳后加入同一可增删行表格，允许编辑和新增；未采纳建议不是正式需求，不阻塞建模/发布。推荐不能编造指标定义；仅有问题标题不足以认定口径已确认。

agent 综合文档和采纳问题规划共享资产，不每题强制新建。文档没有常用问题时仍可增强模型；已有资产完整覆盖时只复用并生成查询示例。

### 构建、验收与发布顺序

已发布模型 + 文档 + 采纳问题 → 澄清关键歧义 → 候选工程生成依赖资产与查询 → agent 自动技术校验 → 必要的关键业务口径与变更确认 → 应用草稿 → 在同一草稿副本实际执行问题 → 用户结果验收 → 资产、规则、有效确认示例和索引整体发布 → 正式问数。

资产依赖按拓扑顺序准备，先基础模型/SQL 定义模型，再依赖视图，再 Cube，再问题查询；顺序以实际依赖图为准。缺失对象或循环依赖阻塞并由 agent 修复。SQL 定义模型指安装版支持的 SQL/ref_sql 等定义方式，不引入未经验证的新资产类型；View/视图是同一类。发布后逻辑模型 SQL 可按 Wren 编译边界执行，不能新增物理直查回退。

验收明确绑定 ownerId/groupId/draftRevision/工程哈希；Wren 指向完整草稿副本，不能只将问题 SQL 发给已发布工程。Cube 实际重放查询规格。验收成功不触发再次创建资产，而是生成可发布确认凭据；资产与示例一起进入新版本。变更后旧结果凭据失效，失败保留旧 published。

### 用户确认的内容与次数

界面名称为“确认关键业务口径与变更”。默认展示指标公式、统计对象/粒度、时间、过滤、关联及归属、业务来源与受影响问题；模型/关系/视图/Cube/SQL 定义模型的技术差异可展开，不要求用户懂工程语法。

需要暂停的情况：新且未审阅的重要资产业务含义、推断关系、缺失且影响结果的定义、来源冲突、改变已确认口径。共享口径及其多个资产合并确认；文档明确且无冲突的普通补充、已有资产复用和已明确授权方案的技术实现无需再确认。

“无需再确认”不是 agent 自动批准：平台保存用户明确批准的具体方案/候选哈希，或记录不需要人工审阅的低影响变更依据。新增重要资产首次仍须具体业务方案确认；已经批准且内容未变的方案直接应用，不插入第二次“应用草稿”批准。没有新增需确认事项时自动进入草稿构建/验收。

平台区分 requiresBusinessReview/reviewReasons、已有审批覆盖与低影响免审，不伪造用户 APPROVED。候选或基准变化使旧批准失效；仅技术修复且业务定义不变时自动重验、刷新技术凭据，不重复口径询问，但必须通过平台范围校验，不能靠 LLM 自称等价。不能证明属于已授权范围时重新提交具体业务变更。

YAML 校验、context build、dry-plan、Cube 表达式检查、查询执行及有界技术修复由 agent 调用受控工具自动完成。技术失败不能甩给用户审批，也不能把执行成功标为业务正确。用户随后集中确认真实问题结果，再明确发布；这保留本项目比官方更严格的常用问题验收门槛。

## 后果与验证

减少重复口径询问和技术审批；保留新增重要语义的审阅及发布隔离。需要依赖图、草稿查询上下文、审批覆盖记录和技术修复边界判断。

验证推荐未采纳不落正式需求、改写后保留来源；依赖资产未发布也可草稿验收；同一业务只确认一次；新资产首次审阅、推断关系/冲突必须暂停；技术修复不重复询问但语义变化重新审阅；最终版本包含所有查询依赖及有效示例，问数不读草稿。

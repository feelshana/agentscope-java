# ADR 0028：文档驱动语义差异分析与人工采纳

- 状态：Accepted
- 日期：2026-10-02

## 背景

平台已有关系、Cube、View、术语和 MDL 发布能力，数据表关联流程也已把 JDBC 注释与低基数枚举样例写入列描述。缺口不是再次生成列描述，而是把业务文档中的指标口径、复杂查询、关系和跨表规则与当前语义状态比较，找出尚未覆盖或发生冲突的内容，并安全地路由到现有资产。

WrenAI `enrich-context` 的关键价值是“差异分析 + 多落点 + 逐项验证”，而不是单一术语抽取。上传自动执行又不能意味着自动修改高影响语义资产。

## 决策

### D1：采用多类型提案，不直接写语义资产

上传后自动创建异步分析任务，LLM 只能生成 TERM、BUSINESS_RULE、RELATIONSHIP、CUBE、VIEW、MANUAL_FIX 提案。所有提案先持久化并等待人工采纳或忽略；禁止自动发布。

### D2：分析当前状态差异，而不是只抽取文档

Prompt 同时携带文档原文与当前表/列、关系、Cube、View、术语、业务规则。候选分为 NEW、PARTIAL、CONFLICT、COVERED；COVERED 不保存，CONFLICT 不允许直接采纳。

### D3：复用现有写入与校验边界

采纳时调用 `MdlSuggestionService` 的现有创建方法，确保列解析、复合键、唯一性和 SELECT/WITH 限制一致。MDL 类型采纳后标记 DIRTY，发布仍走现有 validate/build/snapshot 流程。

### D4：业务规则使用组级租户隔离实体

默认过滤、软删除、权威表、币种、财务周期、NULL/哨兵语义保存为 `SemanticBusinessRuleEntity`，同时记录 ownerId 与 groupId。运行时只注入当前用户、当前选中知识库可见的规则，不扩大现有全局术语字典的影响面。

### D5：上传与对话共享路由规则，交互方式不同

上传入口批量生成待审提案；建模对话先盘点当前状态，再逐条向用户确认并调用同一组写入服务。两者采用相同的类型路由、查重、冲突保护和 MDL 校验规则，但不强制对话先创建提案任务。

### D6：异步失败不阻断上传

任务先持久化为 RUNNING，再在 boundedElastic 执行模型调用和 JPA 操作。模型未配置、重复运行、解析失败均只更新任务状态或静默跳过，不改变知识文档上传结果。

### D7：Calculated Column 暂时降级为人工修复

平台尚无通用计算列实体和 CRUD。文档中的行级计算列声明生成 MANUAL_FIX，不映射为语义不等价的 Cube/View；待未来独立规格补齐落点。

### D8：验证数据与平台元数据隔离

端到端 fixture 建在本地 MySQL 独立 schema 中，覆盖单列/复合键关系、软删、多币种、权威表、聚合和窗口场景。验证文档既可上传，也可原样粘贴到建模对话。

## 取舍

- 选择持久化任务与提案，而非只返回一次性 LLM 输出：支持异步状态、审计、重试和页面审阅。
- 选择 payload JSON，而非每类一张提案表：提案是短生命周期审阅工件；最终资产仍使用强类型实体与既有校验。
- 选择组级业务规则，而非继续扩大全局术语：避免跨租户和跨知识库污染。
- 不采用“上传后直接改 MDL”：错误关系或指标口径的影响高于节省一次点击的收益。

## 影响

- 新增增强任务、提案、业务规则三张表及 Repository；
- 新增 `DocEnhanceService`、建模 API 和语义建模页审阅卡；
- 上传文档增加一个不阻断主流程的异步触发；
- 动态上下文新增组级业务规则，且修正“无自由文档时提前返回”问题；
- 建模助手新增业务规则写入工具并强化差异、冲突与验证剧本；
- 需要多租户、状态机、采纳路由和上下文注入测试。

## 失效条件

若未来引入统一的版本化语义资产仓库、租户级术语域或原生 Calculated Column，则应重新评估 payload JSON、全局术语兼容策略和 MANUAL_FIX 降级规则。

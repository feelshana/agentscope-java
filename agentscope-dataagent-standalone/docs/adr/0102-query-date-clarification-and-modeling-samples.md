# ADR0102：问数日期优先澄清与建模样例约束

## 状态

已接受，2026-10-20。关联 spec088；补充 ADR0097/0099，保留其数据库配置来源、逐表检查及拒绝后同轮停止规则。

## 背景

实际问数在用户未给日期时执行 MIN/MAX/COUNT 探查；补充“最近30天”后仍查询任意历史季度来寻找最新日期。门禁虽能阻止不合规 SQL，但不能替用户决定业务范围。建模样例失败也不应要求用户替技术验证选择日期。

## 决策

- 对涉及已登记受限事实表的问数，缺少日期先询问，禁止自行探查日期。这一要求优先于自主探索、技能加载和样例召回；无法判断涉及哪些模型时可读取必要元数据，但不执行数据探查。结构、规则解释及不受限表查询不强制带日期。
- 每轮注入服务当前时间与时区，与门禁运行环境一致。相对日期、补充日期与追问由 Agent 和原生历史理解；不规定“最近30天”的边界，不增加日期解析器、分类模型或跨轮状态。
- 用户要求的范围被拒绝时展示真实明细，等待用户调整范围或配置，不自动缩小、拆分或切换 Cube/View 绕过。可选探查和建模样例被拒绝时停止验证，不要求用户为技术样例选日期。检查失败不能描述为数据库拒绝或用户日期错误。
- 建模自拟样例先参考当前逐表配置，问题与 SQL 的日期、指标和已确认过滤必须一致。用户问题、历史问答和固定业务周期不能通过缩短范围改变原意；不能执行验证时保留定义并说明未验证。
- 实际 SQL 执行成功但数据为空可视为执行验证成功，不保证业务正确，不继续找日期。编译、dry-plan 不等于执行成功。SQL 保存确认流程不在本次变更内。
- 不修改官方 skill、工具 schema、SQL 或 MDL，不增加自动重试、HTTP 接口、配置项或数据库字段。权限、隔离和门禁停止机制保持。

## 验证与限制

自动测试覆盖动态时间上下文、逐表窗口边界与现有拒绝行为；真实 Agent 是否先询问必须单独验收，提示词断言不能代替行为证据。检查模型输出判定与明细矛盾仍是独立已知缺陷，本次不增加复核机制，也不宣称解决。

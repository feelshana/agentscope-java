# ADR 0060：预检先于业务方案确认

- 状态：Accepted
- 日期：2026-10-09
- 承接：0058、0059；用户已批准减少中间技术确认并进入开发。

## 决策

复用原生 ReAct/HITL，不实现第二套循环。ModelingHitlMiddleware 在发送确认前调用租户受限的工具预检；失败以关联原调用的 ERROR 结果返回 agent，不使用用户 DENIED，不暂停等待用户点击修正。所有阻塞预检运行于 boundedElastic。

扩展既有 write_file，支持 files_json 提交同一业务方案的多个完整 YAML/Markdown 文件，基准指纹绑定工作区。副本一次覆盖全部文件，再校验问题声明、资产依赖、Wren validate/build/dry-plan；成功后才提出一次原生 HITL。审批仍绑定确切工具输入；执行前重新检查基准与技术有效性，运行时失败回滚已写文件。旧单文件写面仍保留 HITL，业务主流程优先一次提交关系、视图/Cube 和完整问题。

不把技术预检通过当成业务确认。文档已有定义标为文档依据，执行成功标为待结果确认；不由缺失月份推断数据完整性。发布与问题结果确认保留。不能通过 files_json 写平台文件、确认实例或其他知识库。

## 取舍

首期采用完整文件批量方案，比另造候选工程持久化状态机更小；技术修复在审批前完成。批量写入在工作区锁内，对进程内读者串行并具备运行时失败回滚；不宣称支持进程崩溃时的多文件原子提交。完整持久化候选恢复仍按 specs/048 后续实施。

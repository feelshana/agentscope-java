# ADR 0048：问题驱动建模、Wren 实查验收与已确认示例

日期：2026-10-07
状态：已接受（用户已授权编写方案并开发）

## 背景

项目的目标是经对话形成正确的 Wren MDL，并在问数时使用已发布语义。实测发现关系确认与工作区不一致、编码前导零丢失，以及“营收”口径歧义。编译通过和 SQL 执行成功均不足以证明业务正确。官方推荐收集常用问题、审阅实际 SQL 并保存可信 Question-SQL Pairs；Core 将确认示例保存在 knowledge/sql，召回只是生成辅助，不是答案保证。

## 决策

1. 将常用问题作为建模需求与验收入口：knowledge/questions/<id>.yml 记录 question、definition、sql、required。无问题的旧知识库兼容；首次对话邀请补充 3–5 个核心问题，逐步扩展。
2. YAML-first 不变。助手通过 write_file/patch_file 与原生 HITL 修改问题、规则和模型，不恢复数据库结构化写工具。验证工具只执行逻辑 SELECT/WITH，不允许显式 LIMIT/OFFSET，不提供物理 SQL 回退。
3. 验证使用草稿副本，经官方 context validate/build 与模型物化后，由独立临时 Wren MCP 实例查询同一数据源；不替换或污染已发布实例，不依赖 Python/Docker。数据库连接选择复用发布规则。
4. 执行成功是“待业务确认”，不是正确。平台在不可由 agent 写入的 .platform/questions 保存真实执行凭据；凭据绑定问题内容、语义工作区指纹、验证 ID、结果、截断标志和确认人。浏览器人员确认才产生可信示例。
5. required=true 的问题必须具有当前草稿的有效确认才能发布；失败、未验证、拒绝、过期和截断不能静默通过。自动基线发布同样不得绕过已设置的业务验收，已有发布快照继续可用。无验收问题不强制阻塞旧流程。
6. 人员确认后生成官方 knowledge/sql Markdown；此路径的 agent 写入需拒绝，防止未执行或未确认示例进入记忆。问数只从已发布快照读取已确认示例，按需展示定义与逻辑 SQL，不预注入全部示例、不直接复用旧数值。问数版本、粒度、单位与时间规则应可追溯。
7. 体验：常用问题工作台展示问题/口径/实际表格/SQL/状态，支持对话完善、验证、确认或退回；提供明确建模阶段指引，不把文件内容当作业务确认说明。视图描述提供定义与输出列线索；语义歧义优先澄清。
8. 修复已验证缺陷：空关系数组合并、非法 YAML 不得吞错覆写、预览与写入同一权限检查、导入前导零保护。沙箱生命周期复用 harness，偶发异常只有在根因明确且有回归证据后修改。

## 权衡

工作区是事实源，无新 JPA 实体或共享可变确认状态。验收按指纹失效较保守，但避免模型改变后信任旧确认。确认表示人员认可逻辑与本次结果，动态数据的值不作永久承诺；固定数值断言另以测试数据验证。临时 MCP 冷启动有成本，换取草稿和发布实例隔离。

## 验证

覆盖不同租户不可读写、失败/截断不得确认、模型修改导致确认过期、草稿查询不影响发布、必验问题发布门、已确认示例不从草稿读取、关系批次不丢失与编码保真。同步 ARCHITECTURE_zh.md 第 3/4/5/11 章。

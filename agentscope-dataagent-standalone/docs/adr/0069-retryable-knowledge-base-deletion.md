# ADR 0069：知识库删除与资源清理

- 日期：2026-10-10
- 状态：已采纳，代码已实现；尚未进行实际删除场景验证。
- 关联：spec 058；ADR 0068；spec 056。

## 背景

原删除入口只删除数据集、知识文档和知识库主记录，并尽力删除导入表、Wren 目录。关系、派生模型、视图、术语、业务规则、文档增强和旧知识图谱记录可能残留；DDL 和文件失败被日志吞掉；在途任务还可能重新写入。

用户已确认清理所有库级资源，保留外部原表、数据源连接配置、历史回答与附件。用户级共享沙箱不整体关闭。

## 决策

1. 删除由独立 `KnowledgeBaseDeletionService` 编排，不放进一个伪装成全原子的数据库事务。MySQL DDL、文件系统、MCP 子进程无法与 JPA 事务共同回滚。
2. 在 `<mdlRoot>/.kb-deletions/<groupId>.json` 原子保存删除任务后阻止该库新操作。知识库保留至库级清理完成，失败时列表显示「删除待完成」并可重试。
3. `KnowledgeBaseOperationAdvisor` 在同步服务调用外层登记执行线程，覆盖事务结束；依据仓库已启用的 `-parameters` 捕获 groupId/group/groupIds，以及 DatasetService 的 datasetId 或 DatasetEntity。异步文档增强、图谱单元、导入批次另外显式登记。HTTP 问答订阅绑定所选知识库并响应删除取消信号。
4. 删除先中断相关线程、取消所选库的聊天订阅，等待登记的工作与 CLI 子进程停止。超时不继续 DROP/删文件，保留任务等待重试。Wren MCP 实例关闭失败同样中止后续清理。
5. 仅删除上传/复制产生的物理表。新导入在 DDL 前写入 `<mdlRoot>/.kb-resources/<groupId>.json`，避免取消导致 JPA 回滚后丢失待清理表名。已有库通过数据集记录取得表名。
6. 删除整个 `<mdlRoot>/<groupId>`，包括 workspace、scratch、staging、published、编译结果、建模方案、问题验证文件及 runtime/business-memory-v1。路径验证限制在 MDL 根下，不跟随符号链接。
7. 文件/DDL 全部成功后，事务删除该库的数据集、关系、Cube、View、术语、规则、知识文档、文档增强提案/任务及旧图谱节点/边/单元/任务，最后删除知识库主记录。
8. 引用该库的例行任务暂停并解除引用，避免后续误用默认库；不删除用户任务历史。保留全局数据源、用户反馈状态文件、历史会话与问答附件、共享运行环境和用户沙箱。
9. 完成后保留精简删除凭据：同一 owner 重复 DELETE 幂等成功；旧后台调用不能重建已删除 ID 的目录。凭据不包含导入表名及错误内容。不得手工删除凭据以恢复知识库。
10. 专用后台线程启动后 30 秒恢复未完成任务，此后每轮间隔 60 秒，最多处理 10 个待清理任务；避免阻塞其他定时任务。失败记录 lastError 并写 `[kb-delete]` 日志。

## 边界与代价

- 一旦进入删除状态，不提供撤销。部分物理表/文件可能已删，失败后应继续完成清理。
- 外部数据库原表绝不删除，不关闭整个用户共享沙箱。订阅取消与线程中断无法瞬间停止不响应取消的第三方调用，因此必须等待而不能强行宣布完成。
- MDL 根目录、删除凭据和资源清单需要持久化并一起迁移。损坏的清单拒绝删除，避免误删其他资源。
- 本次不追溯清理过去已经删除且无主记录的孤立资源，不按目录名猜测归属。
- 旧版本导入失败且从未保存元数据的孤立物理表没有历史资源清单，不能由本次逻辑自动归属；新导入已补登记。

## 验证范围

只进行编译与静态检查，不运行自动化测试、不删除用户现有知识库。实际删除、取消、失败重试与进程重启恢复需要使用独立体验库确认。

# ADR 0059：查询修正与显式模型修复分离

- 状态：Accepted
- 日期：2026-10-09
- 承接：ADR 0057、0058；用户已批准此次简化并进入开发。

## 背景

官方 GenBI Classic 支持修改答案 SQL、保存问题实例或显式保存为视图；当前开源 skills 以文件化上下文构建语义资产；Cloud/Enterprise 的 AI Advisor 从失败评测提出模型修复方案，经过人工审阅后重新验证。这些是不同入口，不能把用户修改查询理解为授权改变共享语义。

## 决策

1. 建模流程保持数据接入、基础模型、文档与问题、业务审阅、验证、发布。批量问题以可增删行的表格填写，文档可选；不要求每个问题产生 Cube 或视图，已有资产足够时保存确认实例。
2. 用户在验证页直接修改当前问题 SQL，仅更新问题 YAML，保留业务定义与其他字段，撤销该问题旧实例的有效性；不更新模型、关系、视图、Cube 或 SQL 定义模型。保存后重新经 Wren 验证与人工确认，执行成功不等于业务正确。
3. 模型修复是独立对话入口：先诊断引用资产与规则，提出有来源的变更；语义写入仍经现有原生 HITL。不得把 SQL 差异直接当成全局业务规则。修改后重新验证问题，旧凭据因模型指纹变化而失效。
4. 暂不处理的问题可由用户显式移出本次验收；保留源文件与历史凭据，不删除资产，也不再发布其确认实例。所有仍参与本次验收的问题需要有效确认，这是本项目约束，不宣称是官方强制流程。
5. 技术修复应在业务审阅前完成；已审阅提案按精确内容应用一次。不实现通用 SQL 语义等价证明或修改后自动继承授权，取代 specs/048 中首期平台证明等价的复杂要求。
6. 验证页清楚显示执行时间、模型指纹、查询 SQL、视图定义快照、确认状态与发布入口。资产依赖未精确解析时必须标为定义目录，不假称物理执行计划。

## 影响

复用 YAML、工作区锁、租户鉴权及现有 Wren 草稿验证；不增加 agent 结构化模型写工具。人工问题修正 API 不接受客户端执行凭据或确认标记，使用问题指纹防止覆盖并发变更。完整候选工程、结构化 Cube 验收、官方 memory 索引仍按 specs/047–050 独立实施，不因界面改进宣称完成。

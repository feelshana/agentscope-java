# ADR0145：用持久意图和已提交元数据恢复本地跨资源操作

## 状态

已接受，2026-11-12。

取代：无（补充ADR0144及既有发布、删除契约）。

## 背景

发布文件先于平台版本保存，原文件回退在数据库保存前已清理旧副本；单数据集删除在平台事务提交前DROP表。数据库事务无法回滚文件替换或另库DDL。现有整库删除已有journal，新的局部操作需要明确中断恢复，不把异常补偿等同于重启恢复。

## 决策

- 保留单进程的现行发布/工作区锁与用户权限；不引入分布式事务或跨实例写入承诺。
- 发布切换先写持久意图，记录前后版本和旧文件存在性；保留旧文件直到平台版本/覆盖修订在独立事务提交。恢复读取已提交平台版本：新版本已提交则完成新快照，否则回退旧快照。无法判定/恢复时保留journal并拒绝使用该库，禁止混合版本继续服务。
- 确认版本前的文件/数据库异常可回退；提交后的清理不允许再回滚已提交快照。启动及后续发布前恢复未完成意图；恢复路径只操作经过验证的库目录和固定内部文件名。
- 单数据集删除先持久登记清理意图，平台元数据事务成功后才执行不可逆物理清理；回滚保留表和注册映射。重启以平台行是否仍存在决定取消未提交删除或继续清理，外部关联表仅去映射。
- 整库删除保留现有journal和重试机制；导入继续使用现有先登记资源、回滚清理并可对账的机制。所有恢复操作幂等，错误可见且不会把清理失败计作资源已完整删除。

## 备选方案

仅加@Transactional不能覆盖文件/另库DDL；全面上分布式事务或异步工作流平台超出现有部署；仅内存回调不能承接进程退出后的恢复。

## 后果

新增内部journal与临时文件生命周期，需备份/保留相同持久根并演练。原部署命令不变，无新生产配置和DDL。正常构建/校验仍可使用旧发布快照，实际切换/残留恢复窗口内该库暂拒绝操作。数据库不可达或journal损坏时宁可阻断恢复，不猜测版本。该机制不保证断电级所有存储刷盘、磁盘损毁或多实例共享目录安全，备份恢复仍须单独验证。

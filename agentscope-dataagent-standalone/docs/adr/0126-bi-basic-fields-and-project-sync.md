# ADR0126：BI基础字段投影与既有项目索引同步

状态：已接受（2026-11-03用户确认39字段、全部操作口径及源库禁止加索引；现场同步待验收）。

补充并局部取代ADR0125的日志取数/事务进度约定；正式两库部署、只读源、公共QUERY、Wren-only和MySQL8+边界不变。

## 原因

纯时间日志计划现场显示全表扫描/排序，源库不允许新增索引；既有项目+时间查询及日志项目枚举均有索引计划证据。用户选择同事基础SQL投影，人员排除password/phone/email，日志全部操作类型保留，不存类型和项目标记。因此不能把日志总数称为查看次数，也不能依赖目标日志项目字段核验。

## 决策

固定7业务表39列，不使用SELECT *自动扩字段。日志项目从源日志索引枚举，不能只遍历现存项目维表；项目只用于源端参数化取数和计数，不落目标四列日志。每项目以时间窗口流式读取，日写入/计数账本/项目进度同事务提交；空日合并推进，表截止日只在全部项目完成且账本日计数与目标一致后前进。verify按源项目索引汇总逐日计数核对目标，不是完整内容校验；不依赖全局纯时间源扫描。

任务归属改v2-basic，拒绝旧版归属/结构复用，不自动删除或迁移已建数据。模型业务文档明确全部操作记录数、无法区分查看/导出、按当前对象项目及人员组织归属，避免引用已移除字段。源索引不存在则拒绝，不自动创建索引或静默回退全表扫描策略；具体项目计划与实际同步耗时仍需现场验收。

## 影响

项目进度与计数仅存私有控制表，不授予问数账号。继承只追加、无迟到和历史变更修复的范围；手动verify历史发现差异后停止核对。新投影和按项目进度需要一起交付，不能只替换表结构或只换查询SQL。

# ADR0112：SQL 时间门禁规则优先，模型只判断规则无法确定的 SQL

## 状态

已接受，2026-10-25。补充 ADR0097/0103：ADR0097 中"检查器仅将原始 SQL 交给无工具 LLM"改为规则优先、模型兜底；登记配置、逐表口径、拒绝明细与留证方式不变。

## 背景

2026-10-25 问数与试问日志中，每条 SQL 的时间门禁都要一次模型调用，耗时 3–20 秒；一次 20 秒超时直接拒绝了一条合规查询（10 月 1 日至 31 日、上限 31 天），用户需要重问。被检查的 SQL 绝大多数是平台注入写法生成的普通形态（`col >= '…' AND col < '…'`、`STR_TO_DATE`/`TO_TIMESTAMP` 包装、数字日期键），窗口可以确定地算出。

## 决策

`SqlWindowGate#check` 先交给 `SqlWindowRules#evaluate`。规则只对窗口确定的形态给出结论：单个 SELECT；每张登记表只出现一次；登记表时间列的条件全部位于 WHERE 顶层 AND 中，且为与字面量的比较、BETWEEN 或等值（可带平台注入的日期解析包装）。逐表计算窗口的口径与模型门禁一致：左闭右开按差值计，闭区间纯日期包含当天，等于上限放行。SQL 未使用登记表时放行；登记表没有完整范围或超过上限时拒绝，明细同样写入 tables。

其余形态一律交给原模型门禁：顶层 OR、NOT、子查询、CTE、UNION、自连接、相对日期函数、时间条件写在 JOIN ON 中，以及无法解析的字面量。规则只会在确定时作出与模型门禁相同口径的结论，从不放宽模型会拒绝的范围；模型仍不可用或超时时，规则无法确定的 SQL 继续拒绝。拒绝理由以"规则判断："开头，便于区分来源。

## 备选方案

- 继续全部交给模型：延迟与超时问题保留，用户已明确不接受。
- 完整 SQL 解析器（引入依赖）：可覆盖更多形态，但新增方言依赖；当前普通形态已覆盖日志中的全部业务查询，暂不引入。
- 模型超时时放行：违反只读与成本边界，不采用。

## 后果

普通查询与确认试问不再等待门禁模型；门禁超时只可能发生在复杂 SQL 上。规则覆盖范围由单元测试固定，新增 SQL 形态默认走模型而不是被误放行。仍未解决：复杂 SQL 的模型门禁延迟不变。

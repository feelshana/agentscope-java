# ADR0138：升级 Wren 0.17.1，指标由 Cube 承担，取值与同义词写入 MDL

## 状态

提议，暂缓（2026-11-05 用户决定先不做）。实施 [spec118](../specs/118-wren-semantic-strengthening.md)。

取代（接受后生效）：ADR-0106（`cube` 命令一律拒绝）、ADR-0107（`cubes/` 不读不写）中针对资产轮次的部分；基础建模轮次仍不读写 `cubes/`。

## 背景

- 2026-11-05 评估是否继续使用 Wren：引擎真正执行的只有名称翻译、查询边界和计算字段；指标、默认过滤、术语、取值含义都是写给模型的文字，Wren 显得没有作用。用户决定继续使用 Wren，并让它承担更多语义。
- 指标（Cube）是 Wren 让"同一指标只定义一次、由引擎生成 SQL"的核心能力。此前因 0.15 读取中文 Cube 元数据的 UTF-8 问题未开放（ADR0128 第 8 条）；0.16.0 已修复，最新 0.17.1（2026-10-30），三个版本均未标注不兼容改动。
- 业界（dbt、Cube.dev、Snowflake Cortex Analyst、Databricks Genie）共同做法：指标一等公民、同义词与取值结构化、基准评测量化准确率。

## 决策

1. 升级到 Wren 0.17.1（含同版本官方技能），完成回归后再开放新能力。
2. 指标是一等语义资产：在资产轮次起草 Cube，验证只展开 SQL、不执行，人工核查后发布，问数优先 `query_cube`；依赖受限事实表时 `query_cube` 必须带合规的时间维度。基础建模仍不读写 `cubes/`。
3. 列的 `values`（取值）与 `synonyms`（同义词）写入 MDL properties，作为平台约定字段由 Wren 工具读出；问数时平台只做命中提示，不改写 SQL、不路由。
4. 建立基准评测：以已确认问答为基准，按草稿重新生成 SQL 并比较展开后的结构，发布前展示准确率变化，不阻止发布。

## 备选方案

- **替换 Wren（自建 Calcite 逻辑层或 Cube.dev）**：控制力更强，但推翻 Wren-only 主线、工作量大，用户选择继续使用 Wren。
- **指标继续写成规则文字**：每次由模型推导公式，同一指标答案不稳定，无法利用引擎。
- **取值与同义词只放平台数据库**：违背"工程 YAML 是唯一事实源"，也无法通过 Wren 工具送达。

## 后果

- 指标由引擎生成 SQL，口径一致性提高；指标治理沿用资产核查流程，数据开发多一类资产要维护。
- 升级 Wren 需要在本地与 66 同步执行并回归；Ossie 改名与 MCP SDK 锁定需逐项确认。
- MDL properties 中的自定义字段依赖 Wren 原样返回，需实施前验证；若不返回，改由平台上下文提供。
- 基准评测让每次改动可量化，但只比较 SQL 结构，不能证明结果正确。

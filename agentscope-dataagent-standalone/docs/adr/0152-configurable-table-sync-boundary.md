# ADR0152 · 管理员单表同步的执行与权限边界

状态：已接受，连接配置与凭证保存部分已被 ADR0153 取代。实施见 [spec148](../specs/148-configurable-table-sync.md)。

## 背景

已有数据源问数入口要求 MySQL 8。部分源表位于 MySQL 5.7，既有两套 BI 同步任务针对固定表配置。新需求允许全局管理员配置单表镜像及执行计划。

## 决策

- 管理 API 与计划调度由平台管理，复制在随应用部署的 Python/mysqlclient 子进程执行。执行面只有固定操作和结构化参数。现有数据源与 Agent 工具的连接和授权机制继续负责发布和读取。
- 允许列表控制源地址。源账号由 DBA 按表授予 SELECT，运行代码生成固定源端 SELECT。独立写入账号管理私有控制库和 `data_agent.sync_*`。目标名、归属标记和字段签名由执行器核对。源凭证由平台用独立 AES-GCM 密钥加密。
- 队列、业务周期覆盖、暂存和未发布镜像存在 `dataagent_table_sync`。全队列同一时刻执行一个写任务，使用目标 MySQL 连接持有互斥锁。首次发布先记录切换意图，再从工作表原子改名。之后整表或单个业务周期提交时，一并写入执行进度。结果突变为空时保留已发布数据，人工确认后可显式应用。

## 影响

源端只读权限及网络允许列表由运维配置。目标 InnoDB 需容纳暂存、首次工作表及更新事务开销。首版定时同步以一次写入完整历史日或月为单位，历史更正可手动补跑。旧两套 BI 同步使用原有执行链路，从新管理员页可访问其监控。

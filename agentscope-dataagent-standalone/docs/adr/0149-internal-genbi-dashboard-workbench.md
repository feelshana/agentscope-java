# ADR0149：内部托管的 GenBI 对话看板工作台

日期：2026-11-16。状态：已接受，试用版本地验收完成，待线上试用。

## 背景

官方 GenBI CLI 输出工程构建说明，由 Agent 编写网页。直接公开部署快照会扩大业务数据分发范围，也不能复用平台知识库撤权。用户已选择先试整张生成、预览修改和管理者发布。

## 决策

复用原生 HarnessAgent、官方 genbi/usage 技能和 genbi build/register/verify。新 Agent 的文件工具仅打开独立看板工程的 apps/<name>/index.html；平台复制已发布语义上下文并准备 mdl.json。CLI 参数由平台固定，不开放 shell、profile、任意路径及外部 deploy。

采用内部 live 托管适配：Agent 按官方构建思路生成完整网页，平台补充单页、ECharts 与异步查询桥协议。浏览器无需下载 Wren WASM 或携带数据库/用户凭证；SQL 仍通过官方 Wren 服务及既有查询门禁。此项是平台对官方通用浏览器执行方案的明确适配，不声称照搬官方 snapshot/wasm。

网页在 opaque-origin sandbox iframe 内运行，查询仅由受控 postMessage 桥请求宿主。宿主验证 frame 来源，服务端绑定看板知识库并重新检查 QUERY、只读 SQL、事实窗口及排队撤权。生成页面不能自行获取平台令牌，也不能直接联网。

草稿归创建者，固定单库和原生对话；发布只能由知识库管理者显式触发，使用期望修订避免误发布。HTML 以不可变版本持久保存，原子替换元数据指针；查看已发布内容仍要求 QUERY。不能把官方 verify 等同于浏览器运行验收。

## 后果

可最快复用官方生成工作流，并保留现有身份、发布和查询边界；需要维护内部 live 桥和预览隔离，不获得原生逐图配置编辑能力。以后若引入逐图钉入/重跑，另评估结构化卡片模型，不把任意网页解析成配置。

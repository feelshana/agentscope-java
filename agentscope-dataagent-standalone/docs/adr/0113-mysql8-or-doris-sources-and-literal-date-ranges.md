# ADR0113：外部数据源限定 MySQL 8.0+ 或 Doris，SQL 用 MySQL 8.0 语法与日期常量范围

## 状态

已接受，2026-10-25。补充 ADR0021（外部源只发布 MySQL）与 ADR0112（规则优先的时间门禁）。

## 背景

问数与试问的 SQL 由官方 Wren 按 MySQL 方言解析后再展开发往数据库，模型常写 CTE、窗口函数，这些在 MySQL 5.7 上会报错。"最近30天"类问题常被写成 `CURDATE() - INTERVAL 30 DAY` 且没有上界，时间门禁只能交给模型判断（延迟、可能超时），规则无法确定。

## 决策

外部数据源在测试连接、新建和修改时都检查数据库引擎：MySQL 主版本 8 及以上通过；Doris 对外报告 5.7 兼容版本号，按 `@@version_comment` 识别后放行；其它版本、无法识别的版本和非 MySQL 类型拒绝，不保存。

问数提示与建模基础提示要求 SQL 使用 MySQL 8.0 语法；日期范围先按运行上下文的当前日期换算成具体日期常量，用 `>=` 起始、`<` 次日或 BETWEEN 表达，不用 CURDATE()、NOW()、DATE_SUB、INTERVAL 等函数，使时间门禁可由规则直接判断。仍写成日期函数的 SQL 照旧交给模型门禁，不因此放宽或直接拒绝。

## 备选方案

- 只按版本号判断 8.0：会拒绝 Doris，不采用。
- 接受 5.7：CTE、窗口函数在库端报错，问数失败难以解释，不采用。
- 门禁直接换算相对日期函数并把缺上界视为截至当前：需要在门禁里解释方言函数，用户选择改为要求生成日期常量。

## 后果

已保存的低版本数据源不会被自动删除，修改时会被拒绝；关联、采样流程不变。模型仍可能写出日期函数，这类 SQL 的门禁延迟不变。

# spec147 看板草稿检查与发布状态

## 用户流程与验收

1. 咨询且页面未变时只结束对话。成功写出新修订后，由服务端收尾检查实际草稿；当前修订已通过时复用结果。检查不发起模型请求，也不发布。
2. 编辑者可对历史未检查、已变化或检查失败的草稿直接补检。检查绑定期望修订，支持查阅进度、失败原因及重试；同一看板检查时互斥写入。正式发布仍复核修订、官方检查和管理权限。
3. 工作台分别显示生成进度、当前草稿文件状态、当前预览运行结果和发布条件。仅有真实任务时显示检查中。可以区分未检查、旧结果过期、检查失败与通过。刷新恢复服务端事实；读页面不会触发生成或检查。
4. 已发布视图始终读取发布快照。撤销和预览诊断仅作用于匹配的草稿修订，发布失败可保留草稿并恢复操作。

沿用 spec145、146 的单进程执行及权限边界。验证覆盖模拟官方 CLI 的成功、失败、慢检查、并发、重试、老草稿和前端工作台状态。

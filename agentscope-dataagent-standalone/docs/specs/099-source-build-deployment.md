# spec099：服务器拉取源码并构建应用镜像

状态：2026-10-30用户回传66演练库核对通过；此前66已从9d378d8b完成builder检查/源码构建及镜像静态预检（Java946项0失败/0错误/28跳过）。应用Compose/启停和更新回退在本地真实镜像验证通过，未提交推送或在66启动；正式两库、65/BI/模型/业务验收仍待完成。

## 目标和范围

用户选择GitHub源码交付：本地测试并提交源码，66按明确提交构建应用镜像，再启动容器。无需镜像托管服务和Jenkins。构建工具在容器中运行，宿主Java8、glibc与既有服务不变；应用仍同容器运行Java17/Python/Wren，分析沙箱为独立兄弟容器。

## 实施要求

- 使用完整仓库所需的core、harness、BOM和扩展模块，不能依赖开发机预装的SNAPSHOT或仅复制standalone模块。
- 只从明确提交构建；源码、镜像、日志记录提交标识。保留旧镜像，不自动覆盖正在运行的服务。
- 构建环境固定JDK/Maven/Node版本，使用项目专属依赖缓存和资源预算；源站访问和旧内核兼容需实测。
- 最终镜像包含应用、前端和已验收运行依赖；生产配置、密钥、模型缓存及业务数据外置，同路径共享沙箱文件。
- 构建完成与业务启动为不同步骤；先检查镜像，再在具备生产数据库/配置后明确启动。构建失败不停止旧服务。
- 源码拉取有限重试并有单次超时，兼容宿主Git1.8.3.1；普通账号执行，项目独立Compose配置/名称，无全局镜像清理，不按参考Dify脚本重写生产配置。
- 不自动提交/推送本地修改、不把私有配置和个人交接加入Git；不操作其他项目，不全局清理或重启Docker。

## 验收

1. 干净源码和空项目依赖缓存可构建，不借用本机Maven仓库掩盖缺失模块。
2. 缺依赖、网络失败、脏工作区和错误提交明确失败，旧服务继续运行。
3. 包内无私有配置，前端前缀正确，镜像记录完整提交和运行依赖信息。
4. 构建资源受限，旧服务保留；镜像启动、历史/附件/权限/沙箱及停启恢复通过。
5. 有明确回退步骤，不把数据库结构回退等同于镜像回退。

## 临时数据库演练（用户已确认）

- 正式两库网络/权限未就绪期间，在66独立Compose项目启动MySQL8.0，用当前完整DDL初始化dataagent_platform，data_agent先保持空库。不是复用Dify已有数据库。
- 数据和私有密码保留在独立演练目录；不发布MySQL宿主端口，后续应用加入该专属Docker网络，Java和同容器Wren均使用mysql:3306。
- 初始化仅在首次空数据目录执行；已有数据不重放完整DDL、不重置密码。单独提供只读核对和日志入口，启动失败保留材料定位。
- 平台库与上传库使用分别授权的账号，普通账号执行脚本，仅Docker操作使用sudo；不全局清理、不自动停止或删除其他资源。
- 演练配置与生产连接分开。正式数据库到位后再核对建表、导入人员、配置/文件/密钥迁移或重新演练，不宣称替换URL即可保留临时库数据。

## 应用Compose及更新验收

- 应用单独Compose项目加入已核对标签的演练库网络，默认只映射66:18080，不创建或变更数据库。明确应用镜像或唯一构建记录后固定image ID；不自动重建、拉取镜像或切分支。
- 准备独立rehearsal-app目录：私有prod配置及独立JWT/模型加密密钥、持久home/state/workspace/mdl/artifacts/logs；已有配置不覆盖。使用当前UID/GID和Docker socket附加组，主目录按宿主相同绝对路径挂载，离线缓存只读挂载。
- check在不启Java时验证Wren依赖、数据库网络/两账号、离线向量和兄弟沙箱同路径读写。start等待HTTP健康和认证选项，再分别验收账号、模型、业务流程；没有模型配置不冒称问答可用。
- status/logs/stop只作用于项目标签和目录匹配的应用。upgrade先对候选镜像执行check，失败不停止旧服务；健康失败恢复此前镜像并验收，保留日志和失败结果。rollback只退应用镜像，不回退数据库、工作区或模型配置。
- 生产数据库切换、65同源Nginx/BI联调及并发问题单独验收；不把18080健康通过等同于带前缀前端/模型正确率通过。

现有并发阻塞是独立业务缺陷，本spec不自动修改；旧运行环境验收不能替代新源码构建或正式上线验收。

# spec117：语义模型工作台——关系图、字段三分类、结构化规则、页面直接修改

> 状态：已确认，主体已实现，浏览器验收进行中（2026-11-05）。原型：语义模型工作台原型（Design 画布，第 3 版）。实施记录见 [test-reports/20261105-spec117-semantic-workbench.md](../test-reports/20261105-spec117-semantic-workbench.md)。

## 背景与目标

语义建模页现在把模型、关系、业务知识拆成三个页签：模型是表格加 YAML，关系是另一张图，规则是原始 Markdown 文件，只能读，修改都要回到建模对话。用户反馈"很杂乱"，希望像业界建模工具（dbt Explorer、Wren 建模页、Power BI 模型视图）一样，一个页面看清全部模型、关系和规则，并能手动修改。

目标：把"模型、关系、业务知识"合成一个「语义模型」页签——中间是模型关系图或结构化规则，右侧是详情抽屉；有管理权限的人在页面上直接修改，修改与对话修改写同一份 Wren 工程文件、同一个草稿，在草稿栏统一发布。

受益人：数据开发（看得清、改得快），问数用户（只读查看已发布的语义）。

## 方案概述

**1. 页签与入口**
- 「模型」「关系」「业务知识」三个页签合并为「语义模型」，内部再分「关系图」「业务规则」两个视图；旧地址 `?asset=models|relations|knowledge` 跳到对应视图，不失效。
- 只有 QUERY 权限的用户进入同一工作台的只读模式，只看线上版本。
- 新手引导步骤不引用这三个页签，不受影响。

**2. 关系图（默认视图）**
- 每个模型一张卡片：表头区分事实表、维度表、SQL 定义的模型；卡片列出全部字段，字段按三类标记：普通字段（主键另标）、衍生字段（`is_calculated`）、关联字段（由 `relationships.yml` 带出，只展示，不写成 Wren 关系列——讨论确定的方案 A）。字段多时折叠，可展开。
- 关系画成连线，从关联键所在行连到对方关联键，两端标 N/1，线上写关联键与类型；点连线打开关系编辑。
- 支持拖动卡片、缩放、自动布局；卡片位置只存在当前浏览器（个人便利），不写入工程。
- 草稿与线上切换；"与线上对比"时，草稿新增或修改的字段、规则用黄色底标出。
- 公共视图（View）只作为只读节点出现，编辑仍在「公共视图」页签（ADR0128 的核查流程不变）。指标（Cube）显示"升级 Wren 后开放"（spec116）。

**3. 右侧详情抽屉**
- 模型：字段（三类分组）、表信息（表角色、说明、物理表、上传时统计的数据概况）、相关规则、YAML。
- 字段：说明、语义角色、同义词，衍生字段另有表达式；显示取值（若 MDL 已有 `values`）和引用它的规则。
- 关系：两端字段、对应关系（多对一等）、说明；可新增、修改、删除。
- 规则：按小节的结构化表单（见第 4 点），并显示写进文件的原文。
- 问题：缺说明的字段、未关联的模型、不在官方小节的规则、校验问题，点一下跳到对象。
- "问助手"：带上当前对象，把一段预填的话放进建模对话输入框并切到建模对话，由用户决定是否发送（复用现有建模对话，不在抽屉里另开会话）。

**3b. 全图与聚焦（实施中按用户反馈调整，取代第 2 点的"卡片列出全部字段"）**
- 全图：模型默认不展开，只显示名称、类型与列数的紧凑节点和关系连线；单击打开抽屉，双击进入聚焦。
- 抽屉里模型字段分为普通列、日期列（已写角色或按类型推断，推断的标"?"）、衍生列、关联；"规则与原文"列出引用它的规则（含规则原文、可识别的来源文档）以及业务文档中提到该模型或字段的段落（新增 `GET /documents/{name}/content`，MANAGE）。
- 聚焦：中间是该模型及其身份键、关联键；左侧是多对一指向它的模型，右侧是它指向的模型；连线标关联字段与 */1，两侧对象显示"+n 其他关系"，点击即以它为中心继续查看；"全图"返回。

**3c. 建模助手图标、改动标红与待确认（2026-11-05 用户确认）**
- 页签由六个变为四个：语义模型、问数优化（合并原"问答"）、公共视图、资料。"建模对话"不再是页签：旧地址 `?asset=modeling` 打开语义模型并展开助手，`?asset=qa` 打开问数优化。
- 页面最右侧是竖向图标栏：详情（仅语义模型页签）、建模助手（运行中有状态点）、待确认（角标为未处理数）。三者共用右侧一个面板位置，再点一次收起；建模助手就是原建模对话的同一个会话实例，切换页签或面板不重建。未发布的知识库默认展开助手；"问助手"与问数优化、公共视图发出的请求都打开助手面板，不再跳页签。试问在助手面板内切换显示。
- 每轮助手结束后自动标出改动（累积到你清除为止）：画布上改过的模型节点与关系标红，详情里改过的字段、规则标"新增/修改"；顶部提示条可逐项查看。红色只表示"助手改了、你还没看过"，在待确认里看过（或定位过）后变灰。"与线上对比"仍用黄色。
- 待确认面板分两组：助手在问你的口径确认卡；助手改了、你还没看过的条目（定位、看前后对比、标为已看、撤销）。撤销按文件恢复为线上版本，会同时撤销该文件中的其他改动，执行前提示。待确认不拦发布，改动仍直接进草稿统一发布（ADR0111）；公共视图与 ref_sql 仍逐项核查（ADR0128）。
- 新手引导中指向建模对话、试问、确认卡的步骤在助手面板中进行；引导进入这些步骤时自动展开助手面板。
- 首次建模（尚未发布）不自动标记改动，语义模型顶部改为"建模结果"摘要：生成了多少模型、关系、规则，需要你看的问题数与类别，以及"检查并发布"。发布之后助手的每轮改动才自动标记；"标出草稿改动"仍可手动打开。
- 建模流程不再试问（2026-11-05 用户决定）：建模结束只显示平台自动生成的 1 个推荐问题（spec103，不生成 SQL、不作为召回示例）；试问移到问数优化页签，只有在那里确认正确的问答发布后才会被召回。新手引导删除"打开试问、提问、核对 SQL"三步，确认口径后直接发布；保存在试问步骤的引导位置继续到发布。
- 左栏去掉"指标"占位，改为常驻"视图"组（+ 打开助手描述要建的视图，View 仍按 ADR0128 核查）；"默认使用"小节改名"指定取数表"并给出实用示例；字段列表不显示语义角色标签，被业务规则引用的字段显示醒目的"规则 N"标记（悬停列出规则）。
- 新增的对象只标"新"（主色小角标、虚线连线），红色只用于修改；新增模型不逐字段标记。待确认的条目默认折叠为一行（新增模型显示"N 个字段，说明已写 x/N"），展开后新增模型是"字段 | 说明"表，修改是上下排列的改前/改后，超过三行的长说明折叠。

**3a. 对话改动联动与空间（实施中按用户反馈补充）**
- 建模对话每轮的"AI 建模结果"提供"在语义模型中查看"：切到关系图（草稿），顶部列出该轮改动（`/draft/items?since=`），点一项定位到表、字段、连线或规则；改动处标黄。左栏"标出草稿改动"可标出全部未发布改动（未发布过的知识库没有"与线上对比"，用它看变化）。
- 工作台"全屏"占满页面（Esc 退出）；自动适应缩放不低于 70%，图大时滚动。
- 紧凑布局（独立打开与嵌入门户都生效）：隐藏只有两级的面包屑（窄屏保留，内含菜单按钮），更深的面包屑压低；进入建模页自动收起左侧菜单；建模页头与页签合为一行。运行在门户 iframe 中时另隐藏与门户重复的品牌行。真正的浏览器全屏（需门户 iframe 允许 fullscreen）与"在新窗口打开"暂不做。

**4. 业务规则结构化显示**
- 规则仍存在 `knowledge/rules/*.md`，Markdown 是唯一事实源；页面按二级标题（小节）分组：默认过滤（`## Default filters`）、术语（`## Naming conventions`）、默认使用（`## Canonical tables`）、其他官方小节，最后是"未归类"（自建标题）。
- 每条规则是一个列表项。页面写入时用固定句式，读取时按句式解析成列；解析不了的旧规则显示原文，照样可改：
  - 默认过滤：`统计「适用于」时：条件（例外：例外）`
  - 术语：沿用 spec100 的 `"术语"（同义词："甲"、"乙"）= 对应`
  - 默认使用：`统计「适用于」时默认使用 目标`
- 涉及字段：识别规则文字中的 `模型.字段`，以及只属于一个模型的字段名，显示为字段标签；字段在草稿中不存在时进入"问题"。
- "未归类"规则可一键移到某个官方小节（同一文件内，删除原条并追加到目标小节）。

**5. 页面修改落到 Wren 文件**
- 只有 MANAGE 权限可改；助手运行中不能改（沿用 `activity.requireIdle`）；每次写入都在工作区锁内复核权限，写入记为"手动修改"（`DraftChangeLog`，`EDIT`）。
- 字段（`models/<模型>/metadata.yml`）：
  - 说明：写 `properties.description`，同时写 `description_source: user`，建模助手不得改写（现有约定）。
  - 语义角色：写 `properties.semanticType`，取值 `IDENTIFIER`/`DIMENSION`/`TIME`/`MEASURE`；没写时页面按主键、关联键、类型推断并标"推断"，不自动写入。引擎忽略这个属性。
  - 同义词：写 `properties.synonyms`（字符串列表）。
  - 衍生字段：新增、修改表达式、删除，只能删衍生字段；保存前先跑写入门禁（YAML 解析、`context validate --strict`、`build`、`dry-plan`），不通过不写入，错误原样提示。
- 关系（`relationships.yml`）：新增（两端模型与字段、对应关系，名称自动生成）、修改对应关系与说明、删除。
- 规则（`knowledge/rules/*.md`）：新增到指定小节、修改、删除、移动小节。
- 整份 YAML：有 MANAGE 权限的人可在"YAML"页直接编辑；保存前先跑写入门禁，不通过不写入。

## 影响面

- 后端：`MdlWorkspaceReader`、`MdlPublishService#view`（列增加 `displayName`、`semanticType`、`synonyms`、`values`、`userDescribed`）；`DraftItemService`（字段修改、新增关系、规则追加与移动、写入前校验钩子）；`DraftReviewController`（`/draft/items` 增加 `COLUMN` 类别与新字段，YAML 整文件保存先过门禁）；复用 `ModelingToolkit#previewChange` 做门禁。
- 前端：新组件 `SemanticWorkbench`（关系图、规则视图、抽屉）、`ruleText.ts`（规则句式解析与生成）；`SemanticModelingPage`、`SemanticReadOnlyWorkspace` 页签合并；`api/draftReview.ts`、`api/semanticModeling.ts` 类型。
- 数据：不新增数据库表；新属性写入 MDL YAML。
- 文档：ARCHITECTURE 第 14 章；spec 索引。

## 验收标准（Given-When-Then）

1. Given 有两个已关联模型的知识库，When 打开「语义模型」，Then 关系图显示两张卡片与连线，连线两端标 N 和 1，字段按普通、衍生、关联三类标记。
2. Given 管理者选中一个字段，When 修改说明、角色、同义词并保存，Then 对应 `metadata.yml` 写入 `description`、`description_source: user`、`semanticType`、`synonyms`，草稿栏计数增加，问数在发布前不受影响。
3. Given 新增衍生字段表达式有语法错误，When 保存，Then 被拒绝并显示 Wren 的错误，文件不变；表达式正确时写入 `is_calculated` 和 `expression`。
4. Given 点连线，When 把多对一改为一对一并保存，Then `relationships.yml` 的 `join_type` 改变；新增关系后图上出现新连线。
5. Given `general.md` 有 `## Default filters` 与自建标题下的规则，When 打开业务规则视图，Then 规则按小节分表显示，自建标题下的出现在"未归类"；点"移到术语"后规则出现在 `## Naming conventions` 下。
6. Given 按句式写入的默认过滤，When 再次打开，Then 适用于、条件、例外分列显示；句式外的旧规则显示原文并可编辑。
7. Given 管理者编辑 YAML 写入非法内容，When 保存，Then 被门禁拒绝，文件不变。
8. Given 只有 QUERY 权限的用户，When 打开同一页面，Then 只看到线上版本，没有编辑按钮；调用修改接口返回无权限。
9. Given 助手正在运行，When 页面保存任何修改，Then 被拒绝并提示稍后再试。
10. Given 旧地址 `?asset=relations`，When 打开，Then 进入「语义模型」的关系图视图。

## 不做的事

- 不把关联字段写成 Wren 关系列；不在抽屉里另开对话会话；不做多人实时协作编辑。
- 不改官方技能文件；不让引擎执行 `semanticType`、`synonyms`（问数命中提示属于 spec116）。
- 不在本 spec 统计取值（spec116 第 3 部分）；不开放 Cube 编辑。
- 卡片位置不写入工程，不跨设备同步。

## 测试要求

- 单元：字段属性写入（含 `description_source`）、衍生字段增删改、只能删衍生字段、门禁拒绝时文件不变、新增关系、规则追加/移动、读取新属性；前端规则句式解析与生成。
- 多租户：QUERY 用户与无权限用户调用修改接口被拒；排队等锁期间撤权被拒。
- 浏览器验收：演示知识库按验收 1–10 实测；全量运行 AGENTS.md 第 8 节验证命令。

# Spec 060：建模会话节奏与确认批次优化

状态：实施中

## 目标

降低官方 Wren 建模流程中重复 skill 注入、无效文件写入和重复确认造成的耗时，同时保留高影响资产的人工确认。

## 行为

- 同一建模会话首次加载官方 skill，后续不重复加载完整内容。
- 写文件前检查工程清单，按文件是否存在选择 `write_file` 或 `edit_file`。
- 同一方案的独立文件以同轮多个原生 `write_file(path, content)` / `edit_file` 调用提交，使用已有 HITL 批次授权。原生工具没有 `files_json` 参数（ADR 0072 / spec 061 契约纠正）。
- YAML 修改后验证，批次结束后构建；不在每个文件后重复构建。
- 新 Cube、视图、关系完成后执行语义查询验证。
- HITL 日志记录一次确认中的工具数量和名称。

## 验收

1. 建模 Agent 的 system prompt 明确上述节奏。
2. 同一响应的多个写工具只产生一个确认事件，并有批次日志。
3. 普通 `context validate/build` 不产生确认。
4. 新增 Cube、视图、关系仍然产生确认。
5. 既有建模和问数测试保持通过。

# spec 067：平台并发与失败处理后续集成

## 背景与目标

用户要求继续合入 data-agent-multiAgent-Mdl-lyf 在 2026-10-14 的两次提交：a29cc754（上传）与 6a75b6cf（问答容量），补齐相关 ADR、spec 和系统文档。上传代码已由 bc11f3a5 合入；本轮核对、完成现有容量移植并验证，不重复覆盖既有修改。

## 方案概述

- 上传保留来源的大小/解析限制、磁盘暂存、全局准入、前端调度、断连状态与失败回滚。
- 集成 ChatCapacity、SSE capacity、Wren 有时限公平锁及实例预算、沙箱空闲驱逐、执行取消、HTTP/1.1 和网关 lease 清理；复用来源的 harness/model 扩展修复并构建相应依赖。
- 当前官方 Wren 建模/问数、动态工具发现及排队后撤权校验优先，修正移植中门锁类型不一致问题。
- 来源 ADR/spec 使用独立导入目录保留原编号，附来源与适用边界；当前集成决策使用 ADR 0078，避免覆盖当前同编号文档。更新 ARCHITECTURE 第 5、7、10、12 章及 README 配置。

## 影响面

后端上传/聊天/网关/Wren/沙箱配置与相关框架依赖；前端上传及排队提示；不新增数据表。部署需同步新后端、前端和沙箱镜像，依赖必须来自同一源码版本。

## 验收标准

1. 超限/重复上传被拒绝，失败回滚和上传者隔离测试通过。
2. 问答限额、排队超时、取消释放及同会话互斥测试通过；排队状态由前后端一致消费。
3. 工具发现及查询共用同一 Wren 门锁，排队撤权后不可访问他人知识库。
4. 当前全量测试、依赖相关回归、前端构建及 package 通过；来源历史云端验收与本轮实测分开记录。

## 边界与测试

容量为单进程机制，不宣称多副本全局限流或已完成容量压测。建模沿用当前官方执行流程，不移植来源的旧 SQL/MDL 路由。运行来源新增回归和本分支官方 Wren 权限/召回回归；不自动提交或重启用户服务。

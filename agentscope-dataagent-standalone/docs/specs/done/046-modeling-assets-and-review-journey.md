# spec 046：问题资产落点与清晰的建模审阅流程

## 背景与目标

已确认问题仅沉淀 SQL 示例，未落实可复用资产；右侧卡片不像列表、已发布状态不清晰、写入疑似重复确认、内容难读，验收后缺少显著发布指引。让用户围绕问题完成业务确认，由助手选择资产类型并让平台校验落点。

## 方案概述

问题 YAML 增加 modeling：strategy（MODEL/VIEW/CUBE/EXAMPLE）、reason、assets（kind/name）；新建或改写的问题经现有工具预检必须声明落点。登记时允许资产待构建，执行验收和发布前要求引用资产存在且 SQL 使用所声明资产（Cube 检查基准对象）；EXAMPLE 必须有明确理由。历史无元数据问题标为历史 SQL 示例，保持已有有效确认。API Review 增加 coverage 与 published 状态，不把草稿确认冒充发布。模型类型选择由助手负责，不新增用户分类开关。

右侧采用编号、可选中问题列表，已发布问题直接显示；详情只显示当前选中项。验收页保持逐项结果审阅，顶部固定阶段反馈，明确待完善/待验证/待确认数量及阻断原因，全部就绪时提供“前往第 4 步发布”；已发布提供问数入口。写入卡采用业务摘要和 15px 带 SQL/YAML 高亮的完整内容，差异单独展示，支持放大阅读。核对并修复重复确认根因，沿用原生 ConfirmResult，单次点击只提交一次，不自动批准新的提案。

## 影响面

- 后端：MdlQuestionStore、ModelingWorkflowService、MdlPublishService、ModelingToolkit、DataAgentConfig；必要的 HITL 边界修复。
- 前端：问题列表/详情、写入预览、ModelingChatPanel、阶段指引与 API 类型。
- 数据：YAML 可选增量字段、无 DB 迁移；历史确认哈希兼容。
- 文档：ADR 0056，ARCHITECTURE_zh.md 问题验收与第 11 章。

## 验收标准

1. 新问题缺落点无法通过写入预检；声明缺失资产时可登记但不能验收/发布；明确 EXAMPLE 不强制新建重复资产。
2. asset/strategy/reason 变化使原确认失效；历史有效确认不因升级过期。越权用户看不到发布状态和资产。
3. 已发布问题显示“已发布”；有草稿变更同时显示待重验/待发布，右侧列表可选中查看详情。
4. 同一提案一次采用即可执行；拒绝、编辑、后续不同提案和刷新恢复仍保留原生 HITL，双击不重复请求。
5. 写入内容保持换行/缩进，SQL/YAML 高亮、正文至少 15px，可放大阅读，不执行内容里的 HTML。
6. 验收后看到准确数量和下一步；全部就绪可一键跳转发布页，未就绪列出原因且不允许发布；已发布可问数。

## 不做的事

不要求每题建新资产，不复活 agent ref_sql 写面，不重写 ReAct 循环，不绕过租户/原生 HITL，不自动发布。

## 测试要求

JUnit 覆盖落点元数据、缺失/未引用资产、Cube 基准、历史指纹与发布状态；保持越权覆盖。真实浏览器验证列表/已发布/内容放大/单击确认/阶段跳转，构建、测试与 Spotless 全绿。

# spec 051：明确的查询修正与模型修复

## 背景与目标

验证页的“对话完善”混合查询和模型变更，问题输入仍为多行文本，移除问题需要多次交互。让用户可以明确编辑本题 SQL、独立提出模型修复、移出暂不处理的问题，并看清保存和发布状态。

## 方案概述

- `QuestionIntakeForm` 改为默认三行的可增删表格，保留批量粘贴，最多 50 个非空问题，去重，继续使用既有受保护 agent 文件写入路径；不假称提交即保存。
- `MdlQuestionStore` 提供人工问题编辑和归档；读取与写入在工作区锁内，预期问题指纹不匹配返回 409。编辑仅修改 SQL 与实例落点，保留其他 YAML 字段；移除旧确认实例，历史凭据保留并失效。禁止写 SQL、多语句、显式 LIMIT/OFFSET。
- `MdlQuestionService` 和 `ModelingQuestionController` 增加租户及 RUN 鉴权的人类操作 API，所有阻塞任务转 boundedElastic；操作后标记草稿变化。
- 验证页提供 SQL 编辑、保存并重新验证、建议修复模型、移出本次验收；模型修复消息要求先诊断提案，实际写入继续走 HITL。确认后立即显示待发布状态及发布快捷入口。
- 同步 ARCHITECTURE_zh.md 第 3、11 章；047–050 的后续候选工程能力不在本条实现范围内，不改变当前发布版本服务。

## 验收标准

1. 编辑已确认问题 SQL 后，模型文件和模型指纹不变，旧实例移除，旧确认不能复用；其他问题确认不失效。
2. 并发更新、非法 SQL 或跨租户操作被拒绝，文件不改变。
3. 用户明确移出问题后，其不再阻塞发布或进入发布实例；源文件、凭据与模型资产保留。
4. 问题表格可增删行与批量粘贴，空行忽略、去重且不越过数量及长度上限。
5. 查询修正和模型修复入口独立，保存 SQL 后 Wren 重验但不自动确认。

## 测试要求

补充 Store、Service 的并发、实例失效、非法 SQL、归档、多租户测试；执行 Maven 测试、Spotless、打包与前端构建。人工检查发布指引与代码可读性。

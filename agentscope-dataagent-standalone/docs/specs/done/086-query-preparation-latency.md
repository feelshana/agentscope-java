# spec086：问数索引准备与分段耗时

## 背景与目标

首次问数22.4秒、热态7秒，首次召回前存在约11秒未分段准备。把已发布工程的官方索引构建移到发布提交后的后台任务，保留问数时源指纹校验与失败重试。

## 方案

发布成功发出工程变更事件，事务提交后在有界后台调度器准备索引；同库事件合并，复用WrenPublishedProject的串行锁及源hash，实际CLI构建至多一次。失败不回滚发布，准备状态及失败写耗时日志，问数仍可重试。点赞既有同步刷新不变。get_instructions仅在同一已发布MCP实例缓存成功的无参数结果，实例失效即丢弃；缓存命中仍执行原授权与排队后复核。提示允许字段已知时减少describe往返，不强制省略必要工具。

增加授权/工具发现、索引等待/部署/hash/index/status、网关排队/准备/执行计时；不记录问题/SQL正文。背景索引不执行SQL或业务召回，不启动额外Agent。不新增用户前端步骤，准备状态通过日志可观测。

## 验收

发布失败不触发；有事务时提交后触发；重复/并发同源只构建一次，内容变化重新构建；任务失败不影响发布且下次可重试。不同库隔离，外用户无授权不能获取缓存，排队撤权仍有效。成功说明缓存随实例销毁，错误不缓存。全量测试、Spotless及前端构建/打包通过。

## 范围

只改平台准备与观测，不改官方Wren、日期门禁、SQL/召回路由、ReAct循环。5–8秒为待真实运行验证的目标，不作为已达成结果；召回模型预热先保留为待测建议。

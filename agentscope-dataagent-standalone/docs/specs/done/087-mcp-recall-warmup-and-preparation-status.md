# spec087：实际MCP召回预热与准备状态

## 目标

先落实上一轮建议4/5并提供状态验收：使用实际复用的MCP预热官方只读召回，不执行SQL；安装版明确LanceDB成功输出时省去第二个status进程，未知输出保留后端验证。准备状态可在建模发布页面观察。候选版本原子切换（建议2/6）涉及运行目录/实例双版本，不与本步混为已完成；由本步真实冷热与容量数据决定后续切换实现。

## 方案

发布事件先使旧实例失效，再在提交后的有界准备任务中indexed+实际MCP recall。预热使用固定技术文本、limit=1，丢弃结果不进入历史、答案、SQL门禁或LLM提示；实际请求仍按题召回。实例受原容量/回收约束，重启/回收后不宣称仍已预热。后端通过当前库QUERY与group校验，排队后再检查，任务受删除取消门锁。

状态含QUEUED/INDEXING/WARMING/READY/FAILED、发布版本、更新时间，端点只允许当前有QUERY的库；页面轮询并在成功/失败后停止高频轮询（降为30秒），不改变SSE协议。失败不回滚当前发布，允许问数按需重试。

官方能力核对：memory index的Indexed N schema items只出现在LanceDB构建分支，grep输出不同；CLI无仅同步样例的独立开关，保留完整index流程，不自建Python服务。增量API需另行验证后采用，避免删改样例残留。

## 验收

预热只调用recall_queries，不执行SQL；权限撤销与删除取消不能越过；失败不能写READY，重复任务同库合并，实例容量不扩大。成功输出省status，grep拒绝，未知输出fallback。后端状态隔离、前端构建、全量测试和有条件真实安装版冷热测试，记录重启/回收/并发等未实测范围，不承诺5–8秒。

关联ADR0101，架构/README/共享记忆同步。


## 展示简化（用户后续确认）

仅本页点击发布且成功后开始查询准备状态；页面初始进入不展示后台阶段，不常驻轮询。QUEUED/INDEXING/WARMING统一显示“正在准备问数…”，READY显示“问数准备完成”2.5秒后隐藏，失败/未准备或读取失败统一显示“问数准备未完成，首次提问时将重试。”，结束停止轮询。没有新的操作、确认或发布阶段；后台详细状态和日志保留。

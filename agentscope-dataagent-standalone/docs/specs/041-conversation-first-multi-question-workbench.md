# spec 041：对话主工作区与多问题建模
状态：已实现；验证见 docs/validation/2026-10-07-conversation-workbench-development.md。
## 背景与目标
用户不清楚按钮顺序，对话在右侧难以成为主入口。让用户通过同一对话录入一组问题、补全共享口径、查看模型产物、验证并发布。
## 方案概述
SemanticModelingPage 将建模聊天置于主区域，右侧显示问题清单；ModelingChatPanel 删除快捷任务按钮，提供可选文档附件与批量问题弹窗。批量录入预填聊天，不自动发送或写文件。ModelingQuestionsPanel 显示全部问题、独立状态和通过对话修改/删除/设置必验入口；验收页批量验证所有完整待验问题。固定“查看模型”进入模型、派生模型、Cube、视图、术语和 MDL 详情，保留 URL 与返回建模。ModelingWorkflowService 全问题进度与必验阻断分离。提示词要求先登记问题、合并共用口径、逐项澄清。
## 影响面
后端：WorkflowService、建模剧本；前端：工作台/聊天/问题清单/详情；无新数据库表或配置。同步架构第 11 节。
## 验收标准
1. 有基础模型时默认进入建模主区；对话是主区域，无四个快捷任务入口。
2. 批量录入三个问题仅预填，用户发送后通过原生 HITL 保存；取消不写入，问题不重复要求填写。
3. 各问题显示独立状态，修改/删除/必验设置均经受保护写面。
4. 可选问题进入澄清、验证、审阅引导，但不阻断发布；混合问题只由未确认必验问题阻断。
5. 模型/Cube/视图/MDL 详情可达，明确草稿与已发布快照，返回不清空聊天。
6. 模型修改后旧问题结果失效；全部待验问题可批量执行，确认仍逐项人工操作。
## 不做的事
不新增独立结构化问题写 API、不更换组件库、不绕过 Wren 或 HITL，不自动确认业务结果。
## 测试要求

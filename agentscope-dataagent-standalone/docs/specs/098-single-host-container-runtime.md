# spec098：旧系统单机容器运行环境

状态（2026-10-29）：66环境部署阶段已验收完成；用户本次明确不含数据库、打包上传与业务启动，后续业务接入验收另行安排，spec保留进行中以追踪完整发布范围。

## 背景与目标

2026-10-28用户已确认：66使用同一应用容器运行Java17/Python/Wren，独立分析沙箱复用宿主Docker；业务tar仍由用户Maven打包上传。66的Anolis7.9/glibc2.17不直接安装当前完整原生依赖；Python、Wren导入和离线向量计算已由用户实测通过。

## 方案概述

新增docker运行镜像、前台入口和宿主控制脚本。入口复用发布包check-wren.py预检，以exec启动原JAR，Java/Wren使用同一文件系统和环境；宿主与应用容器以相同绝对路径挂载项目目录，满足宿主Docker创建兄弟沙箱时解析shared路径。只安装Docker客户端，挂载现有Unix socket，不启动嵌套daemon。原生bin/dataagent.sh保持原有用途。

## 影响面

- 业务Java/前端/数据库/问答协议：无变更。
- 运维：运行镜像、前台JAR参数、单实例容器启停、目录及缓存挂载。
- 文档：ADR0117、ARCHITECTURE第12章、66安装指引；只交付无密钥模板。

## 验收标准

1. 同镜像内Java17、固定Wren CLI/原生依赖、Docker CLI可执行；Docker连接宿主daemon。
2. 缺配置、多个JAR、缺缓存/镜像或错误目录时启动明确失败，不降级依赖或扩大权限。
3. 业务文件使用宿主持久目录；更换运行容器不删除业务目录及模型缓存。
4. 主进程接收TERM；兄弟沙箱可访问相同绝对路径的shared目录；停止操作仅针对本项目带匹配标签的容器。
5. 本地验证与66实际执行分别记录；正式上线业务包仍由用户构建。2026-10-29用户另行授权助手在隔离目录生成测试专用包，并在个人云服务器进行原生/容器对照，不能将测试包当作66正式交付。

## 不做的事

不改宿主glibc/Python/Java8、不重启Docker、不引入Kubernetes、不声称通过真实BI/生产MySQL/问答并发验收。

## 测试要求

实际镜像构建及原生依赖/向量/Docker连接检查；前台入口边界及TERM测试；同路径兄弟沙箱文件验证。公司旧内核需用户执行补验。

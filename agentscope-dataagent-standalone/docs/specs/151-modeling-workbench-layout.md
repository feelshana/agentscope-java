# spec 151：问数优化、公共视图与资料工作台

## 目标

落实已确认的 HTML 设计。三个页签占满可用工作区，使用一致的工具栏、对象目录和详情。用户打开对象即可看到当前状态与下一步。

## 验收标准

1. 问数优化用「待处理」「问答示例库」切换。空队列依据有无草稿引导检查发布或添加问题。主区录入将数量和提交动作放在输入框下，问题建议和示例入口在宽屏并排、窄屏置于录入区下方。示例库合并建模确认、旧版试问、视图验证和点赞来源，支持按来源和状态筛选。「使用指南」放在问数优化的更多菜单。
2. 通过「边聊边核对」打开绑定原题的对话，或从当前 SQL 工具栏进入编辑。手动修改沿用修订校验，修改后可对照上一版并重新核对。共享方案经原有批准流程。录入时点击问题建议即可填入并继续编辑。已确认示例可直接设为问数首页推荐，经应用内弹窗确认后，为该知识库的新对话预填题目。
3. 公共视图用「待处理」「视图库」切换。视图库读取线上快照，待处理列出草稿核查、验证、待发布和待下架事项。同一对象在草稿与线上各有版本，已发布且有待办时可从详情前往草稿；待下架期间保留线上详情。用途、粒度、依赖、口径和限制按说明原文分区。核查、验证和提交判定绑定用户见到的修订。问题验证展示原 SQL、展开后的 SQL 和判定，只做规划检查。判定提交后按题选择保存为问答，同名替换须确认。草稿发布的阻塞项可定位到视图的当前步骤。移除草稿和下架使用项目内影响确认，并排对话带入当前对象。
4. 资料分为业务文档与数据表，目录从标题旁收放。业务文档名称和发布状态显示在目录，查找、阅读模式、字号、引用和管理操作与「新增文档」在桌面共用一排工具栏，正文在主区独立滚动。查找支持逐处定位，文档变更从工具栏检查草稿。数据表主区呈现字段名称、类型、业务说明与纳入范围，长字段清单按关键字和范围筛选，业务说明占用主要列宽。调整字段沿用现有引用检查。窄屏工具栏换行，并排对照保留阅读和核对所需操作。
5. 问答和视图的单条移除从当前对象的「更多」进入。目录的「批量处理」显示可操作项的复选框，勾选独立于当前查看项。批量工具栏显示数量和清空入口，勾选后显示红色移除按钮，悬停和聚焦时显示中文提示。确认框逐项说明草稿移除、示例删除或发布后下架及视图引用影响。切换筛选或集合时清空选择。批量请求逐项沿用现有校验，部分失败保留成功结果并提示重新检查。建模对话输入「移除这道题」或「移除业务问题：题名」可打开同一个确认弹窗，目标不唯一时先选题。未上线的题移出后，该题的新增草稿差异立即消失。已有线上示例经确认后在示例库和草稿栏显示「待下架」，发布后生效。归档保留已保存题目的历史，释放常用问题名额，首页推荐由用户单独维护。
6. 绑定题目的对话根据该题的工作台状态和近期对话理解用户最新要求。核对阶段的「确认」「保存」或明确认可当前 SQL 的其他表达，与「确认并保存」共用验收接口及修订校验。确认成功后同步刷新详情、对话结果卡和草稿状态。尚未并排展示该题时先打开题目供用户核对。明确要求上线或检查发布时，打开本知识库的草稿检查，展示整批发布范围，由用户在窗口内确认发布。询问状态、暂缓或要求先改 SQL 的情况继续交给建模对话。

## 实施与验证

三页采用同一模块工具栏。左侧为集合切换，中间为选中对象操作，右侧为模块操作。可收放目录展示对象名称和状态。全屏详情从内容或当前步骤开始，目录收起和并排对照时在工具栏显示紧凑对象名。代码编辑和内容验证保持在各自工作区。

主导航保留原页签和全局操作，顶栏「变更与待办」统一进入变更比较和处理事项。变更按业务对象汇总，对应文件可查看差异。待办取现有口径确认、问答依赖复核和视图核查／验证状态，显示理由、发布影响和定位入口。未查看的改动在变更区标记。保留现有发布校验和处理权限。

问数优化按待处理和示例库组织。单题和多题共用主按钮「添加业务问题」，队列空且无发布事项时主区直接录入，提交后选中原题并进入待处理。问题与示例目录在目录标题旁收起，从原位展开。宽屏并排展示口径和 SQL。SQL 版本按钮采用白底和加粗文字，当前版本加描边。代码框提供短 SQL 的基准高度，长 SQL 填充可用空间，在框内滚动。常规状态用一行提示，口径和校验异常提供对应操作。首页推荐设置在示例库中维护。草稿检查使用独立弹窗，保留按题对话、修订校验与统一发布。

工程与快照、问数优化的「核对规则与版本」、模型 YAML 和视图工程文件复用同一可全屏工作窗。全库草稿与已发布版本可只读对比，打开时保留原页面。模型详情将字段、表属性和关联规则作为常用栏目，源文件从更多菜单打开。模型和视图的草稿编辑器显示跟随正文的行号，并沿用各自的校验和后续核查。问数依据展示知识库版本上下文。

复用现有模型工作台、统一草稿栏与 Wren 校验。所有查询验证仍为 dry-plan。资料上传、问答确认及资产验收沿用 MANAGE 权限与现有 API。更新架构文档第 14.1 节，运行前端测试、构建和文档一致性检查。

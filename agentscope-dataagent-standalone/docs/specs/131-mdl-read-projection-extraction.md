# spec131：发布服务只读预览职责抽取

## 范围与授权

用户要求继续上一轮确定的只读预览职责拆分。在codex/architecture-phase1保留全部既有修改，按ADR0144进行小批职责抽取；不新增产品能力或长期边界，故不新增ADR。

## 设计

- 独立MdlTypes保存现有MDL结果record（文件/问题、预览/结构视图/编译文本及验证/发布结果），字段、顺序和JSON不变，内部Java类型归属调整并同步所有调用方。避免MdlWorkspaceReader及新读取组件依赖MdlPublishService的嵌套类型。
- MdlReadService负责preview、compiled、view及其只读辅助：工作区/发布文件比较、编译文本限额与时间、模型/关系/Cube/View投影。依赖只有组仓库、属性、工作区路径和解析器；不持有WrenCli、Seeder、事件发布器、写服务或发布锁。
- MdlPublishService保留三个同名方法委托，不改变现有构造器签名及Spring装配；查询仍由原HTTP入口授权并在boundedElastic执行。MdlReadService作为内部协作对象构造，不新增运行配置或框架。
- 发布、validate/prepareModeling、互斥/锁顺序、文件替换、版本写入、授权、异常和恢复策略不修改。原只读逻辑与缺失/限额行为按原样迁移，不借重构修复未确认的行为。

## 验收

1. 原发布/只读预览、控制器、草稿评审、建模工作流等断言保留并通过；HTTP JSON字段和嵌套结构不变，源码中无旧嵌套类型残留。
2. 新组件能独立构造测试，不依赖发布服务或Wren执行链；读操作不调用保存/构建/播种、不创建staging或修改版本、工作区文件。架构规则保护此分工。
3. 覆盖编译文件缺失、真实文本/时间、4MiB限额；差异过滤、物理/派生模型和用户字段投影沿用现有行为并验证。
4. 对照快照确认非抽取发布/写入方法逻辑未变化；重点测试、单元通道、相关完整应用装配、格式及文档通过。前端未变更不重复构建，合并前仍完整clean verify。
5. 不提交/push/合并/部署，不读取生产数据或停止现有开发进程；记录真实测试范围和未验证的外部环境。

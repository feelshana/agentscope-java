# spec106：语义建模工作台（模型、关系分开与新关系图）

> 状态：已实施，待重启后真实验收（2026-11-01）。原型：[语义模型页面原型](https://claude.ai/artifact/TC6fUnz69oEiXJRUaVExvo)。

## 背景与目标

语义模型藏得很深：语义建模 → 选知识库 → 进入建模 → “语义模型”页签 → 下拉选类型。关系图只显示大色块和字段数，看不出哪个字段连哪个字段，页面又窄又要滚动。业务术语还单独占一个左侧菜单。

目标：所有语义内容都在现有“语义建模”里，模型和关系分开，用字段级 ER 图看关系。建模、试问、草稿、发布的逻辑不变。

## 方案概述

**1. 入口**：左侧保留“语义建模”，不改名、不新增菜单，移除“业务术语”菜单。列表页增加模型数、关系数和“需要关注”（未关联模型数）。

**2. 页签**：进入知识库后一层页签，取代现有的三页签和下拉框。

| 页签 | 内容 | MANAGE | 只有 QUERY |
|---|---|---|---|
| 建模对话 | 现有对话、试问、新手指引，不改 | 有 | 无 |
| 资料 | 现有数据与业务文档，不改 | 有 | 无 |
| 模型 | 物理模型和 SQL 定义模型的列表与详情 | 草稿/线上可切换 | 线上版本 |
| 关系 | 关系图、关系列表 | 草稿/线上可切换 | 线上版本 |
| 业务知识 | 业务术语（沿用可编辑表格）、业务规则与样例 | 术语可编辑，进草稿 | 线上版本只读 |
| 问答 | 现有 SQL 问答对 | 沿用 | 只读 |

- 默认页签：有 MANAGE 且未发布进“建模对话”，其余进“模型”。带 `asset` 参数时按参数打开，新手指引继续用 `asset=modeling`。
- 旧地址仍可用：`asset=schema` 进“模型”，`glossary` 进“业务知识”，`sql` 进“问答”；`derived` 进“模型”；`views`、`cubes`、`mdl` 进“模型”的高级查看；`/configure/semantic` 跳到所选知识库的“业务知识”，未选时跳列表页。
- 草稿栏在有 MANAGE 的页签上都显示，发布逻辑不变。
- 视图、Cube 不做主页签，只在 YAML/高级查看中只读展示，不新增读写能力。

**3. 模型页**：左侧模型列表和搜索（搜模型名、字段名），右侧说明、字段表（字段、类型、业务含义、标记）、“关联到”跳转，可切换 YAML。列表标记事实/维度/SQL 定义/未关联。

**4. 关系页**：默认关系图，可切换关系列表。

- 卡片：232px 宽，显示模型名、中文说明、角色；默认只列关联字段，其余可展开，展开时连线不重算错位。
- 连线：从字段连到字段，按 `sourceColumns`/`targetColumns`；线上标 `N : 1`、`1 : N`、`1 : 1`、`N : N`，点击后右侧显示类型、条件和说明。
- 布局：事实表在左、维度表在右；未关联的模型单独排放并标“未关联”。
- 交互：缩放、平移、适应画布、“只看相关”，详情固定在右侧，不用悬浮框遮挡。
- 角色判定：现有事实/维度登记优先；没有登记时显示为“模型”，不猜测。
- 标记：`PK` 只来自 MDL 声明；未声明时被关联字段标“关联键”，不写成主键。

**5. 关系只读**：模型、关系页都不提供编辑，“让建模助手修改”跳到建模对话并预填内容，用户确认后再发送。QUERY 用户不显示该入口。

**6. 技术**：用项目内 SVG 连线加定位的 React 卡片（`relationLayout`），不新增依赖。G6 的 HTML 节点按字符串渲染，卡片内按钮和键盘操作都要另做，所以未采用，也未做 G6 样机。现有 HITL 卡片仍用 `ReadOnlyRelationGraph`，不受影响。

## 影响面

- 后端：`SemanticModelingController#mdlView` 已限 MANAGE，继续只用于草稿；线上版本扩展现有 `KnowledgeBaseBrowseService#browse`（已校验 QUERY），不放宽草稿接口；`MdlColumnView` 增加主键声明；`MdlRelationView` 补说明；列表页的线上模型数、关系数由 `GET /api/knowledge-bases/summaries` 一次返回，不新增逐库请求。
- 前端：`SemanticModelingPage`、`ModelingHubPage`、`SessionsSidebar`、`main.tsx`；新增模型页、关系页组件；`SemanticConfigPage` 拆出术语面板；`MdlGraphView` 重做；`GuidedTour`、`Onboarding` 中的相关跳转和文案核对。
- 数据：无表结构变更，不改 MDL。
- 文档：ARCHITECTURE_zh.md 建模相关章节；spec 索引；不写 ADR。

## 验收标准

1. Given 有已发布知识库的 MANAGE 用户，When 从左侧进入语义建模并打开知识库，Then 默认在“模型”，两次点击内可看到关系图。
2. Given 未发布的知识库，When 进入，Then 默认在“建模对话”，新手指引两条路线都能走完。
3. Given 指示3，When 打开关系图，Then 3 条关系从字段连到字段，`report` 标“未关联”，不用滚动就能看到全部卡片。
4. Given 关系图，When 点卡片、点连线、开“只看相关”、缩放、展开字段，Then 右侧详情正确，无关内容变淡，连线不错位。
5. Given 30 个模型，When 打开关系图，Then 可缩放、可定位，操作不卡顿。
6. Given 有修改未发布，When 切换草稿和线上版本，Then 模型和关系显示对应版本，默认状态明确标出。
7. Given 业务术语，When 从“业务知识”新增或修改并发布，Then 行为与现有术语页一致；左侧不再有“业务术语”。
8. Given 旧链接 `/configure/semantic`、`asset=schema`、`asset=glossary`，When 打开，Then 跳到对应新位置。
9. Given 只有 QUERY 的用户，When 打开，Then 只看到线上的模型、关系、业务知识和问答，没有草稿、对话和编辑入口；访问草稿接口被拒绝。
10. Given 无权限的用户，When 用地址访问别人的知识库，Then 被拒绝，看不到任何模型内容。

## 不做的事

- 不在页面内编辑模型或关系，不支持拖线建关系。
- 不做建模对话右侧分屏（第二期再评估）。
- 不改建模助手、试问、发布逻辑，不修改官方 Wren 技能和 MDL 内容。
- 不自动补主键或关系；`report` 缺 ID 的数据问题不在本 spec 处理。
- 不新增视图、Cube 读写，不恢复知识图谱。
- 不保存用户拖动后的卡片位置。

## 测试要求

- 后端：主键字段输出；线上版本 QUERY 可读、草稿 QUERY 被拒、无权限被拒并在排队后复核撤权（看不到别人的数据）；列表统计只算可见知识库。
- 前端：`npm run build`；新旧地址映射；浏览器验收 1360×820 和 iframe 宽度下的页签、关系图、术语编辑；走完两条新手指引路线。
- 全量：`mvn spotless:check`、`mvn test`、`mvn package -DskipTests`。

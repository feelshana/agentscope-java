# spec102：问数分析技能（归因、异常检测、预测）

> 状态：已实施，待真实验收（2026-10-29）。依赖 spec101（结果文件通道与可视化分层）。ADR0121。

## 背景与目标

现在问数只能回答"发生了什么"。用户接着问"为什么下降""哪几天异常""下个月大概多少"时，助手要么拒答，要么临时写算法代码，结果不稳定，也无法复现。

业界做法分两类：
- ChatBI 产品主推"问数 → 归因 → 建议"的闭环；
- 开源 Agent（DB-GPT、Agent Skills 标准）把分析方法打包成"技能 + 沙箱脚本"。

目标：
- 提供平台内置的分析技能，用户可以显式选择，助手也可以在合适时推荐；
- 每个技能 = 操作说明加固定、可测试的 Python 脚本；
- 首批做三个技能：指标波动归因、异常检测、趋势预测。

## 方案概述

1. **技能形态（Agent Skills 标准）**
   - 目录 `src/main/resources/analysis-skills/<id>/`：`SKILL.md`（参数确认、取数、调用脚本、报告结构、边界）与固定脚本 `<id>.py`。
   - `AnalysisSkills#materialize` 每次启动把技能复制到 `~/.agentscope/dataagent/analysis-skills`（覆盖旧版本），以只读 `FileSystemSkillRepository` 挂到问数助手，白名单为官方 `usage` 加三个分析技能；建模助手不挂载。
2. **脚本契约**
   - 调用方式：`run_python` 中 `subprocess.run([sys.executable, "skills/<id>/<id>.py", "--input", "data/<文件>.csv", "--params", json])`。
   - 脚本只读输入的 CSV，不联网；只依赖标准库、numpy、matplotlib（沙箱镜像已有，**不新增镜像依赖**）。
   - 输出：标准输出一段 JSON（`ok`、方法、派生数值、文件路径、提醒；失败为 `ok=false` 与 `reason`）；`outputs/<主题>.png`（中文字体、统一配色）与 `outputs/<主题>_结果.csv`。
   - 相同输入得到相同输出（无随机性，参数按固定网格选取）。
   - 代码引用 `skills/` 时，`RunPythonTool` 把脚本上传到会话沙箱 `skills/<id>/` 并链接到本次运行目录，模型不能改写；普通 Python 运行不受影响。
3. **首批技能**
   - **attribution（指标归因）**：SQL 按"期间 × 维度"聚合两期；脚本按两期结构差异（Jensen-Shannon 散度，Adtributor 思路）选择解释力最强的维度，贡献度 = 维度值变化 ÷ 总变化，对贡献最大的维度值在剩余维度上下钻一层；校验各项之和等于总变化；输出瀑布图与下钻图。 去重指标（人数、用户数）不可加和：SQL 输出长表（期间、维度、维度值、指标，每个维度单独去重，另有“合计”行单独去重两期总数），`additive=false`，脚本按维度值分别比较、不做加和拆解与自动下钻，报告注明“各项变化之和不等于总变化”。
   - **anomaly（异常检测）**：SQL 按天或小时聚合；趋势为 4 个周期窗口的滚动中位数；季节项按天满 4 周按星期、满 2 周按工作日 / 周末、按小时满 3 天按小时，否则不估计；残差稳健标准差 σ = 1.4826 × MAD，超过 3σ 判为异常。
   - **forecast（趋势预测）**：Holt-Winters 加法模型（按日带周季节项，按月满 24 点带年季节项），平滑参数在固定网格上按一步误差选取；80% / 95% 近似区间，历史非负时下限截断为 0；按日 <14、按周 <8、按月 <12 个点时不预测。
4. **入口与交互**（2026-10-29 已与用户确认，原型见 Design 画布"问数分析技能原型"）
   - **入口一：分析菜单。** 输入框底栏、知识库按钮旁的"分析 ▾"菜单，默认收起（业界做法：高级分析不常驻），列出指标归因 / 异常检测 / 趋势预测及一句说明；选中后显示为可取消的"方法名 ×"标签，提示语随之切换，发送后自动恢复。不选即普通问数，不设"自动"选项。请求带上 `analysis=<id>`，平台校验 id 在白名单内后注入本轮指令。
   - **入口二：结果追问。** 普通问数回答下方显示"为什么变化？/ 有没有异常？/ 未来走势？"，带着本轮的指标、维度和时间进入对应分析。
   - **自动识别意图本期不做**：选"自动"或不选时，问数流程不变。
   - **出现规则**（2026-10-29 确认）：
     - "分析"菜单在选中知识库后可用。所选知识库的语义模型没有日期或时间字段（或选了多个知识库）时，菜单中三个方法都**置灰**，并提示"该知识库没有时间字段"（一期归因只支持时间段对比）。
     - "继续分析"按钮由**固定规则**判断，依据是本轮最后一次成功的查询结果，不由模型决定。实施时改为由前端 `analysisSuggestions` 根据回答中已有的工具结果计算，**不改 SSE 协议**（兼容性更好，历史会话同样生效）：
       - **归因**：有数值指标，并且有日期列且至少覆盖 2 个时间单位，或者问题本身是两个时间段对比；
       - **异常检测**：时间序列（按天或按小时）至少 7 个点；
       - **预测**：时间序列点数足够（按日 ≥14、按周 ≥8、按月 ≥12），**不够时不显示**按钮。
     - 以下情况都不显示按钮：单值或明细清单、没有数值指标、联网搜索类回答、查询失败或结果为空。
     - 日期列识别与 ID 列排除与 `ChartBuilder` 的规则一致。
     - 点击按钮时，带上本轮的指标、维度和时间范围，进入对应方法的参数确认卡。
   - **参数确认卡**：每次分析先确认参数，再执行。确认卡由助手根据问题和语义模型预填，用户可修改：
     - 指标（含口径来源）；
     - 当前期和对比期（快捷选"上一周期 / 去年同期"）；
     - 归因维度（候选来自模型中可分组的字段，最多 4 个）；
     - 下钻层级；
     - 知识库业务规则中的默认过滤（可见、可关）。

     日期字段并入确认卡，受限事实表的"缺日期先问"不再单独问一次。
   - **执行进度**：分"取数 → 计算 → 生成报告"三步展示，执行过程（SQL、脚本、参数）可以展开查看。
   - **报告结构统一**：
     1. 结论；
     2. 关键数字；
     3. **Python 生成的图**（matplotlib，中文字体，统一配色）；
     4. 明细表；
     5. 下钻；
     6. 方法与口径（折叠）；
     7. 下载图表或 CSV、继续分析。

     推断性解读必须加"推断"标记。
   - 分析类回答可以点赞或点踩，只作反馈，**不进入问答召回**。
   - 一期不做管理员预配置"可归因维度"。
5. **边界**
   - 原始统计值只来自 SQL；脚本算出的派生值（贡献度、预测值、异常点）在回答中标明方法。
   - 受限事实表的时间门禁照常生效：技能取数和普通问数走同一套官方工具。
   - 每个问题最多调用 2 次 `run_python`。
6. **两阶段执行**
   - 选择方法后的第一轮只确认参数：`AnalysisSkillMiddleware` 注入"只确认参数"，助手调用 `propose_analysis`（页面渲染为参数确认卡）后结束；本轮 `WrenScopedMcpClient` 拒绝 `run_sql` / `query_cube`（代码约束）。
   - 用户在卡片上点"开始分析"后，请求带 `analysis` 与 `analysisParams`，第二轮按确认参数取数并运行脚本；"取消"按普通问数回答原问题。
   - 选择只对当前一轮有效：每次问数请求都会替换 `ConversationScopeRegistry` 中的选择，`/send` 端点清除选择。
7. **清理与镜像**
   - `shared/agents/data-agent/skills/` 下的三个旧种子技能**保留**：它们还被技能市场、用户绑定使用，且未挂载到问数助手；留待技能市场整理时处理。
   - 沙箱镜像不变。
8. **ADR**：ADR0121 记录脚本随平台发布按需上传、问数请求新增 `analysis` / `analysisParams`、派生数值的可信边界与两阶段执行。

## 验收标准

使用"测试"知识库：报表访问明细 9/20–10/7，点击详情数据 9/1–9/4。

1. Given 选择"归因"，When 问"10 月 1–7 日比 9 月 24–30 日访问次数变化的主要原因"，Then：
   - 助手用 SQL 取两期按部门、项目的聚合数据并运行 attribution 脚本；
   - 回答给出贡献最大的 3 个维度值及贡献比例，配图；
   - 两期总数与 SQL 结果一致。
2. Given 选择"异常检测"，When 问"9 月 20 日以来每天访问量有没有异常"，Then 输出异常日期和偏离程度，图上标出异常点；数据点不足以估计季节项时说明所用方法。
3. Given 选择"预测"，When 问"预测未来 7 天访问量"，Then：
   - 数据点足够时给出预测值和区间并配图；
   - 不足 14 个点时不给预测数，并说明需要多少数据。
4. Given 选择"自动"，When 问"9 月 25 日访问量"，Then 只走普通问数，不加载分析技能；回答下方出现三个"继续分析"按钮，点击后进入对应方法的参数确认卡。
5. Given 选择任一分析方法并提问，Then 先出现预填好的参数确认卡；点"开始分析"之前不执行 SQL；点"取消"则按普通问数回答。
6. Given 沙箱不可用，Then 报告位置显示"分析计算暂不可用"，同时给出取数得到的对比数据（来自 SQL），不静默失败。
7. Given 用户对分析类回答点赞，Then 只记录反馈，`recall_queries` 召回不到该回答的 SQL。
8. Given 请求带了不在白名单内的 `analysis` 值，Then 平台拒绝或按"自动"处理，不加载任意技能。
9. Given 同一份 CSV 和参数，When 两次运行同一脚本，Then 输出 JSON 完全一致。
10. Given 用户 A 的分析会话，Then 用户 B 读不到 A 的数据文件和产物。
11. Given 涉及受限事实表且没有给日期，Then 和普通问数一样先问日期，技能不能绕过时间门禁。

12. Given 所选知识库没有时间字段，Then 三个分析方法置灰并提示原因；When 问"10 月各部门访问次数 Top10"（结果没有日期列），Then 不显示"继续分析"按钮。
13. Given 问"最近 10 天每天访问次数"，Then 只显示"为什么变化？"和"有没有异常？"，不显示"未来走势？"（不足 14 个点）。

## 不做的事

- 二期技能先不做：对比检验、驱动因素、用户分群、帕累托、留存、漏斗。
- 不支持用户上传或编辑技能，也不接入外部技能市场。
- 不用 Prophet、深度学习模型，也不做 AutoML 调参。
- 技能不写入语义模型，不生成问答对，不进入建模助手。
- 不做定时巡检式的异常告警（可以留给例行任务另立 spec）。
- 本期不做：自动识别分析意图、管理员预配置归因维度、多步深度研究报告（Genie Agent mode 那一类）。

## 测试要求

- **脚本测试：**
  - 每个脚本配固定 CSV 夹具，校验输出 JSON（贡献度之和约等于 100%、已知异常点能检出、数据点不足时拒绝预测）。
  - 由条件启用的 JUnit 测试调用本机 Python 运行；跳过时在报告中注明。
- `AnalysisSkillMiddleware` 测试：
  - 白名单校验；
  - 注入文本；
  - 选"自动"时不注入。
- 推荐规则测试（`suggestions`，前端 `analysisSuggestions`；项目暂无前端测试框架，以浏览器验收为准）：
  - 单值、明细、无日期列时不推荐；
  - 7 / 14 个点的边界；
  - 按周、按月的阈值；
  - ID 列不被当作指标；
  - 查询失败或结果为空时不推荐。
- 技能挂载测试：问数助手可用技能包含三个分析技能和官方 usage；建模助手不含分析技能。
- `RunPythonTool` 测试：技能脚本上传到会话目录；跨会话隔离。
- 多租户：数据文件和产物跨用户不可见。
- 真实验收：重启后按验收 1–4 实际提问，以 `LLM.log` / `execution-timing.log` 核对工具调用顺序；Docker 不可用时注明未验证。

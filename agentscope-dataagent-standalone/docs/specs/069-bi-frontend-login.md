# spec 069：BI 前端加密免登与同域嵌入

## 背景与目标

2026-10-16 用户确认：BI 前端直接使用共享密钥加密当前用户名，调用 DataAgent 换取固定 30 分钟 JWT；不接 BI 后端或 IM SDK。生产不显示密码登录，本地保留。用户知悉并接受前端密钥可提取、可伪造包括管理员在内的用户名凭据的限制；此方案不是可信 BI 身份证明。

## 方案概述

- POST `/api/auth/bi-login` 接收 `{ticket}`。AES-256-GCM，32 字节 Base64 密钥、随机 12 字节 IV、128 位标签、UTF-8；`v1.<base64url(iv)>.<base64url(ciphertext+tag)>`，无 padding、无 AAD。明文仅 username、issuedAt（毫秒整数）、requestId（UUID）。60 秒有效，未来容差30秒。
- 校验后在元数据表原子消费 requestId，防重复跨重启保留。用户创建与消费使用各自事务：复用已有 userId/角色，未知用户自动创建普通用户，无可用初始密码；并发首次登录复用唯一用户名记录。不扩大知识库授权。中途失败需重新生成ticket，可能已有用户记录但未完成登录。
- JWT 1800 秒固定到期；刷新不续期，已开始 SSE 不中途截断。失效后提示从分析云重新进入。前端 sessionStorage；旧 localStorage 凭据不迁移。BI iframe 就绪握手、同源及窗口校验，每次显式进入更换凭据并整页重载，隔离旧缓存和请求。
- `/api/auth/options` 提供非秘密入口配置。prod 强制关闭密码登录/Java演示种子，prod配置关闭SQL演示初始化；默认开发可密码登录，BI 默认关闭。密钥只在私有配置/BI 端交付，不提交。
- 同域 `/dataagent/`：构建时前端基础路径、Router basename、API/附件路径统一；Nginx 剥离此前缀并配置流式代理。只允许同源 iframe。

## 影响面

后端 AuthController/JwtService/SecurityConfig、新免登服务与JPA消费记录；前端 auth/SessionGate/免登入口/存储读取/URL前缀；新增消费表SQL；README中英文、架构认证和配置章节、对接说明、单机部署与共享记忆。

## 验收标准

1. 已有用户沿用身份和角色；首次并发进入只产生一个普通用户；不接收前端角色。
2. 篡改、过期、未来超限、格式错误和重放均失败；消费记录重启后有效；无凭据日志或URL。
3. prod 密码接口拒绝且无密码表单；dev 密码登录可用；配置/网络失败可重试且不错误展示登录表单。
4. 30分钟刷新不续期；新BI入口切换用户后旧数据组件卸载；401仅清除当前被拒凭据。
5. root和/dataagent/构建均可访问API、资源、深链和流式回答；不改问数/建模逻辑。

## 不做的事

不反向验证 BI、不关联退出/禁用、不实现注销撤销或多副本Agent状态协调；不处理既有验收P1、UI原型和向量性能任务。关页不代表JWT立即撤销。

## 验证要求

协议互通、认证边界、事务并发和前端入口应有可复现验证；真实BI和生产Nginx联调必须独立标明，不能以本地检查替代。关联 ADR0081。

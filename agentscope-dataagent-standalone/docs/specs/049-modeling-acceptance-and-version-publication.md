# spec 049: 业务结果验收与完整版本发布

> 2026-10-09 修订（ADR 0059）：每个保留问题须有效确认是本项目约束，允许用户明确移出暂不处理的问题，保留历史且从下一次发布中剔除实例。查询编辑只修改问题 SQL，旧确认失效，重新验证并确认；不反向修改 Cube、视图或 ref_sql。模型修复单独提出业务变更，经审阅/HITL 写入后重验。首期沿用保守模型指纹使旧凭据失效，自动验证不能代替人工确认，也不能把 SQL 文本相同当作结果正确。

## 背景与目标

业务方案应用后自动执行技术验证，用户集中审阅真实结果并明确发布。解决“执行成功即口径正确”、查询与视图定义不一致、确认后缺少下一步指引的问题。

## 方案概述

- ADR 0058 明确顺序：依赖资产先在候选工程构建、完成必要业务确认并应用草稿，agent 再在完整草稿副本验收；不要求先正式发布。依赖图包含模型、SQL 定义模型、视图、Cube 和查询，按实际拓扑构建；缺失或循环依赖阻塞执行。SQL 定义模型仅采用本机 Wren 验证支持的 SQL/ref_sql 定义方式。
- 所有检查由 agent 调用受控工具自动完成：YAML 校验、context build、dry-plan、Cube 查询编译、真实执行和有界技术修复；用户无需逐项点击启动。失败显示原因与处理进度，不能以批准代替技术验证。
- 每次验收显式绑定 draftRevision/完整工程哈希，执行网关指向草稿副本，模型、视图、Cube、规则及问题查询必须同源。不能在草稿缺依赖时误用 published 同名对象。验收通过只保存确认凭据和待发布示例，不重新创建资产或提前更新 published。

- 校验分为工程结构、Wren 计划/执行、业务确认三层；前两层自动执行并显示失败。查询路径按方案重放：Cube 规格及引擎生成 SQL，或 View/逻辑模型 SQL；禁止以普通 base_object 查询代替 Cube 验收。
- 验收列表逐题展示问题、口径与来源、规则范围、资产、逻辑 SQL、展开依据、真实结果和状态；技术内容可放大。参考答案单独标注为预期，不作为查询结果。
- 每题未执行、待审阅、已确认、退回、失败、过期状态明确。支持逐题确认、勾选批量确认；默认不勾选，批量请求绑定每题 validationId/问题哈希/工程哈希，任一过期则整批拒绝。空结果可确认但需显著提示；失败/截断结果不可确认。修改工程继续保守使全部确认过期，重验后再确认。
- 自动执行结构化口径检查：明确时间边界、过滤适用范围、去重粒度、排名固定 N/包含并列、关联基数及归属策略。可证明的约束用确定性检查；无法证明的风险作为待审阅项，LLM 结论不能充当验证凭据。实际预期比对支持参考值和可配置容差，不能将历史数据数值永久锁定。
- 发布前预检查要求所有未归档问题完成有效确认、方案已应用、工程/资产验证通过、无阻塞冲突；零问题可发布已审阅且校验通过的文档方案。不新增必验分类，移除需求必须用户显式操作。
- “发布并开始问数”在就绪时突出展示；未就绪显示具体问题及跳转。发布生成不可变 version，包含 MDL、规则、有效确认示例及检索索引/词法目录，全部准备成功后原子切换版本指针。索引失败保留旧版本；发布日志与任务状态可恢复。示例使用 Wren 官方知识格式，保留问题/凭据来源。
- 数据更新不自动变成口径变化，但实际问数始终重新查询；回归在固定夹具上校验数值，在真实可变数据上校验结构/约束。

## 影响面

- 后端：MdlPublishService、MdlQuestionStore、ModelingWorkflowService、发布版本与索引管理。
- 前端：ModelingQuestionsPanel、发布面板、modelingQuestions API；确认后显示已保存状态、发布或待办入口。
- 数据/文档：兼容旧凭据与 published；实施同步 ARCHITECTURE_zh.md 的凭据/发布章节。

## 验收标准（Given-When-Then）

1. Given 有效草稿，When 自动验证，Then 返回 Wren 真正结果和查询依据，执行成功仅标记待审阅。
2. Given 三题结果已审阅，When 勾选确认，Then 凭据保存一次且页面显示确认数量与发布入口。
3. Given 任一题失败、截断或凭据过期，When 批量确认/发布，Then 拒绝并定位阻塞问题。
4. Given 旧版本可用，When 新版本索引或发布失败，Then 问数继续使用完整旧版本。
5. Given 固定前十的并列夹具/排除人员夹具/多归属账号夹具，When 验证对应方案，Then 能检出超过十行、漏过滤及不合法归属，修复后通过。
6. Given 其他租户知识库，When 验证、确认或发布，Then 拒绝且凭据/版本不改变。

## 不做的事

不自动确认业务结果、不宣称自然语言与 SQL 等价已被完全证明、不因为三题生成了四个视图就判定完成。

补充验收：Given 已发布 v1 和仅草稿新增的视图/SQL 定义模型/Cube，When agent 自动执行验收，Then 查询成功来自指定草稿、v1 正式问数仍不可见；确认并发布 v2 后资产及示例同时可见。修改依赖使旧凭据失效，构建失败无错误版本切换。

## 测试要求

凭据、批量确认原子性、发布故障及版本切换用例；针对日志缺陷构建确定性夹具；浏览器走完方案应用、真实验证、确认、发布、进入问数。

# spec 071：工具右侧详情栏

状态：已实施并验收，2026-10-19纳入本轮主题提交，尚未部署。

## 背景与目标

沿用已评审的整体HTML原型中的工具详情设计，只改善普通问答点开工具后的右侧内容。
结果、输入和原始字符分开阅读，减少嵌套折叠与Python代码重复，准确区分错误、空数据和缺失回执。

## 方案

- `ToolInspector` 使用“结果 / 输入 / 原始内容”页签、调用标题及状态、放大阅读和关闭。
- SQL展示回执、实际SQL、已返回表格和附件；长表分段展开，不自动查询下一批。
- Python展示标准输出及本次文件，代码放在输入页；汇总产物按调用分组，同名文件不跨调用合并。
- 图表解开JSON字符串后复用ECharts；其他工具按结构/文本展示，保留原始输入与返回供复制。
- 解析只负责展示，不执行工具、不重新查询、不改变权限或SSE。复制/附件失败明确反馈。
- 保持现有侧栏宽度及拖宽逻辑；只给侧栏容器补窄屏覆盖样式。页签支持方向键，Esc及关闭恢复焦点。

## 合同边界

当前payload不含调用耗时、整轮调用列表或可靠的结束标志，因此不补造这些信息。
未收到结果统一显示“结果未确认”；原始内容保留现有字符，不猜测恢复历史中丢失的内容。
保留聊天轨迹、`ToolCallBlock`、建模页面及其他布局，不实施整体原型，不增加重跑按钮和后端接口。

## 验收

1. 真实SQL/Python/图表调用可查看、复制、预览和下载；切换工具后回到结果页。
2. 空表不显示成错误或业务零；明确错误不显示成功；无结果、历史截断和无法解析的文本分别说明。
3. 同名不同调用文件分别保留；表格展开和原文展开只使用本次已有返回。
4. 桌面、390px窄屏、键盘页签、放大/关闭、长内容和下载失败通过浏览器检查。
5. 纯解析回归及前端构建通过，实际截图与既有原型截图比较并记录保留的合同差异。

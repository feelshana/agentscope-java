# spec109：建模对话统一说需求，资产先提议后起草，按官方去处选型

> 状态：已实施（2026-11-03），实施前实测与实施后验收见 [报告](../test-reports/20261103-spec109-pre-tests.md)；验收 10 沿用现有权限校验未单独实测。决策见 [ADR0126](../adr/0126-single-modeling-conversation-and-official-asset-sinks.md)。

## 背景与目标

现在有两个地方可以说需求：建模对话和语义资产页。用户要先判断需求属于哪一类，分错了还要换地方说。同时，"排除测试账号"这类默认过滤被做成加工表（ref_sql），这与官方不一致，也带来了重复逻辑、依赖不实等问题（ADR0126 背景）。

目标：
- 用户只在建模对话里用业务语言说需求；
- 助手按官方去处判断：规则、计算字段、查询模板，或指标（指标暂缓）；
- 影响面大的资产先提议，用户点"起草"才建；
- 语义资产页专注于清单、核查、验证和删除。

受益人是有 MANAGE 权限的数据开发。

## 用户流程

```text
建模对话里说需求
├─ 描述、口径、关系、术语         → 直接写入草稿（不变）
├─ 默认过滤（排除、只保留）       → 写 ## Default filters 规则，不确定时先用确认卡问
├─ 一列的换算或分类              → 确认卡 → 计算字段
└─ 固定拼接、窗口函数、多步计算    → 提议卡：类型、名称、要解决的问题、起草要点
     └─ 用户点"起草" → 页面发起资产轮次 → 起草 + 默认使用规则
          → 语义资产页"待核查" → 核查 → 问题验证 → 草稿栏发布
```

语义资产页的输入框保留，作为快捷方式：内容直接发起资产轮次，结果回到同一个建模对话。

## 方案概述

**1. 提议卡（新工具）**
- 在 `tools/data` 新增 `propose_semantic_asset` 工具，参数如下，名称不能与已有模型或资产重名：
  - `kind`：`view`；`cube` 在 P4 开放前不可用；
  - `name`：建议名称；
  - `need`：要解决的问题，用业务语言写；
  - `outline`：起草要点，例如拼哪些模型、按什么键、输出哪些列；
  - `reason`：为什么不只写规则或计算字段。
- 工具只登记提议，不写任何工程文件，立即返回。
- 在除资产轮次外的所有建模轮次可用，自动建模轮也可用（只提议，不起草）。
- 前端在对话里把这次工具调用渲染成提议卡，带"起草"和"不需要"两个按钮：
  - "起草"：用卡片内容发起资产轮次（`purpose=asset`），请求正文包含 `need` 与 `outline`；
  - "不需要"：只关闭卡片，不发消息。
- 提议卡同时出现在语义资产页的"待处理提议"里，在两处点"起草"效果相同。提议存于工程 `.platform/asset-proposals.json`（Agent 不可写），处理后标为已起草或已忽略。

**2. 选型规则（提示词）**
- `MODELING_SCRIPT` 在资产轮次外的规则从"Cube/View 不读不写"改为"不读不写，需要时调用 `propose_semantic_asset`"。另外加一小段去处判断：默认过滤写规则，单行表达式用计算字段，跨模型拼接、窗口函数、CTE 用提议卡。
- `ModelingTurnRules.ASSET`：
  - 去掉"筛选或排除一张表 → 加工表"；
  - 需求只是默认过滤时，在本轮写 `## Default filters` 规则，回复里说明"这类需求写成规则即可，没有建资产"；
  - 默认过滤一律写在官方 `## Default filters` 小节下，不自建小节（实测中助手写成了"## 测试账号口径"）；
  - 查询模板用逻辑模型名，可以引用已有加工表；保留应用已有默认过滤所需的列（如用户列表的账号列），不用 `IFNULL` 等默认值掩盖空值的含义；窗口函数列在描述中写明统计范围（实测发现问数用"公司 <> '未知公司'"代替账号存在判断，误排除公司为空的账号）；
  - 加工表只在用户明确要求、且 View 无法表达时起草，并在描述中写明原因与实际读取的物理表；
  - 默认使用规则、规则冲突时先问（spec108）保持不变。
- 写入边界不变：`WrenProjectAccess` 仍只在资产轮次开放 `views/`、加工表文件。

**3. 语义资产页**
- 顶部的说明和示例改为两种资产：查询模板、指标（指标标注"即将开放"）。示例按当前模型生成（`AssetExampleService`），不再生成默认过滤类示例。
- "什么需求在这里说"的对照表改为"所有需求都可以在建模对话里说，这里负责核查和验证"，并列出去处判断。
- 新增"待处理提议"列表。
- **删除资产**：查询模板与加工表都可以删除。删除前列出提到该资产的规则条目和依赖它的问答，确认后删除资产文件和对应规则条目，依赖它的问答按 spec108 进入待复核。删除只进草稿，发布后生效。

**4. 上线前必须先做的两项实测**（结果写入验收报告，不通过时回到本 spec 调整）
- **只写规则时，问数能否稳定加上过滤**：只用 `## Default filters`"默认排除用户列表里找不到的账号"，连续问 5 个不提过滤的问题，看是否每次都加上条件；明确要求包含时，是否去掉条件。
- **查询模板在 MySQL 上是否可用**：在查询模板里使用 `DATE_FORMAT`、`IFNULL`、窗口函数，分别执行 dry-run 与问数查询，确认 ADR0042 记录的 DuckDB 函数绑定问题是否仍然存在。

## 验收标准（Given-When-Then）

1. Given 建模对话，When 用户说"统计访问时默认排除用户列表里找不到的账号，我明确说包含时才算"，Then 助手只写 `## Default filters` 规则，不建任何资产。
2. Given 规则已发布，When 问 5 个不提过滤的访问统计问题，Then 每个 SQL 都带排除条件；When 明确要求"包含测试账号"，Then SQL 不带该条件。
3. Given 建模对话，When 用户说"以后按公司、部门分析访问时直接用拼好的结果"，Then 助手调用 `propose_semantic_asset`，对话中出现提议卡，`views/` 下没有新文件。
4. Given 提议卡，When 用户点"起草"，Then 发起资产轮次，起草查询模板（使用逻辑模型名）和 `## Canonical tables` 规则，语义资产页出现该资产，状态为"待核查"。
5. Given 提议卡，When 用户点"不需要"，Then 不发消息、不写文件，语义资产页的提议标为已忽略。
6. Given 普通建模轮次或自动建模轮次，When 助手尝试写 `views/` 或加工表文件，Then 被拒绝（ADR0123 边界不变）。
7. Given 语义资产页输入框，When 用户输入只是默认过滤，Then 本轮写规则并说明没有建资产；When 输入固定拼接需求，Then 直接起草查询模板。
8. Given 已发布加工表与提到它的规则，When 用户在语义资产页删除它，Then 草稿中的资产文件与对应规则条目一起删除，依赖它的问答进入"口径变更待复核"；发布前线上不受影响。
9. Given 查询模板使用 MySQL 函数和窗口函数，When dry-run 与问数查询，Then 都成功；不成功时记录限制，并在资产提示词中写明可用的写法。
10. Given 只有 QUERY 权限的用户，When 调用提议、删除、资产接口，Then 被拒绝，看不到提议内容。

## 不做的事

- 不迁移或自动删除已有加工表。
- 不做建议收件箱的自动发现（从文档、重复 SQL、点踩中识别），另写 spec。
- 不开放指标（Cube），等 spec107 P4。
- 不允许助手在任意轮次直接写资产；不改 ADR0123 的写入边界。
- 不改基础建模的自动流程和官方技能文件。

## 测试要求

- 单元测试：
  - `propose_semantic_asset` 只登记、不写工程文件，名称冲突时拒绝；
  - 各建模轮次的 `views/` 写入权限；
  - 提议的存储、忽略与重复处理；
  - 删除资产时同步规则条目，并让依赖的问答进入待复核；
  - 提示词断言：资产规则中去掉加工表默认选型，资产轮次外的规则改为提议。
- 多租户：QUERY 用户与其他用户看不到提议；删除排队期间被撤销 MANAGE 时拒绝。
- 真实验收：方案第 4 节的两项实测，以及验收 1、3、4、5、8，以重启后的日志为准。
- 全量运行 AGENTS.md 第 8 节验证命令。

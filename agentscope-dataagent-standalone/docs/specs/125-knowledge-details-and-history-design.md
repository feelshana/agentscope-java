# spec 125：知识库详情与用户对话历史设计落地

## 背景与目标

用户于 2026-11-11 明确确认按主界面 HTML 实现知识库详情、空库、数据集详情及用户历史会话，授权包含实际接口适配。以 `docs/design/dataagent-main-screens-20261109.html` 为视觉和交互依据。

## 方案概述

- 复用现有上传、示例导入、关联、权限与建模发布流程；详情采用状态条、合并规模列和分段页签。空库突出拖入文件，关联及示例为次入口。
- 字段接口兼容已有的 displayName。按用户后续要求，详情字段表使用「字段名称 / 原字段名称 / 数据类型 / 业务说明」，此页只显式保存业务说明；原字段名称保留导入表头，不能用 displayName 别名替代。物理名称及类型只读，源资料更新仍要求建模发布，不直接改线上快照。
- 详情、空库和历史页严格沿用已认可 HTML 的字体顺序、字号、按钮和表格尺寸，使用局部样式避免旧 CSS 覆盖。预览表按视口剩余高度延伸，桌面底部约留 56px、窄屏 28px，少量数据不伪造记录。
- 现场反馈补充：知识库说明始终另起一行，建模主按钮移至进度条右侧；数据集技术页左右上下齐平。历史用户候选空输入按活动日期取用户，输入时仍查全量目录。字段说明使用锚定按钮的非模态浮层，数字表头与单元格同向对齐。
- 管理员历史使用独立问题搜索及用户选择器；新增服务端分页、稳定排序、统一筛选统计、分页用户统计与 CSV 导出。问题只搜标题或用户正文，用户需明确选择。
- 在既有 session_message 投影增加角色和用户正文，随消息写入更新；现有历史后台任务分批补齐旧记录，整理期间显式提示。列表不逐会话读取消息或访问引擎日志。

## 影响面

前端：DatasetGroupPage、DatasetDetailPage、AdminConversationHistoryPage 及相关 API/CSS。后端：DatasetService/Controller、会话消息投影和管理员查询。数据：消息表两列及索引的增量迁移。同步架构第 5、7 章；投影取舍见 ADR0143。

## 验收标准

1. 管理者与只读用户看到相应操作；空库三条入口沿用真实导入流程，外部表移除不删除源表。
2. 数据集切换页签保持页头，业务说明编辑可保存/取消，失败保留输入；仅提交字段标识与说明，不改变原字段名称、既有别名或物理类型，预览原始精度保持。
3. 输入问题自动查询，中文组词不触发半成品请求；用户按姓名/账号查找、明确选中或清除，列表用户按钮同步筛选。
4. 列表、摘要、用户统计和导出使用同一筛选；时间范围按会话最后活动时间，提问数只计匹配会话中的 USER 消息。
5. 管理员撤权后旧凭证不能调用新接口；抽屉仍仅展示脱敏的提问和回复，不扩展附件访问。
6. 服务端分页限制单页规模、排序有确定的并列顺序；窄屏、iframe、加载、空态和错误可用。

## 不做的事

不改问数/建模 Agent、自动发布、SQL 口径、角色体系；不将 HTML 示例数据或设计说明入口带入真实产品。不推送或部署。

## 测试要求

真实 HTTP 验证搜索、统计、排序、分页、导出及撤权；字段元数据和权限回归；前端构建、现有测试及浏览器布局/交互检查；执行仓库完整检查并注明条件跳过。

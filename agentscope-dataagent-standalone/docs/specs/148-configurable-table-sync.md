# spec148 · 管理员表同步

状态：首版开发，等待正式环境试运行。支持全量、业务日和业务月。

正式只使用现有 `data_agent_platform` 和 `data_agent`。平台同步元数据表和空目标表由管理员在 BI 数据开发执行 SQL。源数据只读，运行端在任务绑定的目标表执行数据读写，并记录平台同步进度。见 ADR0154。

## 背景与目标

全局管理员在页面配置 MySQL 5.7/8 源表到 `data_agent`（MySQL 8）的单表复制，执行首次导入，启用定时更新，查看进度并补跑。目标表完成首次同步后，可按现有流程关联知识库、建模和发布。

## 方案概述

- **入口** · “更多 → 数据同步”显示任务列表和“新建同步任务”，内设“已有 BI 同步监控”入口，打开现有基础 7 表、扩展 6 表只读页签。原任务、脚本、调度、控制表和后端 API 沿用。
- **新建** · 手工应用 0152 后在页面保存目标连接。填写源连接后选表，确认字段并复制预览的目标 DDL，到 BI 数据开发执行。回到页面核对目标表结构和同步标记，再提交首次同步。任务复用同一个 `data_agent` 实例，可更新目标账号及密码。已确认的列定义变更时停在结构校验阶段。
- **源库只读** · 源连接使用专门的最小权限账号。源码仅发出固定元数据查询和指定表明确列清单的普通 `SELECT`，日期值绑定参数，库表列从已发现的元数据校验并转义。无自由 SQL 输入、锁定读、DML、DDL、写文件查询或存储过程。源与目标使用独立账号和连接，任务只允许独占管理指定的新镜像表。按用户要求凭证直接保存在服务端，接口只返回非密码信息。
- **全量刷新** · 首次对空表写入，刷新时先读取第一批源数据，再在同一事务中删除原范围、分批插入并核验。若结果由非空变为空，保留上一份数据。管理员确认源确实为空后可显式补跑。
- **按业务日** · 管理员选定日期字段。支持 `YYYYMMDD`（整数或文本）、`YYYY-MM-DD`、`YYYY/MM/DD` 和 MySQL 日期、时间类型。11 月 18 日发起回填，截止 11 月 17 日。每日定时逐日刷新前两个完整业务日，例如 11 月 19 日同步 17 日、18 日，范围最早从首次起始日开始。时间列存 UTC 时按东八区换算，再按左闭右开区间查询。
- **按业务月** · 支持月份键 `YYYYMM`（整数或文本）或 `YYYY-MM`，选择月份即可。首次回填仍截止上一个完整业务月。已有每月 1 日同步上月的计划继续运行，管理员也可选择每天逐月刷新上月和当月，当月数据标为「当月累计」。首次回填、立即运行与手动补跑继续按完整月。计划方式保存在任务配置中，沿用现有平台表和时间设置。
- **日期字段无源索引** · 页面允许选择。与有索引时一样，按业务日或月执行各自的有超时流式 SELECT，写完并提交本期后再查询下期。每期最多 10 万条匹配行及 128 MiB 估算写入体积，历史范围的合计行数不设此上限。无索引的日期查询可能逐期扫描源表；匹配条件排除空日期。某期失败时回滚当期，先前提交的期间保留，首次同步可继续未提交的期间。
- **源索引调整** · 源表新增或删除普通索引时，已有任务保持原字段映射与目标表标记。字段定义和主键仍需匹配。源库自行选择执行计划。
- **测试与补跑** · 管理员选日期字段和格式，可试查一个业务日或月。试查复用同步查询条件，最多取三行，仅返回业务日期值和样本行数。页面显示下次计划、历史覆盖与缺口。手动补跑支持一个或一段完整周期，只替换所选周期，保留源数据中的合法重复行。空周期与未覆盖分别显示，已有数据的周期突变为空时保留原数据。
- **执行与观测** · 独立 Python/mysqlclient 进程处理任务，同一目标 MySQL 实例同一时间执行一个任务。按周期流式读取，每批最多 500 行且按估算体积切分。整表、单日或单月为一个事务，最多 10 万行及 128 MiB 估算写入体积。结果和进度同一事务提交，失败一起回滚。长回填按已提交周期恢复，中间可看到已经提交的周期。

## 影响面

- 前端新增管理员任务列表、创建向导与运行详情，嵌入现有 BI 监控入口。后端仅全局管理员可配置、运行和查看，记录操作者和运行结果。
- 控制元数据与源凭证使用平台库。目标同步账号对授权目标表和指定同步元数据表拥有必要的数据读写权限。知识库查询账号仅取得已授权镜像表的读权限。
- 实施后更新架构第 5、12 章与部署手册，另记源／目标权限及执行进程隔离的 ADR。

## 验收标准

1. 使用只读账号连接 MySQL 5.7 后，可选表与确认字段。检查源端实际语句，只有允许的查询。普通用户无法访问同步管理接口。
2. 小表全量成功后数据与行数匹配。源断连、批写失败、结构变化或异常空结果时，正式表仍可读且内容不变。
3. 日表回填至昨天，月表回填至上月。试查可验证指定业务日或业务月。失败的业务周期出现缺口，后续计划照常执行。补跑保留范围外的数据及源端合法重复行。
4. 中断后重启可恢复到确定状态。重跑同一天无重复累计，并发启动同一目标表只能有一次实际写入。执行次数与数据成功覆盖日期分别记录。
5. 旧 6 表和 7 表两个监控页签可查看，原任务按现有方式运行。新任务目标表受现有数据源与知识库授权约束。

## 范围与验证

- 首版采用单库单表映射、全量或按业务日／业务月复制。CDC、数据转换和多表联动留待另行设计。
- 隔离 MySQL 5.7→8 集成验证，覆盖日期与时区边界、重复行、异常空结果、半途失败、重启恢复、目标冲突和权限；模拟含数十万行的回填核对内存与批量耗时。上线前使用一张小表和一张有索引的大表做试运行。

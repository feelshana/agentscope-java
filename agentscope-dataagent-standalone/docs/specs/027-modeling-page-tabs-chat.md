# specs/027 — 语义建模页信息架构重组：完善度标示 + 资产分 tab + 对话建模主入口

日期：2026-10-04 ｜ 状态：已实施（交互形态经用户确认：对话窗=仅居中大窗，drawer 保留为可选）

## 背景

用户诉求：①数据源关联/上传后系统已自动播种基线语义（specs/029），上传文档再增强——界面要标示「语义尚未完善」；②语义建模页按资产分 tab（表/关系/Cube…）；③对话建模入口显著、对话框加大；④建模完成后全部 tab 更新。

**边界（ADR 0018 D10，必须尊重）**：建模是可选增强层——未完善语义的库可以正常问数（直查通道），交互措辞不得暗示「不建模不能问数」。

## 现状

- SemanticModelingPage：单页纵向堆 8 张卡（数据集/关系候选/Cube/视图/文档增强/术语/业务规则/发布），头部有「表单建模/MDL 视图」二分与「对话建模」小按钮（开 ModelingChatPanel 抽屉）。
- 术语按库绑定后（specs/026）术语卡天然归属本页。

## 交互设计

### A. 语义完善度指示器（状态头升级）

状态头新增三档徽章（纯可计算信号，无 LLM）：

| 档位 | 判定（对 overview 一次拉取的数据即可算） |
|---|---|
| 基线 | 确认关系=0 且 Cube=0 且 视图=0 且（规则≤脚手架 且 术语=0） |
| 完善中 | 有部分资产但未达「已完善」 |
| 已完善 | (Cube>0 或 View>0) 且（规则>0 或 术语>0） |

- 徽章 tooltip：「完善度影响问数的口径准确性，不影响能否问数」。
- **非「已完善」时状态头下方显示引导条**：「已可正常问数（基线语义）。上传业务文档或使用对话建模可提升口径准确性 →」引导条右侧按钮：上传文档（滚到文档增强卡）、对话建模（开大窗）。
- 「已完善」不显示引导条。

### B. 资产分 tab

`subView` 的「表单建模/MDL 视图」二分升级为六 tab（纯前端分组，overview 数据不变，后端零改动）：

```
总览 ｜ 表与关系(n) ｜ 指标(n) ｜ 视图(n) ｜ 术语与规则(n) ｜ MDL
```

- **总览**：完善度说明 + 各资产计数一览 + 「对话建模」大按钮 + 文档增强卡（增强是横向动作，放总览）。
- 表与关系：数据集卡 + 关系候选卡（原样搬迁）。
- 指标：Cube 卡。视图：视图卡。术语与规则：术语卡 + 业务规则卡（specs/026 后术语即本库资产）。
- MDL：现「MDL 视图」内容。发布按钮常驻状态头（不分 tab）。
- tab 标题带计数；引导条按钮可跳转对应 tab。

### C. 对话建模升级为主入口 + 大窗

- 头部「对话建模」升级为主按钮样式（da-btn-primary）。
- ModelingChatPanel 加 `variant: 'modal' | 'drawer'`：modal 为居中大窗（约 min(1100px, 86vw) × min(720px, 84vh)，圆角卡片带遮罩），drawer 保留现抽屉。默认 modal。
- 大窗顶部保留「发布需回本页」提示；Esc/遮罩点击关闭。

### D. 建模完成后全 tab 更新

- ModelingChatPanel 在两个时机通知父页：①HITL 确认卡（confirmModeling）成功后立即；②面板关闭时兜底。
- 实现用 `window.dispatchEvent(new CustomEvent('modeling:updated', { detail: { groupId } }))`，SemanticModelingPage 监听后调 `refresh()`（overview 全量刷新 → 所有 tab 数据更新）。解耦、不层层传 callback。
- 刷新不打断用户当前 tab（只更新数据，不重置 activeTab）。

## 验收

- G1：新库（仅 associate 后）进建模页显示「基线」徽章+引导条；文案不含「必须建模才能问数」语义。
- G2：六 tab 计数正确；对话确认一张 HITL 卡后，对应 tab 计数实时 +1。
- G3：对话大窗可开可关，关闭后回到原 tab；drawer 形态仍可用（props 可选）。
- G4：npm run build 绿；手工点检六大 tab 渲染无回归（原有操作流：确认关系/Cube 表单/发布）。

## 不做

- 对话窗常驻分栏钉住（后续可加，本版只做 modal 默认）。
- 完善度评分算法复杂化（固定三档规则）。

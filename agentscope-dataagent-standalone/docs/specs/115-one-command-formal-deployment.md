# spec115：正式环境日常发布一条命令

状态：用户已确认实施；本地代码及隔离验收完成，待66首次现场验收；2026-11-04 Asia/Shanghai。

## 背景与目标

66现有拉源码、构建、预检和正式upgrade已逐段现场通过，但需要人工传递镜像、适配容器Python/Compose，且网络异常依赖助手接续。提供固定入口，让有既有部署权限的同事执行一次命令完成日常应用更新，无需逐阶段人工确认。

## 方案概述

已新增`docker/deploy-formal.sh`，在模块目录执行`bash docker/deploy-formal.sh`：

1. 核对正式目录/项目标记、现行18080服务、源码主线和干净工作区，获得覆盖全流程的发布锁；缺失首次部署配置时停止，不自动初始化。
2. 在子shell内按可配置策略取主线。66默认沿用临时清代理/NO_PROXY=*，支持继承既有代理；短时可达检查、有限次数及单次超时，失败明确是连通性/分支读取/传输阶段，保持旧服务。
3. 复用`update-source.sh`显式获取develop-2.0，仅快进并记录完整目标提交；避免入口脚本在拉取时被改写导致同一次执行混用版本，使用明确版本的阶段入口。
4. 复用`build-from-source.sh`归档同一提交构建，为其提供本次机器可读结果文件机制；从该作业记录核对source/image/imageId及镜像revision，不猜最新镜像或模糊搜索最后一份记录。
5. 自动复用本次已验收的临时容器Python、宿主Compose插件、当前UID/GID/socket组和配置中的模型缓存路径，调用`formal-app.py upgrade`。端口和配置继续来自现行compose.env。
6. 复用现有两库只读/离线向量/兄弟沙箱预检、Compose等待健康、BI入口选项检查及失败恢复；输出提交、镜像、健康、作业日志和阶段结果，不把健康通过宣称为真实问答验收。

入口自身由Git交付。首次需要将此脚本合入主线并同步到66；以后同事无需复制本次临时命令或更改哈希/镜像标签。候选失败自动恢复仍由现有upgrade负责，不另写回退系统。无新提交且运行镜像revision与目标一致、健康正常时明确跳过重复构建/重启。

## 影响面

- 运维：新增入口、对既有更新/构建脚本作最小机器可读输出/网络参数适配，复用正式控制器；支持66 Bash、Git1.8.3.1和宿主无Python3。
- 后端/前端/数据模型：不改；不新增API、平台迁移或权限模型。
- 文档：补日常发布指南及桌面同事版操作说明；ARCHITECTURE第12章同步入口，shared-memory记录真实验证。
- 日志：沿用专属发布目录和受限权限，保存阶段及版本；不打印完整env、凭据或敏感诊断头，不修改永久代理/sudoers。

## 验收标准

1. 现行正式环境可用时，一条命令拉取、构建、预检、升级至同一明确提交；Python/Compose适配无需用户填长命令或镜像名。
2. 脏工作区、错误分支、目录归属不符或并发发布时停止，不覆盖修改；已有业务继续运行。
3. 代理503、直连EOF、超时、Git失败、构建失败或镜像/记录不匹配时停止，日志明确阶段；不拿旧构建冒充本次发布。
4. 预检失败不替换应用；新应用启动失败调用现有恢复，明确区分“已恢复原镜像”和“恢复也失败”。
5. 保留现有数据库、runtime配置、模型主密钥、会话、知识库、文件、旧镜像及每日02:00任务；不触碰同机其他项目。
6. 脚本自身有新版本时阶段版本一致；重复运行且无需更新时不重启；检查最终提交/镜像/healthy/UP与真实阶段一致。

## 明确排除

不做首次安装/切库、自动数据库迁移、人员导入、重配模型、cron安装、资源清理或自动公网模型切换。离线包仅保留为显式人工备用，不作为网络第一次失败的默认分支。本期不新增后台发布服务，执行时保持SSH连接；中断后先按阶段日志核对，不盲目重放升级。

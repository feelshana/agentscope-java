# spec 074：Wren 数据源断连恢复

状态：2026-10-18已实施并完成真实MySQL/Doris、全量回归及分发构建；2026-10-19纳入本轮主题提交，尚未部署。见[验收报告](../test-reports/20261018-wren-connection-recovery.md)。

## 目标与边界

解决外部连接恢复后旧MCP仍持有不可用连接的P1。保留官方Wren技能、CLI、MDL、只读执行、当前发布快照和本轮权限；不重新建模或发布，不增加物理SQL回退，不修改官方安装目录。

## 最小方案

- 在`WrenInstanceRegistry#doCall`识别官方执行错误中明确的MySQL兼容连接故障（2002/2003/2006/2013/2055及对应连接诊断），仅对`run_sql`、`dry_run`、`query_cube`生效；成功内容、SQL/字段/权限等业务错误不触发。
- 在现有每库门锁内失效故障实例，复用原始参数并重新鉴权，至多新建一次并重放一次。两次工具执行共享调用等待预算，子进程初始化仍受现有初始化上限保护。取消/撤权不重试。
- 同库失败恢复后冷却30秒，期间工具发现与调用快速返回暂不可用，不循环重建；成功立即解除。不同知识库并行，元数据发现不额外探测数据库。恢复过程中重新获取当前发布快照，不强制发布或更改版本。
- 原失败不能产生成功回执。第二次失败保留原始诊断并说明恢复状态；关闭失败沿用名额保留及清理重试机制。

## 验收

覆盖断连后恢复、持续断连与冷却后恢复、错误分类、一次重试、撤权/取消、同库并发和异库不受影响、名额回收。以实际官方Wren和可控本地代理分别验证MySQL、Doris；不得中断用户现有连接或修改发布模型。记录未完成或条件跳过项目，不外推生产SLA。

# Spec 063：两类问答召回与问数工具展示

## 背景与目标

用户要求继续完成建模推荐问答和点赞 SQL 问答的召回，并优化问数工具详情。沿用已接受的 ADR 0069/0073 与 spec 058/062，修复现有链路，不引入新的检索服务。最新知识库仅建立 schema 索引，没有通过 memory store 保存建模问答；两个独立来源生成的中文文件名还可能同为 query.md。

## 方案概述

- 建模提示明确按官方技能将已成功验证的推荐问答通过 memory store 保存，经原生写授权后进入草稿；发布后可召回。未回答的问题、诊断 SQL 和仅有 schema 索引不算问答已保存；问题仍可选，用户拒绝写入时如实报告。
- WrenPublishedProject 合并已发布和点赞 Markdown 时保留双方内容，用派生文件名消除冲突；源码、官方技能及 MDL 不变。官方 memory index/recall_queries 继续负责索引与检索，不迁移历史数据。
- AnswerQueryMemory 完善缺失调用关联的兼容及回归，只有本人知识库的成功业务回执可保存；已存在但不匹配的调用不得放行，空候选的历史点赞可显式重试。
- ToolCallBlock/ToolInspector 显示实际官方操作中文名，召回按问题+SQL卡片显示，结果行用表格，模型/Cube定义用结构化字段，保留可展开原始结果。解析失败保留原文，不将所有非 JSON 文本误报为截断。

## 验收

- 同名的建模/点赞样例可同时召回；草稿、其他 owner/group 数据不可见；发布后样例及点赞新增会触发官方索引更新。
- 调用 ID 缺失、重复业务问题、失败/诊断/异租户回执有用例；重复点赞幂等，失败可重试。
- 真实官方 CLI/MCP 在隔离工程验证两类中文问题及 SQL；前端覆盖 JSON 字符串、嵌套对象、空召回、查询行、回执和错误展示。
- 根目录 Maven test/package 与 frontend build；更新架构相关章节和共享记忆，记录在线服务是否加载。

## 授权与范围

按用户本轮“继续进行”执行既有方案的修复与展示优化，不重启用户服务、不操作历史业务问答或发布生产草稿。真实测试使用独立临时工程。

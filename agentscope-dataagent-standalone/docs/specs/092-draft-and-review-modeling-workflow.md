# spec092：建模改为"草稿 + 发布前审阅"，多业务文档，入口与增量建模

> 状态：用户已确认（2026-10-21），第 1–6 节已实施；第 7 节（2026-10-22 交互改版，取代第 4、5 节的页面结构与审阅页）已实施，待真实验收。依据 [ADR0111](../adr/0111-draft-changes-reviewed-before-publish.md)。沿用 [spec091](091-modeling-interaction-flow.md) 的推荐问题、问题直接确认和发布时 dry-plan；取代 spec091 中与确认卡、排队提示相关的交互。

## 背景与目标

2026-10-21 验收与讨论确认：逐项确认卡会阻塞后续请求；文档、确认卡、问题确认分散三处；发布后再上传文档时用户不知道下一步。目标是让用户只理解两个概念：**草稿**（随便改，不影响线上）和**审阅并发布**（看清改了什么再上线），并且任何时候都能在页面顶部看到下一步。

## 方案概述

### 1. 入口：上传数据后自动建模

- 知识库页上传数据或关联表的弹窗增加"业务文档（可选）"，文档在建模开始前就绪。
- 采样完成后跳转到建模页"对话建模"。只有外部数据源事实表需要先配置时间窗口（现有弹窗，增加提示"保存后立即生效，不需要发布"）。
- 配置完成后自动开始基础建模，修改写入草稿。
- 已建过模的知识库再上传或关联新表：同样自动建模，请求中列出本次新增的表，助手只处理这些表，不修改已有内容。

### 2. 修改直接写入草稿（取消确认卡）

- `ModelingHitlMiddleware` 对建模工程文件写入不再暂停等待确认，直接写入；安全校验保持（权限、路径、YAML、models 布局、Cube/View、问答对、平台文件）。
- 每次写入记录：文件、来源、触发用户、时间。来源由本轮请求的用途决定，扩展现有 `ModelingTurnPurpose`：
  - 自动建模、文档更新、用户对话、问题处理。
- 推断约束（代码约束）：来源为"自动建模"且知识库没有业务文档时，拒绝写入 `knowledge/rules/`，提示写入 `knowledge/caveats/`。
- 平台记录正在运行的建模轮次；运行期间发布接口拒绝并提示。

### 3. 业务文档：多份，新增、替换、删除

- 每个知识库可以有多份文档，存放在草稿工程 `raw/docs/<名称>.md`，随发布进入快照；替换时保留历史版本。删除也是一项草稿修改。
- 上传、替换、删除文档后，页面自动发出一条"文档更新"请求（排在当前轮次之后）。助手只读取有变化的文档，对照现有描述、规则和待确认事项更新草稿；删除文档时，把可能来自该文档的内容列入待确认事项。
- 问数不直接读取文档，使用发布后的描述和规则。现有单文档 `raw/business-document.md` 改为多文档目录；按"不考虑历史数据"，不做迁移。

### 4. 页面结构

- 标签页：资料｜对话建模｜审阅与发布｜语义模型（去掉 1/2/3 序号）。
- 顶部常驻：线上版本、助手状态（空闲 / 运行中 / 有请求排队）、主按钮"审阅并发布（N）"，N 为草稿与线上的差异文件数。
- 去掉"开始对话建模"通用按钮和"让助手按新文档更新口径"按钮；对话直接输入。
- 添加问题只保留"审阅与发布"页一个入口；首次建模完成后的问题弹窗保留（spec091）。

### 5. 审阅与发布页

- 检查结果：编译检查、已确认问答的 dry-plan。
- 修改清单：按类型分组（模型、关系、业务规则、待确认事项、业务文档、示例问答），每项显示文件、确定性的差异摘要（修改了哪些列或段落）、来源、作者、时间；点开看差异。
- 单项撤销：把该文件恢复为已发布版本（新增的文件则删除），撤销后自动重新编译检查。
- "放弃全部草稿"：草稿整体恢复为已发布版本。
- 助手修改了用户在对话中写入的内容时，该项标红提示。
- 待确认事项（caveats）单独展示，提示"在对话中确认后，由助手改写为规则"。
- 示例问答：沿用 spec091 的列表与直接确认；确认时的模型指纹与当前不同的已确认问答，标为"口径可能受影响，建议复核"，不阻止发布。
- 发布按钮：助手运行中或编译不通过时不可用，并说明原因；发布包含其他成员的修改时在确认中提示数量。

### 6. 补充（2026-10-21 晚，用户确认）：只问真正需要确认的

- 写入原则：采样和表结构能确定的列含义、文档写清楚的定义/过滤/术语、用户在对话中说明的口径，助手直接写入列描述或业务规则，不向用户确认，只在"本次修改"中展示。
- 只有口径确实有歧义、且不同选择会改变统计结果时，助手用 `request_user_confirmation` 工具提问：每题 2–4 个选项，第一个为推荐，每个选项附写入的规则原文；每轮最多 3 题，同一问题不重复，待确认上限 10。问题保存在工作区 `.platform/confirmations/`，不发布、问数不可见。
- 页面以弹窗逐题展示（参照 Claude Code 提问方式）：选项、"不采用"、"自己写"、"跳过"。确认的答复交还助手（`purpose=confirm`），由助手写入 `knowledge/rules/`（指标定义、默认过滤、术语）或对应模型的列描述（字段含义），问数通过 `get_instructions`、`describe_model` 读取。未确认的问题不生效，也不阻止发布。
- 审阅页：顶部"待你确认 N 项 · 本次修改 M 项"与唯一的"发布"；"需要你确认"区打开弹窗；"本次修改"只展示，可编辑（模型、关系、规则、待确认说明等文本文件）或撤销，不需逐项确认。
- 左侧导航在"业务术语"上方新增"语义建模"入口，列出可管理的知识库及线上版本、待你确认数、草稿修改数、助手状态。
- 修复：文档上传后审阅页立即显示文档修改；助手修改草稿时提示并逐个文件刷新；已在审阅页时顶部不再显示无效按钮。

### 7. 交互改版（2026-10-22，用户确认）：以对话为中心，不再单独审阅

参照编程工具（Copilot/Cursor/Claude Code）与 ChatBI（Genie、Cortex Analyst、Power BI 为 AI 准备数据）：

- **工作台**：标签页"建模对话｜资料｜语义模型"。建模对话页左侧为对话，右侧为"试问"，底部为草稿栏。取消"审阅与发布"标签页、示例问题弹窗与阻断式确认弹窗。
- **AI 建模结果**：每轮结束在该轮回复下方列出本轮写入的内容，按"模型、关系、业务语义、注意事项"分组，逐条显示；可打开查看详情（修改部分高亮，依据为小字），可编辑；关系、业务语义、注意事项可按条删除，模型只能编辑。平台解析模型字段说明、关系条目与 Markdown 条目实现逐条操作；无法拆分的内容按整段显示和编辑。
- **需要你确定的部分**：对话内卡片（非弹窗），内容与操作同第 6 节；确定后助手写入规则或列描述。
- **试问**：推荐 3 个问题，也可自由提问；助手基于草稿生成 SQL 并执行，平台试运行展示结果，二者都过时间门禁。"确认正确"写入草稿 `knowledge/sql/<ID>.md`（source: user-confirmed），发布后可被召回；"不正确，告诉助手"把问题转给左侧对话修正口径。推荐问题在用户打开试问时生成，须简单（单指标、至多一个维度）。
- **草稿栏**：显示草稿修改数、待你确定数、示例数；展开为相对线上版本的全部建模结果与检查结果。发布前自动检查；仍有待确定项时按钮提示"还有 X 项待处理"并可定位，也可跳过未处理项发布。一次发布对应一次完整处理。
- **开始建模前**：采样与时间配置完成后不自动开始，先提示上传业务文档（可选），点"开始自动建模"才开始；上传数据弹窗中的文档字段取消，资料页统一管理文档。
- **页面细化（2026-10-22 下午，用户确认原型）**：页头合并为一行；连续工具步骤完成后折叠为一行；AI 建模结果每项一行（图标、名称、改动标签、依据），展开后模型按"字段｜说明"显示，取值/空值等标注显示为小标签，平台采样固定文字不显示，原内容收在"查看原来"；"需要你确定"逐题显示，最后一题后一起交还；试问为按需打开的右侧栏；草稿栏为一行，"查看全部"向上展开。外部表候选关系由"需要你确定"决定后写入。
- **补充（2026-10-22 傍晚）**：确认完口径后对话末尾给出"下一步"（试问、检查并发布）；对话自动跟随新内容；时间条件写法由平台按列格式给出，不用 LIKE；规则所注依据须可在来源中找到，文档未写的指标口径须提问。
- **日期识别**：采样识别不补零（`2026/10/7 9:05`）、无分隔符（`20261007093000`）的文本日期与数字类型的日期键；未识别出时间列的外部表不列入时间配置。

## 影响面

- 后端：`ModelingHitlMiddleware`（建模写入不再中断）、写入层增加修改记录、`ModelingTurnPurpose` 扩展来源、规则写入约束、运行中轮次登记与发布拒绝、`MdlPublishService`（撤销单项、放弃草稿）、多文档存储与接口、`ModelingWorkflowService`（差异清单含来源与作者、受影响问答）、增量建模请求。
- 前端：`SemanticModelingPage`（标签页、顶部状态、去掉旧按钮与确认卡排队逻辑）、审阅与发布页（新）、资料页多文档、知识库上传弹窗、`ModelingChatPanel`（移除确认卡交互）、`ModelingQuestionsPanel`（受影响标记）。
- 数据：业务文档由单行存储改为多文档；新增修改记录（存放于工程平台目录或数据库，实施时定）。
- 文档：ARCHITECTURE_zh.md 第 14 章与建模相关章节；ADR 索引主线；AGENTS.md 第 5、6 节中"确认卡"相关表述。

## 验收标准

1. Given 新建知识库上传两张外部表并附带业务文档，When 采样完成并配置时间窗口，Then 自动建模全程不出现确认卡，修改出现在审阅页，来源为"自动建模"，文档内容反映在描述和规则中。
2. Given 自动建模且没有业务文档，When 助手尝试写入 `knowledge/rules/`，Then 写入被拒绝，推断内容写入 `knowledge/caveats/`。
3. Given 建模进行中，When 用户上传第二份文档，Then 文档立即成为草稿修改，文档更新请求排在当前轮次后自动执行，顶部显示有请求排队。
4. Given 助手正在运行，When 点"审阅并发布"中的发布，Then 发布不可用并说明原因。
5. Given 审阅页有 5 项修改，When 撤销其中 1 项，Then 该文件恢复为已发布版本，重新编译检查，按钮数字减 1；When "放弃全部草稿"，Then 草稿与线上一致，按钮数字为 0。
6. Given 用户在对话里写入规则后助手又修改了该规则，Then 审阅页该项标红提示。
7. Given 已发布 v1，When 替换业务文档，Then 线上问数仍用 v1；助手更新草稿后发布 v2，问数使用新口径。
8. Given 已发布知识库新增一张表，When 自动建模，Then 只为新表写入描述，已有模型与规则不变。
9. Given 口径修改后，Then 确认时模型指纹不同的已确认问答标为"建议复核"，不阻止发布。
10. Given 两位管理者先后修改草稿，Then 审阅页显示各自作者，发布确认提示包含其他成员的修改。

## 不做的事

- 不提供"停止建模"按钮（框架是否支持中途取消未核实）。
- 不做多草稿分支、不做冲突合并。
- 不做问数反馈列表、不从点踩生成问答。
- 不让问数直接读取业务文档。
- 不预先生成计算字段、视图、ref_sql、Cube；派生资产按问答沉淀另立 spec。
- 不迁移历史单文档与历史确认卡记录。

## 测试要求

- 写入层：建模写入不再中断；安全校验仍拒绝越权、路径逃逸、平台文件、YAML 错误；无文档自动建模拒绝写规则。
- 修改记录：来源、作者、时间正确；单项撤销、放弃草稿后与已发布快照一致；撤销后重新编译。
- 发布：助手运行中拒绝发布；多人修改提示。
- 多文档：新增、替换（保留历史）、删除；只能访问本人有 MANAGE 的知识库（看不到别人的文档）。
- 增量建模：新表请求只包含新表。
- 前端 `npm run build`；按验收标准 1–10 真实走一遍并记录日志。

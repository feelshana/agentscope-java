# spec107：仅放开 MySQL 5.7 数据源接入并实测流程

## 状态与范围

**当前：已撤销并回退（2026-11-02）。** 用户和同事决定上线暂不支持MySQL5.7，恢复仅接受MySQL8.0及以上或Doris的原门禁。ADR0123撤销，ADR0113完整有效。以下为历史方案与验收标准，不能作为当前支持承诺。

2026-11-02，最小范围已实施并实测：只调整数据源管理的连接检测、新建和修改，允许MySQL 5.7接入；不改Wren、SQL转换、建模/问数提示词或其他业务流程。此前完整兼容方案不实施，保留为后续候选。起点develop-2.0@0e9f25ee。

## 背景与目标

用户生产源返回5.7.28-log，连接及认证成功后被8.0最低版本拦截。允许保存5.7连接，然后用隔离真实5.7走创建知识库、关联表、建模、发布与问答，客观判断现有链路能否工作；入口通过不等于全流程兼容。

## 方案

- DataSourceIntrospector识别5.7并放行；8.0及以上/Doris保持，5.6及更早和无法识别版本仍拒绝。
- 保留真实JDBC连接、isValid、版本查询、认证、URL策略、所有权与只读检查。
- 同步门禁测试及文档。无新字段、迁移、配置、前端页面、运行时转换器或提示词变更。
- 隔离H2平台库、独立MySQL 5.7合成业务表与独立应用/工作区；使用当前构建和实际官方Wren，必要时调用配置的真实模型。不得操作生产源或已有本地业务数据。

## 验收标准

1. 5.7.28-log/5.7.44/5.7通过版本测试；8.0+/Doris保持通过；5.6/5.5、未知版本仍拒绝。
2. 实库连接、保存、更新和浏览表字段可用；错误密码和不可达地址仍失败，其他用户不能复用凭据。
3. 使用同一个5.7连接创建知识库、关联表并尝试建模、发布、问答，记录阶段、SQL、返回值及耗时，与人工SQL参考结果对照。
4. 若失败，指出具体阻碍，保留证据，不临时追加兼容改造或物理SQL回退，不把伪造结果当成功。

## 测试与关联

- Java门禁/API/URL策略回归，格式及文档检查；隔离真实HTTP/SSE流程和官方CLI/MCP验证，未验部分明确记录。
- 决策：[ADR0123](../adr/0123-mysql57-connection-admission-only.md)，仅取代ADR0113的最低接入版本；原日期常量与SQL提示保持。
- 已知证据：固定wrenai 0.15.0本机dry_plan对COUNT/SUM自动生成WITH；此项无数据库规划试验不能代替本次实库结论。
- 本次[真实验收](../test-reports/20261102-mysql57-connection-admission.md)：5.7.44连接/关联/基础建模及发布通过；实际问数失败1064，WITH不兼容已用独立SQL对照确认。不是完整查询兼容实现。

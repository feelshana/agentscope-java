# spec123：BI多源六表同步扩展

状态：2026-11-06用户确认六表字段及可扩展要求，授权开始实施；生产执行另行安排。

## 背景与范围
新增页面点击、IAM用户、租户优化、项目容量、大屏对象及大屏访问六张业务表，共77业务列和2个生成主键；明确字段及来源见[资料](../ai/BI_SYNC_EXTENSION_INTAKE_20261106.md)。源只读、目标data_agent，旧七表、控制表、调度和知识库不改。页面逐条保留，不按eid或业务列去重；URL解码；优化容量沿用TRUNCATE(SUM/1072741824,2)，容量沿用原报表聚合及单位，百分比存数值。大屏仅排除两个global配置字段；用户post/OA状态沿用原SQL。

## 实现
- 独立extra_sync.py、代码白名单schema和SQL、私有多源配置及容器/cron入口；复用旧私有配置的easybi源与data_agent目标，不复制凭据到源码。无新应用配置项或前端改动；更新架构12.2、操作指南和业务口径。
- 用户/大屏全量快照；四日期表从2026-01-01起至东八区当天00:00（排他上界），日常默认重刷最近3个完整日，可指定--from/--until/--tables重跑。容量日期按yyyyMMdd等值过滤，空日期不分配到业务日。
- 各次抽取进入私有staging，流式分批、前后计数与目标类型校验；完整后事务替换目标对应全表或一天，并同事务记账/推进进度。生成主键不参与源去重。失败保留旧目标和已完成进度，可重试。
- 记录源可用下界、请求下界、缺失区间与每日结果；Doris实时解析日分区，不硬编码8月8日，缺分区不删除目标历史。优化从源实际首日开始；空监控快照标缺失，不当0或清空已有日数据；状态明确SUCCESS_WITH_GAPS，不能宣称全年完整。
- 新任务独立owner/源指纹/锁/暂停状态，目标未归属同名表拒绝接管；init显式创建，migrate仅代码已声明可空列的加法升级，不自动删列或修改源表。check/status完全只读，verify只读源及业务表并记录私有核对元信息；pause/resume保留数据。
- 交互getpass生成600权限私有配置，错误仅固定阶段/类型/数字码，不输出驱动异常、用户数据或密码。新cron默认02:15、独立标记，需人工完成sync/verify后显式安装；无自动部署/启用。

## 验收
1. 相同/空eid和完全相同点击均保留；同日重跑条数与内容不叠加，长中文URL不截断。
2. 源中断、并发、暂停、错源/目标归属、缺列、计数变化均不暴露空表或不完整日；已提交日可续作。
3. 当前快照移除源已删对象；日期日志已归档历史不随源retention删除；缺失首段/空快照明示，不冒充0。
4. 容量/优化公式与给定SQL对齐，用户JOIN/CASE一致；不加状态、产品、项目或etp筛选；目标字段类型、注释、主键/索引有明确DDL。
5. 隔离MySQL5.7→8集成验证事务、原始重复、断点及旧七表不变；Doris真实查询以用户现场验收为准，替身不冒充实测。

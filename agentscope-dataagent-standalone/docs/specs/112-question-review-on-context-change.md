# spec112：口径变更后问答复核，资产验证通过的问题存为问答

> 状态：已实施（2026-11-03），验收见 [报告](../test-reports/20261103-spec112-acceptance.md)；验收 11 未实测。决策见 [ADR0130](../adr/0130-question-review-on-context-change-and-asset-verified-questions.md)。

## 背景与目标

用户先走普通建模，试问并确认了问答，再在建模对话或语义资产里调整口径（改规则、建加工表或查询模板）。已确认的问答只绑定问题与 SQL，口径变了也保持"已确认"、页面不能修改，发布后作为问数示例把问数带回旧口径（2026-11-03："每天的报表访问次数"建加工表后仍查原表）。资产验证中用户判定"符合预期"的问题却不会成为问答。

目标：
- 只让受改动影响的问答重新复核；
- 待复核的问答不再作为示例误导问数；
- 资产验证确认过的问题可以直接成为问答；
- 建资产时新规则与已有规则冲突要提示。

受益人是有 MANAGE 权限的数据开发。问数用户在发布后得到与新口径一致的示例。

## 用户流程

```text
普通建模 → 试问并确认 → 发布 → 问数
→ 在建模对话或语义资产中调整口径（进入草稿）
→ 试问面板与"问答"页把受影响的问答标为"口径变更待复核"，写明原因
→ 用户逐条处理：仍然正确 / 按新口径让助手重写 / 自己修改 SQL
→ 资产验证判定"符合预期"的问题默认同时存为问答（同名则更新原问答）
→ 草稿栏统一发布；待复核的问答暂不作为问数示例
```

## 方案概述

**1. 确认时记录依赖（后端）**
- `MdlQuestionStore#decide` 在确认时计算依赖快照，写入收据（`.platform` 下，Agent 不可写）：
  - SQL 读到的模型与资产，沿用 `PublishedAssetWindows#names` 的解析；
  - 每个依赖的定义摘要：`models/<名称>/` 下的 `metadata.yml`、`ref_sql.sql`，以及 `views/` 下的定义；
  - 两端任一为依赖的关系；
  - `knowledge/rules/` 中提到任一依赖名称的条目，每条单独摘要；
  - 新建资产的定义里读到了某个依赖时，也记为这个依赖的变化。
- 每一项单独保存摘要，以便比对时说出是哪一项变了。

**2. 待复核状态（后端）**
- `MdlQuestionStore` 列表时，把已确认问答的快照与当前草稿比对。有差异时，状态为 `REVIEW`（口径变更待复核），并附原因列表，例如：
  - "新增规则：统计报表访问……默认使用「报表访问明细_有效账号」"；
  - "加工表「X」的定义已修改"；
  - "关系「A–B」已修改"。
- 历史收据没有快照时，以已发布版本作为基线；从未发布过的知识库没有可比对的基线，保持"已确认"，下次确认时补上快照。
- 状态由比对实时计算，不单独存储，也不改写问题文件。
- `filterPublishedExamples` 只发布 `CONFIRMED`；`REVIEW` 与 `STALE` 一样不作为示例。
- 发布结果和草稿栏列出"N 条问答因口径变更待复核，暂不作为问数示例"，不阻止发布。

**3. 复核操作（前端 `TrialPanel`、问答页）**
- 待复核卡片显示原因，并提供三个按钮：
  - **仍然正确**：调用现有确认接口重新确认，同时刷新快照；
  - **按新口径让助手重写**：沿用今天已加的重写请求，写回后变成"待重新运行"；
  - **自己修改 SQL**。
- 已确认的问答始终保留"修改"入口（2026-11-03 已加）。
- 今天前端按"草稿中有未发布资产"做的临时提示，改为使用后端给出的状态和原因。

**4. 资产验证存为问答**
- 验证判定接口 `POST .../assets/{kind}/{name}/verdict` 增加每题的问题文字、SQL 和 `saveAsQuestion` 三项。
  - 资产核查记录只保存 SQL 摘要，服务端要核对 SQL 摘要与本次运行的一致。
- 判定为"符合预期"且勾选保存的题，经 `MdlQuestionStore` 处理：
  - 新问题：写入 `knowledge/questions/<ID>.yml`，ID 由平台生成，`definition` 写明"使用加工表/查询模板「名称」，资产验证符合预期"；
  - 问题文字与已有问答相同：替换原问答的 SQL；
  - 然后走现有确认链路（时间门禁、只读与笛卡尔积检查、草稿 dry-plan），写入 `knowledge/sql/<ID>.md`，标记来源为资产验证。
- 页面判定区每题增加"同时保存为问答"勾选（默认勾选，仅"符合预期"时可选）。将替换已有问答时，写明被替换的问题。
- 试问面板和问答页对这类问答标注"来自资产验证"，可以移除。

**5. 资产轮次的规则冲突（提示词）**
- `ModelingTurnRules` 的资产规则增加一项要求：写默认使用规则前先读已有规则。新规则与已有规则说法相反时，用 `request_user_confirmation` 让用户选择保留哪一种，不并存两条相反规则，也不改写已有规则。这是官方 enrich-context 的 Lane 2 冲突处理。

## 影响面

- 后端：
  - `MdlQuestionStore`：快照、比对、`REVIEW`、资产验证问题保存；
  - `MdlQuestionService`、`SemanticAssetService#verdict`、`SemanticAssetController`（判定请求体）；
  - `MdlPublishService`：发布结果中的待复核数；
  - `ModelingTurnRules`。
- 前端：
  - `TrialPanel`（待复核卡片）；
  - 问答页（状态与来源标注）；
  - `SemanticAssetsPanel`（判定区勾选）；
  - `DraftBar`（待复核数）；
  - `api/modelingQuestions.ts`、`api/semanticAssets.ts`。
- 数据：不新增数据库表；收据 JSON 增加依赖快照字段，兼容旧收据。
- 文档：
  - ARCHITECTURE_zh.md 第 3.3 节（语义资产）、第 14.2 节（问答确认与发布）；
  - AGENTS.md 第 6 节"问答"一行：增加资产验证来源与待复核；
  - spec111 关联本 spec；ADR 与 spec 索引。

## 验收标准（Given-When-Then）

1. Given 已确认并发布的问答"每天的报表访问次数"查原表，When 在语义资产中建成加工表并写入默认使用规则，Then 该问答在试问面板和问答页显示"口径变更待复核"，原因指出新增的默认使用规则。
2. Given 同上，When 只修改了"用户列表"某列描述，而该问答的 SQL 不读"用户列表"，Then 该问答仍为"已确认"。
3. Given 问答待复核，When 直接发布，Then 发布成功，草稿栏提示 1 条待复核；问数召回不到这条旧 SQL。
4. Given 问答待复核，When 用户点"仍然正确"，Then 状态回到"已确认"，下次发布恢复为示例。
5. Given 问答待复核，When 用户点"按新口径让助手重写"，Then 助手改为查加工表，状态变为"待重新运行"，确认后发布，问数召回新 SQL。
6. Given 问答待复核，When 修改的是它所读加工表的定义（SQL 文本不变），Then 同样标为待复核，原因指出加工表定义已修改。
7. Given 资产验证中某题判定"符合预期"且保持勾选，When 提交判定，Then 问答列表出现该题，状态"已确认"，标注"来自资产验证"；判定为"有问题"的题不保存。
8. Given 资产验证问题与已有问答问题文字相同，When 保存，Then 原问答的 SQL 被替换并重新确认，没有新增重复问答。
9. Given 判定请求中的 SQL 与本次运行的不一致，When 提交，Then 被拒绝，不保存任何问答。
10. Given 历史知识库的收据没有依赖快照，When 打开试问面板，Then 以已发布版本为基线比对，没有变化的问答保持"已确认"。
11. Given 已有规则"按公司统计保留未匹配账号"，When 资产轮次要写"默认排除未匹配账号"的规则，Then 助手先用确认卡请用户选择，不同时写入两条相反规则。
12. Given 只有 QUERY 权限的用户，When 调用问答列表或资产判定接口，Then 被拒绝，看不到草稿问答和依赖原因。

## 不做的事

- 不由 LLM 判断改动是否影响语义，只按依赖比对。
- 不自动重写或撤销问答；不因待复核而阻止发布。
- 不把样本数据变化、事实表时间窗口配置变化视为口径变更。
- 不涉及 Cube（P4 未开放）；问数点赞问答不在建模页复核。
- 不做跨知识库的问答复核。

## 测试要求

- 单元测试：
  - 依赖快照的计算：模型、资产、关系、规则条目；
  - 各类变化触发 `REVIEW` 并给出原因，无关变化不触发；
  - 旧收据的基线；
  - `filterPublishedExamples` 排除 `REVIEW`；
  - 判定接口校验 SQL 摘要、同名替换、只保存"符合预期"的题。
- 多租户：QUERY 用户与其他用户看不到待复核原因与资产验证问题；判定排队期间被撤销 MANAGE 时拒绝保存。
- 真实验收：用 2026-11-03 的知识库场景跑通验收 1、3、5、7、11，并以问数日志确认召回到的是新 SQL。
- 全量运行 AGENTS.md 第 8 节验证命令。

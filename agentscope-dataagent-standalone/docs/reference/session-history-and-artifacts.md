# 会话历史、附件与沙箱生命周期

## 数据存储

- `session_registry` 保留原来的会话身份、路由和引擎上下文路径。
- `session_history` 保存列表需要的标题、最后消息摘要和最后活动时间。
- `session_message` 保存用于页面展示的完整消息、工具输入/输出，按会话和顺序分页。
- `session_artifact` 保存附件身份、所有者、会话、执行批次、原始路径及大小；文件内容保存到 `dataagent.artifacts.directory`。
- Harness 的本地 JSONL 和运行状态继续承担续聊恢复。展示历史被复制到数据库，不改变同事维护的 Wren 推理流程。

新版列表接口为 `GET /api/agents/{agentId}/sessions/inbox-page?limit=20&cursor=...`，返回 `items / nextCursor / hasMore`；旧 `/inbox` 保持数组返回格式。正文分页接口为 `GET /api/agents/{agentId}/sessions/{key}/messages?limit=50&before=...`，返回 `items / nextBefore / hasMore`。

历史列表完全不读文件、不访问 Docker。默认 20 个会话，游标为最后活动时间与会话键；前端下滑加载并按会话键去重。聊天正文默认最近 50 条，向上加载更早消息。兼容的旧详情接口仍返回完整消息。

## 写入与旧数据迁移

启动后后台每批扫描 20 个已登记会话，按本地文件时间和大小判断是否需要补齐数据库。运行中的事件只登记待处理会话，合并后由单独线程刷新；正常回答完成时再刷新一次，避免列表刷新早于历史写入。失败、取消和进程重启通过后台扫描补偿。数据库索引失败会保留本地原件并记录日志，下一批重试。

该机制是“本地引擎日志 + 数据库展示投影”。它不能保存引擎尚未写入日志的 token，也不是跨实例的分布式事件日志。数据库展示消息存在时，本地文件缺失不会清空已保存消息；但继续问答仍需要引擎工作区及上下文。必须一起备份平台数据库、工作区和附件目录。

旧历史标题可能在首次启动后逐批出现；列表请求不会等待迁移。后台仅处理已登记会话，不扫描并复活已删除会话。已删除容器内的旧文件无法恢复。新方案不会把旧沙箱路径冒充永久附件；旧附件只尝试现存容器，缺少容器时返回过期，不创建空容器。

## 附件写入和恢复

每次 Python 调用使用独立 `runs/<UUID>` 目录。Docker 产物使用二进制通道读取并核对字节数，绕过命令输出 512 KiB 截断限制。图片、CSV、文本报告读取后，先写临时文件，再移动到以 UUID 命名的持久文件，最后登记数据库；失败会明确返回保存失败，不生成永久链接。工具结果引用 `/api/artifacts/<id>/content`，页面访问时检查登录用户及所属会话，不需要 Docker。图片预览和下载使用 Authorization 请求头获取 Blob；永久附件接口不再接受 URL 的 token 参数，登录失效、无权限和文件缺失会提示错误。SVG 响应带限制脚本的 CSP。

Wren 查询 CSV 也作为会话输入保存，并提供持久下载链接；查询结束时不再上传沙箱，因此这条文件交接链路不再触发容器创建。只有实际执行 Python 时才自动准备最近 10 个分析输入文件（不是 10 轮对话），总大小预算 100 MiB；恢复前检查当前会话输入目录占用和沙箱剩余空间，并给沙箱保留 32 MiB 余量。旧文件的持久副本不会被删除，暖沙箱中已有旧输入也不会自动清除；空间不够时停止自动恢复更多文件并向模型返回提示。需要重新分析历史产物时，Agent 可调用 `restore_artifact`，用附件 UUID 恢复成当前会话的输入。展示历史不恢复计算环境，也不保证保留 Python 内存变量。

工具完成收集后清理该次临时输出；持久副本不受影响。删除或重置会话同时删除关联附件与展示消息。删除失败留下的孤立附件、文件写入后崩溃留下的无登记文件，由定时任务在一天宽限期后清理。正常附件不自动过期，受用户配额限制。

## 配置与部署

以下是初始保守限制，需按部署机器和数据规模调整：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `dataagent.artifacts.directory` | `./data/artifacts` | 持久目录，必须挂载到应用容器生命周期外 |
| `dataagent.artifacts.max-file-mb` | 20 | 单个附件大小上限 |
| `dataagent.artifacts.user-quota-mb` | 1024 | 每用户持久附件配额，包含分析输入 |
| `dataagent.artifacts.max-session-files` | 100 | 每会话文件数量上限，包含分析输入 |
| `dataagent.sandbox.instance-id` | `standalone` | 同一 Docker 主机上的每个部署必须不同，重启保持稳定 |
| `dataagent.sandbox.max-containers` | 8 | 当前进程管理的容器数量上限；满时拒绝新建 |
| `dataagent.sandbox.memory-mb` | 1024 | 每容器内存上限，禁用额外 swap |
| `dataagent.sandbox.cpus` | 1 | 每容器 CPU 上限 |
| `dataagent.sandbox.workspace-mb` | 512 | `/workspace` 临时文件系统上限，占用也计入容器内存 |
| `dataagent.sandbox.idle-ttl-min` | 15 | 空闲回收时间 |

沙箱镜像根目录只读，`/workspace` 与 64 MiB 的 `/tmp` 使用有大小上限的临时文件系统，Matplotlib 缓存放在 `/tmp`。自定义镜像及脚本必须将可写文件放在这些目录。

沙箱正在执行或保存产物时持有占用凭证，不因空闲时间误删。Python 在容器内部也设置了 120 秒执行时限，避免只终止 Docker 客户端却留下无限运行的脚本。宿主机仍需为 Java、数据库、Wren 和系统预留内存；8 个容器的默认上限不代表任何机器都适合同时运行 8 个容器。

附件默认总配额 10 GiB，磁盘预留空间默认 2 GiB。新增保存会将并发写入预占量计入检查；低空间和总配额耗尽记录告警日志（尚未对接外部告警平台）。存储容量仅覆盖附件，数据库、引擎日志仍需单独管理。用户保存和删除使用 64 个分段锁；全局锁仅保护容量预占检查，不覆盖完整文件写入。后台每分钟最多处理 100 条元数据和 100 个目录项，遇到正在保存的用户跳过并在后续扫描重试；大量历史孤立文件清理可能跨多个周期。配额锁、容器注册表和历史索引器均面向单应用实例。多实例部署需要共享文件存储、数据库级配额协调及统一执行调度，不能直接将本方案当作集群协调机制。

## 升级步骤

1. 备份平台数据库、现有 `.agentscope` 工作区及旧容器中需要保留的输出。
2. 配置绝对附件目录，并确认该目录与工作区均位于持久卷。
3. 开发环境 `ddl-auto=update` 会创建新增表；使用 `validate` 的部署先执行本目录 `migrations/20261008-session-history-artifacts.sql`。
4. 配置本部署唯一且稳定的 `sandbox.instance-id`，检查资源限制与宿主机容量。
5. 重启后等待后台补齐旧会话索引；可查看 `session-history-index` 相关日志。

启动清理只删除同时匹配 `dataagent.managed=true` 和本部署 instance 标签的容器。不要让多个在线实例使用相同标签。旧版无标签容器不会自动删除，必须先导出需要的文件，再由运维明确清理；这些旧容器也不计入新注册表的数量上限。

本次没有启动应用、运行 Docker 场景或执行自动化测试；实际部署前还需结合目标数据库、镜像和存储卷进行运行验证。

### Docker 回收失败时的处理

删除容器后会再次确认容器已不存在，确认前保留容量名额；回收失败会由后台任务重试，避免释放名额后容器实际仍在运行。启动时孤儿清理失败时，历史页面仍可使用，但拒绝创建新沙箱，需要修复 Docker 后重启服务。

## 本轮新增配置

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `DATAAGENT_ARTIFACTS_TOTAL_QUOTA_MB` | 10240 | 全部用户附件合计上限 |
| `DATAAGENT_ARTIFACTS_MIN_FREE_DISK_MB` | 2048 | 保存附件后需保留的磁盘空间 |
| `DATAAGENT_ARTIFACTS_RESTORE_MAX_FILES` | 10 | 自动准备最近的分析输入文件数量 |
| `DATAAGENT_ARTIFACTS_RESTORE_MAX_MB` | 100 | 自动准备文件总量及输入目录恢复预算 |

减少配额不会主动删除现存附件，只会限制后续新增保存。输入恢复失败或达到空间预算时，可在新会话使用 `restore_artifact` 显式恢复所需文件；该工具同样检查恢复空间。上述输入恢复规则不影响永久附件的展示和下载。

## 备份与恢复的含义

备份是把平台数据库、附件目录、引擎工作区额外保存到独立存储，建议使用一致的维护窗口或快照策略。故障后的恢复是将这三部分恢复到匹配的时间点，再确认历史、文件及续聊上下文一致。沙箱仅是可重建的临时执行环境，不需要作为备份主体。本次未执行备份或恢复，也未安装或接入对象存储。

对象存储是通过接口保存、读取文件的独立服务，例如 MinIO、S3 或 OSS。当前使用本地持久目录，单实例部署暂不需要迁移对象存储。

## 历史保留任务

正常会话不会仅因升级而自动删除。可选保留任务默认关闭；启用后按最后活动时间清理完整会话，包括展示消息、引擎历史、会话登记、已读状态和关联附件。当前不支持仅删除附件，以免历史页面留下失效图片和下载链接。

推荐首次配置如下，先观察至少一个调度周期的日志，再将 `DRY_RUN` 改为 `false`：

```text
DATAAGENT_HISTORY_RETENTION_ENABLED=true
DATAAGENT_HISTORY_RETENTION_DAYS=90
DATAAGENT_HISTORY_RETENTION_DRY_RUN=true
DATAAGENT_HISTORY_RETENTION_CRON=0 0 3 * * *
DATAAGENT_HISTORY_RETENTION_ZONE=Asia/Shanghai
DATAAGENT_HISTORY_RETENTION_BATCH_SIZE=50
DATAAGENT_HISTORY_RETENTION_MAX_PER_RUN=500
DATAAGENT_HISTORY_RETENTION_MODE=full-session
```

运行中的会话会跳过，单条失败不影响同批其他会话。试运行中的预计释放空间只统计附件字节。该任务面向单应用实例；多实例部署前必须增加统一任务所有权和分布式会话锁。

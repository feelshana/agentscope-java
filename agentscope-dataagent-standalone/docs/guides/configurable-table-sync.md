# 管理员表同步

## 上线和第一次配置

发布前，由管理员打开 BI 数据开发的新查询，在正式 MySQL 连接执行 [0152](../migrations/0152-table-sync-mysql.sql)。该脚本只在既有 `data_agent_platform` 新增四张同步元数据表。应用部署、启动、保存连接和执行任务均由此读取现有结构。

应用的平台账号对 `dataagent_table_sync_target` 执行 SELECT、INSERT、UPDATE。同步目标账号对平台同步任务、运行、覆盖三表执行 SELECT、INSERT、UPDATE，对指定 `data_agent.sync_*` 目标表执行 SELECT、INSERT、DELETE，两库处于同一目标 MySQL 实例以支持跨库事务。源账号仅授予所选源表 SELECT。

全局管理员进入「更多 → 数据同步 → 新建同步任务」。保存目标连接并填写源库连接，选择源表及范围后点击「生成目标建表 SQL」。在 BI 数据开发审核并执行此 SQL，再回页面核对目标表、提交首次同步。目标表应为空，使用页面生成的同步标记，限该任务写入。目标连接可页面更新，源密码随任务直接保存在平台库，接口只提供连接摘要。

66 的[日常发布](66-daily-release.md)使用既有运行镜像，镜像已有 mysqlclient。正式应用已有的启动约束见[平台数据库初始化](../migrations/README.md)中的 `DATAAGENT_SQL_INIT_MODE=never`、`DATAAGENT_JPA_DDL_AUTO=validate`。旧实验控制库和旧同步表不自动迁移。

## IDEA 本地验证

用原 `dev` 配置启动 `DataAgentApp`。本地平台库名以 JDBC 实际连接为准，本地建表时把 0152 中的正式库名替换为本机平台库名。前端 `http://localhost:5173` 的 `/api` 转发到 `http://localhost:8080`。目标 MySQL 与源库都在本机时，主机可填 `127.0.0.1`，端口填实际监听端口。IDEA 的 Python 需能导入 `MySQLdb`。两条连接默认使用 TLS。

可以先点「连接并读取表」或「测试日期查询」验证源连接。创建任务后才会开始复制源表数据。

## 任务配置与观测

每张源表对应一个任务。可以一次提交多个历史回填任务，或为多张表设置同一计划时间。到点只入队，同一目标实例串行执行，等待中的任务显示「排队中」。耗时长的历史回填会延后它后面的任务。旧七表、六表脚本使用各自的锁，文档计划分别是 02:00、02:15。正式首次回填应核对现场旧脚本是否已完成，并选择低峰窗口。

- 日期试查使用所选日期条件，只返回日期列的最多三条样本，结果显示在按钮旁。试查检查日期字段本身，所选的其他 `TIMESTAMP` 列在核对目标表和正式写入时再校验时区。
- 按日或按月同步逐期流式查询和提交，日期列无索引时每期可能扫描整表。单批最多 500 行且估算体积最多 4 MiB，批间等待 50 毫秒。整表、单个业务日或单个业务月各是一个事务，限制为最多 10 万条匹配行及 128 MiB 估算写入体积。多期合计可以超过 10 万行。超限回滚本期并保留此前已提交的期间。一个目标 MySQL 实例同一时间运行一个同步任务。
- 日表可使用 `20261118`（整数或字符串）、`2026-11-18`、`2026/11/18` 或 MySQL 日期、时间类型。选「按业务日」时回填至昨天，每日计划逐日刷新前两个完整业务日。
- 月表可使用 `202610`（整数或字符串）或 `2026-10`。选「按业务月」时回填至上月，运行计划可选「每月 1 日同步上月」或「每天刷新上月和当月」。后者按月分别写入，页面标示当月累计。已有月计划保持原频率，需在任务详情选择新模式并更新计划。
- 上游为源表增加普通索引后，已有任务可继续运行，查询由源库自行选择执行计划。字段和主键变化仍会触发校验。加索引前先确认源日期列、列类型和已有索引首列。
- 「测试日期查询」用选定字段和格式查一个日期或月份，最多显示三个日期样本。结果为零时，可检查日期是否确有数据及源字段格式。
- 按日或月新建任务时，可选择一个文本或整数源列作为等值筛选。比如取消勾选 `city_name` 后，仍可在「源表筛选字段」选择它并填「全省」。试查、回填和后续运行只读符合该条件的行。用页面预览的 DDL 创建专用空目标表，DDL 只包含勾选的字段。业务日期字段需选入目标。首次同步成功后可启用计划。旧任务没有筛选项时沿用原查询。升级此项功能无需新增平台数据库迁移。
- 补跑替换选定周期。已有数据的周期突然变空时自动保留原数据。管理员确认清空范围后，可勾选接受空结果再补跑。原 6 表和 7 表继续通过「已有 BI 同步监控」查看。
- 滚动计划中某期有原数据却查到零行时，保留该期，并尝试窗口内其余期。运行记录标出受保护的期；下次计划会重新检查仍在窗口内的日期。
- 回退到仍将索引纳入校验的旧版本前，确认源表索引状态和任务建立时匹配。已选择月报每日刷新的任务，回退前在新版页面改回每月计划。
- 回退到未支持源表筛选的版本前，在新版关闭带筛选任务的计划并等待它们结束。旧版无法校验该类任务的配置，恢复新版后再启用计划。

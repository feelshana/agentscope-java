# 《表名》取数口径（业务文档模板）

> 一张表一份文档，可以分多次上传。平台按本文档起草口径清单（spec149），核查后生成查询模板视图和指标 Cube。
> 括号里的“必填/选填”和说明在正式文档里删掉。完整示例见 `E:/总部常规性分析/会员规模-取数口径.md` 对应的写法：平台会原样照抄文档内容，不确定的地方用【】标出，上传前改掉。示例取自咪咕视频多维会员表，按实际业务替换。
> 写文档的原则：只写业务事实和取值，不写 SQL；文档没写的，平台不推断，起草时会标成“待确认”。

适用模型：`hhweb_video_vip_more_dimension_m`

（必填，单独一行，放在文档前 40 行内；平台按这一行把文档关联到表，写在表格里识别不到。一份文档对应多张表时写“适用模型：`表A`、`表B`”。）

## 1. 基本信息（必填）

**业务和统计对象决定问数选哪张表**：问“咪咕视频的会员”查本表，问“咪咕视频的活跃用户”“咪咕音乐的活跃用户”查其他表。每张表都要写，且同一业务在各份文档里写法一致；两张表业务和对象都相同时，写明区别（例如粒度是日还是月）。

| 项目 | 内容 |
|---|---|
| 业务（产品） | 咪咕视频（常见说法：咪咕视频、视频） |
| 统计对象 | 会员（常见说法：会员数、订购用户、付费用户） |
| 这张表回答什么 | 按月统计各类会员的主动订购、新增、净新增、退订人数（预统计值） |
| 适合问的问题 | 某会员口径某月的人数；按月份看趋势；口径之间对比 |
| 不适合问的问题 | 订单明细、金额；跨口径相加的总数 |
| 时间列与格式 | `period_id`，按月，格式 `yyyymm`（如 202610） |
| 一行代表什么 | 一个月 × 一个会员组合 × 一个省份 × 一个渠道 × 一个支付方式的人数 |

## 2. 指标（必填）

每个数值列一行。**“用户常见说法”和“默认指标”一定要写**：用户说“会员数”“用户数”时取哪一列，文档不写，问数时只能反问。

| 列名 | 指标名 | 含义（业务定义） | 用户常见说法 | 默认指标 |
|---|---|---|---|---|
| `cnt_zd` | 主动订购数 | 月末处于主动订购状态的会员人数 | 会员数、用户数、订购用户数 | 是 |
| `cnt_xz` | 新增数 | 当月新订购的会员人数 | 新增会员、新增用户 | |
| `cnt_jxz` | 净新增数 | （写清业务定义，不要让平台推断，例如是否等于新增减退订） | 净增 | |
| `cnt_td` | 退订数 | 当月退订的会员人数 | 退订用户 | |

## 3. 会员口径（必填）

一行一个口径，从左到右的一级至六级对应 `vip_type_1` 至 `vip_type_6`，同一行的条件同时生效。

- **全部**：字段等于库里的字符串“全部”，即该层的汇总行。
- **不限**：该字段不加条件。
- **具体值**：字段等于库里的取值原文，要和库里一个字不差（例如写“足球通会员”，不要写成“足球通”）。
- 一格写了多个值（“A或B”）时，必须在“合并方式”里写明：相加成一个口径，还是拆成两个口径分别查。

| 口径名 | 一级 | 二级 | 三级 | 四级 | 五级 | 六级 | 用户常见说法 | 所属体系 | 合并方式 |
|---|---|---|---|---|---|---|---|---|---|
| 咪咕视频会员总体 | 全部 | 全部 | 全部 | 全部 | 全部 | 全部 | 咪咕视频、咪咕视频会员、全部会员 | 总体 | |
| 视频钻石会员 | 全部 | 标准会员 | 钻石会员或黄金会员 | 全部 | 全部 | 全部 | 钻石会员 | 标准会员 | 相加 / 拆成两个口径（二选一） |
| 体育会员 | 全部 | 不限 | 体育赛事 | 全部 | 全部 | 全部 | 体育 | 体育会员 | |
| 足球通 | 全部 | 不限 | 体育赛事 | 足球 | 足球通 | 足球通会员 | 足球会员 | 体育会员 | |
| …… | | | | | | | | | |

包含关系（选填，便于核查）：例如“体育会员包含足球通、篮球通等单项”。口径之间有包含关系时不能相加，平台会自动拦截。

## 4. 统计范围（有分省、分渠道、分支付数据时必填）

每个范围列一行。**“汇总值”和“没指定时取什么”一定要写**，否则问“10 月足球通人数”时无法确定是取全国还是各省。

| 列名 | 范围名 | 汇总值 | 没指定时取 | 取值写法 |
|---|---|---|---|---|
| `province_name` | 省份 | 全国 | 全国 | 省份简称，如“浙江”“广东”（写清是否带“省”字） |
| `channel_type` | 渠道 | 全部 | 全部 | 渠道1、渠道2……（列出常用值及其业务名称） |
| `pay_type1` | 支付一级 | 全部 | 全部 | |
| `pay_type2` | 支付二级 | 全部 | 全部 | |
| `pay_type3` | 支付三级 | 全部 | 全部 | |

说明：汇总行和明细行同时存在（例如“全国”和各省），不能相加；用户指定了省份或渠道时，用指定的值，不用汇总行替代。

## 5. 读数规则（选填，有特殊约定时写）

- 条件全部确定时，一个口径一个月预期一行，直接读取，不求和、不取最大值。
- 没有匹配的行表示无记录，不等于 0。
- 其他特殊约定（例如某月数据口径调整、某口径从某月起才有数据）。

## 6. 待确认事项（选填）

列出文档作者自己也没确定的地方，平台起草时会原样标成“待确认”，核查前不会发布。

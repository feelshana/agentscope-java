# 生成曜境零售旗舰经营样板

请使用官方GenBI技能和已发布的四表模型生成一张完整、精致、可交互的“曜境零售｜全渠道经营驾驶舱”。这是明确标注的虚构演示数据。不是草图，直接编写可运行页面，生成后verify，等待我预览后再发布。

## 设计目标（请严格落实）

参考企业级Tableau/Sigma经营分析与国内经营驾驶舱的信息层次，避免普通默认蓝色图表堆砌。整页无外部侧栏，没有营销标语和假控件。顶部深海军蓝 #132441 品牌横栏，品牌曜境零售、标题全渠道经营驾驶舱，右侧时间/区域/渠道/刷新；其余画布 #f5f7fa，面板纯白，正文 #172b46，辅助文字 #7f8b9e，青绿 #0b9488 主色，钴蓝 #4c72df 第二色，琥珀 #d99838 仅目标未达。12px圆角、1px淡边、极轻阴影、16~20px间距，中文系统字体。标题22px，KPI主数32px，图表标题15px，表格/控制至少12px。不要过多图标徽章，不用大面积渐变或炫光。金额按万/百万统一可读，数字等宽对齐，鼠标tooltip给出精确人民币元。

初始页面自然展示2026Q3全区域全渠道。四张KPI横排：净销售额（同比）、商品毛利率（同比百分点）、成交订单（同比）、目标达成（实际/目标）；不要把net_profit称为净利润。下方主次分明：左侧宽约2/3“收入趋势”，青绿销售面积线与浅色2025同期虚线对比，支持按周/按月切换；右侧约1/3“渠道结构”环图+三渠道精确金额、份额列表。第二行左右分别“区域经营表现”六区域水平子弹图（实际vs目标，100%刻线、低于目标琥珀）和“商品增长引擎”四品类销售贡献横向条形图，显示毛利率。第三行全宽“门店经营明细”12行表格：门店、区域、净销售、同比、毛利率、目标达成；可排序，可点击门店打开详细信息面板，详细数必须源自查询。页脚演示数据声明及“指标口径”展开说明。主图和表格有适当留白，不需要大段说明占据首屏。

时间下拉必须有2026Q3、2026Q2、2025Q3；区域全部/六区域；渠道全部/三渠道。所有控件有效：切换时刷新全部面板，区域图/表格点击可联动筛选并能清除，排序真实改变行序；空数据有空态、错误不能显示成0。区域筛选后区域图可仅显示当前区域，必须与其余指标一致。门店详情如果无可靠查询可用，宁可只做可排序表格，不做假抽屉。

## 数据、查询和口径

先核对模型名和字段，读取业务文档对应规则，通过官方SQL检查真实数据。模型名保留retail_orders、retail_stores、retail_products、retail_targets；若安装版模型不同，以工具返回为准。订单到门店和商品均多对一；目标只有门店/月/渠道粒度，不要用交易行直接JOIN目标后SUM（会重复）。分别聚合实际和目标，再按同一粒度对齐比较；可以独立查询两套聚合后仅由页面做对齐展示。同比、毛利率和KPI统计用SQL计算，不手写统计值。

默认区间2026-07-01 <= order_date < 2026-10-01，对比2025同区间。选择Q2则2026-04-01至07-01，对比2025同期。成交订单只计net_sales>0；净销售和商品毛利分别SUM(net_sales)、SUM(net_profit)，毛利率为毛利/净销售。目标取相同完整月份、区域、渠道。所有汇总使用相同筛选条件。所有日期上界排他，避免丢失最后一天；源数据日期字段若字符串，用官方支持的DATE_FORMAT/STR_TO_DATE方式，经工具确认，不假定整数时间戳。

每次页面加载/筛选调用 dataagent.query(sql)。桥返回columns为字符串或{name}、rows为位置数组，请正确映射。页面没有MCP收据前缀，直接得到JSON对象。ECharts全局echarts已预载，不加CDN/import/wasm/fetch。各查询最多1000行；使用SQL聚合，让结果远小于1000。并发不超过4，完整刷新尽量5~7条聚合查询并复用结果。请避免任一刷新超过120次请求。防止快速筛选旧请求覆盖新结果，用版本序号丢弃旧刷新结果。resize图表并支持prefers-reduced-motion。

所有图表、数值、排序和详情由真实查询驱动；不能硬编码样例销售/同比/目标/洞察。保留清晰加载和错误提示。日期/区域/渠道可固定列举其取值。页脚固定写“合成演示数据 · 2025.04—2026.09 · 数据与品牌均为虚构”，不要在生成页面里写草稿/尚未发布等发布状态，宿主负责显示状态。

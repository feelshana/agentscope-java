# 合并版本体验指南：电商数据从导入、建模到问答

更新日期：2026-10-10。依据合并提交 `488de6ba` 与 `test_data` 的四个 Excel 文件编写。

本指南中的数值对照由直接读取原始 Excel 计算得到，**不代表已经在应用中跑通**。体验时请逐项核对，尤其是关系、订单去重和业务口径。

## 一、这次重点体验什么

建议按以下顺序走一遍：

1. 新建知识库，一次导入四张表，检查基础模型是否发布成功。
2. 体验数据集描述与字段说明的人工修改。
3. 不填写预设问题，直接通过对话完善 Wren 业务模型，检查并发布。
4. 用固定日期的问题核对单表、跨表、聚合、图表和文件输出。
5. 对正确答案点赞，再用新会话问相似问题；体验历史会话继续提问。

知识图谱、树结构目录目前已隐藏，不需要体验。业务术语、例行任务页面可以观察界面，本指南不把完整定时执行、推送作为本轮验收项。BI 登录、知识库授权和十人并发也不由这次单人体验证明。

## 二、开始前

- 启动最新后端与前端。仅刷新浏览器不能更新后端建模、反馈逻辑。
- 确认当前模型接口可用、应用数据库可连接、Docker 正常运行。
- Wren 使用的是**后端配置的可执行文件**，配置项为 `dataagent.wren.executable`，可由 `DATAAGENT_WREN_EXECUTABLE` 覆盖。
- 当前仓库 `requirements-wren.txt` 固定 `wrenai[memory-onnx]==0.15.0`。之前检查到 PATH 中的安装版是 0.14.0；如果后端仍使用该环境，先同步依赖，尤其再体验点赞记忆功能。

若使用 Python 虚拟环境，请在模块目录用该环境的 Python 安装，而不是随意升级系统 Python：

```powershell
# 把路径替换为后端实际使用的 Wren 虚拟环境
& '你的虚拟环境\Scripts\python.exe' -m pip install -r requirements-wren.txt
```

安装依赖可能需要网络；点赞记忆的 ONNX 模型首次初始化也可能需要下载。环境异常与模型口径错误应分别记录。

## 四、先认识这批数据的口径

订单日期范围为 **2025-01-01 至 2025-09-28**。当前系统日期已经是 2026 年，直接问「今年」「上个月」「最近30天」可能查询不到数据。本轮优先使用固定日期。

### 表关系

```text
客户.customer_id  1 ── N  订单.customer_id
订单.order_id     1 ── N  订单明细.order_id
商品.product_id   1 ── N  订单明细.product_id
```

原始文件中，上述关联没有孤立记录。订单状态为：已完成 927、已取消 101、已发货 218、待发货 165、已退款 89。

本轮统一采用以下**体验口径**：

- 销售额：明细 `amount` 求和，排除订单状态「已取消」。
- 保留「已退款」「待发货」「已发货」以便核对基准；该指标不称为实际到账收入或净收入。
- 订单数：符合过滤条件的订单 `order_id` 去重。
- 平均订单金额：销售额 ÷ 去重订单数，不能直接平均明细金额。
- 销售渠道默认取**订单.channel**；客户.channel 是客户来源渠道，两者不能混用。
- 金额单位：元，显示两位小数。金额不再乘折扣率；全部 4,339 条明细的 amount 均已等于数量乘单价。
- 品类订单数允许重叠：一张订单可以包含多个品类，不能把各品类订单数相加当总订单数。

## 五、直接对话建模，再显式发布

进入知识库的「语义建模」。新版主要步骤是「1 · 数据准备」「2 · 对话建模」「3 · 检查与发布」；「问题验证（可选）」可以暂时不填，模型详情可展开查看表与关系、派生模型、视图、术语与规则、MDL。

在「对话建模」粘贴：

```text
请根据当前知识库中的客户、商品、订单、订单明细四张表完善电商问数模型。

关联关系：客户.customer_id 对应订单.customer_id；订单.order_id 对应订单明细.order_id；商品.product_id 对应订单明细.product_id。

业务口径：
1. 本轮销售额是订单明细.amount求和，仅排除订单.status为已取消的订单；保留已退款、待发货、已发货。它不是实际到账收入。
2. 订单数按order_id去重；平均订单金额=销售额/去重订单数，不能平均明细金额。
3. 销售渠道默认使用订单.channel；客户.channel表示客户来源渠道。
4. 按订单.order_date统计时间；数据范围为2025-01-01至2025-09-28。
5. amount已等于quantity乘unit_price，不要再乘discount_rate。discount_rate是折扣系数，0.9表示九折，值越低折扣力度越大。
6. 品类订单数允许跨品类重叠，不能相加作为整体订单数。

请先审阅已有模型，复用已有合适的资产，提出需要我确认的业务方案，再执行建模与工程检查。暂时不要求我填写预设问题，不要未经确认新增实际到账收入等口径。
```

如果 Agent 给出方案审阅或确认入口，检查关系、过滤条件、时间字段、粒度后再确认。它若提出不一致的规则，先说明修改理由，避免直接回复「全部同意」。

随后可发送：

```text
请检查当前草稿的YAML、编译和查询执行，技术错误自动修复。预设问题验证是可选的。工程检查通过后告诉我待发布变更与发布入口。
```

进入「3 · 检查与发布」，查看预览和「工程校验」，有有效草稿变更时点击「发布」。

**观察点：**

- 零预设问题不应成为发布阻碍，工程检查失败仍应阻止发布。
- Agent 说「完成」不等于已经发布。页面应显示实际已发布版本；没有变更时发布按钮禁用是正常的。
- 草稿变更在发布前不应影响正式问数；发布失败应保留原发布版本。
- 基础模型已有发布版本，不代表自定义业务口径已经全部正确，仍需下面的结果核对。

## 七、正确答案点赞：体验新版查询记忆

1. 对已经与上面数值对照一致的**最终答案**点「正确」。不要为了试功能给错误答案点赞。
2. 查看反馈消息：成功业务查询可保存中文问题—SQL 样例；一轮执行多条成功业务查询时，保存数可能大于 1。
3. 刷新或重新打开会话，观察反馈选择是否恢复。
4. 新建会话，选择同一知识库，问：`按订单渠道统计2025年9月销售额和去重订单数，仅排除已取消。`
5. 结果应重新查询新范围，不能直接复述全日期旧答案。需要确认是否召回，可查看本轮工具过程或日志中的 memory recall，单凭回答更快不能证明召回成功。

**按当前 spec 056：**

- 点赞保存的是合格的成功业务问题—SQL 样例，不是把旧答案作为事实永久复用。
- 没有合格业务查询时，可能只记录反馈，没有样例可保存；失败、诊断类查询不应作为业务样例。
- 重复点赞应避免重复保存；保存失败可按提示再次点击「正确」重试。
- 点「不正确」只记录反馈，**不会撤回此前已保存的点赞样例，也不会自动修复或发布模型**。
- 如果要修正口径，回到对话建模明确修改、检查、发布，再重新问答核对。

## 九、出现异常时怎么定位和记录

| 现象 | 优先查看 |
| --- | --- |
| 文件导入成功但无法问数 | 基础模型发布状态、导入/发布报错，不只看数据集列表 |
| 订单数明显过大 | 是否把明细行数当订单数，是否遗漏 DISTINCT |
| 销售额比对照值偏低 | 是否重复乘折扣，额外排除了退款/未完成，时间范围是否不同 |
| 渠道汇总不同 | 是否误用了客户.channel |
| 点赞记忆失败 | 后端实际 Wren 环境版本、ONNX 初始化、memory store 错误 |
| 知识库列表加载慢 | 浏览器请求「时间」页：排队/Stalled、连接、等待服务器响应分别耗时多少 |
| 文件或图片不出现 | 本轮工具执行、文件是否生成、附件请求状态码、下载是否成功 |

接口慢时记录请求 URL、状态码、等待时间、requestId 与对应时间的后端日志。浏览器 Stalled 20 秒与服务器处理 20 秒不是一回事；Docker 容器数量也不能直接说明慢在哪里。后端 `[page-read]` 慢请求日志可辅助核对。

可复制下面的记录模板，不贴数据库密码或模型密钥：

知识库 / 账号：
发生时间：
步骤 / 原始问题：
期望结果：

## 参考产品与设计判断

参考的是以下官方公开交互说明，未登录或实际体验这些产品，也不据此做“全球最好”的排名。

- [ThoughtSpot Spotter](https://developers.thoughtspot.com/docs/customize-spotter-chat-experience)：对话嵌入、推荐问题与品牌定制。对本项目的启发是 BI 中使用一致的导航与品牌，空页面给少量可执行的业务问题。
- [Hex Chat with App](https://learn.hex.tech/docs/explore-data/chat-with-app)：应用侧栏问答，保留应用上下文，可进入完整 Thread。对本项目的启发是将结果浏览与问答衔接起来，较宽屏幕利用侧栏查看工具或图表详情。
- [Wren AI 产品 UI](https://docs.getwren.ai/oss/overview/how_wrenai_works)：回答、结果预览、图表和追问形成连续工作流。对本项目的启发是结论与数据结果优先呈现，执行详情按需展开。此处仅参考产品交互，不调整 Wren 核心流程。

据此建议：保留浅色中性画布；主色用于主操作和当前选中项；执行过程轻量显示；结论、图表、表格、下载入口有清晰层级；空状态、加载、失败与无权限状态使用统一规则。旧分支的方向适合，但硬编码黑白/紫色应适配当前主题变量。

## 建议实施顺序

1. 对话顶部、内联过程、Markdown 表格/代码块和返回导航：最先实施，收益明显且不依赖业务权限变更。
2. 知识库列表修改名称/说明及更多菜单：独立补齐后端和界面，再验证删除、上传进度与列表刷新。
3. 按真实回答评估图表/表格/附件结果区；验证窄屏、长会话和中断状态后，再考虑卡片化。

UI 验收应至少覆盖：长中文回答、宽表格、长代码、多个附件、失败/停止、历史分页、知识库上传、建模确认、浏览器返回和窄屏布局。当前结论来自 Git 与源代码对比，尚未做两个分支的浏览器逐屏截图比较。

## 当前分支实施记录

- 已将执行过程调整为内联摘要与步骤列表，缩短状态文案；保留失败、手动停止、部分步骤重试及耗时的语义。历史失败或中断记录默认展开。
- 已为 Markdown 表格添加独立滚动容器和表头定位，为代码块设定最大高度；保留当前附件鉴权下载和图片预览实现。
- 已移除聊天顶部的会话 UUID 展示。二级页面统一使用紧凑返回入口；数据集详情返回知识库，避免顶部与内容区重复返回按钮。
- 知识库列表新增“更多操作”菜单和编辑名称/说明表单；后端 `PUT /api/dataset-groups/{id}` 先校验当前用户是创建者，再校验名称、描述及同名冲突。知识库 ID、文件和建模数据不随改名变化；此功能不涉及待办中的多人共享权限。
- 图表、表格与附件结果仍沿用当前输出结构。本轮统一回答正文与可视化、附件面板的纵向间距并提升表格阅读体验；完整结果区卡片化待真实回答样本和窄屏检查后决定。

前端 TypeScript 检查通过；浏览器真实会话和不同屏幕宽度仍需人工验收。当前改动没有对远程提交进行整笔 cherry-pick。

## 后续反馈与定稿

- 侧栏采用微弱灰蓝底色，去掉品牌区和底部用户区横线。用户按钮显示头像与用户名，点击只显示名称；该入口不等于已经实现 BI 单点登录。
- 历史会话只展示问题标题与时间，不展示回答摘要；保留现有分页与批量删除。
- Agent 图标使用渐变紫色，正文加大行距并强化标题层级；工具调用继续采用内联展开结构。
- 用户确定表格填满回答宽度、全部内容居中。少列按等宽布局，多列允许横向滚动；不继续采用数字靠右的自动对齐方案。
- 数据源表单左侧提供当前参数试连，右侧取消和保存；试连不保存数据源，成功后可保存。内网新建源默认不加密，保留可选择的 TLS 模式。
- 正式前端构建已同步到后端静态资源目录。构建报告主包约 4.23 MB（gzip 约 1.31 MB），按需加载图谱和可视化依赖属于后续工程优化。

## 推荐方案

1. 回答末尾：复制、正确、不正确排列在同一条轻工具栏，左侧与回答正文对齐。不常驻“评价回答”、按钮文字和通用说明。桌面图标约18px，32px点击区；手机点击区至少44px。
2. 悬停/键盘聚焦显示有名称的提示；按钮保留aria-label和评价aria-pressed。复制成功原位显示勾号与短时“已复制”，随后恢复；不能把复制动作误当反馈提交。
3. 评价选中紫色，另一项保持中性；提交中禁用评价并保留选择。加载反馈时不常驻“正在处理反馈”一整行。复制按钮不受反馈加载状态影响。
4. 无反馈时不占说明行；有实际保存结果、问题或重试时，在工具栏下显示简洁状态。状态必须按服务端结果表达：反馈失败不能画成功；参考样例保存失败不能被“反馈已记录”掩盖。普通问数正确反馈会保留成功查询参考样例的现有说明移到按需提示；分析回答只记录反馈，不保存样例。
5. 首页/对话输入区都去掉Enter/Shift+Enter常驻提示，只去文案；键盘发送、换行与中文输入法保护不改变。
6. 发送：36px石墨圆形按钮、20px白色向上箭头，取代纸飞机。生成中原位切换12px白色圆角方块，尺寸/位置不跳动，悬停提示“停止生成”。空输入为灰色禁用，键盘聚焦有可见外圈；按钮需要分别有发送/停止可访问名称。
7. 输入区白底细边、圆角16，无常驻紫色光晕；知识库与分析入口仍在左下。生成时这些控件是否禁用沿用真实运行逻辑，不凭图新增行为。

图稿中的外层大框用于分组展示，不要求给回答正文增加卡片。示例文字只用于设计，实际回答不改为固定模板。将来实施应复用现有复制、停止、反馈API及错误恢复逻辑，不能因视觉合并改变业务边界或SSE。

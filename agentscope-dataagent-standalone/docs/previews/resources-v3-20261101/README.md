2026-11-01，状态：**待用户确认**。上一轮更多方案获准实施；上一轮知识库卡片被否决，以本轮提案继续评审，未改正式知识库/数据源页面。

## 依据与边界

- 经用户授权使用独立Playwright浏览器登录本地已启动页面，查看真实知识库、数据源、详情、配置弹窗；未创建/修改数据或凭据，没有手动执行连接检测、导入、问数、发布或模型激活。数据源页面自己会进行已有GET连通检查。
- 实际知识库2个，数据集数量4/5，均无说明；实际数据源5个，4未连通/1已连通（仅本次页面观察）。用于提案的数据源名称和库名已简化为示例，不传播真实连接地址。
- 原始截图仅保留在Git忽略的output/playwright/resource-review-20261101，不把登录信息、Token或连接凭据写入交接文档。
- 前端只正式实施MorePage；本目录是独立静态HTML，无API和数据库连接。所有“检测/保存/删除/提问”等动作仅演示，不能替代真实产品验收。

## 推荐方案

知识库卡片按“标识与权限→名称/说明→数据量与归属→操作”组织。名称不再挤在图标旁；管理者无说明时通过“添加业务说明”进入既有编辑能力。数据集数量、创建者及明确标注的创建日期归为一组；提问为石墨色实心按钮，查看数据为次入口。只读共享卡片隐藏编辑和删除，无数据卡片引导添加数据。实际实施时必须保留现有canQuery/准备状态/删除待完成等边界，不能用数据集数量推断可问数。

数据源列表保留表格，主行高度一致，状态仅显示本次结果；失败原因只在所选行下面按需展开，技术详情继续折叠。查看/检测保留，配置/删除收入更多菜单。新增搜索为本地轻筛选候选，不需新API；不虚构持续监控、检测时间、原生Doris类型、同步或健康评分。

连接弹窗将连接参数与访问凭据分组，在主机旁解释“由应用服务器发起、localhost指服务器自身”；可选数据库与更多连接选项保留。检测通过后才保存的真实规则保持。预览只演示失败，没有连接真实数据库。

# DataAgent 整体 UI 原型 · 2026-10-14

状态：供用户评审的独立 HTML 原型，未替换业务前端。10 月 10 日旧版原型原样保留。

## 打开与体验

打开同目录 [新版原型](dataagent-design-preview-20261014.html)。无需安装依赖、启动后端或联网，所有状态只保留在当前页面内存中，刷新重置。

默认展示对话中的待确认业务方案。建议依次体验：

1. 点击“查看详细变更”，理解业务视图和表关系；技术内容按需展开。
2. 返回消息，点击“确认并写入草稿”。此时问数版本不改变，按钮提示下一步去检查发布。
3. 进入“检查与发布”，运行工程检查；通过后确认发布，再进入问答。
4. 问答选择一个、多个或全部知识库；同会话调整范围。清空后只普通聊天，旧消息仍显示当时选库。
5. 从知识库列表进入详情，查看字段说明、成员授权、上传及关联表；术语按知识库切换。
6. 查看保留的例行任务，体验创建、编辑与配置启停，不模拟调度或邮件送达。
7. 点击顶部“体验说明”，选择首次建模、检查失败、发布失败、问答排队/停止、上传部分成功等状态。
8. 顶部角色预览可切换使用成员、管理成员、全局管理员。这是原型工具，不是生产界面提供的权限切换功能。

原型所有表格、消息、查询结果、文件导入和发布均为演示。不请求真实数据库、模型、上传或授权接口。文件选择只读取文件名；CSV 下载生成带“原型演示”名称的固定示例。账号、知识库、业务数据和已运行的本地服务未因这次原型改造而更改。

## 本次核对依据

在现有 localhost:5173 的已登录 admin 会话中，实际查看了知识库列表、云 MySQL 电商库详情、数据准备、对话建模、检查发布、语义模型、可选问题验证、成员与权限、术语、例行任务列表和创建表单、普通问答及多选弹层、更多菜单。没有向真实库提交建模、发布、上传、删除或授权修改。

同时核对了 `SemanticModelingPage`、`ModelingHitlCard`、当前路由，以及共享权限、上传治理、外部源和并发验收记录。当前应用的建模说明中仍有“问题确认后再发布”等旧提示，与可选验证规则相冲突；本次只在原型中统一文案，不修改业务实现。

## 相比 10 月 10 日，为什么调整

旧原型采用常驻“左侧对话、右侧审阅”的工作台。业务问题、方案和下一步操作被分散到两处，且改变了现有用户熟悉的建模布局。本次把重要操作收回同一条对话，详细信息再展开。

| 设计点 | 本版做法 | 对应现有逻辑 |
| --- | --- | --- |
| 全局结构 | 延续浅灰侧栏、白色内容、紫色主操作；页面只保留一套面包屑 | 现有导航及知识库上下文 |
| 建模主线 | 保留“数据准备 → 对话建模 → 检查与发布”，步骤可自由返回 | 不增加必须按顺序填写的新向导 |
| 对话布局 | 默认单栏消息；方案直接出现在助手消息中 | 延续当前 ModelingChatPanel / HITL 卡片 |
| 方案审阅 | 先展示金额、状态、去重、时间等业务定义，再展开字段、SQL、文件 | 现有提案、关系和文件确认能力 |
| 辅助入口 | 文档、问题收成一行；详情用抽屉或独立页面 | 不常驻第二个审阅工作区 |
| 状态与下一步 | 待确认、已写入草稿、工程检查、发布完成分开 | 写入工作区与正式发布是不同操作 |
| 问题验证 | 保留入口，始终注明可选；旧结果失效后需重验 | 不再把问题确认作为发布门槛 |
| 语义模型 | 基础模型、关系、视图、规则、技术文件分类 | 不恢复知识图谱或树结构目录 |
| 普通问答 | 本轮选库，历史保留范围；多库结果标明来源，不直接混成一张无来源表 | 无库只聊天、全选每轮取最新授权、可同会话切库 |
| 权限 | 使用成员可问答和下载本人结果；管理成员维护库；全局管理员有系统入口 | 不新增角色，不为管理员展示他人私有附件 |
| 上传反馈 | 区分导入失败、数据已保存但模型未就绪、部分成功 | 避免失败后重复上传同一数据 |
| 排队与失败 | 排队可停止；失败有明确状态，不展示伪造结果 | 当前准入、取消与工具错误处理 |
| 例行任务 | 保留入口和配置表单；原型不假装已有真实运行记录 | 用户已确认首发保留，执行器等缺口继续记录 |

## 实施时的边界

这是界面提案，不构成所有后端改造的自动授权。

- 优先映射现有接口和状态，单栏方案卡、抽屉、导航、文案与状态提示可先做。正式实施前再对照接口确认改动范围。
- 不把多个独立工具调用的审批伪装成一个原子操作。已有批量文件提案可以按原有协议整体审阅；分步 HITL 则在同一对话里逐项显示确认状态，不跳过服务端门禁。
- “只使用已发布业务口径”的目标交互，不代表草稿/发布上下文一致性 P1 已修复。普通问答读取草稿的问题仍在待办。
- 已有业务模型后新增/删表的自动发布规则仍未确定，本版没有设计成“修改数据后一定只产生草稿”。数据删除、覆盖上传、多 Sheet 的规则未获确认，原型不执行它们。
- 原型里的上传完成、工程检查和发布结果是状态示意，没有证明后台稳定性、回滚或历史版本恢复能力。
- 业务术语按知识库展示和维护；不能把界面保存提示当作额外的版本发布承诺。
- Doris 文案注明使用 MySQL 协议路径，不表示新增独立 Doris 适配器或支持全部版本和字段。
- 例行任务的调度、投递及任务归属授权仍未补齐；用户决定先保留，不能因此在文档里标为验收完成。
- 更多中的工具/管理仅统一入口示意，现有复杂管理控制台不在本轮逐页重画范围。
- 原型没有 BI 登录联调，不新增注册/同步/角色管理；用户名映射、SQL 管理管理员沿用已讨论方案，可信入口等等待 BI 同事确认。

## 设计系统与视觉核对

- 主色 `#6654ce`，正文 `#252936`，白色内容，浅灰侧栏 `#f5f6fa`，分隔线 `#e7e9f0`。
- 字体使用系统中文无衬线；正文 13–14px、辅助 11–12px、标题 24–25px；按钮明确字号，不使用浏览器默认排版。
- 主导航宽 216px；对话可读宽度 850px，大屏扩至 930px。内容区铺满剩余空间，限制的是阅读列，不是整个应用根容器。
- 方案沿用一张轻边框确认卡；常驻右侧面板移除，避免对话、方案、问题清单三方争抢空间。
- 在低高度笔记本上压缩顶部和输入区，滚动到最近方案；在窄屏上折叠侧栏，保留全部建模步骤和可选验证入口。
- 减少动效、键盘焦点、弹窗 Escape 和焦点循环均有处理。表格横向滚动限制在各自容器，避免撑宽全页。

使用内置 Image Gen 生成单栏建模概念图，再以代码实现所有文字、控件、表格与状态；图片不是页面背景。概念与截图在 `output/ui-preview-20261014/`，仅作为忽略目录中的评审证据，不进入发布包。

概念提示核心：保留现有浅灰侧栏与三个步骤；单列建模对话；消息内业务定义确认卡；技术详情按需展示；固定底部输入；白底和克制紫色，不增加常驻右栏或无关导航。

有意调整：新增原型专用工具条；业务定义补充分析维度；小屏压缩尺寸；工程错误等实际状态补入。它们服务本次交互评审，不是逐像素复制生成图的文字。

## 预览与验证记录

本次浏览器验证只针对独立原型，不把它算作真实业务回归。内置浏览器拒绝 file 协议，因此使用只监听 `127.0.0.1:18764`、只白名单提供原型及说明文件的临时预览服务；HTML 交付仍可由本机浏览器直接打开。

已实际点通：方案确认 → 草稿 → 工程检查 → 发布确认 → 进入问答；无库普通聊天；多选、全选和同会话范围切换；按来源展示演示结果；问答排队停止；工程检查失败返回对话；上传部分成功；知识库搜索；演示成员添加；字段说明；角色入口差异；Doris 协议连接配置；业务文档建议审阅与采纳；问题确认与修改后失效；按库隔离术语；例行任务配置保存；新库选择部分外部表；演示 CSV 实际下载。

### 最终布局检查

- 15 个主要页面分别检查 1280×720、390×844，共 30 个页面/尺寸组合，均未出现整页横向溢出。表格需要时在自己的容器滚动。
- 另在概念原图尺寸 1536×1024 查看建模页；默认笔记本尺寸及窄屏的方案确认按钮也在视口内，确认后的“去检查与发布”仍可见。
- 浏览器控制台未见日志错误。独立 HTML 的内联 JavaScript 语法检查通过；无 fetch 请求，没有运行真实业务测试或修改应用制品。
- 内置浏览器完成验证，未使用 Playwright CLI 作为浏览器替代，也没有通过浏览器读取本机任意文件。
- 评审截图保留在忽略目录：`modeling-final.jpg`、`modeling-1536.jpg`、`modeling-390.jpg`、`detail-390.jpg`、`knowledge.jpg`、`published.jpg`、`assets.jpg`、`tasks.jpg`、`upload-partial.jpg`；尺寸记录在 `responsive-checks.json`。它们是交付评审证据，非临时编译制品。

### 视觉复核与修正

使用 `view_image` 同轮查看生成概念与最终浏览器截图，按以下方面核对。单栏布局、浅色体系、消息内确认与技术详情按需展开沿用概念方向；不宣称原型是对生成图文字的逐像素复制。

| 检查项 | 结果与调整 |
| --- | --- |
| 布局 | 保留左侧导航、三个步骤和单列对话；未引入常驻右侧审阅面板 |
| 业务文案 | 核对确认、草稿、检查、发布的边界；删除“必须确认全部问题才发布”的冲突提示；新增分析维度为有意补充 |
| 字体层级 | 代码明确正文、控件、状态、表格字号；采用适合现有应用的密度，字号较生成概念克制，属于有意差异 |
| 色彩与边界 | 白色内容、浅灰导航、低饱和紫色、细边线；阴影只用于弹窗，不增加渐变背景或装饰插图 |
| 空间与按钮 | 修正 720px 高度下确认按钮被输入区挤出的问题；状态切换后定位到最新方案 |
| 窄屏 | 修正工具栏逐字换行；抽屉底部操作固定在底部；主步骤与可选验证均保留入口 |
| 图标与焦点 | 使用统一描边图标；弹窗背景 inert，Escape、焦点循环与关闭返回焦点可用 |
| 数据呈现 | 修正问题结果类型不对应、已发布页仍显示“等待检查”、部分关联表数量不一致等原型问题 |

首屏主要文案与本版定义一致：语义建模、三个步骤、文档/可选问题、待确认业务定义、确认写入草稿、需要调整、详细变更。额外工具条明确属于原型评审层；不混入实际产品导航。

# 平台配置页面化：后续规划参考

记录日期：2026-10-21。

**状态：用户明确“先不做”，仅保留参考，未排期、未授权开发，也不是上线阻断项。** 以下先后顺序为评估建议，未来需结合使用反馈重新确认。管理员大模型服务属于已单独实现的spec080，不受本页暂缓范围影响；其验证、提交和部署状态以[当前任务](../ai/CURRENT_TASK.md)为准。

## 筛选原则

- 业务管理员需要日常调整、能清晰说明影响范围的使用策略，才考虑放到页面。
- 服务启动、基础设施连接、密钥和部署拓扑仍由外置配置或部署环境管理。
- 页面可查看当前状态，不代表必须允许修改；已有业务管理入口优先复用。
- 页面保存与热生效是不同能力。需核对配置的实际使用路径，不能只保存数值就宣称已生效。

## 可以考虑的候选

| 候选 | 建议顺序与价值 | 实施前提及生效边界 |
| --- | --- | --- |
| 上传限制：单文件/批次大小、文件数、行/列/单元格上限 | 较优先；便于根据实际文件调整接收策略 | 新上传采用一致的策略快照，在途导入沿用原规则；页面上限受部署层请求体、内存/磁盘及解析能力约束，调大数值不代表容量已验收 |
| 文件配额：单文件大小、每用户存储量、每会话文件数 | 较优先；便于管理分析结果与附件占用 | 只影响后续文件接收，不自动删除存量；低于已用量时显示占用及受限原因，最低剩余磁盘等运维保护保留硬上限 |
| 运行状态查看 | 较优先；帮助上线后定位问题 | 复用现有管理页结构并核对接口，展示实际限制、资源占用、依赖健康和配置生效状态；按全局管理员权限脱敏展示，无需修改基础设施连接 |
| 历史保留：保留天数、是否清理、执行时间 | 后续候选；积累真实存储压力后评估 | 涉及完整会话及关联文件删除，先提供候选数量/空间预估与试运行，再明确启用；现有启用条件和定时调度需专门改造 |
| 问答并发、每用户并发、排队人数、等待/执行时限 | 后续候选；便于在已验容量内调整 | 等同事性能分支合并并确认配额；处理降额时的在途/排队请求，不强制中断来凑额度。当前ChatCapacity仅覆盖问答入口，不能标成全平台或全部建模/外部通道的并发上限 |

可选组织方式：全局管理员的“平台设置”先承载上传与文件配额；“运行状态”承载查看与诊断；已实现的“大模型服务”保留独立入口。历史保留和并发控制待实际需要再纳入，不预先开放大批参数。

## 继续保留在配置文件或部署环境中的内容

| 内容 | 原因 |
| --- | --- |
| 平台元数据库、上传存储数据库的连接、账号密码、连接池与DDL/SQL初始化策略 | 决定服务启动与持久化位置，变更涉及迁移、连接池和回退；不等同于用户管理的业务数据源 |
| JWT密钥、BI共享密钥、模型配置加密主密钥、生产认证方式 | 属于认证与密钥管理，需要和运维、备份恢复流程配套 |
| 服务端口、部署前缀、CORS、代理/HTTPS、管理端点暴露范围 | 依赖网关和部署拓扑，页面改值不能同步完成整个部署链路 |
| 持久目录、Wren/Python路径与技能目录、Docker镜像、实例标识 | 与文件布局、依赖安装、资源归属和生命周期相关 |
| Wren/沙箱实例预算、CPU/内存/磁盘、空闲回收等底层参数 | 暂留运维配置，页面可展示；未来若需可写，先设计资源生命周期与配额验证，不直接包装成普通开关 |
| 演示账号开关、底层日志配置 | 继续由部署流程管理，避免混入日常业务设置 |

数据源、知识库权限、业务术语继续使用已有入口。Agent提示词、工具和技能沿用现有管理边界；不得借通用设置页面修改官方Wren技能或扩大权限。

## 将来实施时的检查点

1. 重新确认范围并编写具体spec；本页不是已接受的架构决策或实施授权。
2. 页面与API均校验全局管理员，限定可修改字段、单位、取值及部署硬上限；不做任意application/JSON编辑器。
3. 明确持久化来源、配置文件与页面策略的优先级，显示当前有效值、待生效值和生效范围；保留版本、操作记录及恢复方式。
4. 启动时绑定的字段、构造时创建的队列/信号量、定时任务及缓存不会因数据库保存而自动更新。模型服务的整轮快照只作参考，不能机械复用于所有配置。
5. 验证在途一致性、并发编辑、重启恢复、降低限制后的行为和前后端限制一致性；高负载性能、真实配额及清理预估另行验收。

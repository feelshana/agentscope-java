## 1. 建议与价值

建议探索：聊天输入区增加默认不选中的“深度分析”，开启后交付简短文字摘要和一份可在右侧预览、下载的 HTML 报告。普通问答继续走原入口与默认 Agent；深度分析作为独立、可关闭的能力。

价值来自有目的的探索、可核对的分析和可交付的报告。增加调用次数、堆积分析术语或生成漂亮 HTML，都不能单独保证专业性。目标是让用户得到“发现了什么、证据是什么、还不能断言什么、下一步该做什么”。

## 3. 当前可以复用什么，缺什么

本轮按代码核对，文件存在不等于相应能力已完整启用：

- `DataAgentConfig` 为当前问数配置官方 Wren skills、发布目录中间件和模型代理；`DataToolkitRegistrar#registerDataToolkit` 将 Wren MCP、图表及 Python 工具注册到当前主 Agent。新增 Agent 不会自动获得同样的业务工具与查询范围，必须显式、受权限约束地装配。
- 当前问数的原生文件工具和 shell 工具被禁用。规划、证据文件不能假定可直接通过任意文件工具写入；实施时选择受限的分析工作目录或专用产物接口，不为此开放宿主文件与任意 shell。
- `RunPythonTool` 可以执行计算并将产物交给 `ArtifactStore`。当前收集后缀只包含图片、CSV、TXT、Markdown，**不包含 HTML**；需要明确扩展产物契约，避免将完整报告源码塞入模型上下文和聊天正文。
- `ArtifactStore` 已有持久文件、用户/会话归属与配额；沙箱回收不会自动使已保存附件失效，会话删除/重置会清理附件。报告沿用这个生命周期还是独立保留，需要显式说明，第一版建议沿用会话附件。
- `ArtifactController#content` 当前对非图片按二进制附件下载，并设置严格 CSP；前端 `PythonCodeBlock`/`ToolInspector` 仅有图片预览。**已有通用附件，不等于已有 HTML 预览**。
- 现有 `ChatCapacity`、Wren 门锁/实例预算及沙箱预算是不同层次的限制。独立 Agent 不会自动获得计算资源隔离，也不能声称深度任务绝不影响普通请求的等待时间。

## 4. 分析方法：通用步骤与按需方法库

建议由 AgentScope 原生 Agent 在分析技能指导下推进，而不是在业务层重新写 ReAct 循环或 SQL 路由。通用步骤用于保证完整性，具体方法按问题、字段和数据质量选择。

1. **定义问题与范围**：明确决策目的、已授权选库、对象、指标口径、时间区间、比较基准；关键歧义才询问，次要假设在报告中注明。未选库时不自动查询所有库。
2. **检查可分析性**：通过官方 Wren 了解可用模型/指标，检查数据覆盖、缺失、重复、粒度、更新日期和期末不完整情况。不擅自修改源数据或发布模型。
3. **制定可调整计划**：把业务问题拆成少量可验证子问题，每项说明方法、所需指标/维度、预期证据及停止条件。发现新线索后调整，不预先遍历所有维度组合。
4. **查询、计算与补证据**：只经受当前权限约束的 Wren MCP 查询；Python 对查询结果做计算。先总体、再定位贡献较大的部分，必要时下钻；无价值或无数据的分支及时停止。
5. **复核与质疑**：检查总分一致、分母/去重口径、时间可比、百分比/百分点、单位和图文数字；用可执行计算复核关键结论。另一轮模型自评只能辅助，不能替代验证。
6. **综合与交付**：区分事实、解释假设和行动建议；保留未解决问题及数据限制。用实际证据生成 HTML，给出简短摘要与下载入口。

建议首版方法库：

| 问题类型 | 可用方法 | 必要条件/容易误用之处 |
| --- | --- | --- |
| 经营概览 | 核心指标、趋势、结构/集中度、重点异常 | 根据业务目标选指标，不机械展示所有字段；区分金额、数量和比率 |
| 变化与异常解释 | 可比期间对比、维度增减贡献、业务恒等式拆解、重点分群下钻 | 贡献需包含抵消项并对账；订单数×客单价等公式须匹配口径，交互项需明确分配方法，数值分解不能直接证明因果 |
| 目标与差距 | 目标完成率、缺口、进度对比 | 需要真实目标数据及同口径时间；不能编造目标或将不完整月份直接与整月比较 |
| 客群、漏斗或留存 | 分群、阶段转化、同期群比较 | 需要身份标识、事件/阶段和时间；仅有销售汇总表时不能声称完成留存分析 |

预测、因果推断、复杂优化放在后续专题能力中评估；有足够数据、合适方法及验证结果时才使用。探索大量切片时关注小样本、季节性和偶然异常，不把随机波动写成确定结论。

例如“为什么本月销售下降”：先确认本月覆盖日期与销售口径 → 确认变化幅度 → 核对订单数/客单价等可用因子 → 找地区、渠道、商品的主要正负贡献 → 围绕高影响分组进一步验证 → 对账并列明无法验证的解释。数据只能支持“哪个部分贡献了变化”时，报告不能编造“促销不足”“竞争加剧”等真实原因。

## 5. 证据与报告质量

- 每个关键发现保留证据编号，关联查询/执行记录、指标定义、过滤条件、数据覆盖及计算结果；可追溯不等于要求大模型反复抄写大量原始行。
- 计算用 SQL 结果和 Python，报告中的数值与图表引用同一份已校验结果。总计、排名、比例等做可执行校验，禁止根据漂亮文案重新编造图表数据。
- 一个分析涉及多次查询，不天然具有数据库一致快照。记录各结果时间/覆盖范围；数据期间发生更新导致无法对账时，应说明或重新取数，不能声称完全复现同一时点。
- 查询失败、关键数据缺失或执行预算耗尽时，保留已验证成果并标明“部分完成”；不能把无法获取的证据当成零值或输出假完成报告。
- 建议必须指向具体发现，可提出需要业务人员验证的行动及指标；没有实验/因果证据时不承诺行动能带来多少收益。

## 6. HTML 交付与视觉

建议“统一设计基础 + 灵活章节”：统一字体、间距、配色、图表标签、金额/百分比格式、打印样式，章节由问题决定。默认包含结论摘要、范围与口径、关键指标、图表/发现、建议与局限、证据附录；没有目标或漏斗数据就不输出对应章节。

第一版优先独立 HTML + 内联 CSS + 嵌入的静态图像/受约束 SVG，保证下载后离线查看，不依赖外部 CDN、字体或模型临时 URL。静态报告也可以有清晰的目录、良好的排版和高质量图表；交互图表后续再评估，若增加仍沿用 ECharts。

前端只处理稳定的文件级信息（如 artifactId、标题、完成状态和类型），无需理解每一种分析业务结构。但后端仍需有分析计划、证据和计算结果的内部记录；“交付 HTML”不能等同于“整个系统完全无结构”。

HTML 必须视为不可信内容。预览使用受限 iframe、内容约束与独立 CSP，第一版禁脚本、外联、表单与应用身份访问；不能把任意模型 HTML 直接注入主页面。下载文件同样需剔除脚本与外联，不能只依赖服务器响应头（文件下载后不再有该响应头保护）。报告、正文和查询数据中的文本都需正确转义。

复用现有 ArtifactStore 的持久化、认证下载与配额，补报告类型、预览和可靠保存状态；会话删除后不再提供报告。是否知识库撤权后还允许读取历史导出需要与现有历史策略一起确认，不能把附件 owner 校验描述成已包含库权限复核。

## 7. 可插拔与不改变普通问答

- 产品上是一个按需能力；实现建议独立分析 Agent/调用上下文，复用现有原生运行时，不向普通问答默认提示词或工具目录加入深度分析技能，避免普通请求也自动加载。
- 请求显式选择普通/深度模式，由服务端确定入口；缺省始终普通。独立上下文绑定原对话和选库，不能把深度探索的大量中间步骤混入普通问答记忆。后续普通追问可引用最终摘要，新增查询仍复核当轮范围。
- 新 Agent 显式装配 QUERY 只读的官方 Wren、Python 与报告能力，不继承建模的 MANAGE/发布权，不新增物理 SQL 回退，不修改官方 Wren skills。
- 第一版优先一个分析 Agent + 按需方法技能 + 中间文件/证据 + 可执行验证，不按每个维度启动一个 Agent。确有评测收益后再考虑专门的审阅或并行探索；不让多 Agent 数量成为产品卖点或质量证明。
- 前端控制入口显示，后端另有总开关及必要的灰度用户范围。隐藏按钮只是不再从该界面发起，不能停用直调 API、旧客户端或在途任务；后端关闭时明确拒绝新深度请求，并明确在途任务处置。
- 深度任务需要自己的准入、预算和取消能力：限制并发、查询/数据量、运行时长、模型消耗和报告大小；优先保障普通问答。仍共享的模型服务、Wren、数据库与物理资源可能引起竞争，需要混合负载实测；不能承诺“完全零性能影响”。
- 页面流式展示简短的计划/进度和已验证摘要，不暴露模型隐式思维过程，不展示大段 HTML 源码。普通 SSE 路径保持兼容，新增事件若需要须前后端同步。
- 第一版不增加后台调度平台。长任务可否在刷新/断开后继续、如何恢复结果与取消，要在 spec 中明确验证；不能拿普通会话状态持久化代替长任务恢复能力。

## 8. 建议实施顺序与验收

1. 用户确认试做方向后，先选真实业务数据和少量典型问题，确定评价标准：数字正确、证据可追溯、回答问题、探索有价值、措辞诚实、图表可读、建议具体。
2. 写 spec/ADR 并补一个报告视觉样例；样例明确演示数据，不能作为真实分析能力证据。首版聚焦经营概览与变化分析，设置默认关闭的独立入口和完整的报告保存/预览/下载闭环。
3. 同题对比普通问答与深度报告，用业务人员盲评与可执行数字核验评估增益，同时记录耗时、查询次数、模型消耗和失败率；不能只选择最漂亮的一次演示。
4. 覆盖开关关闭/未选按钮仍走原路、权限与排队撤权、跨用户附件拒读、HTML隔离/离线查看、文件保存失败、超时取消、刷新后的状态、混合负载。存在重大缺口时不启用全量。
5. 首版有稳定收益后再扩充方法和交互。例行任务、自动联网补充行业信息、自动改模型/发布、跨公司/公网自动切换不在首版范围。

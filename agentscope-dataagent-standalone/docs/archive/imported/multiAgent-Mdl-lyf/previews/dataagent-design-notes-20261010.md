# DataAgent 产品界面设计预览

日期：2026-10-10
状态：供评审的 HTML 原型，尚未实施到业务代码。

## 打开方式

使用本机浏览器打开同目录的 `dataagent-design-preview.html`。默认进入语义建模的「待审阅方案」状态。文件无需安装依赖，无需启动后端，不调用数据库、模型或外部服务。

所有数据、AI 回复、检查和发布结果均为设计演示；修改仅保留在页面内存中，刷新恢复。部分边缘操作仅展示表单或提示，不代表后端已有对应能力。

## 本次梳理范围

结合当前代码、建模相关规格和本地已登录的电商场景知识库，查看了数据准备、业务文档、对话建模、待确认方案、语义资产、问题验证、检查发布，以及知识库、数据集、业务术语和例行任务等页面。

当前界面的主要问题：

- 建模入口、说明、问题列表、状态和操作同时占据首屏，主任务不够突出。
- 对话与草稿变更之间缺少清晰对应关系，用户需要自行判断下一步操作。
- 业务含义、工程信息和原始文件混在同一层级，阅读负担较重。
- 个别旧提示仍把问题验证描述为发布前置条件，与当前可选验证流程不一致。
- 资产列表存在数量、实际内容和空状态提示不一致的展示现象，需要在正式改造时同步核查数据映射。

## 设计方向

延续此前认可的知识库第一版：浅灰侧栏、白色内容区、低饱和紫色、细边线、适量留白。通过布局和信息层级形成一致性。

### 全局

- 稳定的侧栏和紧凑的面包屑；建模保留知识库上下文，可折叠侧栏扩大工作空间。
- 页面级主操作、局部操作、辅助操作分级；危险操作收进菜单。
- 统一按钮、搜索框、页签、状态标签、弹窗、空状态和表格。
- 保留创建人、来源、行数、字段数等有助于判断的数据，技术细节按需展开。
- 表格预览保留便于辨读的轻分隔线；问答结果表格延续用户要求的满宽和居中。

### 语义建模

主流程为「数据准备 → 对话建模 → 检查与发布」，问题验证保持可选，语义资产单独查看。

| 页面 | 设计重点 |
| --- | --- |
| 数据准备 | 数据集、业务文档分别成组，补充问题作为可选入口 |
| 对话建模 | 左侧讨论业务，右侧审阅具体变更；明确采纳、退回、写入草稿的边界 |
| 待审阅方案 | 先说明业务视图、规则和影响，再按需展开 SQL 与文件变更 |
| 语义资产 | 基础模型、派生模型、表关系、业务视图、规则、技术文件分组浏览 |
| 问题验证 | 问题列表与查询结果并列；区分执行成功、业务确认、失效和退回 |
| 检查与发布 | 变更摘要、工程检查、发布影响集中展示；当前问数使用哪个版本始终可见 |
| 异常状态 | 给出失败原因、影响范围和修复入口，避免只出现原始错误文本 |

表关系仅指语义模型中的数据表关联，不恢复已暂缓的知识图谱和树结构目录。

业务文档保存与提案采纳保持区分。查询修改后旧确认失效；问题未确认不阻碍发布，工程检查仍必须通过。原型中的发布只改变演示状态。

## 建议体验顺序

1. 默认页面查看右侧方案，点击「采纳并写入草稿」。
2. 进入「检查与发布」，查看变更与检查结果，体验发布确认。
3. 返回对话建模，通过「预览状态」切换首次进入、分析中、待审阅、已采纳、失败和已发布。
4. 打开「查看语义资产」，查看视图详情、表关系和技术文件。
5. 打开「问题验证」，体验确认、退回、修改查询与失效提示。
6. 查看数据准备中的业务文档与文档提案。
7. 用左侧导航查看知识库、数据集、数据源、对话、业务术语和例行任务。
8. 点击右上角说明图标，可以直接跳转到各个预览页面。

## 实施边界

- 本次没有更改前后端业务代码、真实知识库内容或建模任务。
- 原型建议不自动构成新的后端需求；确认设计后，再逐项映射现有接口和权限。
- 业务术语、例行任务中的演示内容只用于呈现有数据时的样式，不能视为后端功能已完成。
- 表模型字段和部分资产结构为演示数据，正式实现须从真实元数据读取。
- 已进行脚本语法检查；当前浏览器工具禁止打开本地文件协议，尚未完成浏览器视觉及交互验收。

## 后续建议

先确认建模主界面的双栏布局、页签组织、方案审阅卡片和发布界面，再统一组件样式，最后逐页落地。正式实现时覆盖空数据、长字段名、超长 SQL、失败重试、无管理权限和较小屏幕等状态。

## 二、整体信息架构

保留熟悉的左侧导航：新建对话、知识库、业务术语、例行任务、更多。更多以当前代码中的工作区为主，不为设计效果新增一组管理产品。

知识库主线：

1. **数据与资料**：确认数据集，查看样本和字段；维护一份当前业务文档；可选填写分析问题。
2. **对话建模**：一个主对话区域；资料、常用问题、SQL 问答对放在顶部轻量工具栏；复杂定义通过抽屉查看。
3. **检查与发布**：草稿差异、工程检查、正式发布。问数继续使用当前正式版本。

“查看语义模型”是浏览与核对入口，避免将模型列表、编辑器、审批表、问题验证同时铺在聊天左右两侧。大屏使用完整可用画布、固定输入区和居中的可读内容列；小屏收起导航、列表按需滚动，弹窗保持在视口内。

## 三、重点页面的变化

### 1. 对话建模

- 默认展示业务需求、助手简要说明、内嵌文件授权卡和输入框。
- 示例批次包括关系、销售明细视图、销售指标 Cube、业务规则四项独立操作。文件内容仅为原型片段，不是可执行工程交付物。
- 主操作为“允许本批写入”；拒绝时可以附反馈。路径或“查看逐项差异”打开抽屉。
- 写入中、部分写入失败、工程检查失败、检查通过、发布失败、发布完成均可从体验说明切换。
- 固定输入框不遮挡操作；低高度浏览器滚动对话内容，移动端文件路径可换行。

### 2. 当前业务文档与可选问题

- 每库一份当前文档，新文档替换原文档，对应 `raw/business-document.md`。
- 保存文档不等于已分析，不自动生成一套文档提案；“交给助手解读”回到建模对话。
- 实际组件 `BusinessDocumentGuide` 使用文件上传；原型用名称与内容输入演示替换语义，不真实解析文件。
- 问题输入沿用 `QuestionIntakeForm` 的规则：每行一个，去重后最多 50 条，每条不超过 1000 字；提交为消息，不是独立问题审核表。
- 不再显示旧原型的“已确认 X/Y 题”发布流程，不将问题输入直接当成 SQL 问答对已保存。

### 3. 语义模型浏览

分类与合并版保持一致：模型与关系、SQL 定义模型、视图、Cube、业务知识与样例、SQL 问答对、MDL 与工程快照。

- 默认看当前草稿，标题提醒正式问数版本。
- 展示名称、业务用途、粒度等摘要；技术定义和路径折叠查看。
- `ref_sql` 与 Cube 是已有官方能力的展示，不新增平台派生 SQL 引擎。
- 表关系展示不称为知识图谱；不恢复旧手工关系阶段工具作为主流程。

### 4. SQL 问答对维护

对应 `SqlQaExamplesPanel`、`SqlQaExampleService` 与现有列表/编辑/删除接口，需要 MANAGE：

| 来源 | 位置 | 修改后的生效方式 |
|---|---|---|
| 建模积累 | `workspace/knowledge/sql/*.md` | 修改草稿，重新检查发布 |
| 回答点赞 | `runtime/liked-examples/knowledge/sql/*.md` | 更新本库点赞资料的官方检索索引，无需 MDL 重新发布 |

- 列表按来源筛选，详情展示问题、SQL 和来源路径。允许不同来源下同名文件，不把 `query.md` 当唯一标识。
- 保留原 SQL，不自动追加 LIMIT；只读查询边界以真实服务为准，原型只做基本输入演示。
- 只使用已有的列表、编辑、删除能力；“让助手积累样例”返回对话，不虚构新增问答对 API。
- 写文件后索引可能失败，错误提示要求刷新核对，不声称保存操作是原子回滚。
- 点赞资料是**本库共享资料**。个人会话、问题反馈记录、附件与工作区结果仍私有。

### 5. 普通问答与反馈

- 不选库：普通聊天，不查数据；单选/多选：本轮授权范围；全选：每次发送重新按最新可用范围解析。
- 同一会话可切换选择，历史上下文保留，新查询只在本轮范围内执行。
- 多库答案标注来源，分别查询，不把多库选择包装成跨库明细 JOIN。
- 每轮显示查询所用发布版本，避免后来发布覆盖历史回答的标记。
- 正确/不正确反馈保持轻量；正确反馈只积累成功且用于答案的业务查询，不保存诊断或失败查询。原型无真实执行凭据，只演示保存结果。
- 未选库的普通聊天反馈可以记录，但没有可保存的业务 SQL。点踩只记录反馈，不自动重写模型，也不删除以前保存的点赞样例。
- 保留排队、执行、停止、失败与重试状态。

### 6. 数据源、样本与字段

- 外部表总行数为未知时显示“未统计”，不能把 1000 条样本显示成表总行数；上传表仍可显示实际导入行数。
- 展示最近成功样本条数/时间和刷新操作；刷新失败保留上次摘要，给出失败提示。
- 样本内观察值不等于完整枚举，不证明唯一性、完整日期边界或准确业务统计。
- 字段类型只读，业务说明可维护；影响正式问数的工程资料仍需发布。
- 数据源维持一个知识库使用文件上传或一个外部连接的首发边界。多个来源通过分库建模、多库问答组合。

**本轮核对：**`9454c1c7` 已补齐 `DatasetSampling`、`DatasetSampleDocuments` 等原缺失文件。本轮更新本地匹配框架依赖后，当前代码可以编译启动；本轮 UI 体验使用上传表，没有把外部采样刷新记为已重验通过。

### 7. 业务术语、权限与例行任务

- 术语表仍可按库查看维护，但主 Agent 的事实源是官方工程文件；术语保存不宣称自动注入已发布口径。
- QUERY 可问答；MANAGE 可维护数据、建模、发布、授权和 SQL 问答对；库 owner 与当前操作者身份不混用。
- 顶部角色选择仅用于设计评审，不是生产切换身份入口。
- 例行任务保留配置页面、创建、编辑与启停演示；当前调度、邮件、全局读取等边界按代码和待办单独处理。
- BI 集成仍待与同事确认，不在本原型虚构一个已经可用的免登录流程。

### 看到的具体展示问题

| 实际观察 | 当前代码原因/入口 | 设计处理 |
|---|---|---|
| SQL 已能显示表格，但输入、结果、SQL、原文叠加多层折叠框，展开输入后结果被推远 | `ToolInspector` 的 Section + `WrenToolResult` 内层 details 和滚动容器 | 分成结果/输入/原始内容页签；默认结果；表格使用右栏完整内容宽度 |
| Python 输入展示 JSON code，结果又重复完整代码；输出与文件在下方不容易找到 | `JsonViewer` + `PythonCodeBlock` 都展示代码 | 结果页默认标准输出、警告、当前调用产物；代码只在输入页展示 |
| 多次 Python 调用有同名产物，汇总列表容易混淆初版与后续生成结果 | `PythonArtifactsView` 聚合与工具调用上下文分离 | 默认按当前调用列文件，标出第几项调用生成；不按文件名覆盖不同版本 |
| `render_chart` 返回字符串包裹的 JSON，右栏显示带引号原文 | `ToolDetail` / `formatResult` 没有统一处理多层字符串对象 | 有界解包 JSON 字符串，识别现有图表回执，用 ChartBlock/ECharts 预览；原始返回保留 |
| 切换同名工具要回到长过程里找；缺少当前库/步骤等持续上下文 | `ToolInspectPayload` 只带当前调用，`ChatPage` 只选 inspectorId | 从当前消息有序工具列表派生同轮导航；显示库与版本、上/下一项和调用选择器 |
| 技能加载返回 Error 但行标签仍为“完成”，整轮后来成功 | `ModelingChatPanel` TaskRow 的完成状态与字符串错误信息分离 | 区分已返回、执行成功、返回错误、运行中、结果未确认；保留失败后的后续调用 |
| 小窗口中右栏挤压主对话，长代码有多层滚动 | 固定侧栏与多层 max-height/overflow | 宽屏停靠并可调宽，窄屏抽屉/手机全屏，提供放大阅读；右栏保持一个主竖向滚动区 |

这些问题本轮只记录与设计，实际业务组件未修复；图表返回类型/最终呈现是否符合用户意图及历史 owner 隔离问题仍不能靠原型宣称解决。

### HTML 里的体验入口

- 原文件新增 `#tools`，顶部预览工具栏提供“工具详情方案”；设计说明页也有入口。它是预览用示例对话，不增加产品主导航菜单。
- “月度订单分析”：按真实第一轮调用顺序组织 12 项示例，默认显示部分关键调用，可以展开全部；右栏打开第 8 项 SQL。
- “交互式图表”：单独演示第二轮图表调用，避免与第一轮 12 步混在一起。
- “建模只读检查”：压缩为 4 项示例，保留失败技能加载、后续官方 CLI、只读文件、validate；不是完整原始执行录像。
- “异常与边界”：独立合成的失败、空表、120 行已截断结果、历史 JSON 截断、执行中、结束无回执、相似问答与普通文本；这些不是本次真实服务都出现过的故障。
- 下载仅导出 HTML 内的演示 CSV/SVG；不会请求真实附件，不触发重跑。正式实现继续调用现有附件下载路径。
- 手机和平板采用抽屉/全屏，关闭后回到原对话；放大阅读与图表预览支持 Escape、焦点恢复，输入/结果/原始内容页签支持左右键。

### 后续实际改造建议（待确认）

2. 不需要为这套布局新增业务路由、SQL 代理或执行 API。接收现有 SSE 与历史记录，再做前端投影。现有 payload 没有可靠的每工具耗时，首版只显示已有的整轮耗时，不伪造每步秒数。
3. 复用 `wrenToolPresentation` 的回执解析思路，限定次数解包 JSON 字符串；结构明确时显示表格/规则/模型/召回卡片。不能全局替换反斜线，不能破坏 SQL 转义，也不能把截断 JSON 补成一个“成功对象”。
4. 图表复用现有 ChartBlock/ECharts；Python 复用 parseResult/artifactSrc/downloadArtifact 并按调用保留文件关联。未知类型直接显示可读文本和原文。
5. 优先使用结构化错误/退出码；资料不足时显示“已返回”或“结果未确认”。空数据、结果上限和历史截断分别提示，不推出业务值为零。
6. 建模授权卡继续放在对话里。详情侧栏只读，不新增另一套业务审阅/确认，也不提供绕开会话权限的“重跑工具”按钮。

# ADR 0085：在平台实例层有界恢复 Wren 数据源连接

日期：2026-10-18

状态：接受（用户已批准）

## 背景

10.17受控代理断连实验中，MySQL新连接已恢复，但原MCP进程继续返回2006；重建实例后恢复100条。安装版官方Wren0.15.0的`Engine#_get_connector`缓存连接器，`MySqlConnector#query/dry_run`复用初始化的MySQLdb连接，断连后该路径没有主动重连。DataAgent原先只因MCP传输异常失效实例，正常返回的数据库错误不会触发失效。

## 决策

1. 在`WrenInstanceRegistry#doCall`统一处理实例恢复。`WrenConnectionFailure#matches`只识别官方错误前缀、当前工具名与明确MySQL兼容断连码及诊断；连接器初始化错误可能没有GENERIC_USER_ERROR包装，两种官方形态都支持。2002/2003/2006/2013/2055之外的未知错误保守返回。
2. 只对现有只读`run_sql/dry_run/query_cube`重放一次。SQL仍由入口只读检查和官方默认不开放写入的MCP约束；参数不改写，不增加领域路由。SQL/字段/账号权限/缺库缺表错误、成功结果中的错误文本不触发重建。
3. 在同库公平门锁内关闭特定旧实例，重新获取当前发布工程；重试前、重新获取实例后重新鉴权，取消不进入重试。两次执行共享原调用等待预算，子进程初始化仍有现有60/90秒上限；不声称全链路严格等于单次工具超时。
4. 恢复失败后按单JVM知识库记录30秒单调时钟冷却，拦截工具发现及调用，防止发现路径绕过冷却启动进程。成功立即解除；冷却结束后由下一请求惰性恢复，不后台轮询、不无限重试。创建/传输异常同样保留冷却。
5. 保留现有实例预算与关闭失败重试。按实例身份移除，避免迟到异常误关替代实例。故障返回不形成成功查询回执；不变更SSE、前端、数据源表或发布版本。

## 取舍与限制

- 正常路径只增加本地状态判断，无数据库心跳。故障请求增加一次进程启动及连接建立；冷却中即便网络先恢复仍最多等待30秒后再问。
- 重试对象是只读查询，不保证数据库层“恰好执行一次”；如果服务器完成读取后回包丢失，读取可能再执行一次。只向调用方返回最终成功的一份结果。
- 错误识别以已验证官方版本及MySQL协议诊断为边界，未知驱动/版本错误不猜测分类。升级Wren后重新验证。
- 不修改官方库、连接器或技能，不重建业务语义，不采用重新发布或重启整个服务作为恢复手段。当前单进程门锁/冷却不是多副本协调。

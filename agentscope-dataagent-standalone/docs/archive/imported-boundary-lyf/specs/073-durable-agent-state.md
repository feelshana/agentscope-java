# spec 073：会话上下文持久化

状态：2026-10-18已实施并完成专项验收，2026-10-19纳入本轮主题提交，尚未部署；见实测报告（来源 `boundary-lyf@b67a179a:docs/test-reports/20261018-durable-agent-state.md`）。

## 背景与目标

用户已确认将当前内存中的会话状态存入项目MySQL元数据库，以支持重启后继续历史会话追问。保留现有展示历史和用户/会话隔离，复用框架状态存储，不调整业务模型、问数规则或Wren主链。

## 方案概述

- 默认提供框架`MysqlAgentStateStore`，使用平台DataSource当前数据库、新表`dataagent_agent_state`；`agent_state`每会话保留最新JSON快照，版本校验由框架负责。
- 开发`ddl-auto=update/create/create-drop`初始化兼容表；生产`validate/none`提前执行迁移，缺表/列或不安全的命名空间排序规则启动失败，不静默降为内存。H2开发使用框架JSON文件存储；显式自定义`AgentStateStore`优先。
- `DataAgentConfig#builderBootstrap`要求持久存储；框架按本轮用户/session读取保存。`SessionAgentManager#resetSession/removeSession`在移除旧会话标识前清理状态，失败保留登记以便重试；API和自动保留策略共用。
- 不将旧展示历史全量拼入提示词。上线前已经遗失的状态不自动重建；新保存状态跨重启恢复，当前授权与本轮选库仍重新校验。

## 影响面

后端装配、Maven MySQL扩展依赖、状态表初始化/迁移、会话清理。无前端/SSE变更。同步ARCHITECTURE第2/7/12章、README、发布手册、上线总账和共享记忆；ADR0084记录存储取舍。

## 验收标准

1. MySQL真实问答结束后保存快照，重启同一隔离服务后原会话可理解先前约定；新会话及其他用户不能获得该上下文。
2. 状态读写按用户/会话主键，更新不会每轮插入整份新快照；版本冲突遵循框架契约。
3. 删除/重置/维护移除相应旧状态，不影响其他会话；清理失败不删除登记，忙碌会话仍拒绝删除。
4. H2及自定义Bean兼容；生产缺少迁移明确失败；正常查询授权/本轮零单多全选不因恢复而扩大。
5. 测量实际MySQL快照字节、点查/更新耗时及并发状态隔离；不将单机小样本作为生产SLA。

## 不做的事

不改建模/业务规则，不重建已丢失旧状态，不自动续跑被重启打断的工具，不部署生产、不自动提交；旧MCP恢复P1另行处理。

# spec080：管理员大模型服务配置与热切换（已确认实施）

日期2026-10-21。用户说明生产默认接公司提供的OpenAI兼容服务，担心故障时需切换自有公网账号，询问管理员页面手动切换与自动回退的选择。用户后续明确授权第一版多服务配置与手动热切换，以下建议升级为实施范围；完成/验证状态以报告和CURRENT_TASK为准，不把本页当作实现已完成。

## 当前证据

- `DataAgentConfig#openaiModel`在启动时按一组URL/Key/model name构建Model Bean，并设置stream、HTTP协议及thinking参数。`dashscopeModel`只在未配置OpenAI Key时选择，不是公司服务请求失败后的自动回退。
- 现有`ConfigPage`为原始agentscope配置编辑，提示需重启；没有确认可直接使用的“公司/公网双源、热切换、健康检查”产品功能。不能只在页面加一个select就声称所有缓存Agent都换用了新模型。
- 用户授权只读参考Supersonic本地代码。`OpenAiModelFactory#createChatModel/createStreamChatModel`使用baseUrl、modelName、`ChatModelConfig#keyDecrypt`后的apiKey；`keyDecrypt`用于Supersonic自身AES存储解密。所查看创建路径未见每次请求重新计算公司HMAC签名的逻辑，不能据此断言公司凭据永不过期。
- 截图公司凭据带签名/时间等字段；应确认提供方要求的是长期Bearer凭据、定期换发，还是每次动态签名。Supersonic数据库密文不能直接作为本项目Bearer值。截图URL/Key/签名不抄入本文。
- 本项目`OpenAIClient#buildApiUrl`会拼接路径、`#buildHeaders`构造Bearer授权；Supersonic另一客户端可用不证明当前SDK最终路径一定兼容，需要脱敏桩和真实受控验收。公司服务还需支持SSE、tool_calls/tool消息与实际thinking参数。

## 建议：第一阶段管理员手动切换

用户进一步明确希望管理多个模型服务，并由全局管理员选择当前使用哪一个。建议支持多条连接，初始可配置公司/公网两条，公司作为生产默认；仅全局管理员管理，知识库MANAGE权限不等于全局模型配置权限。由管理员测试、选择并显式应用，不默认跨到公网。

### 页面与入口（用户已确认第一版）

- 放在“更多 > 大模型服务”，仅全局管理员看到入口；使用现有admin路由体系新增 `/admin/models`，无需为单项功能另建一套系统管理门户或给普通用户增加主侧栏菜单。页面面包屑“对话 > 更多 > 大模型服务”，样式沿用现有页面。
- 前端入口隐藏、路由保护、后端API的全局管理员鉴权同时落实；不能只根据前端JWT角色隐藏按钮。普通用户/库管理员直接访问API仍拒绝。
- 顶部显示当前生效连接、配置版本和切换时间。下方列表包含连接名称、model name、内网/公网标识、最近测试结果、当前使用标记，以及测试/编辑/设为当前等操作；不展示Key明文。
- 支持新增、编辑、删除多条服务连接。第一阶段聚焦实际需要的OpenAI兼容协议，不因“多个服务”扩大到未验证的多协议适配。
- “保存连接”与“设为当前”分开。编辑当前连接先保存新版本草稿，显式应用才替换有效版本；避免改一个字段就影响线上请求。当前有效连接不直接删除，需先切到其他连接；在途请求仍持有原配置版本，凭据和客户端回收不得使其失效。
- 全局当前连接统一用于问数与建模，新轮开始读取，进行中的轮次仍用原连接；不需要用户重建知识库或清空会话。当前轮失败不会因为管理员切换而自动重跑。
- 配置和当前选择需持久化，应用重启后保留。切换审计只记录连接ID/版本及操作者等元数据，不记录凭据或业务内容。

用户已确认实施此范围；实际采用原生Model代理与onAgent中间件固定整轮快照，不改框架循环或重建缓存Agent。Model代理采用保守能力声明；兼容旧启动配置，数据库/JWT/BI仍外置。

热切换通过Primary SwitchingModel覆盖启动单例、按用户缓存Agent及标题/字段分析等辅助调用。复用框架Model/onAgent契约固定每次调用；不销毁Agent/历史，不重写框架ReAct循环。HITL显式恢复及独立异步任务为新的调用边界；未增加自动工具重播。

公司服务失败时，当前轮明确显示失败及可重试；不后台自动重跑工具或整轮请求。切换后用户发起下一轮/显式重试，须保留已经执行的工具/确认事实，不假定前轮没有执行过。

## 暂不默认自动回退的原因

1. 请求包含提示、工程/字段资料、历史消息及部分数据结果。切到公网改变数据接收方，必须先明确公司允许范围；可用性不能隐式覆盖该边界。
2. 超时并不证明上游未处理，SSE可能已经输出部分内容或tool_calls；不能把半轮响应拼到另一模型，也不能重播写文件、发布、memory store或HITL。
3. 主备模型的tool_calls、上下文上限、thinking参数及输出质量可能不同，不能把普通文本请求成功当作等价。
4. 401/403、签名过期、模型名/参数错误属于认证/配置问题，不应伪装为网络故障后静默切公网。

未来若确实需要自动模式，应单独确认允许公网的数据范围，默认关闭；限定错误分类、全轮总时限/重试次数、熔断/冷却/半开探测与切换可见性。保守起点是在**尚未取得输出或工具计划**、网络连接失败/有限5xx时最多换一次，并且不得重试非幂等业务动作；不可恢复或已经开始输出时结束当前轮。具体策略需专项设计与验证，不能凭此草案直接实现自动回退。

## 第一阶段验收建议

1. 普通用户及库管理员无法读写模型配置；凭据不进入GET响应、日志、审计内容或Git。
2. 公司/公网分别通过短请求、SSE、工具调用、多轮上下文和建模HITL；URL拼接、公司认证及有效期按提供方合同核对。
3. 管理员A→B切换后新轮采用B，在途整轮仍A；重启保留选择，未执行请求不造成功记录；并发会话互不串源版本。
4. 模拟连接失败、超时、429/5xx、401/403、部分流中断；没有暗中发往另一端、重复工具或跨模型拼答案。
5. 公司网络异常时手动切换及切回可用；公网出站、费用和数据范围获确认，公网不可达时有明确结果。
6. 公共配置的两项疑似模型Key明文默认值需清除并确认轮换，替换为显式外置凭据后再构建候选；主备都不能继续依赖代码内默认值。

# spec 076：Wren 保存、索引与召回分段计时

日期：2026-10-19；状态：计时实现及本地/云端隔离诊断完成，新Java代码尚未部署云端。

2026-10-20整理：用户授权将既有修改收口提交。保留本页诊断能力及配套测试，性能优化由同事处理；本次不新增索引/预热行为，不将历史验证当本次重跑。

## 目标与边界

为保存/点赞/召回中的长等待提供可核对的分段证据。本轮只加诊断，不修改官方Wren安装文件、技能、业务模型、向量算法、权限或同步完成契约，不先实施增量索引或常驻模型优化。

## 方案

- Java记录每次CLI准备、进程启动、执行等待、输出读取及总耗时；发布工程记录锁等待、工程准备、指纹计算、索引重建和状态检查；点赞记录锁等待、初始化、保存、发布索引及总耗时。日志仅有随机trace、阶段、库ID、数值和成功/失败，不增加问题、SQL、路径内容或命令参数。
- 发布包增加按需运行的`bin/profile-wren.py`，用Python标准库sys.setprofile及单调时钟测量同环境官方CLI调用边界。输出安全的阶段汇总JSON，拆分导入、模型文件定位、模型加载、分词、推理、向量写入和schema/示例同步；不修改安装文件、不默认挂载到线上请求、不输出原始profile或用户文本。兼容资源按原环境注入。
- 深度计时包含嵌套调用，inclusive耗时不能直接相加；Python解释器及sitecustomize启动发生在脚本之前，需用外部进程总耗时对照。对每项报告调用次数，区分冷进程与同进程模型复用。异常保留原CLI退出行为。

## 验收

Java定向测试检查成功/失败/超时日志及参数不泄漏，既有发布索引/权限测试保持通过；Python标准库测试校验阶段归类和退出码/敏感参数不进JSON。独立目录复用真实6表工程，只操作测试示例和向量索引，重复测量普通CLI与profile模式并说明诊断开销。记录本地实际结果，云端未装新JAR不得称有新日志；不自动提交或部署。

实际结果：Java定向68项、Python11项通过；本地真实Java/CLI及云端临时副本完成冷进程、跟踪模式和无全局跟踪的同进程对照。详见分段计时报告（来源 `boundary-lyf@b67a179a:docs/test-reports/20261019-wren-phase-timing.md`）。本轮没有实施性能优化。

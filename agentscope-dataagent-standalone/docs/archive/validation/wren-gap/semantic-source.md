# 电商测试库业务口径

所有金额字段以人民币分保存，面向用户展示时除以100，禁止把“分”当成“元”。

有效订单：status=PAID、is_deleted=0，且关联客户存在、is_internal=0。
未知客户、空客户都不计入有效订单，但应在数据质量报告中保留异常数量。
金额为0的有效订单仍计入订单数和付费客户数。

总额按订单粒度计算，付费客户数为有效订单customer_id去重。
客户名称不能用于去重，使用customer_id。
净营收=有效订单金额减去关联该订单的SUCCESS退款金额。
FAILED退款不冲减，退款按原订单月份归属；多条退款先按order_id汇总再连接。

订单与明细为一对多：禁止连接明细后直接累加订单amount_cents。
product_code刻意包含重复P2，不允许凭字段名声明明细到商品为多对一。
refund与order虽均为事实表，refund.order_id到order.order_id仍有业务关联。
本用例用于检验“事实表之间一律禁止关系”的提示词是否过度限制。

时间范围左闭右开，时间为Asia/Shanghai本地时间，没有UTC换算。
1至4月趋势须补齐3月为0；仅按订单分组不会自然产生3月行。
“销售额”默认指有效订单总额；“净营收”指扣退款后金额。
若用户说“退款率”而未明确笔数/金额口径，应先澄清。

事件表有10005行，每行value_cents=1，总额100.05元。
默认1000行样本只有10元；10000行上限也只有100元。不能据样本回答总体总额。
code=000123是编码字符串，必须保留前导零。
note的空字符串与NULL有不同业务含义，CSV通道需声明是否保留差异。

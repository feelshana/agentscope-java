# 实施计划：Wren 原生建模与问数

日期：2026-10-11。状态：用户已确认并开始实施；各阶段完成情况追加在文末。关联 [ADR 0069](../adr/0069-wren-native-modeling-and-query-agents.md)、[spec 058](../specs/058-wren-native-modeling-and-query-agents.md)。

## 1. 目标与执行边界

本项目保留通用 AgentScope 运行时与平台服务，领域能力交给同版本官方 Wren。建模不是本体构建：输出官方工程文件，经官方编译成为 MDL；图展示是对 MDL 的只读呈现。问数也不另写一套 SQL 业务流程，而由官方 usage、schema/context/memory、SQL/Cube 工具完成。结果分析继续使用当前 Python、ECharts 和沙箱。

采用官方开源 CLI/skills/MCP，保留本项目配置的 LLM。该 LLM 仍生成 MDL/SQL，Wren 不会替我们保证业务定义正确；这与转发到 Wren 官方完整产品的聊天服务不同。实施不修改官方技能或源码，不安装一套新的本体训练服务。

用户已审阅并授权实施整体计划。不自动提交 Git，不覆盖已有未提交修改，不迁移旧数据。各阶段更新 shared-memory，记录本次测试及尚未完成事项。

## 2. 当前基线及缺口

| 环节 | 已存在且应复用 | 本轮必须处理 |
| --- | --- | --- |
| 基本模型 | MdlSeeder、YAML 工程、官方 context 构建 | 复核 seeder 不覆盖 Agent 语义成果；补充无文档/无问题端到端 |
| 建模 Agent | 官方四个技能、原生文件工具、wren_cli、单工程绑定 | Cube 禁用、参数契约偏差、同批错误串扰、重复确认、受限回滚能力 |
| 发布 | 草稿/线上分离、官方校验构建、原子快照、MCP 失效 | 移除 RefSqlMaterializer 对官方 manifest 的二次改写；保留所有官方资产及知识 |
| 问数 Agent | 原生 HarnessAgent、已发布 MCP 进程、Python/图表 | 平台 SQL 提示和 sql-analysis、WrenToolkit 专有参数/路由、未挂载官方 usage |
| 知识与示例 | 官方 memory CLI、点赞入口、knowledge/sql | 草稿/线上知识来源不统一、独立 memory 工程、向量依赖未验证、官方工具回执适配 |
| 页面 | 对话、问题表格、工程文件预览、检查与发布 | 多个遗留领域入口、Cube 目录缺失、用户不知道当前是否发布及下一步 |

实际版本：wrenai 0.15.0、wren-core-py 0.8.0。2026-10-11 PyPI 最新 wrenai 为 0.15.0（2026-09-21 发布、Beta）。现有根 pom.xml 为 standalone 构建，Java 属性 17/Boot 4.0.4，与旧 AGENTS.md 的多模块说明有差异；实施同步现状，不盲用旧 -pl 路径。

最新建模日志证明官方 Cube 提案被阻止；Agent 的指标 Markdown 漏掉内部客户排除条件。build/validate 成功不能验证这个口径。官方 memory 返回 grep/零示例，尚无真实向量召回证据。上一阶段 486 测试通过属于历史，未覆盖本轮全链路。

## 3. 目标调用方式

| 职责 | 决定流程/语义的能力 | 本项目适配 |
| --- | --- | --- |
| 数据与文档入库 | 官方工程格式与 generate-mdl | 上传、表结构材料、资料保存、owner/group 绑定 |
| 语义增强 | 官方 enrich-context、MDL/Cube 规范 | 原生受限文件工具和 CLI；不添加资产选型规则 |
| 技术检查 | 官方 validate/build/dry-plan/dry-run/query | 命令执行、时限、连接绑定和状态展示 |
| 线上问数 | 官方 usage + MCP schema/query/context/knowledge | 原生 MCP 客户端、已发布工程选择和授权 |
| 示例复用 | 官方 store/index/recall | 点赞授权、调用来源、owner/group 隔离、保存状态 |
| 分析与呈现 | 已有 run_python/render_chart | Wren 结果文件交接、图表和最终答复 |

建模 CLI 白名单围绕实际安装版完整能力审核，而非继续逐个补报错命令；仅排除未授权的外部发布、宿主环境管理或连接管理等平台权限操作。命令参数若只是官方合法语义选项，不因平台偏好禁止。工具 schema 与官方技能来自同一发布版。

问数采用通用 MCP 工程适配：从官方 listTools 获取名称/schema，按已授权工程透传工具名和原 arguments。优先原生工具注册；会话动态项目选择需薄适配时，仅增加项目选择外层，不再定义业务工具参数。调用使用 AgentScope 原生 MCP ClientWrapper，不能自写协议或 ReAct 循环。

已核对 ClientWrapper 提供 listTools/callTool，未提供 resource/prompt 的统一方法。本轮先用官方工具读取 instructions/context/knowledge；确需 resource 内容时，在 P0 验证当前 SDK 的公开接口，或使用通用只读文件能力读取同一已发布知识。不得假造框架方法，也不得以平台摘要替代官方内容。适配方式须在阶段记录中明确。

## 4. 用户旅程与确认边界

1. 上传数据/关联表：自动形成基本 Wren 工程；显示建模及发布状态。已有成功发布的基本模型即可试问，不强迫先提交文档或问题。
2. 上传业务文档、添加问题（均可选）：资料区显著展示文件、保存结果与是否已用于当前草稿；问题表格可增行/删除，不与对话入口形成两个强制流程。
3. 由官方 Agent 增强：按 enrich-context 的模式澄清口径、修复问题和提出资产。用户确认的是实际业务歧义、高影响公共资产变更；不要求用户逐项确认 YAML 校验、编译和每一条文件写操作。
4. Agent 自动检查与试问：展示正在执行、成功/失败及错误，可查看 SQL、资产定义和结果；执行失败不得宣称业务正确。不设置必验问题，也不要求两个固定验收回合。
5. 显式发布：显示草稿差异、检查状态和发布按钮；发布成功明确版本/时间、提供“去问数”。build 结束本身不显示“已发布”。
6. 问数与反馈：在发布工程上调用官方能力，结果后保留强提示点赞/点踩；点赞成功显示保存条数，未保存显示实际原因。

通用 HITL 用于授权写权限。已有业务确认覆盖的同一变更批次应只授权一次，保留拒绝与恢复；不能把批准无条件扩为整个宿主机权限。具体复用已有框架授权机制，P0/P1 检查能力后实现，不自建确认状态机。

## 5. 阶段任务、依赖和退出条件

### P0：固定版本、原生能力与基线

- 整理官方版本/skills/CLI 帮助/MCP schema 清单，固定 wrenai 0.15.0 与验证过的 engine；在项目可复现环境安装所需 mysql/mcp/memory 或 memory-onnx 依赖，不擅自改写外部共享 venv。
- 核对 strict_mode、profile/凭据绑定、read-only、memory 模型和中文支持；测试 native MCP 注册与资源读取方案、native 文件删除/回滚与授权作用域。
- 保存当前 Agent 提示、工具 schema、直接 CLI/MCP 输出和固定测试集基线。只记录脱敏信息。
- 退出：能力矩阵可核查，选定通用 MCP/知识适配，无虚构框架 API；确认同版本安装可启动、build、查询、Cube 和 memory。

### P1：补齐通用建模能力

- 修改 WrenProjectAccess、MdlWorkspaceService 的 cubes/ 访问规则；OfficialWrenToolkit 按安装版支持 cube list/describe/query 和相关合法参数。
- 撤除 Cube 禁用提示及领域选型脚本；审计 path/mdl/profile/memory 参数强绑只涉及范围和权限，不篡改官方意义。
- 通用文件操作允许官方技能在当前工程内安全撤回失败变更，禁止 symlink、越界、平台配置删除；优先已有框架方法。
- 修复 ModelingHitlMiddleware 单个 preflight 失败污染整个批次，检查重复点击/恢复；同一授权变更不重复确认。
- 不恢复旧关系/视图/问题/模式工具注册；文档上传只保存，增强由官方 Agent 执行。
- 退出：真实 official enrich-context 流程可创建关系、视图、Cube、知识并自主修复；只发生必要业务澄清与权限确认；多租户与路径测试通过。

### P2：官方产物发布与完整展示

- MdlPublishService 使用官方校验/构建产物，不再运行 RefSqlMaterializer 的 manifest 重写；检查 ref_sql 在安装版中的实际要求，并让源码符合它。
- 保留 models/views/cubes/relationships/knowledge 的官方工程内容；知识样例不再因为项目 verified 字段缺失而被过滤。平台目录解析只供展示，不影响 engine MDL。
- 发布维持原子切换及失败保持旧版；发布后更新 profile/MDL/knowledge 同一工程并失效旧 MCP 进程。对草稿的 query/build 不切线上。
- MDL UI 增加 Cube 及其底层对象、指标表达式、维度/时间维度；保留视图 SQL/ref_sql/YAML 查看。关系图直接来源 MDL，不推断本体。
- 退出：直接官方 build 与发布 engine manifest 一致；ref_sql/view/Cube 查询正常；无未发布规则泄露和失败半发布。

### P3：问数切换官方 usage 与 MCP

- DataAgentConfig 为 data-agent 挂载官方 usage，去除平台 SQL 步骤、sql-analysis 与普通模型/视图强制分支；项目身份信息保持轻量，不注入未发布业务规则。
- DataToolkitRegistrar/WrenInstanceRegistry 增加通用官方 schema 发现与 scope 绑定执行；旧 WrenToolkit 的领域工具退出注册。不回接旧 Cube 日期解析/路由实现。
- 官方 get_instructions/schema/context/knowledge/recall/run_sql/query_cube 等能力按实际服务 schema 使用；不将 CLI 版 usage 与 MCP 方法名机械混拼。如果官方技能需 CLI，也提供同一发布工程只读 CLI，读写权限与建模分离。
- Wren strict_mode 拒绝未声明模型，平台继续只读权限/函数约束/资源限制；支持官方 LIMIT 等合法语法。行数截断要展示，不能把截断数据当作完整汇总。
- 通用结果适配保留原官方响应，外加沙箱 CSV/JSON 文件及调用来源供 Python/图表使用，不更改 SQL 或业务结果。
- 退出：实际 LLM 请求中是官方技能及官方能力，SQL 与 Cube 均可调用；与直接 MCP 返回一致；越权、只读及结果文件测试通过。

### P4：统一官方 memory 与答案反馈

- 建模可选问题只有真正存入官方 knowledge/sql 的样例才进入 recall；“填写问题”“执行成功”不能冒充“已有样例”。普通知识资料按官方知识入口读取，不当作 NL/SQL 示例。
- 已发布知识为问数基础，点赞样例为授权追加来源；在当前 owner/group 的问数 runtime 工程提供这两者及同一编译 MDL，用官方后端索引。runtime 工程是部署镜像，不成为另一套模型事实源，不能混入草稿知识。
- AnswerQueryMemory 适配新的官方工具调用记录，不再仅匹配 wren_run_sql 字符串。成功采用的业务 SQL 才可保存，Cube 如未能获取实际执行 SQL 则不伪造问答对，并显示原因。
- 原始问题保持调用来源；单个 SQL 完整回答时可作 NL，多查询则使用对应业务子问题和原始问题辅助，不把整个问题无条件配给每条局部 SQL。失败/诊断/未用于答案的查询排除；选择依据记录在原生调用/产物来源中，不加项目必填语义参数到官方工具。
- 单次点赞幂等，记录成功/失败条数；不绕过点赞让 Agent 随意 store_query。点踩不撤回、不自动修改资产。官方 read-only MCP 不为所有会话开启写权限。
- 实测 memory status/index/recall 的真实后端、多语言改写、空库/未命中/依赖故障；不自研 rerank 或词项回退。召回命中后仍按当前问题生成/检查并执行查询，不直接复读旧答案。
- 退出：一问三查询（成功业务/诊断/失败）只保存业务，跨会话中文改写可官方召回；租户与草稿隔离，保存/召回链条可观测。

### P5：交互收敛与遗留链路退出

- SemanticModelingPage 主流程统一为资料 → 官方建模 → 工程检查/显式发布，模型资产查看固定可见；保留单一主要对话入口及可选问题表格。
- 去除主流程中 DocEnhanceService 手动 JSON 推断、旧领域编辑/确认和本体入口；既有 API 是否删除先扫描调用，无旧数据迁移。
- 业务文档保存成功、等待处理、处理中、草稿有更改/已发布、下一步动作要明确；修复狭窄对话及过高资料区，SQL/YAML 内容可格式化查看。
- 用户入口不展示底层安装/debug 参数，技术详情放可展开区域。
- 退出：浏览器完成无文档建模、文档增强、可选问题、多资产查看、发布、问数反馈；无需从多个按钮猜下一步。

### P6：效果对照、全量检查和交接

- 在隔离知识库生成 orders/customers 等测试表，覆盖跨月/跨年同客户、内部客户、软删除、订单状态、空值、重复关联和空时间段；为金额/客户数设独立标准 SQL 与结果。
- 固定至少 30 个中文问题，包含明确聚合、探索查询、年度/月度 DISTINCT、TopN、多查询分析、歧义澄清和近义召回。退款数据的正确口径必须由 fixture 文档定义，不能假定一律扣减。
- 对比当前基线与改造 Agent；直接 CLI/MCP 对照只能验证工具集成，不能替代 LLM 理解准确性。保存原问题、资产/参数/SQL、结果、执行错误、轮数、耗时和需澄清情况。
- 本项目建议验收目标：关键去重/过滤/权限案例 100% 正确；固定无歧义问题结果至少 90% 正确；直接工具与适配工具同输入结果 100% 一致。目标待本计划接受后生效，不是 Wren 官方公布的性能。
- 运行全量测试、打包及前端构建，检查实际服务加载新版本，再进行真实模型与浏览器验收。按固定依赖记录复现步骤。
- 退出：关键案例无遗漏、有可审阅评估报告和剩余限制；没有用执行成功或旧测试通过替代本次结果正确性。

## 6. 测试与交付方式

本 standalone 项目使用：

```powershell
mvn -Dskip.npm=true -Dskip.installnodenpm=true spotless:apply test
mvn package -DskipTests
cd frontend
npm run build
```

package 本身包含前端时不为重复验证额外重跑同一 build，除非前端随后又改动。真实 CLI/MCP 集成与向量模型依赖单独记录通过/失败/跳过，不能隐藏依赖缺失。业务效果评估不把测试 SQL 物理直查暴露成 Agent 的生产回退工具。

交付：ADR/spec/计划、通用工具实现及测试、统一页面、隔离 fixture 与标准答案、实际效果报告、ARCHITECTURE_zh.md/README/AGENTS.md 和共享记忆。新配置只写名称及安全默认值，不记录密钥。

## 7. 风险及决策原则

- 本机版本新但 Beta，不能据此保证业务效果；若固定案例失败，先根据真实 trace 区分错误源码、工具契约、知识未读和模型理解，不再加通用性不足的硬编码修补。
- official skills 依赖通用 Agent 遵守步骤，不是编译器强制约束；技术验证不能检查所有业务口径。用户只确认必要口径，开发用固定 ground truth 验证效果。
- 官方 Cube 的 COUNT DISTINCT 由声明表达式与查询时间范围决定；错误 base/过滤条件依然会错。使用官方 Cube，不使用项目旧月度聚合再累加方案。
- 向量模型安装/下载及 native SDK 资源能力需要验证；P0 尽早消除不确定性，明确记录环境限制，不能宣称已启用。
- 现有连接只支持当前已验证的上传 MySQL/单外部源范围；Wren 支持更多连接不代表平台已支持它们。本轮不扩展跨数据库连接能力。
- 上游 LLM EOF/流错误与 Wren 接入是独立问题；保留可观测性，不更换模型或传输配置来掩盖未确认根因。

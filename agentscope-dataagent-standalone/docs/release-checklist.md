# DataAgent 上线执行清单

维护日期：2026-10-21。本文只维护执行顺序和验收要求；当前分支、提交、修改及本轮验证见[当前任务](ai/CURRENT_TASK.md)，已知风险与发布待办见[上线总账](go-live-gap-review-20261012.md)。具体安装、启停命令统一引用 [Linux 单机发布手册](single-host-release.md)，不另建一套部署实现。

交运维的环境采集/条件安装与数据库命令见[65准备单](65-server-preparation.md)。系统版本未知，32CPU/252GiB不是应用配额；BI入口网关与65可以分机，但浏览器仍使用同源/dataagent/。

当前结论：主功能已实现且有分阶段真实验收，处于云端试运行及正式上线收口。最新 UI 已提交并完成构建及接口桩验证；尚未在真实后端/Nginx/BI重验。本文没有执行部署、备份、迁移或生产测试，也未重新探测云端运行版本。

## 0. 先确定发布范围

- [ ] 与同事确认性能优化、事实表时间范围限制的交付提交和配套框架依赖，核对实际代码与验收结果。当前基线不包含可确认的这两项交付。
- [ ] 确认建模工具非零退出的失败显示和同批工具结束通知由谁修复，避免两人重复改框架。
- [ ] 首发保持例行任务占位，不开放调度API；业务术语维护不会自动改写已发布模型。
- [ ] 明确目标服务器实际分配给本项目的CPU、内存、磁盘、Docker及数据库连接预算；整机总资源不等于项目配额。当前仅支持单机单实例的预算与锁语义。
- [ ] 选定真实BI同域前缀（现有方案 `/dataagent/`）、域名/HTTPS、服务运行账号、管理员名单和灰度人员。明确可接受的首问/暖问/并发等待指标；当前没有已验收的生产SLO。

完成标志：确定一个候选提交及依赖、首发范围、资源配置、验收负责人；不能只写版本名 `2.0.3-SNAPSHOT`。

## 1. 冻结候选版本并构建

在干净的候选源码副本执行。以下为 PowerShell 示例，路径为本项目目录；先安装匹配框架依赖的说明见 [发布手册](single-host-release.md#构建)。尚未接到同事提交时，不把当前包命名为“包含性能修复”。

```powershell
Set-Location D:\code\agentscope\agentscope-java\agentscope-dataagent-standalone
git rev-parse HEAD
$env:DATAAGENT_BASE_PATH = '/dataagent/'
mvn clean test
# 仅当前一条命令成功时继续
mvn package -DskipTests
# 仅构建成功时记录并交付产物
Get-FileHash target/agentscope-dataagent-2.0.3-SNAPSHOT-exec.jar -Algorithm SHA256
Get-FileHash target/dataagent-2.0.3-SNAPSHOT.tar.gz -Algorithm SHA256
Remove-Item Env:\DATAAGENT_BASE_PATH
```

- [ ] 两条Maven命令都退出0，记录通过、失败和条件跳过项。默认构建前端，Spotless也是门禁；不能跳过失败后仍交付。
- [ ] 前端统一入口为 frontend 下的 `npm test`，自动覆盖根路径与 `/dataagent/`；默认 Maven 在前端构建前执行，失败即停止。`-DskipTests` 不跳过此前端检查。旧的直接 Node 命令/data URL 编译不是当前入口；历史加载失败保留在对应报告，不代表当前模块测试仍失败。
- [ ] 核对候选JAR中的static/index.html引用实际部署前缀 `/dataagent/`，不能用根路径构建包替代。测试覆盖两种前缀不等于应用包同时支持两种前缀；clean构建可避免target/classes中的历史散列资源带入新包。
- [ ] 包内不带私有application-dev/prod配置、密钥或本机运行数据。按现有布局交付tar.gz、对应沙箱镜像及校验值；模型缓存另行交付或准备。
- [ ] spec080已移除公共application两项模型Key默认值；正式候选重新打包后检查产物，并由凭据负责人确认历史凭据是否需轮换；不能用私有配置排除检查代替整个候选凭据检查。旧包不会自动更新。
- [ ] **配套材料另行交付**：当前assembly只放bin/conf/lib、requirements与根README，迁移SQL、BI脚本和完整docs并未内置。请从同一候选提交导出受版本管理的正式docs资料并保持层级，使用其中docs/single-host-release.md及本清单；不复制工作区中的忽略文件、个人交接或私有运行材料。包根README的相对文档链接不能当作所有附件均已携带。

记录提交号、匹配框架版本/制品、JAR与tar SHA256、镜像imageId/归档SHA256、Wren依赖版本、前缀和外置配置版本（不记录密钥值）。构建前缀会改本地生成的static，勿因此未经审阅又提交生成结果。

## 2. 准备服务器及依赖

- [ ] Linux、Java17+、Python3.11+、Bash、flock/util-linux、Docker准备完成；运行账号能读取发布目录/Wren环境及访问Docker和两个数据库。
- [ ] 按 [首次部署](single-host-release.md#首次部署) 安装Wren系统编译依赖及独立venv，使用随包 `requirements-wren.txt` 的固定版本。不要在正式环境临时升级官方Wren。
- [ ] 以实际运行账号执行包内 `check-wren.py dependencies`，CLI/Python必须同一环境；不要用root检查通过代替运行账号检查。
- [ ] 按 [沙箱镜像](single-host-release.md#沙箱镜像与离线导入) 构建或离线导入对应架构镜像，验分析库、中文字体及setsid；正式配置的镜像必须与验收一致。tabulate不在当前Dockerfile中，若业务代码需要DataFrame.to_markdown，应补镜像依赖或采用不依赖它的输出，不能临时在隔离沙箱联网安装。
- [ ] 向量模型在实际应用HOME/HF_HOME下缓存并由运行账号做离线加载检查；依赖导入通过不等于模型可用。历史云机已准备不等于新服务器也已准备。

完成标志：运行账号依赖预检及离线模型通过，目标镜像可运行且有校验记录。此时还不算业务验收通过。

## 3. 准备数据库及私有配置

- [ ] 平台元数据库与上传数据集MySQL分开配置。平台保存用户/权限/会话状态等，上传库保存ds_物理表；备份和恢复两者都必须覆盖。
- [ ] 核对实际平台schema后应用需要的 [0080](migrations/0080-dataset-sampling-mysql.sql)、[0081](migrations/0081-bi-login-mysql.sql)、[0083](migrations/0083-chart-owner-mysql.sql)、[0084](migrations/0084-agent-state-mysql.sql)、[0088](migrations/0088-model-services-mysql.sql)。增量迁移不等于完整首次建库脚本；已存在列不重复ALTER。
- [ ] 为模型配置注入独立`DATAAGENT_MODEL_ENCRYPTION_KEY`，或持久保存应用HOME中的model-services.key；主密钥与平台库配套备份。管理员页面配置公司/公网连接，完成受控测试后显式应用。公司路径、Bearer签名有效期、SSE/tool_calls和公网数据范围需真实确认。
- [ ] **全新空平台库的缺口**：当前没有一份完整、已验收的首次schema初始化脚本。先由候选版本在隔离空库生成并核对结构，导出纯结构经DBA复核后导入目标库；不能只执行以上增量SQL就直接启prod，也不把生产临时改为update作为默认部署步骤。这个准备未完成则停在本步。
- [ ] 从发布包 `conf/application-prod.yml.example` 创建目标配置，生产保持ddl-auto=validate、SQL演示初始化关闭、密码登录关闭/BI启用。私有配置不入Git，不复制开发数据库或开发用户种子。
- [ ] 配置平台DB URL/账号/密码、独立上传库连接、JWT密钥、独立BI Base64共享密钥、CORS同源地址、模型供应商key/base URL/model name、Wren CLI/Python、实际镜像/资源预算。变量及配置位置见 [生产配置清单](single-host-release.md#生产配置清单)。
- [ ] 生产公司模型默认接入需分别验证认证有效期、最终URL、SSE及tool_calls；自有公网备用先确认允许的数据范围及65出站。spec080管理员配置、测试和手动热切换已实现，目标环境仍需验证；没有请求失败自动切公网的行为。
- [ ] 管理员使用稳定的真实BI用户名维护roles_csv，不覆盖已有user_id；新JWT才反映角色变更。首次普通用户可自动创建，不代表管理员已准备好。

## 4. 安装与启动

- [ ] 按 [启停与升级](single-host-release.md#启停与升级) 备份旧包/配置，使用相邻版本目录与版本外持久data；不要覆盖正在运行的同名SNAPSHOT目录或同时启动两个版本。
- [ ] 升级前暂停入口、等待或取消在途工作，备份平台库、上传库、data持久目录及外置配置/模型缓存位置；记录备份时间与恢复点。
- [ ] 按手册执行 `./bin/dataagent.sh start`，读取该版本logs/launcher.log。脚本依赖预检和HTTP健康通过后才返回成功；失败先看日志，不重复启动未知进程。
- [ ] 核对实际PID、JAR路径/哈希、配置版本和镜像，与候选记录一致。健康接口UP仅代表应用就绪，不代表问数/发布/召回通过。

## 5. 接入Nginx与真实BI

- [ ] 按 [BI对接](integration/bi-login.md#同域构建与nginx) 配置HTTPS同源 `/dataagent/`、正确剥离前缀、关闭SSE缓冲、上传大小及长请求超时；应用8080不直接作为公共入口。
- [ ] BI前端使用 [bi-login.mjs](integration/bi-login.mjs)，读取真实用户名；正式密钥私下交付，JWT不放URL。模拟BI联通只能作为预演。
- [ ] 验证新进入、刷新、30分钟固定过期、切账号、无权限、深层路由刷新、附件下载和流式输出；prod密码入口应禁用。
- [ ] 确认已接受的认证边界仍符合使用范围：前端共享密钥可提取并伪造用户名，包含管理员；BI退出不即时撤销已发JWT。若使用范围改变，需要另行设计认证，不能当作当前已具备可信SSO。

## 6. 在候选版本执行正式验收

使用独立验收账号/知识库和可核对数据，保留原用户资产。每项记录时间、候选制品、输入、预期、实际和证据。

| 类别 | 必须验证 |
| --- | --- |
| 基本链路 | 上传→基础模型→资料/HITL→检查→显式发布→问数→SQL/图表/Python/下载→点赞保存→跨会话召回 |
| 本次UI真实联调 | 数据源配置/检测/详情，术语新增/编辑/删除/切库，历史导航和工作区权限；原型截图/API桩不能替代 |
| 权限 | QUERY/MANAGE、撤权后排队请求、零/单/多/全选、不读其他用户会话/图表/附件；任务API仍禁用 |
| 故障与恢复 | CLI非零显示失败、发布失败保留旧快照、MySQL/Doris断连及冷却恢复、应用重启后继续追问、取消后Python子进程退出 |
| 业务结果 | 业务人员核对关键指标及对应SQL，包含时间边界、去重粒度、取消订单/复购；不要求本轮新增准确性规则定制，但不能只看有回答 |
| 规模与性能 | 目标配额下10人以上同库/多库混合，冷首问/发布后首问/暖问/点赞，排队/取消；若首发宣称支持50万行则补测该边界，否则先降低承诺/配置 |
| 稳定性 | 按实际业务周期持续运行，观察RSS/子进程/容器、磁盘、数据库连接、错误率和时延，配置对应监控与告警 |

当前历史10用户通过、最大168893行、六份云端文件和暖召回数据只作为参考；不是最终候选在目标机器的验收结果。建议做一次覆盖日常使用周期的长稳演练，时长与通过阈值在执行前确定。

## 7. 验证回退、恢复，再灰度

- [ ] 在隔离环境实际演练停止新版本、恢复兼容旧版本及配置；数据库向后兼容另核验，不能只换JAR。
- [ ] 实际还原备份的两个数据库与持久文件，检查用户/授权/上传表、历史/Agent状态、工程/published和附件一致；仅有备份文件不算恢复通过。
- [ ] 明确告警、值守/回退负责人和触发条件；先小范围授权，观察再扩人。以上有阻断失败就回到对应步骤处理。

**正式放行条件**：候选制品与实际部署一致；首发链路、权限及恢复检查通过；同事交付已验收；目标配额性能达到约定；真实BI/HTTPS通过；已知未修项有负责人及明确接受范围。最终上线决定由用户作出。
